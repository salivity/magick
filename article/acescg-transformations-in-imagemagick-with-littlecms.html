ACEScg Transformations in ImageMagick with LittleCMS

When compiled with LittleCMS (lcms2) support, ImageMagick manages wide-gamut ACEScg transformations by delegating International Color Consortium (ICC) profile operations to the LittleCMS color management engine. This integration allows ImageMagick to translate pixel data between standard spaces (such as sRGB, Display P3, or Adobe RGB) and the scene-linear, wide-gamut ACEScg (AP1) color space. By coupling LittleCMS with ImageMagick's High Dynamic Range Imaging (HDRI) architecture, the software preserves extended dynamic range values, handles chromatic adaptation between distinct white points, and ensures accurate color conversions across visual effects and rendering pipelines.

The Role of LittleCMS Delegation

ImageMagick's native color capabilities are primarily restricted to basic colorspace flags, simple matrices, and gamma shifts. By compiling ImageMagick with the --with-lcms2 flag, color-management tasks are delegated directly to the LittleCMS library. LittleCMS is an open-source, C-based color engine that calculates exact mathematical conversions through standard ICC profiles, ensuring that wide-gamut definitions are evaluated with mathematical rigor rather than simple approximations.

HDRI Requirement for Linear ACEScg Data

ACEScg is an encoding standard under the Academy Color Encoding System tailored for computer graphics, utilizing AP1 primaries and a linear (gamma 1.0) transfer curve. Because ACEScg is scene-referred, pixel values are not bounded between 0.0 and 1.0; specular highlights, light sources, and reflections routinely exceed 1.0, while camera noise or gamut conversion artifacts can fall below 0.0.

To maintain integrity during an ACEScg transformation, ImageMagick must be compiled in an HDRI-enabled build (such as Q16HDRI or Q32HDRI). Without HDRI, LittleCMS would receive and return clamped integer pixel buffers, clipping negative values to pure black and values above 1.0 to maximum white, fundamentally destroying the high-dynamic-range data. In an HDRI build, ImageMagick feeds LittleCMS floating-point buffers, enabling calculations across the entire exposure range.

Managing ACEScg via ICC Profiles

While many visual effects pipelines utilize OpenColorIO (OCIO) for ACES handling, ImageMagick operates via ICC-based management. Transforming to or from ACEScg requires an ICC profile that accurately encodes:

  1. The AP1 Primaries: The wide color gamut coordinates defining the red, green, and blue corners of ACEScg.
  2. The White Point: The standard ACES white point, which approximates D60 (x: 0.32168, y: 0.33767).
  3. The Linear Transfer Characteristic: An uncurved gamma of 1.0 (TRC tags set to linear).

In an ImageMagick command pipeline, the -profile operator orchestrates the execution. For an image lacking an embedded profile, the first -profile call assigns the source profile (e.g., standard sRGB). A secondary -profile call dictates the destination profile (e.g., an ACEScg profile):

magick input_srgb.png -profile sRGB.icc -profile ACEScg.icc output_acescg.exr

Profile Connection Space and Chromatic Adaptation

When the transformation is triggered, LittleCMS constructs a multi-stage transform pipeline (cmsCreateTransform):

  • Decoding: LittleCMS parses the source profile, applying inverse tone response curves (TRCs) to convert non-linear input (such as an sRGB gamma curve) into linear color metrics.
  • PCS Translation: Pixels are projected into the Profile Connection Space (PCS), typically CIEXYZ or CIELAB.
  • Chromatic Adaptation: ACEScg uses a ~D60 white point, whereas common gamuts like sRGB or Rec.709 are calibrated to D65. LittleCMS automatically detects this discrepancy via the chromaticAdaptationTag embedded in the ICC profiles. It executes a chromatic adaptation matrix transformation—typically using the Bradford or CIECAM02 model—to align the source white point to the ACEScg target.
  • Gamut Matrixing: The linear, adapted XYZ coordinates are mapped against the AP1 primary matrix defined in the ACEScg ICC profile.

Rendering Intents and Gamut Mapping

ImageMagick exposes LittleCMS rendering intents via the -intent flag. During ACEScg transformations:

  • Relative Colorimetric (-intent Relative): The standard choice for scene-referred imagery. It aligns the white points via the adaptation matrix and scales color data into the destination primaries without applying artificial gamut compression curves.
  • Perceptual (-intent Perceptual): Often avoided when converting to ACEScg, as it attempts to compress dynamic range into a target gamut based on vendor-specific lookup tables, which disrupts linear calculations.

Through this sequence—pairing floating-point HDRI memory storage with LittleCMS-driven ICC profile mathematics—ImageMagick translates imagery into and out of the ACEScg color space without dynamic range clipping, unexpected color clipping, or tonal distortion.
