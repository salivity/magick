Benchmark ImageMagick Execution Speed with -bench

This article explains how to measure and analyze the execution performance of ImageMagick commands using its built-in -bench switch. ImageMagick includes this native benchmarking tool to help developers and system administrators evaluate image processing speed, compare algorithm efficiency, test multi-threading performance, and identify resource bottlenecks across multiple iterations without relying on external timing utilities.

What is the -bench Switch?

The -bench option instructs ImageMagick to repeat a given command pipeline for a specified number of iterations. Instead of simply processing the command once, it loops the operation and outputs precise performance metrics, including total execution time, user time, system time, and throughput measured in operations per second.

Basic Syntax

To use the benchmark switch, place -bench <iterations> within your command:

magick input.jpg [operations] -bench <iterations> null:

Note: In ImageMagick v7, the primary CLI tool is magick. For ImageMagick v6, replace magick with convert.

Using null: as the output destination discards disk write overhead, ensuring the benchmark measures image processing performance rather than disk input/output speed.

Practical Examples

1. Benchmarking an Image Resize

To benchmark resizing an image 50 times:

magick input.jpg -resize 800x600 -bench 50 null:

2. Measuring Complex Processing Pipelines

You can test complex chains involving multiple filters, color profile conversions, and sharpening:

magick input.png -colorspace Gray -gaussian-blur 0x2 -bench 20 null:

3. Comparing Formats and Encoders

To measure encoding performance when converting to modern formats like WebP or AVIF, benchmark direct writes:

magick input.jpg -quality 80 -bench 10 output.webp

4. Testing Multi-Core and OpenMP Scalability

ImageMagick utilizes OpenMP for multi-threaded processing. You can test multi-core scaling by combining -bench with the -limit option:

Single-threaded test:

magick input.jpg -limit thread 1 -resize 1920x1080 -bench 20 null:

Multi-threaded test (e.g., 4 threads):

magick input.jpg -limit thread 4 -resize 1920x1080 -bench 20 null:

Understanding the Benchmark Output

After completing the iterations, ImageMagick prints a performance summary to the standard error stream:

Performance: 50i 0.485ips 103.010e 28.320u 1:43.080R

The metrics break down as follows:

  • 50i (Iterations): The total number of iterations executed.
  • 0.485ips (Iterations Per Second): Throughput of the command pipeline. Higher values indicate better performance.
  • 103.010e (Elapsed Time): Total wall-clock time in seconds spent processing.
  • 28.320u (User Time): Total CPU time spent in user-mode code.
  • 1:43.080R (Real Time): Total time displayed in standard minutes:seconds.milliseconds format.

Best Practices for Accurate Benchmarking

  • Warm up the cache: Run a short iteration first (e.g., -bench 5) to load libraries and populate file system caches before running a larger benchmark (e.g., -bench 100).
  • Isolate tests: Minimize background tasks and CPU usage from other applications to prevent resource contention.
  • Use adequate iteration counts: Small images or simple operations execute quickly; use at least 50 to 100 iterations to minimize timing anomalies caused by CPU frequency scaling.
