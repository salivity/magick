Benchmark ImageMagick Resizing Across Threads

This guide explains how to benchmark image resizing algorithms across multiple CPU thread counts using ImageMagick. You will learn the primary command structure, how to limit thread utilization, how to select specific resampling filters, and how to automate tests across multiple thread configurations to measure scaling performance.

The ImageMagick Benchmark Command

The standard command to benchmark image resizing in ImageMagick 7 utilizing a specific thread count is:

magick -bench 20 -limit thread 4 input.jpg -filter Lanczos -resize 50% null:

For ImageMagick 6, replace magick with convert:

convert -bench 20 -limit thread 4 input.jpg -filter Lanczos -resize 50% null:

Breakdown of Command Parameters

  • -bench 20: Runs the operation 20 times in succession. ImageMagick measures the execution time and outputs total elapsed time, user time, system time, and performance throughput in operations per second.
  • -limit thread 4: Restricts the OpenMP thread pool to 4 threads. Adjust this number to test performance across single-core, quad-core, or higher core counts.
  • input.jpg: The source image you want to resize.
  • -filter Lanczos: Specifies the resampling filter to benchmark. ImageMagick supports numerous filters, including Triangle (bilinear), Box, Mitchell, Gaussian, and Bicubic.
  • -resize 50%: The target geometry. You can use percentages or explicit pixel values (e.g., 1920x1080).
  • null:: A special sink output format that discards the result in memory, preventing disk write speeds from skewing your CPU performance measurements.

Benchmarking Across Multiple Thread Counts

Because ImageMagick does not accept a list of thread values in a single argument, you can automate tests across multiple thread configurations using a shell loop.

Bash / Linux / macOS Shell Script

#!/bin/bash
IMAGE="input.jpg"
ITERATIONS=10
FILTER="Lanczos"
GEOMETRY="50%"

for THREADS in 1 2 4 8 16; do
  echo "Testing with $THREADS thread(s)..."
  magick -bench $ITERATIONS -limit thread $THREADS "$IMAGE" -filter $FILTER -resize $GEOMETRY null:
done

Windows PowerShell Script

$image = "input.jpg"
$iterations = 10
$filter = "Lanczos"
$geometry = "50%"
$threadCounts = @(1, 2, 4, 8, 16)

foreach ($threads in $threadCounts) {
    Write-Host "Testing with $threads thread(s)..."
    magick -bench $iterations -limit thread $threads $image -filter $filter -resize $geometry null:
}

Benchmarking Multiple Resizing Algorithms

To compare how different algorithms scale across different thread counts, nest the thread loop inside a filter loop:

#!/bin/bash
IMAGE="input.jpg"

for FILTER in Triangle Mitchell Lanczos Gaussian; do
  echo "=========================================="
  echo "Algorithm: $FILTER"
  echo "=========================================="
  for THREADS in 1 2 4 8; do
    echo "Threads: $THREADS"
    magick -bench 10 -limit thread $THREADS "$IMAGE" -filter $FILTER -resize 50% null:
  done
done

Interpreting the Output

When -bench completes, ImageMagick prints timing data to the terminal:

Performance: 10i 0.421ips 23.750e 18.210u 0.320s
  • 10i: Total completed iterations.
  • 0.421ips: Iterations per second (higher is better).
  • 23.750e: Total elapsed wall-clock time in seconds (lower is better).
  • 18.210u: Total user CPU time spent across all threads.
  • 0.320s: Total system CPU time spent on kernel-level operations.

To calculate multithreading efficiency, compare the elapsed wall-clock time (e) between single-thread (-limit thread 1) and multi-thread runs.
