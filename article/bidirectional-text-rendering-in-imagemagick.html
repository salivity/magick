Bidirectional Text Rendering in ImageMagick

This article explains how to handle bidirectional (BiDi) text rendering in ImageMagick for scripts that mix right-to-left (RTL) and left-to-right (LTR) languages, such as Arabic or Hebrew combined with English. It covers the primary -direction parameter, the underlying library requirements for proper glyph shaping, and practical command-line examples.

The Bidirectional Parameter: -direction

In ImageMagick, the primary parameter used to control bidirectional text rendering and writing direction is -direction.

To specify right-to-left text processing, use:

-direction right-to-left

For standard left-to-right text:

-direction left-to-right

Underlying Dependencies for BiDi Support

The -direction setting relies on ImageMagick being compiled with Complex Text Layout (CTL) support via libraqm, FriBidi, and HarfBuzz. Without these libraries enabled in your ImageMagick build, setting -direction right-to-left may reverse character order without applying the necessary contextual shaping required by scripts like Arabic.

You can verify if your installation supports Raqm by running:

magick -version

Look for raqm under the Delegates (built-in) output.

Command-Line Examples

Basic Right-to-Left Text Rendering

To render Arabic or Hebrew text correctly on an image canvas:

magick -size 500x200 xc:white \
  -font "Amiri-Regular" -pointsize 32 -fill black \
  -direction right-to-left -annotate +450+100 "مرحبا بالعالم" \
  output.png

Mixed BiDi Text

When rendering strings containing both RTL and LTR segments (for example, Arabic text containing an English product name or numbers), setting -direction right-to-left ensures the BiDi algorithm correctly positions the embedded LTR text according to Unicode Bidirectional Algorithm standards.

magick -size 600x200 xc:lightgray \
  -font "Arial" -pointsize 28 -fill black \
  -direction right-to-left -annotate +550+110 "ImageMagick الإصدار 7" \
  bidi_output.png

Alternative Method: Using the Pango Delegate

If your ImageMagick build lacks direct Raqm support, bidirectional text can also be rendered using the pango: delegate, which handles BiDi processing automatically via the Pango engine:

magick -background white -fill black -font "Amiri" \
  pango:"مرحبا بالعالم 2026" pango_output.png
