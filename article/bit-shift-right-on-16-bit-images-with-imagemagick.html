Bit Shift Right on 16-Bit Images with ImageMagick

This guide explains how to perform a bitwise right shift operation on 16-bit image pixels using ImageMagick's command-line tools. You will learn the specific operators required for bit shifting, how to verify that your ImageMagick build supports 16-bit operations, and alternative methods to achieve equivalent pixel value scaling.

Verify 16-Bit Support (Q16)

Before performing bitwise operations on 16-bit images, ensure your ImageMagick installation is built with Quantum Depth 16 (Q16). Run the following command in your terminal:

magick -version

Look for Q16 or Q16-HDRI in the output features. A Q8 version will restrict internal processing to 8-bit values (0–255), which will truncate 16-bit image data.

Using the RightShift Operator

ImageMagick provides a direct bitwise operator via the -evaluate command. A right shift moves all binary bits of the pixel value to the right by a specified number of positions, effectively dividing the pixel value by \(2^n\) (where \(n\) is the shift amount) and discarding any fractional remainder.

To shift all channels right by 2 bits on a 16-bit TIFF image:

magick input.tif -depth 16 -evaluate RightShift 2 output.tif

If you are using ImageMagick 6, replace magick with convert:

convert input.tif -depth 16 -evaluate RightShift 2 output.tif

Applying the Shift to Specific Channels

By default, -evaluate operates on all channels except the alpha channel in modern ImageMagick versions. To explicitly control which channels receive the bit shift, use the -channel flag:

magick input.tif -depth 16 -channel RGB -evaluate RightShift 4 +channel output.tif

The +channel switch resets the channel mask back to default after the operation.

Mathematical Alternative: Division

In digital imaging, a bit shift right by \(n\) bits is functionally identical to integer division by \(2^n\):

  • Shifting right by 1 bit = divide by 2
  • Shifting right by 2 bits = divide by 4
  • Shifting right by 4 bits = divide by 16
  • Shifting right by 8 bits = divide by 256

If you are running an environment where RightShift behaves unexpectedly due to High Dynamic Range Imaging (HDRI) floating-point conversions, use the Divide operator instead:

magick input.tif -depth 16 -evaluate Divide 4 output.tif

This ensures the 16-bit pixel values (ranging from 0 to 65,535) are reduced predictably across non-integer pixel pipelines.
