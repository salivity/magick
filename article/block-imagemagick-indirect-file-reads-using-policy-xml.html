Block ImageMagick Indirect File Reads Using policy.xml

ImageMagick includes a feature where an at-sign (@) preceding a filename indicates an indirect read, instructing the program to read arguments or data directly from the specified file. While useful in scripted environments, this feature can lead to arbitrary local file disclosure (LFI) vulnerabilities if untrusted user input is processed. This article explains the specific security policy directive used to disable indirect file reads in ImageMagick and how to implement it to harden your server.

The Security Setting

To prevent ImageMagick from processing indirect reads using the @ character, you must define a path policy in the policy.xml configuration file with the rights attribute set to none for any path starting with an at-sign.

Add the following directive inside the <policymap> section:

<policy domain="path" rights="none" pattern="@*" />

This rule prevents ImageMagick from interpreting file paths or parameters beginning with @, effectively neutralizing attempts by attackers to read arbitrary files from the underlying operating system.

Locating policy.xml

The policy.xml file is typically located in your system's global ImageMagick configuration directory. Common paths include:

  • Linux (Debian/Ubuntu): /etc/ImageMagick-6/policy.xml or /etc/ImageMagick-7/policy.xml
  • Linux (RHEL/CentOS): /etc/ImageMagick/policy.xml
  • macOS (Homebrew): /usr/local/etc/ImageMagick-7/policy.xml or /opt/homebrew/etc/ImageMagick-7/policy.xml

You can verify the exact configuration path used by your installation by running:

magick -list configure | grep CONFIGURE_PATH

(On ImageMagick 6, replace magick with convert)

Implementation and Verification

  1. Open policy.xml with administrative privileges:

    sudo nano /etc/ImageMagick-6/policy.xml

  2. Place the directive within the <policymap> block:

    <policymap>
  <!-- Prevent indirect reads using the '@' prefix -->
  <policy domain="path" rights="none" pattern="@*" />
</policymap>

  3. Save the file and exit. The policy takes effect immediately without needing to restart system services.

  4. Test the configuration by attempting to read a file using the @ prefix:

    magick convert @/etc/passwd output.png

    If configured correctly, ImageMagick will reject the operation and output a policy error:

    convert: not authorized `@/etc/passwd' @ error/property.c/GetProperty/3860.
