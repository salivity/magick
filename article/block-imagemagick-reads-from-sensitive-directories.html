Block ImageMagick Reads from Sensitive Directories

Securing ImageMagick requires restricting its access to the underlying filesystem to prevent Local File Inclusion (LFI) and unauthorized data disclosure vulnerabilities. By modifying the policy.xml configuration file, administrators can define granular path policies that explicitly deny read and write permissions to sensitive system paths such as /etc, /root, or application-specific configuration directories.

1. Locate the ImageMagick Policy File

ImageMagick's security policies are managed in the policy.xml file. The exact path depends on your operating system and ImageMagick version:

  • ImageMagick 6 (Debian/Ubuntu): /etc/ImageMagick-6/policy.xml
  • ImageMagick 7 (Debian/Ubuntu/RHEL): /etc/ImageMagick-7/policy.xml
  • General Unix/Linux systems: /etc/ImageMagick/policy.xml or /usr/local/etc/ImageMagick-7/policy.xml

You can verify the exact file location by running:

magick -list configure | grep -i "CONFIGURE_PATH\|POLICY_PATH"

(Use convert -list configure for ImageMagick 6).

2. Configure Path-Based Read Restrictions

Open policy.xml in a text editor with root or administrative privileges:

sudo nano /etc/ImageMagick-6/policy.xml

Locate the <policymap> block. You can block read access using policies with the domain="path" attribute.

Option A: Blacklist Sensitive Directories

To prevent ImageMagick from reading or writing to specific directories such as /etc, /root, or hidden configuration files, add the following rules inside the <policymap> tags:

<policymap>
  <!-- Block access to sensitive system paths -->
  <policy domain="path" rights="none" pattern="/etc/*"/>
  <policy domain="path" rights="none" pattern="/root/*"/>
  <policy domain="path" rights="none" pattern="/var/run/*"/>
  <policy domain="path" rights="none" pattern="/proc/*"/>
  <policy domain="path" rights="none" pattern="/sys/*"/>
  <policy domain="path" rights="none" pattern=".*"/> <!-- Blocks hidden files like .env -->
</policymap>

Option B: Use an Allowlist (Recommended)

A more secure approach is to block access to the entire filesystem by default and only allow read operations in designated application directories:

<policymap>
  <!-- Deny access to everything by default -->
  <policy domain="path" rights="none" pattern="*"/>

  <!-- Allow read and write access only to specific directories -->
  <policy domain="path" rights="read | write" pattern="/var/www/html/uploads/*"/>
  <policy domain="path" rights="read | write" pattern="/tmp/*"/>
</policymap>

Note: Rules are evaluated in the order they appear. Place generic denial rules above specific allow rules if your ImageMagick version processes rules sequentially.

3. Disable Dangerous Coders

Attackers frequently bypass path policies using built-in ImageMagick coders designed to read local files (such as TEXT, SHOW, MSL, or LABEL). Disable these directly in policy.xml:

<policy domain="coder" rights="none" pattern="TEXT" />
<policy domain="coder" rights="none" pattern="SHOW" />
<policy domain="coder" rights="none" pattern="MSL" />
<policy domain="coder" rights="none" pattern="LABEL" />

4. Verify the Policy Enforcement

Test the configuration to ensure the restrictions are active. Attempt to read a protected file using the convert or magick command:

convert /etc/passwd output.png

If the policy is configured correctly, ImageMagick will reject the operation with an error message:

convert: not authorized `/etc/passwd' @ error/constitute.c/ReadImage/412.
