Build ImageMagick as a Static Binary on Linux

Building ImageMagick as a fully static, standalone binary on Linux allows you to distribute and run the magick executable across any distribution without shared library dependencies or glibc version conflicts. This guide provides a direct, step-by-step walkthrough to compiling ImageMagick using Alpine Linux and musl-libc—the most reliable environment for producing true static binaries—including downloading source code, compiling static delegates for image format support, configuring static linkage flags, and verifying the final output.

Why Use Alpine Linux (musl-libc)

While it is possible to compile statically on glibc-based systems (like Ubuntu or CentOS), glibc is not designed for true static linking and often issues runtime warnings regarding Name Service Switch (NSS) functions. Alpine Linux uses musl, which fully supports 100% static compilation. You can run these commands inside an Alpine Linux container or directly on an Alpine host.

Step 1: Install Build Dependencies and Static Delegates

Launch an Alpine Linux shell and install the build tools and static development packages for the image formats you intend to support:

apk update
apk add --no-cache \
    build-base \
    pkgconf \
    curl \
    tar \
    zlib-dev zlib-static \
    libpng-dev libpng-static \
    libjpeg-turbo-dev libjpeg-turbo-static \
    libwebp-dev libwebp-static \
    freetype-dev freetype-static \
    libxml2-dev libxml2-static

If you require other delegates (such as OpenJPEG, TIFF, or Ghostscript), ensure you install their corresponding static (*-static) packages.

Step 2: Download and Extract ImageMagick Source

Fetch the latest source release from ImageMagick's source repository:

IMAGE_MAGICK_VER="7.1.1-43"
curl -LO https://download.imagemagick.org/ImageMagick/download/ImageMagick-${IMAGE_MAGICK_VER}.tar.gz
tar -xzf ImageMagick-${IMAGE_MAGICK_VER}.tar.gz
cd ImageMagick-${IMAGE_MAGICK_VER}

Step 3: Configure the Build for Static Compilation

Configure the build system to enforce static linking, disable dynamic loading, and disable shared libraries:

./configure \
    CC=gcc \
    CXX=g++ \
    CFLAGS="-O2 -fPIC" \
    CXXFLAGS="-O2 -fPIC" \
    LDFLAGS="-static -all-static" \
    PKG_CONFIG="pkg-config --static" \
    --enable-static \
    --disable-shared \
    --disable-modules \
    --disable-installed \
    --without-x \
    --without-utilities-extra \
    --without-perl \
    --without-magick-plus-plus \
    --with-zlib=yes \
    --with-png=yes \
    --with-jpeg=yes \
    --with-webp=yes \
    --with-freetype=yes \
    --with-xml=yes

Key configuration flags explained:

  • --enable-static --disable-shared: Builds static archives (.a) instead of dynamic objects (.so).
  • --disable-modules: Links all delegate decoders and encoders directly into the core binary rather than loading them as external .so plugins.
  • LDFLAGS="-static -all-static": Directs the linker to bind all C runtime and delegate library symbols into the executable.
  • PKG_CONFIG="pkg-config --static": Ensures dependent library flags pull in their nested dependencies.

Step 4: Compile and Link

Compile the project using all available CPU cores:

make -j$(nproc)

Once compilation completes, the main standalone binary will be located at utilities/magick.

You can optionally strip debug symbols to significantly reduce binary size:

strip --strip-all utilities/magick

Step 5: Verify the Static Binary

Verify that the binary has no shared library dependencies by running ldd and file:

file utilities/magick

The output should report: ELF 64-bit LSB executable, statically linked.

Next, run:

ldd utilities/magick

The output should state:

utilities/magick: Not a dynamic executable

Test image format decoding and conversion:

./utilities/magick -version
./utilities/magick logo: logo.png
./utilities/magick logo.png logo.jpg

The resulting magick file is now a completely portable, standalone binary that can be copied to and run on any x86_64 Linux machine.
