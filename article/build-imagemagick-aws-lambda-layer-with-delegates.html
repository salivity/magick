Build ImageMagick AWS Lambda Layer with Delegates

This guide explains how to compile ImageMagick alongside its essential shared library delegates—such as libpng, libjpeg, and libwebp—into an AWS Lambda layer. Because the standard AWS Lambda runtime lacks native image processing binaries and common delegate libraries, compiling ImageMagick inside an official Amazon Linux container ensures binary compatibility and enables full support for reading and writing multiple image formats.

Why Delegates Are Required

ImageMagick relies on external shared libraries (delegates) to decode and encode formats like JPEG, PNG, TIFF, and WebP. If you compile ImageMagick without these development packages installed and linked, running the resulting binary inside Lambda will fail whenever you attempt to process standard image formats. To package these dependencies properly, binaries must reside in /opt/bin and shared objects (.so files) in /opt/lib.

Step 1: Create the Dockerfile

Using an Amazon Linux 2023 base image ensures the compiled binaries are compatible with modern Lambda runtimes.

Create a file named Dockerfile:

FROM public.ecr.aws/sam/build-provided.al2023:latest AS builder

# Install build tools and delegate development libraries
RUN dnf install -y \
    gcc \
    gcc-c++ \
    make \
    tar \
    gzip \
    zip \
    libpng-devel \
    libjpeg-turbo-devel \
    libwebp-devel \
    libtiff-devel \
    freetype-devel \
    ghostscript-devel

# Set up build directories
WORKDIR /build

# Download and extract ImageMagick source code
ARG IM_VERSION=7.1.1-32
RUN curl -L https://github.com/ImageMagick/ImageMagick/archive/refs/tags/${IM_VERSION}.tar.gz -o ImageMagick.tar.gz && \
    tar -xzf ImageMagick.tar.gz && \
    cd ImageMagick-${IM_VERSION} && \
    ./configure \
        --prefix=/opt \
        --enable-shared \
        --disable-static \
        --with-png=yes \
        --with-jpeg=yes \
        --with-webp=yes \
        --with-tiff=yes \
        --with-freetype=yes \
        --without-x \
        --without-perl && \
    make -j$(nproc) && \
    make install

# Collect ImageMagick binaries and delegate shared libraries
WORKDIR /opt
RUN mkdir -p /layer/bin /layer/lib

# Copy compiled binaries
RUN cp /opt/bin/magick /layer/bin/ && \
    ln -s /layer/bin/magick /layer/bin/convert && \
    ln -s /layer/bin/magick /layer/bin/identify

# Copy dependent shared libraries to layer lib directory
RUN cp /opt/lib/libMagickCore-*.so* /layer/lib/ && \
    cp /opt/lib/libMagickWand-*.so* /layer/lib/

# Identify and copy shared libraries from the system to /layer/lib
RUN for bin in /opt/bin/magick /layer/lib/*.so*; do \
        ldd "$bin" | grep "=> /" | awk '{print $3}' | while read -r lib; do \
            if [ -f "$lib" ] && [[ "$lib" != /lib64/libc.so* ]] && [[ "$lib" != /lib64/libdl.so* ]]; then \
                cp -n "$lib" /layer/lib/ 2>/dev/null || true; \
            fi; \
        done; \
    done

# Create the deployment archive
WORKDIR /layer
RUN zip -r9 /imagemagick-layer.zip bin lib

Step 2: Build the Container and Extract the Archive

Build the Docker image and copy the generated .zip layer file to your host machine:

# Build the Docker image
docker build -t imagemagick-layer .

# Create a temporary container
CONTAINER_ID=$(docker create imagemagick-layer)

# Copy the zip archive to the local directory
docker cp ${CONTAINER_ID}:/imagemagick-layer.zip ./imagemagick-layer.zip

# Remove the temporary container
docker rm ${CONTAINER_ID}

Step 3: Publish the AWS Lambda Layer

Publish the zip file as a Lambda layer using the AWS CLI:

aws lambda publish-layer-version \
    --layer-name imagemagick-delegates \
    --description "ImageMagick with libjpeg, libpng, and libwebp delegates" \
    --zip-file fileb://imagemagick-layer.zip \
    --compatible-runtimes provided.al2023 nodejs18.x nodejs20.x python3.11 python3.12 \
    --compatible-architectures x86_64

Step 4: Configure Your Lambda Function

After attaching the layer to your Lambda function:

  1. Environment Variables: Ensure your function finds the binaries and shared libraries by configuring the paths:

    • PATH: /opt/bin:$PATH
    • LD_LIBRARY_PATH: /opt/lib:$LD_LIBRARY_PATH

  2. Verify Installation: In your Lambda function code, execute:

    magick -version

    Check the output under Delegates (built-in) to confirm that jpeg, png, webp, and other compiled formats are listed.
