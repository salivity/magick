CCITT Group 4 Compression in ImageMagick Explained

ImageMagick compresses 1-bit monochrome images by converting pixel data into a strictly bilevel format and encoding the resulting bitstream using the CCITT Group 4 standard. This process relies on a two-dimensional relative addressing algorithm that identifies transitions between black and white pixels across consecutive scanlines, discarding redundancies to produce compact, lossless files ideal for scanned text, line art, and architectural blueprints.

The Conversion to 1-Bit Monochrome

Before compression begins, ImageMagick ensures that the image consists strictly of binary data—either black or white pixels with a bit-depth of 1. If the input image is in color or grayscale, ImageMagick first reduces the dynamic range using bilevel thresholding, dithering, or quantization:

magick input.jpg -monochrome -depth 1 -compress Group4 output.tif

During this step, each pixel is mapped directly to a single bit (0 for black and 1 for white), eliminating color palettes, alpha channels, and intermediate gray levels.

The CCITT Group 4 (ITU-T T.6) Encoding Mechanism

Once the image data is reduced to a 1-bit grid, ImageMagick invokes its underlying encoder (typically via libtiff) to execute CCITT Group 4 compression. Unlike 1D compression algorithms that evaluate each line independently, Group 4 utilizes a two-dimensional coding scheme based on the Modified Modified READ (MMR) technique.

The compression functions through the following mechanisms:

  1. Reference and Coding Lines: Group 4 compression evaluates two horizontal lines at a time: the reference line (the line directly above) and the coding line (the current line being compressed). The very first line of the image uses an imaginary all-white reference line.

  2. Transition Detection: The algorithm detects specific points along the scanline where color changes (from white to black or black to white). It identifies five key transition points:

    • \(a_0\): The starting point or last identified transition on the coding line.
    • \(a_1\): The next transition point to the right of \(a_0\) on the coding line.
    • \(a_2\): The transition point following \(a_1\) on the coding line.
    • \(b_1\): The first transition on the reference line occurring to the right of \(a_0\) with the same color transition as \(a_1\).
    • \(b_2\): The transition following \(b_1\) on the reference line.

  3. Coding Modes: Based on the relative positions of these transition points, the encoder chooses one of three modes:

    • Vertical Mode: Used when the transition \(a_1\) on the current line is within 3 pixels (left or right) of the transition \(b_1\) on the reference line. A compact variable-length code records this minor offset.
    • Pass Mode: Used when the reference line transition \(b_2\) is located to the left of \(a_1\). This indicates that a feature on the reference line does not exist on the coding line, allowing the encoder to skip ahead.
    • Horizontal Mode: Used when the distance between \(a_1\) and \(b_1\) is greater than 3 pixels. The distance \(a_0a_1\) and \(a_1a_2\) is coded using run-length Huffman tables.

End-of-Line and Error Resistance

Unlike CCITT Group 3, Group 4 assumes an error-free transmission environment. As a result, it eliminates explicit End-of-Line (EOL) markers between scanlines to maximize compression efficiency. The stream concludes with an End-of-Facsimile-Block (EOFB) code, consisting of two consecutive EOL markers, which signals to the decoder that all lines have been processed.

Why ImageMagick Uses CCITT Group 4

ImageMagick utilizes Group 4 compression primarily within TIFF and PDF containers because it offers:

  • Lossless Quality: Every pixel is preserved exactly as defined in the source monochrome raster.
  • Maximum Space Reduction: By only recording relative offsets between lines rather than raw pixel sequences, file sizes are significantly smaller compared to standard run-length encoding (RLE) or LZW compression for document-based imagery.
