Clear ImageMagick Canvas Geometry with +repage

When you crop an image using ImageMagick, the software often preserves the original image dimensions and positional offsets as virtual canvas metadata. This guide explains why this hidden canvas geometry persists in cropped files, the rendering problems it causes, and how to use the +repage operator to permanently reset and remove canvas offsets for clean, accurately sized image outputs.

Understanding Virtual Canvas Geometry

When executing a -crop operation in ImageMagick, the program retains the coordinate data and the bounding box of the original source file by default. This metadata—known as the page geometry or virtual canvas—records where the cropped section was positioned on the original image (e.g., 300x300+50+50).

While this behavior is useful for multi-frame animations or layered files, it creates unintended issues for standard image formats like PNG and GIF. Web browsers, image viewers, and editing tools often read this page offset metadata, causing the cropped image to display with unwanted transparent margins, shifted positions, or incorrect canvas bounds.

How to Use the +repage Operator

The +repage operator completely removes the virtual canvas metadata and recalculates the page geometry to match the exact dimensions of the newly cropped image.

To apply it correctly, always specify +repage immediately after your -crop command:

magick input.png -crop 400x300+50+50 +repage output.png

For older ImageMagick versions (v6 and below), use convert:

convert input.png -crop 400x300+50+50 +repage output.png

The Difference Between -repage and +repage

Understanding the syntax difference between the hyphen (-) and plus (+) prefixes is essential:

  • -repage [geometry]: Manually assigns a new virtual canvas size and offset (e.g., -repage 800x600+0+0).
  • +repage: Automatically strips the offset and sets the canvas size to match the current image boundary, effectively resetting the geometry to WxH+0+0.

Cropping Multi-Tile or Batch Outputs

When using -crop without explicit coordinates to split an image into multiple tiles, omitting +repage will cause every generated tile to retain the original canvas dimensions. Adding +repage ensures every cropped tile functions as an independent, correctly bounded image:

magick input.jpg -crop 2x2@ +repage tile_%d.jpg

Always include +repage as a standard step in your cropping pipelines unless your specific workflow relies on maintaining relative positioning for layered compositions.
