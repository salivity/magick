Compile ImageMagick with 16-Bit Depth and No HDRI

This guide explains how to compile ImageMagick from source with a 16-bit quantum depth while explicitly disabling High Dynamic Range Imaging (HDRI). By applying the appropriate configure script flags, you can build a lightweight binary tailored for standard 16-bit integer operations, reducing the memory overhead and processing cost associated with floating-point calculations.

The Configure Flags

To configure ImageMagick for 16-bit depth with HDRI disabled, use the following two flags together during the configuration step:

  • --with-quantum-depth=16
  • --disable-hdri

Combined into a single command:

./configure --with-quantum-depth=16 --disable-hdri

Why Use These Flags

In modern versions of ImageMagick (ImageMagick 7 and later), the default build configuration is Q16HDRI (16-bit quantum depth with HDRI enabled). Under this default, pixel values are stored as 32-bit single-precision floating-point numbers to prevent clipping and precision loss during complex transformations.

However, enabling HDRI roughly doubles the memory footprint of processed images and can introduce performance penalties for workflows that only require standard integer calculations. Supplying --disable-hdri forces ImageMagick to use 16-bit integer values (spanning 0 to 65,535) rather than floats.

Complete Compilation Process

To build and install ImageMagick with these settings from source, run the standard build sequence:

  1. Configure the build:

    ./configure --with-quantum-depth=16 --disable-hdri

  2. Compile the source:

    make

  3. Install the binaries:

    sudo make install
sudo ldconfig /usr/local/lib

Verifying the Build

Once installation is complete, verify that the configuration was applied correctly by checking the installed version:

magick -version

Look at the output under Features. A build without HDRI will list features such as Cipher DPC, but it will not list HDRI. The quantum depth should explicitly show Q16.
