Compute Pixel Hash in ImageMagick: MD5 and SHA-256

Generating cryptographic hashes like MD5 and SHA-256 directly from image pixel data allows you to verify visual content integrity regardless of metadata, container formats, or compression changes. This guide demonstrates how to extract ImageMagick's built-in SHA-256 pixel signature and how to stream raw pixel bytes into standard hashing tools to compute custom MD5 and SHA-256 checksums.

1. Using ImageMagick's Built-in Pixel Signature (SHA-256)

ImageMagick provides a native pixel signature feature that calculates a canonical SHA-256 hash strictly from the normalized pixel stream, ignoring EXIF tags, creation dates, and container metadata.

To display the built-in SHA-256 signature, use the %# format specifier or %[signature]:

magick input.png -format "%#\n" info:

Or using the standard identify syntax:

magick identify -format "%#\n" input.jpg

This output is deterministic: two files with different metadata, file names, or file formats (such as a PNG and a lossless TIFF with identical pixel values) will output the exact same signature.

2. Generating MD5 and SHA-256 Hashes via Raw Pixel Streams

If you specifically require an MD5 hash or want to generate a standard SHA-256 hash using external command-line utilities, you can instruct ImageMagick to dump raw, uncompressed pixel bytes to standard output and pipe them directly into md5sum or sha256sum.

MD5 Checksum of Pixel Data

To compute an MD5 hash on 8-bit RGB pixel data:

magick input.jpg -depth 8 rgb:- | md5sum

For images containing an alpha channel (transparency), use the rgba stream format instead:

magick input.png -depth 8 rgba:- | md5sum

SHA-256 Checksum of Pixel Data

To compute a SHA-256 hash using system utilities:

magick input.jpg -depth 8 rgb:- | sha256sum

3. Best Practices for Deterministic Pixel Hashing

When hashing raw pixel streams, ensure consistency across comparisons by controlling the following parameters:

  • Bit Depth (-depth): Enforce a fixed bit depth (such as -depth 8 or -depth 16) to ensure images saved at different color depths evaluate identically.
  • Color Channels: Standardize the output format (rgb:-, rgba:-, or gray:-). Hashing an RGB stream on an RGBA file will produce a different hash if alpha values are included or stripped.
  • Colorspace (-colorspace): If working across different color profiles, normalize the pixel colorspace (e.g., -colorspace sRGB) before exporting the raw stream.
