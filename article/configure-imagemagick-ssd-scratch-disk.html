Configure ImageMagick SSD Scratch Disk

Processing exceptionally large images in ImageMagick often exhausts system RAM, causing the software to page pixel data to disk via its pixel cache mechanism. Configuring ImageMagick to target a fast Solid State Drive (SSD) or NVMe drive as its scratch disk prevents severe performance bottlenecks caused by slow storage I/O. This guide explains how to define an SSD scratch location using both runtime environment variables and persistent XML configuration files.

Method 1: Set the Temporary Path via Environment Variables

The quickest way to route ImageMagick's pixel cache to an SSD is by defining the MAGICK_TEMPORARY_PATH environment variable. If this variable is not defined, ImageMagick defaults to standard system variables like TMPDIR, TEMP, or /tmp.

For Linux and macOS, point the variable to your mounted SSD directory in your current terminal session:

export MAGICK_TEMPORARY_PATH="/mnt/fast_ssd/magick_tmp"

To make this permanent for a specific user, append the export line above to your ~/.bashrc, ~/.zshrc, or system-wide profile.

For Windows environments using PowerShell, execute:

$env:MAGICK_TEMPORARY_PATH = "D:\MagickTmp"

To make it permanent in Windows, set a system environment variable named MAGICK_TEMPORARY_PATH pointing to the target folder on your SSD.

Method 2: Configure policy.xml for Global Persistence

To enforce SSD scratch disk usage across all users and background services (such as web servers running PHP or Python workers), modify the ImageMagick security and resource policy file.

  1. Locate your policy.xml file. On Linux systems, this is typically found at /etc/ImageMagick-7/policy.xml or /etc/ImageMagick-6/policy.xml. On Windows, it resides in the root installation directory.
  2. Open the file with administrative privileges.
  3. Add or update the temporary-path resource policy inside the <policymap> block:
<policymap>
  <!-- Direct temporary files and pixel cache paging to the SSD -->
  <policy domain="resource" name="temporary-path" value="/mnt/fast_ssd/magick_tmp"/>
</policymap>

Ensure that the directory specified in value exists and has read/write permissions for the user running the ImageMagick processes.

Fine-Tuning Cache Thresholds

ImageMagick only writes to the disk cache when internal memory thresholds are exceeded. You can configure when paging begins by setting the memory (RAM) and map (memory-mapped file) resource limits in policy.xml:

<policy domain="resource" name="memory" value="8GiB"/>
<policy domain="resource" name="map" value="16GiB"/>
<policy domain="resource" name="disk" value="500GiB"/>

When an operation exceeds the memory limit, ImageMagick begins caching pixel data to the designated temporary-path on your SSD up to the specified disk limit.

Verifying the Configuration

To confirm that ImageMagick recognizes the new scratch path and resource limits, execute the following command:

magick identify -list resource

Inspect the output under Resource limits to ensure the Disk and Temporary path parameters match your designated SSD mount point. You can also monitor active paging during heavy operations by appending the -debug cache flag to your command to inspect real-time disk allocation.
