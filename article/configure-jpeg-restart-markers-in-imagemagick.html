Configure JPEG Restart Markers in ImageMagick

This article explains how to configure JPEG restart markers using the -define jpeg:restart-interval setting in ImageMagick. You will learn the command-line syntax for setting intervals, how to target specific block or row intervals, the practical benefits of restart markers for network transmission and parallel decoding, and the trade-offs regarding resulting file sizes.

What Are JPEG Restart Markers?

JPEG restart markers (RST markers) are special byte sequences placed at regular intervals inside a JPEG compressed data stream. They reset the entropy decoding state (the DC predictor and the Huffman or arithmetic decoding state) at fixed boundaries.

Restart markers offer two main benefits:

  1. Fault tolerance: If data corruption occurs during transmission, the decoder only loses data up to the next restart marker, preventing corrupted data from cascading across the entire image.
  2. Parallel decoding: Decoders can divide the file at marker boundaries and decode multiple segments concurrently across multiple CPU threads.

Setting the Restart Interval

To inject restart markers into an output JPEG using ImageMagick, pass the jpeg:restart-interval option using the -define flag.

The basic command syntax is:

magick input.png -define jpeg:restart-interval=VALUE output.jpg

(Note: Use convert instead of magick if using ImageMagick 6.)

Specifying Blocks vs. Rows

ImageMagick allows you to specify the interval in either Minimum Coded Units (MCUs) or MCU rows by appending specific suffixes to the value:

  • MCU Blocks: Set a numerical value directly, or append b or B to explicitly set the interval in MCU blocks:

    magick input.png -define jpeg:restart-interval=64 output.jpg

    This command inserts a restart marker after every 64 MCU blocks.

  • MCU Rows: Append r or R to specify the interval by the number of MCU rows:

    magick input.png -define jpeg:restart-interval=1r output.jpg

    Setting 1r inserts a restart marker at the end of every row of MCUs, which is the most common configuration for parallelized decoders like libjpeg-turbo.

Verifying the Configuration

To confirm that the output JPEG contains restart markers, inspect the image metadata using ImageMagick's verbose output:

magick identify -verbose output.jpg

Look for the Quality and compression details, or inspect the file markers directly using standard tools like jpegdump or a hex editor to search for the byte markers FF D0 through FF D7.

File Size Trade-Offs

Adding restart markers increases overall file size because each marker consumes 2 bytes, and resetting the predictor eliminates the compression benefit of referencing the previous MCU's DC coefficient. A frequent interval (such as every 1 MCU) produces a significantly larger file, whereas an interval of 1 row (1r) or every 64 to 128 MCUs typically introduces a negligible file size overhead (less than 1–2%) while providing full support for error recovery and multithreaded decoding.
