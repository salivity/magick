Configure WebP Partition Limits in ImageMagick

Configuring WebP partition limits in ImageMagick allows you to control how the libwebp encoder balances file constraints against image quality across segmented macroblock bitstreams. This article covers how to apply the webp:partition-limit configuration option using ImageMagick's command-line interface, explains the accepted values, and clarifies the distinction between partition limits and partition counts.

Understanding WebP Partition Limits

In lossy WebP compression, the bitstream is broken into discrete partitions holding DCT/WHT coefficients and macroblock header data. When aiming for strict memory constraints or predictable decoding performance, libwebp provides a partition limit mechanism. This setting forces the encoder to degrade certain partition quality levels if they exceed designated bit boundaries.

The limit is expressed as an integer percentage from 0 to 100:

  • 0: No degradation is allowed (default).
  • 1 to 99: Allows progressive quality degradation of high-frequency coefficients to respect partition size boundaries.
  • 100: Maximum degradation permitted to enforce the smallest possible partition footprints.

Setting Partition Limits in ImageMagick

ImageMagick exposes low-level libwebp encoder parameters via the -define operator. To adjust the partition limit, pass webp:partition-limit=<0-100> before the output filename.

Basic Command Syntax

magick input.png -define webp:partition-limit=50 output.webp

If you are using ImageMagick v6, replace magick with convert:

convert input.png -define webp:partition-limit=50 output.webp

Partition Limit vs. Partition Count

Do not confuse partition-limit with the total number of partitions:

  • webp:partition-limit: Determines degradation tolerance (values 0 to 100).
  • webp:partitions: Configures the total number of partitions to use for parallel decoding. It accepts values from 0 to 3, which correspond to \(2^n\) partitions (\(1\), \(2\), \(4\), or \(8\) partitions).

You can combine both definitions in a single conversion command to tune decoding parallelism and partition size constraints simultaneously:

magick input.jpg -define webp:partitions=2 -define webp:partition-limit=25 output.webp
