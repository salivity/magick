Convert Animated GIF to PDF with ImageMagick

Converting an animated GIF to a PDF document using ImageMagick transforms the animation into a multi-page document where each individual frame is rendered as a separate static page. Because PDF does not support native GIF-style looping animations through standard conversion commands, ImageMagick breaks the file down into its component images. This guide explains how the conversion process behaves, addresses the common visual glitches caused by GIF optimization, and details the correct commands to use for clean results.

Frame-by-Page Mapping

When ImageMagick reads an animated GIF, it treats each sequential frame as a distinct, indexed image within a stack. When exporting this image sequence to a format that supports multiple pages—such as PDF—ImageMagick automatically assigns each frame to its own page. For example, a GIF composed of 30 frames will produce a 30-page PDF document, effectively turning the animation into a static, sequential storyboard.

The Frame Optimization Problem

Directly converting an animated GIF using a basic command like magick input.gif output.pdf often produces distorted or incomplete pages. This occurs because GIFs typically use optimization techniques where only the pixels that change from one frame to the next are stored, rather than the full image. Subsequent frames rely on transparent backgrounds and coordinate offsets relative to the base frame.

If you convert an optimized GIF directly, ImageMagick exports these raw, partial delta frames onto individual PDF pages. As a result, pages after the first one may contain fragmented graphics, floating elements, or transparent holes instead of the complete scene.

The Solution: Using the -coalesce Flag

To ensure every page in the PDF displays the complete visual state of the animation at that exact moment, the frames must be reconstructed before they are saved. ImageMagick includes the -coalesce operator for this purpose.

The -coalesce command reads the canvas dimensions, image offsets, and disposal methods of each frame, then paints them sequentially to generate a complete, full-size image for every step in the animation.

To convert an animated GIF correctly, use the following syntax:

magick input.gif -coalesce output.pdf

For older versions of ImageMagick (v6 and earlier), the syntax uses the convert binary:

convert input.gif -coalesce output.pdf

Extracting Specific Frames

If a multi-page PDF containing every single frame is not desirable, you can extract individual frames using bracket notation:

  • Extract only the first frame (single-page PDF):
    magick input.gif[0] output.pdf
  • Extract a specific range of frames:
    magick "input.gif[0-9]" -coalesce output.pdf

GIFs with high frame counts can result in excessively large PDF files. Extracting select frames or downsampling the frame rate beforehand is recommended to maintain manageable file sizes.
