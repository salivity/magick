Convert DCI-P3 Theater to Display P3 in ImageMagick

This article provides an overview of how ImageMagick transforms chromaticity coordinates and color data when converting an image from DCI-P3 Theater (DCI Cinema) to standard Display P3. While both color spaces share the exact same primary chromaticity coordinates, they differ in their target white points and transfer curves. Below is a breakdown of how ImageMagick processes this transformation through linearization, chromatic adaptation transforms, and tone curve encoding.

The Underlying Specifications

Before understanding how ImageMagick processes the shift, it is essential to look at the specifications of each color space:

  • DCI-P3 Theater (Cinema): Uses P3 primaries (Red: \(x=0.680, y=0.320\); Green: \(x=0.265, y=0.690\); Blue: \(x=0.150, y=0.060\)) with an theatrical calibration white point (\(x=0.314, y=0.351\), roughly 5900K) and a pure \(2.6\) power gamma curve.
  • Display P3: Uses the exact same P3 primaries, but pairs them with the CIE Standard Illuminant D65 white point (\(x=0.3127, y=0.3290\), roughly 6500K) and an sRGB transfer function.

Because the color primaries are identical, the chromaticity transformation is governed entirely by the difference in white point and tone response.

The Color Transformation Pipeline in ImageMagick

ImageMagick performs profile conversions primarily by delegating color management tasks to the LittleCMS (lcms2) library using ICC color profiles. When remapping from DCI-P3 Theater to Display P3 using the -profile operator, ImageMagick performs the conversion in four distinct stages:

1. Linearization (Inverse OETF)

ImageMagick reads the source RGB encoded values and applies the inverse of the DCI-P3 transfer curve (a constant gamma of 2.6). This removes the non-linear encoding and produces linear optical intensity values for Red, Green, and Blue.

2. Conversion to CIE XYZ and Profile Connection Space (PCS)

The linear RGB values are multiplied by a \(3 \times 3\) primary matrix derived from the DCI-P3 Theater profile to convert the values into CIE \(1931\ XYZ\) tristimulus values. LittleCMS transforms these values into the Profile Connection Space (PCS), which is defined as CIE XYZ or CIE \(L^*a^*b^*\) under a CIE Standard Illuminant D50 reference white point.

3. Chromatic Adaptation Transform (CAT)

The transition between the DCI-P3 Theater white point (\(x=0.314, y=0.351\)) and the D65 white point (\(x=0.3127, y=0.3290\)) requires chromatic adaptation:

  • Bradford Transform: LittleCMS uses the Bradford Chromatic Adaptation Transform by default. It maps the theatrical white point into the D50 reference white point of the PCS, and then maps from D50 out to the destination D65 white point.
  • Rendering Intent Impact:
    • Relative Colorimetric (Default): The source white point is mapped directly to the destination white point. Because the eye adapts to the display white point, chromaticity values are normalized relative to D65. The primary colors maintain their maximum saturation relative to the respective white points.
    • Absolute Colorimetric: The source white point is preserved in absolute space without adaptation. When viewed on a D65 monitor, the image will display the visible greenish-yellow cast characteristic of DCI-P3 Theater white.

4. Re-encoding with Display P3 Transfer Curve

Once the linear tristimulus values are adapted to D65 within the destination profile's coordinate system, they are converted into Display P3 linear RGB. ImageMagick then applies the non-linear sRGB transfer function (a linear segment near zero followed by a \(2.4\) exponential curve with an offset) to produce the final 8-bit, 16-bit, or floating-point values suitable for Display P3 output.

Practical Implementation

To execute this pipeline correctly, you should use ICC profiles rather than simple -colorspace operators to ensure proper chromatic adaptation matrices are applied:

magick input_theater.tif -profile DCI-P3-Theater.icc -profile DisplayP3.icc output_display.tif

Using ICC-driven color management ensures that LittleCMS handles the mathematical transformation of the chromaticity coordinates without manual matrix calculation.
