Convert DPX Files Preserving Metadata in ImageMagick

Converting motion picture DPX (Digital Picture Exchange) frames in ImageMagick while maintaining SMPTE industry metadata requires an understanding of how the tool parses, maps, and writes DPX headers. DPX files serve as a primary interchange format in film post-production, carrying not only uncompressed raster data but also essential metadata such as timecode, keycode, film gauge, reel identification, and colorimetry standards. ImageMagick can process, re-encode, or transform these frames without stripping crucial production tags by mapping the SMPTE 268M header blocks to internal image properties and rewriting them on output.

Understanding DPX SMPTE Metadata Structure

The DPX standard (SMPTE 268M) divides image headers into specific sections: Generic Image Data, Industry Specific Information (motion picture and television headers), and User Defined Data. In Hollywood workflows, the Motion Picture and Television headers store essential tracking data, including:

  • SMPTE Timecode: Direct synchronization references for picture and audio.
  • Keycode / Edgecode: Film stock identification, manufacturer code, and frame offset markers.
  • Reel Information and Frame Position: Sequence identity within a long-form timeline.
  • Colorimetric Information: Transfer characteristics (e.g., Cineon printing density, Rec. 709, or log curves).

How ImageMagick Processes DPX Headers

ImageMagick utilizes a dedicated DPX coder (coders/dpx.c) to read and write the format. When reading an input frame, the coder unpacks the binary header fields and assigns them to internal string properties prefixed with dpx:.

Key mapped properties include:

  • dpx:television.time.code
  • dpx:television.user.bits
  • dpx:mp.film.id
  • dpx:mp.frame_position
  • dpx:mp.sequence_length
  • dpx:film.id
  • dpx:film.frame_attribute

When converting from one DPX file to another, ImageMagick automatically retains these internal properties in memory. As long as destructive operations do not purge the metadata pool, the DPX writer reads these internal dpx: key-value pairs and serializes them back into their respective binary offsets within the newly created DPX header.

Preserving Metadata During Command Execution

By default, executing a standard ImageMagick processing command between DPX files keeps the existing properties intact:

magick input_frame.dpx -resize 50% output_frame.dpx

To guarantee that metadata is strictly preserved, avoid flags that strip profile and header data:

  1. Avoid -strip: Running -strip removes all text attributes, ICC profiles, and DPX-specific metadata, resulting in a generic DPX header that breaks production conform workflows.
  2. Compile with Q16 or Q32 (HDRI): Hollywood DPX frames typically use 10-bit or 12-bit packing (such as 10-bit RGB packed into 32-bit words, method A or B). To prevent metadata truncation and color depth degradation, ensure ImageMagick is built with at least 16-bit quantum depth (Q16 or Q16-HDRI).

Overriding and Defining Specific DPX Header Fields

ImageMagick allows manual modification or injection of DPX industry headers using -define and -set flags. This is useful when transcoding from non-DPX sources or correcting corrupted camera logs during conversion:

magick input.dpx \
  -define dpx:mp.frame_position=000144 \
  -define dpx:mp.time.code="01:23:45:12" \
  -define dpx:television.time.code="01:23:45:12" \
  -define dpx:television.user.bits="00:00:00:00" \
  output.dpx

For color space management, you can force the DPX header to declare specific color transfer characteristics without altering the underlying pixel data:

magick input.dpx -define dpx:colorspace=Logarithmic output.dpx

Validating the Metadata Integrity

To ensure that the output frame has retained all SMPTE film and television header details after processing, run ImageMagick’s identification tool formatted to print all properties:

magick identify -verbose output.dpx | grep "dpx:"

This command returns all preserved header fields, confirming that the output DPX remains fully compliant with editorial, finishing, and archival conforming systems.
