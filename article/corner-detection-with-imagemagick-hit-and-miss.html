Corner Detection with ImageMagick Hit-and-Miss

This article explains how to implement corner detection using the Hit-and-Miss morphology operator in ImageMagick. You will learn the command-line syntax for the -morphology HitAndMiss method, how ImageMagick's built-in Corners kernel functions, and how to construct custom 3x3 kernels to target specific corner orientations and types in binary images.

The Basic Command Syntax

The Hit-and-Miss transform (HMT) in ImageMagick searches a binary image for specific pixel patterns matching a foreground mask ("hit") and a background mask ("miss"). The basic command structure is:

magick input.png -morphology HitAndMiss Corners output.png

For legacy ImageMagick versions (ImageMagick 6), use convert instead of magick.

Built-in Corners Kernel

ImageMagick includes a predefined kernel family named Corners. When called without sub-arguments, it searches for all 90-degree convex (outer) corners by automatically rotating a base corner template through four 90-degree rotations.

The base 3x3 pattern ImageMagick uses for an outer corner looks like this:

 0,  0,  -
 0,  1,  1
 -,  1,  -

In this matrix:

  • 1 represents a Hit (must be foreground / white).
  • 0 represents a Miss (must be background / black).
  • - represents a Don't Care (can be either foreground or background).

When executed via:

magick input.png -morphology HitAndMiss Corners output.png

ImageMagick runs this pattern across four orientations (0°, 90°, 180°, and 270°) and combines the results using an additive union, highlighting every single-pixel outer corner.

To isolate a specific corner direction instead of all four, specify the kernel index:

  • Corners:1 — Top-left corner
  • Corners:2 — Top-right corner
  • Corners:3 — Bottom-right corner
  • Corners:4 — Bottom-left corner

Example for isolating top-left corners only:

magick input.png -morphology HitAndMiss Corners:1 output.png

Custom Hit-and-Miss Kernels for Corners

You can define custom kernels directly in the command line using the format 'widthxheight: val,val,...'. This is necessary if you need to detect non-standard corners, acute angles, or concave (inner) corners.

Defining an Outer Corner Manually

To manually define a top-left outer corner and rotate it automatically across all four directions, append the > flag to the kernel definition:

magick input.png -morphology HitAndMiss "3x3>: 0,0,- 0,1,1 -,1,-" output.png

The > modifier tells ImageMagick to generate four 90-degree rotated variations of the defined kernel and combine the matches.

Detecting Inner (Concave) Corners

Built-in Corners only targets convex corners. To detect concave or inside corners, invert the hit and miss relationships where the background cuts into a foreground block:

 1,  1,  -
 1,  0,  0
 -,  0,  -

Execute this kernel with rotation:

magick input.png -morphology HitAndMiss "3x3>: 1,1,- 1,0,0 -,0,-" output.png

This will output single white pixels at the vertices of all 90-degree inside turns.
