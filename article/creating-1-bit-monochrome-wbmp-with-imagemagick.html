Creating 1-Bit Monochrome WBMP with ImageMagick

This article provides an overview of how ImageMagick processes, quantizes, and encodes 1-bit monochrome Wireless Application Protocol Bitmap (WBMP) files for low-bandwidth mobile devices. It covers the internal structure of the WBMP format, the image processing pipeline required to reduce color depth to a single bit, the CLI commands used to generate these files, and how ImageMagick packs binary pixel data to minimize file size.

The WBMP Format Specification

The Wireless Application Protocol Bitmap format is a lightweight raster format designed specifically for resource-constrained mobile devices operating on WAP networks. ImageMagick writes WBMP "Type 0" images, which are strictly uncompressed, 1-bit monochrome bitmaps.

Unlike larger formats such as BMP or PNG, WBMP does not contain metadata blocks, color profiles, or palettes. The header consists of:

  • Type Field: A multi-byte variable-length integer (uintvar) set to 0 representing standard monochrome.
  • FixHeaderField: A byte set to 0 reserving vendor-specific flags.
  • Width: Encoded as a uintvar.
  • Height: Encoded as a uintvar.

Following this minimal header, the raster data contains 1 bit per pixel, where a value of 0 represents black and 1 represents white.

The Color Quantization and Binarization Pipeline

To write a valid WBMP file, ImageMagick must first reduce any multi-channel color or grayscale input image to a binary representation (bilevel). ImageMagick accomplishes this through two primary stages:

  1. Grayscale Conversion: ImageMagick converts input RGB values into luminance values using standard color matrices (typically Rec. 709 or Rec. 601 luma calculations).
  2. Thresholding or Dithering:
    • Thresholding: Divides pixel intensities across a set cutoff (traditionally 50%). Pixels brighter than the threshold become white (1), while darker pixels become black (0).
    • Error Diffusion (Dithering): Distributes quantization errors to neighboring pixels using the Floyd-Steinberg or Riemersma algorithms. This preserves visual gradients and structural details in photographic imagery.

ImageMagick Command Syntax

To generate a fully compliant WBMP file, you instruct ImageMagick to set the image depth, color space, and output format.

Using modern ImageMagick (v7):

magick input.jpg -colorspace Gray -dither FloydSteinberg -monochrome output.wbmp

For hard-thresholding without dithering (ideal for text or sharp line art):

magick input.png -colorspace Gray -threshold 50% -type bilevel output.wbmp

Key arguments include:

  • -colorspace Gray: Ensures color data is reduced to a single luminance channel prior to binarization.
  • -dither FloydSteinberg: Uses error diffusion to simulate tonal variation across binary pixels.
  • -monochrome: Forces the pixel data into two colors (black and white) and sets the internal storage class to pseudo-class bilevel.
  • -type bilevel: Confirms that the output canvas restricts itself to 1-bit data per channel.

Bit-Packing and Data Optimization

Once pixels are converted to binary values, ImageMagick's WBMP encoder serializes the image rows:

  • Horizontal Bit-Packing: Pixels are read sequentially from left to right. The encoder packs eight adjacent 1-bit pixels into a single byte. The most significant bit (MSB) corresponds to the leftmost pixel in the group.
  • Byte Alignment: If the image width is not evenly divisible by 8, the remaining bits in the final byte of that row are padded with trailing zeros to align the start of the next row with a new byte boundary.
  • Header Efficiency: Using uintvar encoding for the dimensions allows smaller images to occupy fewer bytes in the header, keeping overhead to as little as 4 to 5 bytes for typical mobile screen resolutions (such as 96x65 or 128x128).
