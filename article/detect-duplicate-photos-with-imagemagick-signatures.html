Detect Duplicate Photos with ImageMagick Signatures

ImageMagick pixel signatures offer a reliable way to identify identical photos even when their file names, file sizes, or EXIF metadata differ. Unlike traditional file checksums like MD5 or SHA-256—which hash the entire file including its metadata header—ImageMagick's signature algorithm evaluates only the raw pixel values. This article explains how ImageMagick computes pixel signatures, provides the exact commands needed to extract them, and demonstrates how to automate duplicate detection across image collections.

Why Standard File Hashes Fail

When an image is edited to change metadata—such as altering EXIF tags, updating creation dates, or rotating orientation tags without modifying the raw image stream—the underlying file bytes change. Standard hashing utilities (such as md5sum or sha256sum) will generate completely different hash strings for these files, making it impossible to detect them as duplicates.

ImageMagick solves this by reading the decoded pixel buffer and generating a unique SHA-256 hash strictly from the image geometry and color values.

Generating an Image Pixel Signature

To generate a pixel signature for a single image, use the identify tool provided by ImageMagick:

magick identify -format "%#" image.jpg

(Note: In ImageMagick 6, the command is identify -format "%#" image.jpg)

This command outputs an 88-character SHA-256 hash representing the exact pixel matrix. If two files have different EXIF data, embedded color profiles, or file formats, but identical pixel content, their outputs will match precisely.

To view the signature alongside filename and dimensions:

magick identify -format "%f: %wx%h [%#]\n" image.jpg

Batch Processing and Finding Duplicates

To find duplicates across a directory of images, you can extract the signatures in bulk, sort the results, and identify matches.

Using Bash and Core Utilities

Run the following pipeline to scan a folder of JPEG and PNG files, group by signature, and print duplicates:

magick identify -format "%#  %p\n" *.jpg *.png | sort | awk '
{
    sig = $1
    file = $2
    if (sig == prev_sig) {
        if (prev_printed == 0) {
            print "Duplicate set:"
            print "  " prev_file
            prev_printed = 1
        }
        print "  " file
    } else {
        prev_sig = sig
        prev_file = file
        prev_printed = 0
    }
}'

Explanation of the Process:

  1. magick identify -format "%# %p\n" generates the signature followed by the file path for each image.
  2. sort orders the list so identical signatures are placed on adjacent lines.
  3. awk iterates through the list, comparing consecutive signatures and printing matching file paths grouped together.

Considerations and Limitations

  • Lossy Compression: If an image has been re-saved with lossy compression (such as JPEG re-encoding), individual pixel values change slightly, which will result in a completely different signature. Pixel signatures detect exact visual duplicates, not fuzzy or perceptually similar images.
  • Color Space and Channels: Signatures account for all channels, including alpha channels and color depth. An image converted from RGB to CMYK will generate a different pixel signature even if it looks identical to the human eye.
