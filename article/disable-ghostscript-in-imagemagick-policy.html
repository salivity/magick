Disable Ghostscript in ImageMagick Policy

This guide provides a direct walkthrough on how to disable Ghostscript processing within ImageMagick using the security policy configuration file. Due to recurring security vulnerabilities associated with PostScript and PDF rendering delegates, disabling Ghostscript is a standard hardening procedure. The following steps explain how to locate the policy.xml configuration, implement the restrictive policy directives, and verify that PostScript and PDF processing are fully blocked.

Step 1: Locate the ImageMagick Policy File

The ImageMagick security rules are defined in a file named policy.xml. Depending on your operating system and ImageMagick version, the file is typically located in one of the following directories:

  • Debian/Ubuntu: /etc/ImageMagick-6/policy.xml or /etc/ImageMagick-7/policy.xml
  • RHEL/CentOS/Fedora: /etc/ImageMagick/policy.xml
  • macOS (Homebrew): /usr/local/etc/ImageMagick-7/policy.xml or /opt/homebrew/etc/ImageMagick-7/policy.xml

To find the exact path automatically, run:

identify -list policy

Or search using:

find /etc -name "policy.xml" 2>/dev/null

Step 2: Edit policy.xml

Open the policy.xml file in a text editor with administrative privileges:

sudo nano /etc/ImageMagick-6/policy.xml

Locate the <policymap> block inside the file. Add the following rules directly inside the <policymap> tags to disable all coders and delegates that rely on Ghostscript:

<policymap>
  <!-- Disable Ghostscript delegate directly -->
  <policy domain="delegate" rights="none" pattern="gs" />

  <!-- Disable PostScript and PDF coders processed by Ghostscript -->
  <policy domain="coder" rights="none" pattern="PS" />
  <policy domain="coder" rights="none" pattern="PS2" />
  <policy domain="coder" rights="none" pattern="PS3" />
  <policy domain="coder" rights="none" pattern="EPS" />
  <policy domain="coder" rights="none" pattern="PDF" />
  <policy domain="coder" rights="none" pattern="XPS" />
</policymap>

Save the changes and exit the text editor.

Step 3: Verify the Changes

To ensure that Ghostscript delegation and related formats are blocked, attempt to identify or convert a PDF or PS file using ImageMagick:

convert test.pdf test.png

If the policy is applied correctly, ImageMagick will refuse to process the file and output an error message similar to:

convert: attempt to perform an operation not allowed by the security policy `PDF' @ error/constitute.c/IsCoderAuthorized/408.

You can also inspect the active security policies directly by executing:

identify -list policy

Check the output to confirm that rights="none" is listed for PS, EPS, PDF, and gs.
