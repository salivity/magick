Disable Image Coders in ImageMagick Policy

ImageMagick utilizes a centralized configuration file, policy.xml, to regulate system resources, security permissions, and file format handling. This article provides a straightforward guide on how to locate your ImageMagick security configuration and disable specific, high-risk, or unused image coders to mitigate vulnerabilities and secure your environment.

1. Locate the policy.xml File

The security policy configuration is stored in policy.xml. The exact location depends on your operating system and ImageMagick version:

  • Linux (Debian/Ubuntu): /etc/ImageMagick-6/policy.xml or /etc/ImageMagick-7/policy.xml
  • Linux (RHEL/CentOS): /etc/ImageMagick/policy.xml
  • macOS (Homebrew): /usr/local/etc/ImageMagick-7/policy.xml or /opt/homebrew/etc/ImageMagick-7/policy.xml

You can verify the exact path by running:

magick -list configure | grep POLICY_PATH

(Or use identify -list configure for ImageMagick 6)

2. Edit the Policy Configuration

Open the policy.xml file with administrative privileges using a text editor:

sudo nano /etc/ImageMagick-6/policy.xml

To disable a specific coder, add a <policy> directive inside the <policymap> tags. Set the domain to coder, the rights to none, and specify the format pattern in uppercase.

Disable Vulnerable or Risky Formats

Common formats often disabled to prevent remote code execution (especially Ghostscript-related or script formats) include:

<policymap>
  <!-- Disable PostScript/PDF formats -->
  <policy domain="coder" rights="none" pattern="PDF" />
  <policy domain="coder" rights="none" pattern="EPS" />
  <policy domain="coder" rights="none" pattern="PS" />
  <policy domain="coder" rights="none" pattern="XPS" />

  <!-- Disable script and vector execution formats -->
  <policy domain="coder" rights="none" pattern="MVG" />
  <policy domain="coder" rights="none" pattern="MSL" />
  <policy domain="coder" rights="none" pattern="SHOW" />
  <policy domain="coder" rights="none" pattern="WIN" />
  <policy domain="coder" rights="none" pattern="PLT" />

  <!-- Disable remote file inclusion protocols -->
  <policy domain="coder" rights="none" pattern="HTTPS" />
  <policy domain="coder" rights="none" pattern="HTTP" />
  <policy domain="coder" rights="none" pattern="FTP" />
  <policy domain="coder" rights="none" pattern="URL" />
</policymap>

Disable Multiple Coders with Wildcards

You can group multiple formats or use wildcards in the pattern attribute:

<policy domain="coder" rights="none" pattern="{PDF,EPS,PS,MVG,MSL}" />

3. Verify the Disabled Coders

Save the file and exit the editor. ImageMagick applies policy changes immediately without requiring a service restart.

Verify the active policy rules:

magick -list policy

Test that a disabled coder is successfully blocked by attempting to process that format:

magick sample.pdf output.png

If configured correctly, ImageMagick will reject the operation and return an error similar to:

magick: not authorized `sample.pdf' @ error/constitute.c/ReadImage/412.
