Disable ImageMagick HTTP and FTP URL Fetching

This guide explains how to secure an ImageMagick installation by disabling external URL fetching over HTTP, HTTPS, and FTP protocols using security policies. Restricting these network-capable coders and delegates mitigates Server-Side Request Forgery (SSRF) vulnerabilities and prevents the unauthorized retrieval of remote resources when processing untrusted images.

Locate the Policy File

ImageMagick controls its security settings through an XML configuration file named policy.xml. The exact location depends on your operating system and ImageMagick version:

  • Debian/Ubuntu: /etc/ImageMagick-6/policy.xml or /etc/ImageMagick-7/policy.xml
  • RHEL/CentOS/Fedora: /etc/ImageMagick/policy.xml
  • Custom/Source Installations: /usr/local/etc/ImageMagick-7/policy.xml

You can verify the active policy path on your system by running:

magick -list policy
# or for ImageMagick 6:
convert -list policy

Add Restrictive Policy Rules

Open the policy.xml file with administrative privileges in a text editor:

sudo nano /etc/ImageMagick-6/policy.xml

Locate the <policymap> section. Within the <policymap> and </policymap> tags, define policies that revoke read and write permissions for network-based coders and delegates. Add the following lines:

  <!-- Disable URL fetching via coders -->
  <policy domain="coder" rights="none" pattern="URL" />
  <policy domain="coder" rights="none" pattern="HTTP" />
  <policy domain="coder" rights="none" pattern="HTTPS" />
  <policy domain="coder" rights="none" pattern="FTP" />

  <!-- Disable URL fetching via delegates -->
  <policy domain="delegate" rights="none" pattern="URL" />
  <policy domain="delegate" rights="none" pattern="HTTP" />
  <policy domain="delegate" rights="none" pattern="HTTPS" />
  <policy domain="delegate" rights="none" pattern="FTP" />

Setting rights="none" ensures ImageMagick will completely refuse to invoke the coder or delegate when encountered in an input string or image payload.

Save the file and exit the editor.

Verify the Configuration

To confirm that the external URL handlers have been disabled, inspect the active policies:

magick -list policy | grep -E 'HTTP|FTP|URL'

Next, test the restriction by attempting to read an image directly from a remote URL:

magick identify http://example.com/test.png

If the policies are correctly applied, ImageMagick will block the operation and return an error message similar to:

identify: not authorized `http://example.com/test.png' @ error/constitute.c/ReadImage/...
