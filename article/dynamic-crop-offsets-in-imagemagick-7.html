Dynamic Crop Offsets in ImageMagick 7

This guide explains how to dynamically compute crop offsets and dimensions in ImageMagick 7 using inline mathematical expressions. By leveraging the built-in FX expression engine directly inside command-line arguments, you can calculate bounding boxes, center crops, and aspect ratios on the fly based on an image's intrinsic dimensions without relying on external shell scripts or secondary commands.

Understanding Inline Expressions in ImageMagick 7

ImageMagick 7 introduced a unified CLI parser through the magick command that supports inline calculations via the %[fx:...] format. When passed inside geometry arguments, these expressions are evaluated at runtime against the current image properties, such as width (w) and height (h).

The standard crop geometry format is WIDTHxHEIGHT+X+Y. By replacing any or all of these values with %[fx:...] expressions, ImageMagick computes the integer pixel values dynamically.

Syntax and Core Variables

The basic structure for dynamic cropping is:

magick input.png -crop "%[fx:expression_w]x%[fx:expression_h]+%[fx:expression_x]+%[fx:expression_y]" +repage output.png

Common variables available in the FX parser include:

  • w: Current image width in pixels.
  • h: Current image height in pixels.
  • min(a,b) and max(a,b): Minimum and maximum functions.
  • Operators: +, -, *, /.

Always append +repage after a -crop operation to reset the image's virtual canvas offset metadata.

Practical Crop Examples

1. Dynamic Center Square Crop

To crop a centered square from an image regardless of whether it is portrait or landscape, determine the shorter side using min(w,h) and calculate the offset to center it:

magick input.jpg -crop "%[fx:min(w,h)]x%[fx:min(w,h)]+%[fx:(w-min(w,h))/2]+%[fx:(h-min(w,h))/2]" +repage square_crop.jpg
  • Width and Height: Set to min(w,h).
  • X-Offset: (w - min(w,h)) / 2 centers horizontally if landscape; evaluates to 0 if portrait.
  • Y-Offset: (h - min(w,h)) / 2 centers vertically if portrait; evaluates to 0 if landscape.

2. Relative Percentage Cropping with Custom Offsets

To crop a region defined by percentages of the original image—for example, taking a region that is 50% of the width and 50% of the height, offset by 25% from both edges:

magick input.jpg -crop "%[fx:w*0.5]x%[fx:h*0.5]+%[fx:w*0.25]+%[fx:h*0.25]" +repage center_half.jpg

3. Enforcing a Dynamic 16:9 Aspect Ratio Crop

To trim an arbitrary image to a centered 16:9 aspect ratio dynamically:

magick input.jpg -crop "%[fx:(w/h > 16/9) ? (h*16/9) : w]x%[fx:(w/h > 16/9) ? h : (w*9/16)]+%[fx:(w/h > 16/9) ? ((w-(h*16/9))/2) : 0]+%[fx:(w/h > 16/9) ? 0 : ((h-(w*9/16))/2)]" +repage cropped_16_9.jpg

This ternary expression checks if the current aspect ratio (w/h) is wider than 16/9. If true, it restricts the width and offsets horizontally; if false, it restricts the height and offsets vertically.

Assigning Offsets to Custom Variables

For complex pipelines, you can precalculate crop offsets and store them as custom attributes using -set:

magick input.jpg \
  -set option:crop_w "%[fx:w*0.8]" \
  -set option:crop_h "%[fx:h*0.8]" \
  -set option:crop_x "%[fx:w*0.1]" \
  -set option:crop_y "%[fx:h*0.1]" \
  -crop "%[crop_w]x%[crop_h]+%[crop_x]+%[crop_y]" \
  +repage output.jpg

This improves readability when dealing with lengthy conditional evaluations.
