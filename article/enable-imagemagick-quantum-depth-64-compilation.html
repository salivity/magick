Enable ImageMagick Quantum Depth 64 Compilation

This guide explains how to compile ImageMagick with Quantum Depth 64 (Q64) to support extreme-precision scientific, astronomical, and medical imaging. By utilizing the 64-bit quantum depth configuration flag during the build process, users can handle pixel components with standard 64-bit integer or double-precision floating-point accuracy, eliminating quantization errors in demanding computational tasks.

The Compilation Flag

To enable Quantum Depth 64 in ImageMagick, pass the --with-quantum-depth=64 flag to the configure script prior to building the software.

./configure --with-quantum-depth=64

High Dynamic Range Imaging (HDRI) Considerations

When working with scientific imaging, depth precision is often paired with High Dynamic Range Imaging (HDRI) to allow non-clamping floating-point operations:

  • ImageMagick 7: HDRI is enabled by default. Running ./configure --with-quantum-depth=64 automatically configures a Q64HDRI build, mapping pixel channels to 64-bit double-precision floating-point numbers.
  • ImageMagick 6: HDRI must be toggled manually. If floating-point operations are required instead of 64-bit unsigned integers, combine the flags:
./configure --with-quantum-depth=64 --enable-hdri

Step-by-Step Build Instructions

  1. Clone the Source Repository:

    git clone https://github.com/ImageMagick/ImageMagick.git
cd ImageMagick

  2. Configure the Build: Run the configure script with the 64-bit quantum depth setting:

    ./configure --with-quantum-depth=64

  3. Compile and Install: Compile the binaries using available CPU cores, then install them to your system:

    make -j$(nproc)
sudo make install
sudo ldconfig /usr/local/lib

Verifying the Build

Confirm that the Q64 build succeeded by checking the installed version:

magick -version

(For ImageMagick 6, run convert -version)

Look for Features: in the terminal output. It should display Q64 or Q64HDRI.

Performance and Memory Impact

Compiling with Quantum Depth 64 significantly increases resource usage:

  • Memory Footprint: Each pixel channel requires 8 bytes of memory. A standard 4-channel image (RGBA) will consume 32 bytes per pixel in memory, four times the requirement of a default Q16 build.
  • Processing Overhead: Processing 64-bit depths demands more CPU cache and execution time. Only deploy Q64 when the underlying scientific datasets (such as 64-bit TIFF or FITS files) strictly require this level of precision.
