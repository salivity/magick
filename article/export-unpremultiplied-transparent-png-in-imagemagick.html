Export Unpremultiplied Transparent PNG in ImageMagick

Exporting transparent PNGs with clean, un-premultiplied (straight) RGB values is essential for 3D textures, game engines, and compositing pipelines where transparent pixels must retain their underlying color data without dark halos. By default, many image processing workflows either pre-multiply color channels with the alpha channel or clear fully transparent pixels to black to optimize file size. This guide demonstrates how to configure ImageMagick to preserve intact RGB channels alongside an un-premultiplied alpha mask.

Understanding Straight vs. Premultiplied Alpha

The PNG specification requires alpha to be un-premultiplied (straight alpha). In a straight alpha image, a fully transparent red pixel holds the value RGBA(255, 0, 0, 0).

If an image is premultiplied, the RGB values are multiplied by the alpha value (RGB * Alpha). When scaled or rendered, premultiplied images can cause dark fringes around transparent edges if the target renderer interprets them as straight alpha. Furthermore, encoders often zero out color values under zero alpha (RGBA(0, 0, 0, 0)) for compression, ruining texture padding or edge bleeding needed in game development.

Removing Dark Fringes from Premultiplied Inputs

If your input image has already been premultiplied (often indicated by dark borders around semi-transparent edges), use ImageMagick’s -alpha unpremultiply operator before saving:

magick input_premultiplied.png -alpha unpremultiply png32:output_clean.png

For ImageMagick 6, replace magick with convert:

convert input_premultiplied.png -alpha unpremultiply png32:output_clean.png

Specifying the png32: format prefix forces ImageMagick to write a 32-bit RGBA image, preventing it from optimizing the output down to an indexed palette or removing alpha channels.

Preserving RGB Data in Fully Transparent Areas

When you need to preserve custom RGB colors in pixels where the alpha channel is completely transparent (such as UV texture islands with edge padding):

magick rgb_color.png alpha_mask.png -alpha off -compose CopyOpacity -composite png32:output_straight.png

Explanation of flags:

  • rgb_color.png: Contains the exact RGB texture, including color padding in transparent regions.
  • alpha_mask.png: A grayscale image representing the opacity.
  • -alpha off: Disables alpha evaluation while reading the inputs so that underlying color information is not modified or zeroed out.
  • -compose CopyOpacity -composite: Replaces or inserts the alpha channel directly from the second image without mathematically modifying the RGB values of the first.
  • png32:output_straight.png: Ensures the file is saved as full 8-bit-per-channel RGBA without palette reduction or color-key optimization.

Scaling Without Corrupting RGB Values

Resizing an image can inadvertently cause color bleed from empty background pixels into visible edges if the transparency is not isolated. To resize while keeping the RGB channels independent from the alpha channel:

magick input.png \
  \( +clone -alpha extract -resize 50% \) \
  \( -clone 0 -alpha off -resize 50% \) \
  -delete 0 -swap 0,1 \
  -alpha off -compose CopyOpacity -composite \
  png32:resized_straight.png

How this works:

  1. +clone -alpha extract -resize 50%: Extracts the transparency channel as a separate grayscale mask and resizes it independently.
  2. -clone 0 -alpha off -resize 50%: Resizes the RGB data as an opaque image so transparent pixel colors blend cleanly with adjacent colors rather than black.
  3. -compose CopyOpacity -composite: Recombines the resized alpha mask with the resized RGB layer.
  4. png32:: Exports clean, straight RGBA data without color suppression.
