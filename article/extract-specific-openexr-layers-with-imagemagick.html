Extract Specific OpenEXR Layers with ImageMagick

OpenEXR files produced by 3D rendering pipelines often store multiple Arbitrary Output Variables (AOVs)—such as depth, normal passes, specular reflections, and ambient occlusion—within a single multi-channel or multi-part container. ImageMagick can parse these complex data structures, isolate specific sub-layers, and export them to standalone image formats like PNG, TIFF, or individual single-layer EXRs. This guide explains how ImageMagick interprets OpenEXR files and provides the direct commands required to inspect and extract targeted channels.

Inspecting Layers Inside the OpenEXR File

Before extracting a layer, you must identify how the channels and parts are structured inside the file. ImageMagick treats multi-part OpenEXR files similarly to multi-frame image sequences.

Run the identify command to view all available sub-images and channels:

magick identify -verbose render.exr

To output a concise list of layers and sub-image indices without the verbose metadata, use:

magick identify -format "Scene: %s, Geometry: %wx%h, Channels: %[channels]\n" render.exr

Extracting Layers by Frame Index

Multi-part EXRs expose distinct render layers as indexed sub-images (frames). You can extract a specific layer by appending an index number enclosed in brackets directly after the input filename.

To extract the first layer (index 0) to a standard 16-bit PNG:

magick "render.exr[0]" -depth 16 output_diffuse.png

To extract a secondary layer (such as index 2) and save it as a standalone single-layer OpenEXR file:

magick "render.exr[2]" output_specular.exr

Extracting Non-Standard Channels (e.g., Depth or Normals)

In single-part multi-channel EXRs, arbitrary channels (like Z for depth or N.X, N.Y, N.Z for surface normals) may be packed alongside standard RGB data rather than separated into distinct sub-image indices.

To isolate a specific single-channel pass such as depth:

magick render.exr -channel Z -separate output_depth.png

If the pass consists of custom three-channel data, you can isolate and map those specific channels using the -channel flag combined with channel recombination:

magick render.exr -channel-extract "R,G,B" output_beauty.exr

Handling Floating-Point Data and Dynamic Range

OpenEXR files store data in 16-bit half-float or 32-bit float formats, allowing values beyond the 0.0–1.0 range. When extracting layers to standard integer-based formats like PNG or JPEG, high-dynamic-range values may clip or appear entirely white or black.

  • Linear to sRGB Conversion: If extracting an RGB beauty pass to PNG, convert color spaces properly:

    magick "render.exr[0]" -colorspace sRGB -depth 8 diffuse.png

  • Normalizing Passes (Depth/Z-Buffer): Depth passes often contain real-world unit values (e.g., 10.0 to 1000.0) that appear pure white in standard viewers. Normalize the values across the 0–1 range before exporting:

    magick render.exr -channel Z -separate -auto-level depth_visual.png

Batch Extracting All Layers

To split every layer within a multi-part EXR into separate sequential files in a single execution, use the +adjoin operator:

magick render.exr +adjoin -depth 16 layer_%d.png

This command evaluates every internal frame and outputs layer_0.png, layer_1.png, and so on, matching the indices discovered during inspection.
