Force ImageMagick to Use Librsvg for SVG Rendering

ImageMagick does not provide a -define flag to switch between SVG rendering engines; instead, it relies on explicit coder prefixes and build-level delegate configurations. This guide explains how to force ImageMagick to render SVGs using librsvg rather than its internal MSVG engine, how to verify that your installation supports librsvg, and how delegate precedence works.

Forcing Librsvg with the Coder Prefix

To bypass the internal MSVG parser and force ImageMagick to use librsvg, prepend the rsvg: format prefix directly to the input filename on the command line:

magick rsvg:input.svg output.png

For legacy ImageMagick 6 installations:

convert rsvg:input.svg output.png

ImageMagick uses the prefix to route image decoding directly to the librsvg coder (ReadRSVGImage) rather than the built-in, lightweight MSVG delegate (ReadMSVGImage).

Why There Is No Define Flag

ImageMagick implements SVG rendering via distinct coder modules rather than runtime -define properties. While -define handles behavior modifiers (such as parsing limits or density adjustments), delegate selection is handled at the coder level.

ImageMagick recognizes three distinct coder identifiers for SVG:

  • rsvg: Forces the external GNOME librsvg library.
  • msvg: Forces ImageMagick’s built-in MicroSoft SVG parser (internal delegate).
  • svg: Uses the default system priority, which automatically defaults to librsvg if compiled with support, falling back to MSVG or external delegates like Inkscape if librsvg is absent.

Verifying Librsvg Support

If using the rsvg: prefix results in an error such as no decode delegate for this image format, your ImageMagick build was compiled without librsvg support.

Verify available delegates and format support by running:

magick -list format | grep -i svg

A properly configured installation will show RSVG with read (r) mode enabled:

     MSVG* SVG       rw+   ImageMagick's own SVG internal renderer
     RSVG* SVG       r--   Librsvg rendering engine
      SVG  SVG       rw+   Scalable Vector Graphics

Configuring External RSVG in delegates.xml

If ImageMagick was built without the librsvg C library linked directly, you can route SVG operations through the standalone rsvg-convert binary by editing delegates.xml.

Locate the file path with:

magick -list delegate

Add or update the SVG decode line inside delegates.xml:

<delegate decode="svg" command="&quot;rsvg-convert&quot; -o &quot;%o&quot; &quot;%i&quot;"/>

This configuration ensures that any standard svg: input automatically delegates rendering tasks to rsvg-convert.
