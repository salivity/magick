Force Lossless WebP in ImageMagick

This guide explains how to force lossless WebP encoding while maximizing palette size optimization using ImageMagick command-line defines. By utilizing targeted configuration flags, you can ensure bit-exact image reproduction while taking full advantage of WebP's built-in color indexing transform for palletized assets.

The Define for Lossless WebP Encoding

In ImageMagick, the define that explicitly forces lossless encoding is:

-define webp:lossless=true

By default, ImageMagick relies on the quality parameter (-quality) to determine WebP compression mode, treating values below 100 as lossy and 100 as lossless in certain versions. Specifying webp:lossless=true overrides ambiguity, forcing libwebp to bypass the discrete cosine transform (DCT) pipeline and use the WebP lossless specification.

Optimizing Palette Size in Lossless WebP

When lossless mode is forced, WebP automatically applies an internal Color Indexing Transform (palette mode) if the image contains 256 or fewer unique ARGB colors. To optimize this palette and achieve maximum compression, pair the lossless define with the compression effort method:

-define webp:method=6

The method define accepts values from 0 (fastest, larger file) to 6 (slowest, best compression). Setting it to 6 instructs the encoder to exhaustively evaluate spatial predictions, entropy codes, and palette ordering permutations to produce the smallest possible output.

Complete ImageMagick Command

To convert an image to lossless WebP while fully optimizing the palette:

magick input.png -define webp:lossless=true -define webp:method=6 output.webp

For legacy ImageMagick 6 installations, replace magick with convert:

convert input.png -define webp:lossless=true -define webp:method=6 output.webp

Pre-Optimizing the Color Palette

If the source image has more than 256 colors but should use an indexed palette to reduce file size, you can quantize the colors prior to encoding:

magick input.png -colors 256 -define webp:lossless=true -define webp:method=6 output.webp

Using -colors 256 ensures the image qualifies for the WebP palette transform, allowing webp:lossless=true to store the pixel data as 8-bit palette indices rather than full 32-bit ARGB channels.
