Handling Planar vs Interleaved Raw in ImageMagick

Raw image files lack metadata headers, requiring users to explicitly define image dimensions, bit depth, and channel order during decoding. This guide explains how to properly handle both interleaved (pixel-by-pixel) and planar (channel-by-channel) raw image formats using ImageMagick's command-line tools.

Understanding Interleaved vs. Planar Data

When processing uncompressed raw pixel data, the byte layout dictates how color channels are arranged:

  • Interleaved (Chunky): Pixels are stored consecutively with alternating color components (e.g., R1 G1 B1 R2 G2 B2 ...). This is the most common format for standard RGB and RGBA buffers.
  • Planar (Band-Sequential): Color channels are separated into distinct contiguous blocks of memory (e.g., all Red bytes, followed by all Green bytes, followed by all Blue bytes: R1 R2 ... G1 G2 ... B1 B2 ...). This format is common in video processing (such as YUV planar formats) and scientific imaging.

Handling Interleaved Raw Inputs

By default, ImageMagick assumes raw RGB inputs are interleaved. To read an interleaved raw file, define the dimensions, color depth, and the raw format specifier (rgb:, rgba:, bgr:, etc.) before the input filename.

magick -size 1920x1080 -depth 8 rgb:input_interleaved.raw output.png

For 16-bit interleaved data, adjust the depth accordingly:

magick -size 1920x1080 -depth 16 -endian msb rgb:input_16bit.raw output.png

Handling Planar Raw Inputs

To instruct ImageMagick to read channels sequentially rather than pixel-by-pixel, use the -interlace plane setting prior to declaring the input file.

RGB Planar Decoding

magick -size 1920x1080 -depth 8 -interlace plane rgb:input_planar.raw output.png

When -interlace plane is declared alongside rgb:, ImageMagick reads:

  1. Width * Height bytes for the Red channel
  2. Width * Height bytes for the Green channel
  3. Width * Height bytes for the Blue channel

RGBA Planar Decoding

For raw files containing an alpha channel laid out in separate planes (RRR... GGG... BBB... AAA...):

magick -size 1920x1080 -depth 8 -interlace plane rgba:input_planar_rgba.raw output.png

Handling Non-Contiguous or Custom Planar Formats

If a raw file uses planar layout with custom padding, headers, or non-standard channel ordering, you can read the planes individually as grayscale inputs using byte offsets, then combine them using -combine.

For an 8-bit 1920x1080 image where each plane is exactly 2,073,600 bytes:

magick \
  \( -size 1920x1080 -depth 8 gray:input.raw[0] \) \
  \( -size 1920x1080 -depth 8 gray:input.raw[2073600] \) \
  \( -size 1920x1080 -depth 8 gray:input.raw[4147200] \) \
  -combine output.png

The bracketed notation [offset] specifies the starting byte offset for each individual plane, allowing complete control over non-standard planar data structures.
