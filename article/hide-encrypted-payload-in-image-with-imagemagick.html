Hide Encrypted Payload in Image With ImageMagick

This article provides a complete walkthrough on how to securely hide an encrypted payload within an image using OpenSSL and ImageMagick's stegano: operator. You will learn how to encrypt a secret text file with strong symmetric encryption, format the ciphertext into a raw grayscale image, embed it into the least significant bits of a carrier image, and extract and decrypt the original data.

Prerequisites

You need both OpenSSL and ImageMagick installed on your system. On modern systems, ImageMagick v7 uses the magick command, while older versions use standalone utilities like convert and composite.

Step 1: Encrypt the Payload

ImageMagick embeds pixel data rather than handling encryption natively. First, encrypt the secret text into ciphertext using OpenSSL with AES-256-CBC.

openssl enc -aes-256-cbc -salt -pbkdf2 -in secret.txt -out secret.enc

Step 2: Format the Ciphertext as a Raw Image

ImageMagick’s steganography features require the payload to be formatted as an image. Determine the size of the encrypted payload and fit it into a grayscale pixel grid.

Check the file size in bytes:

wc -c < secret.enc

Pick square dimensions that yield enough pixels (bytes) to hold the payload (for example, a 64x64 pixel image holds 4,096 bytes). Pad the encrypted data to match the exact size required:

# Create a 4096-byte blank canvas
dd if=/dev/zero of=payload.bin bs=1 count=4096

# Copy the encrypted payload into the padded container
dd if=secret.enc of=payload.bin conv=notrunc

# Convert raw bytes into a grayscale PNG
magick -depth 8 -size 64x64 gray:payload.bin payload.png

Step 3: Embed the Payload Using Stegano

The carrier image must be significantly larger than the payload image because ImageMagick uses the least significant bits across color channels to hide each bit of the payload. A carrier image of at least 800x800 pixels is sufficient for a 64x64 payload.

Embed the payload using the composite tool with the -stegano option:

magick composite -stegano +0+0 payload.png carrier.png stego_image.png

The resulting stego_image.png visually resembles the original carrier.png, but it contains the encrypted payload embedded within its pixel structure.

Step 4: Extract the Hidden Image

To extract the payload, you must specify the exact dimensions (64x64) and pixel offset (+0+0) used during the embedding step. Read the data directly using the stegano: protocol prefix:

magick -size 64x64+0+0 stegano:stego_image.png extracted.png

Step 5: Decrypt the Extracted Payload

Convert the extracted image back into raw bytes, then decrypt the data with OpenSSL:

# Convert PNG pixels back to a raw binary file
magick extracted.png -depth 8 gray:extracted.bin

# Decrypt the binary using the original password
openssl enc -d -aes-256-cbc -pbkdf2 -in extracted.bin -out recovered_secret.txt

OpenSSL will automatically ignore any trailing null padding bytes that were added during the formatting step, cleanly restoring the original contents of secret.txt.
