How ImageMagick Adjusts Mipmap Filter Coefficients

When generating mipmap pyramids, ImageMagick creates progressively downsampled levels of a texture to ensure smooth rendering and eliminate aliasing artifacts at varying distances. To achieve this, the software applies a scalable, separable 2D convolution algorithm that dynamically widens the reconstruction filter kernel, evaluates the chosen continuous weighting function across pixel neighborhoods, and normalizes the resulting discrete coefficients. This process conserves overall image luminance and prevents high-frequency data from folding back into the lower-resolution mip levels.

Kernel Scaling and Support Dilation

ImageMagick treats downsampling as a continuous signal processing problem. When computing a mipmap level that is half the resolution of the preceding tier, the scale factor \(s\) is defined as \(0.5\).

In standard upsampling or unity scaling (\(s \ge 1.0\)), the filter’s support radius determines the number of neighboring pixels sampled. During downsampling (\(s < 1.0\)), using an unadjusted support width would cause Nyquist-Shannon sampling violations, resulting in severe aliasing. ImageMagick compensates by dilating the filter support radius:

\[\text{Adjusted Support} = \frac{\text{Base Support}}{s}\]

For a standard dyadic mipmap step where \(s = 0.5\), the filter support is effectively doubled. This guarantees that the sampling window expands to cover a sufficient area of the source image, capturing all relevant frequency information needed for the lower-resolution target.

Evaluating Filter Functions

Once the expanded window is established for an output pixel, ImageMagick calculates the discrete contribution (weight) of each input pixel within that window. It samples the mathematical profile of the selected filter (such as Mitchell-Netravali, Lanczos, Box, or Gaussian).

Because the kernel has been stretched in spatial extent, the input coordinates passed into the filter function must be scaled down accordingly:

\[W(x) = f(x \cdot s)\]

Here, \(x\) represents the discrete distance between the input sample position and the target sampling center, and \(f\) is the continuous filter function. Multiplying the distance by the scale factor \(s\) spreads the evaluation curve across the widened support window.

Coefficient Normalization and Energy Conservation

Evaluating the continuous function across discrete grid points can produce a set of weights whose sum does not equal \(1.0\). If applied directly, this would alter the overall brightness (energy) of the texture level and introduce ripple artifacts across uniform areas.

ImageMagick resolves this by summing all evaluated raw weights within the support bounds:

\[\text{Total Weight} = \sum_{i} W(x_i)\]

Each individual raw coefficient is then adjusted by dividing it by this sum:

\[C_i = \frac{W(x_i)}{\text{Total Weight}}\]

This normalization step ensures that the discrete coefficients sum to precisely \(1.0\). As a result, the average luminance and color balance remain consistent across every tier of the mipmap pyramid.

Separable Execution Across Axes

To maintain performance, ImageMagick generates mipmap levels using separable passes rather than a direct 2D matrix calculation. The horizontal dimension is filtered and downsampled first, calculating and applying 1D horizontal coefficients for every row. The vertical dimension is then processed on that intermediate buffer, applying 1D vertical coefficients down each column. Because the scale factor is symmetric (\(0.5\) along both axes for standard mipmaps), the calculated coefficient distributions are identical in both passes, maximizing memory cache efficiency and computational throughput.
