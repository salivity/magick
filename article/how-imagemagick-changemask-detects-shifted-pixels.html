How ImageMagick ChangeMask Detects Shifted Pixels

The ImageMagick ChangeMask operator isolates visual differences between consecutive frames by evaluating coordinate-based color differences rather than tracking motion paths. This article explains how ChangeMask evaluates pixel positions, utilizes color distance thresholds to flag alterations, and converts static regions into transparency to optimize animations and highlight moving elements.

Coordinate-Based Comparison

ChangeMask does not use optical flow or vector estimation to follow a moving subject. Instead, it operates on a strict spatial grid, comparing the pixel at coordinate \((x, y)\) in the source image directly to the pixel at coordinate \((x, y)\) in the destination image.

When an element shifts across the screen between two frames, ChangeMask detects that movement via two distinct coordinate events:

  1. The vacated region: The coordinates where the object used to be now contain background pixels, creating a color mismatch between the old frame and the new frame.
  2. The newly occupied region: The coordinates where the object has moved now contain the object's pixels instead of the previous background, creating a second mismatch.

Both regions register as changed coordinates under direct pixel-by-pixel inspection.

Color Distance and the Fuzz Factor

To determine whether a pixel has changed, ChangeMask calculates the mathematical distance between the color values of the two corresponding coordinates. By default, any slight variation in RGB values registers as a change.

Because video encoding, compression artifacts, and anti-aliasing can cause slight color drifts between frames, ImageMagick uses the -fuzz factor alongside ChangeMask. The fuzz distance represents a tolerance threshold (often defined as a percentage):

  • Within Fuzz Threshold: If the Euclidean distance between the color vectors of the two pixels is less than or equal to the fuzz threshold, ImageMagick treats the pixels as identical.
  • Exceeding Fuzz Threshold: If the color difference exceeds the fuzz threshold, ImageMagick flags the pixel as changed.

Generating the Mask Output

Once ChangeMask identifies which pixels match and which have changed, it alters the pixel data of the target frame:

  • Unchanged Pixels: Pixels determined to be identical (within the fuzz tolerance) are replaced with transparency (alpha channel set to 0).
  • Shifted or Changed Pixels: Pixels that have changed color retain their original color and opacity values from the incoming frame.

The resulting output is a frame where all static content is stripped away, leaving only the newly introduced visual data and the background fills covering the previously occupied spaces. This mechanism forms the foundation for GIF animation optimization (such as -layers OptimizeFrame), significantly reducing file size by storing only the delta of shifted content.
