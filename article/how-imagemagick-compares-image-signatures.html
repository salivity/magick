How ImageMagick Compares Image Signatures

This article explains how ImageMagick detects identical images by generating and comparing cryptographic signatures based exclusively on raw pixel data. While traditional file-hashing tools fail to match identical images that contain different EXIF data, timestamps, or file formats, ImageMagick bypasses all container-level metadata to inspect the actual rendered pixels. Understanding this mechanism allows developers and system administrators to reliably detect visual duplicates, organize digital media archives, and eliminate redundant assets without false negatives caused by extraneous metadata.

The Limitation of Standard File Hashing

Standard operating system utilities like md5sum or sha256sum calculate hashes based on the entire binary byte stream of a file. This stream includes file headers, embedded color profiles, EXIF metadata, IPTC tags, compression parameters, and software timestamps. If two files have pixel-for-pixel identical imagery but one contains an updated timestamp or a different camera tag, standard file hashes will not match.

How ImageMagick Generates an Image Signature

ImageMagick resolves this issue by calculating a cryptographic hash—typically SHA-256—directly from the decoded raster pixel stream rather than the file on disk.

The generation process follows these distinct steps:

  1. Decoding the Image: ImageMagick reads the source file (JPEG, PNG, TIFF, etc.) and uses the appropriate image decoder to extract the raw pixel information into memory.
  2. Normalizing the Pixel Buffer: The image is structured into an uncompressed raster array of scanlines, representing each pixel's color channels (Red, Green, Blue, and optionally Alpha/Opacity) at a consistent color depth.
  3. Excluding Metadata: Headers, EXIF data, XMP blocks, comments, and file creation dates are entirely excluded from the buffer passed to the hashing algorithm.
  4. Hashing the Pixel Stream: ImageMagick feeds the raw pixel array sequentially into a SHA-256 hashing engine. The result is a 64-character hexadecimal digest representing the visual content of the image.

Comparing Signatures Across Formats

Because the signature is calculated on raw decoded pixels, two different lossless formats will produce identical signatures if their pixel dimensions, colors, and alpha values match. For example, an uncompressed 24-bit RGB BMP file and a 24-bit RGB PNG file containing the exact same visual content will yield the same ImageMagick signature.

However, lossy formats like JPEG will only match if their decoded pixel buffers are identical. Compressing an image with different JPEG quality levels alters pixel values slightly, resulting in different signatures.

Using ImageMagick Signatures in Practice

To retrieve the pixel signature of an image, use the identify command with the %# format specifier:

magick identify -format "%#" image1.png

To compare two files directly:

sig1=$(magick identify -format "%#" image1.jpg)
sig2=$(magick identify -format "%#" image2.png)

if [ "$sig1" = "$sig2" ]; then
    echo "Images are pixel-identical."
else
    echo "Images have different pixel data."
fi

By relying on decoded scanlines rather than the underlying file payload, ImageMagick provides a deterministic method to verify that two images are visually and structurally identical, entirely immune to differences in metadata or container formats.
