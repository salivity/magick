How ImageMagick DarkenIntensity Evaluates Pixels

This article provides a technical overview of how ImageMagick's DarkenIntensity compositing operator evaluates and renders pixel data in multi-layer composites. It details the underlying mathematical model, compares its whole-pixel selection behavior against standard channel-by-channel compositing methods, and explains how alpha transparency and luminance metrics influence final output values across image layers.

The Fundamental Logic of DarkenIntensity

In digital image compositing, the standard Darken operator evaluates pixels on a per-channel basis. For an RGB image, it independently compares red to red, green to green, and blue to blue, keeping the lowest numerical value for each channel. While mathematically straightforward, this per-channel comparison often produces unexpected hues and artifacts because the resulting color may be a hybrid mixture that did not exist in either source layer.

The DarkenIntensity operator solves this problem by treating the pixel as an indivisible color unit. Instead of splitting pixel data across independent color channels, DarkenIntensity computes a single scalar intensity (luminance) value for both the source (overlay) pixel and the destination (background) pixel. It then compares these two scalar values and selects the entire color vector—red, green, and blue together—from whichever pixel possesses the lower overall intensity.

The Luminance Calculation

To determine which pixel is darker, ImageMagick converts the color information of each pixel into an intensity value using standard photometric weighting. Under typical sRGB or linear RGB profiles, the intensity (\(Y\)) is computed using standardized luma coefficients:

\[Y = 0.299R + 0.587G + 0.114B\]

Depending on the active colorspace and ImageMagick compilation settings (such as Rec709 or Rec601 standards), the exact weights assigned to red, green, and blue may vary slightly, but green consistently carries the highest perceptual weight due to the human visual system's sensitivity.

Pixel Evaluation and Selection

During a composite operation between a destination image (\(D\)) and a source image (\(S\)), the evaluation follows this conditional logic for every overlapping pixel:

  1. Calculate Intensities: Compute \(Y_S\) for the source pixel and \(Y_D\) for the destination pixel.
  2. Compare Values: Compare \(Y_S\) against \(Y_D\).
  3. Assign Color Output:
    • If \(Y_S < Y_D\), the output color \((R_{out}, G_{out}, B_{out})\) is taken directly from the source: \((R_S, G_S, B_S)\).
    • If \(Y_S \ge Y_D\), the output color \((R_{out}, G_{out}, B_{out})\) remains the destination value: \((R_D, G_D, B_D)\).

Because the entire RGB triplet is preserved from the winning pixel, DarkenIntensity prevents the hue shifting and chromatic distortions common to standard minimum-channel operations.

Handling Alpha Channels

When layers contain transparency, ImageMagick applies the intensity comparison to the color components while scaling the final result by the respective alpha values.

If a pixel has partial opacity, the intensity comparison determines the target color, and the standard over-compositing algebra blends the source and destination according to their coverage:

\[\alpha_{out} = \alpha_S + \alpha_D \cdot (1 - \alpha_S)\]

If the source pixel is completely transparent (\(\alpha_S = 0\)), the destination pixel remains unaltered regardless of theoretical intensity differences. When both pixels possess partial transparency, the operator evaluates the premultiplied color values to ensure that transparent regions do not artificially evaluate as black (zero intensity).

Behavior in Multi-Layer Stacks

When processing more than two layers, ImageMagick applies the DarkenIntensity operation sequentially down the layer stack:

  1. The first layer serves as the initial destination (\(D\)).
  2. The second layer acts as the source (\(S\)), generating an intermediate composite image based on the intensity comparison.
  3. Each subsequent layer acts as a new source against the accumulated composite, progressively retaining the lowest-intensity pixel at every coordinate across the entire stack.
