How ImageMagick Draw Polygon Fills Enclosed Areas

The ImageMagick -draw 'polygon' operator renders solid shapes by converting arbitrary vertex coordinates into closed geometric paths, processing them through a scanline rasterization algorithm, and evaluating boundary rules to determine which pixels reside inside the shape. By projecting edges across a discrete pixel grid and calculating fractional coverage, ImageMagick accurately fills standard, concave, and self-intersecting polygons while applying antialiasing to smooth the outer edges.

Path Closure and Edge Table Construction

When you pass a series of coordinate pairs to -draw 'polygon x0,y0 x1,y1 ... xN,yN', ImageMagick first establishes the polygon perimeter by connecting consecutive points with straight line segments. Unlike the polyline primitive, polygon automatically adds an implicit closing segment connecting the final coordinate back to the initial coordinate if they do not match.

Once the path is defined, ImageMagick's rendering engine constructs an Edge Table (ET). It decomposes the linear boundaries into a collection of directed vectors, discarding horizontal edges and sorting the remaining segments vertically by their minimum Y-coordinates.

Scanline Rasterization

To paint the interior, ImageMagick processes the shape row by row using a scanline algorithm:

  1. Active Edge Management: For each horizontal scanline crossing the bounding box of the polygon, the renderer maintains an Active Edge Table (AET) containing only the edges intersecting the current Y-level.
  2. Intersection Calculation: The exact X-axis intersections between the scanline and the active edges are computed.
  3. Sorting: The intersection points along the scanline are sorted from left to right.

Interior Determination: Fill Rules

When a polygon self-intersects, loops back on itself, or contains nested paths, the rendering engine must decide which enclosed spaces are "inside" (filled) and which are "outside" (holes). ImageMagick resolves this using fill rules, which determine whether a pixel span between two intersections receives paint:

  • Non-Zero Winding Rule (Default): The algorithm tracks a winding number, initialized to zero. As the scanline moves left to right, intersecting a ray drawn upward adds +1 to the counter, while intersecting a downward-pointing ray subtracts 1. Regions where the winding number is non-zero are marked as interior and filled with the active -fill color. Regions where the count returns to zero are treated as exterior.
  • Even-Odd Rule: Configured using the -fill-rule evenodd setting, this rule simply counts the number of edge crossings. An odd number of crossings indicates an interior point, while an even number indicates an exterior point.

Subpixel Coverage and Antialiasing

Unless disabled via +antialias, ImageMagick does not make purely binary (in or out) decisions for edge pixels. Instead, it evaluates polygon boundaries at subpixel resolution or uses analytical area integration.

The rasterizer determines what fraction of each boundary pixel is covered by the enclosed polygon area. It then calculates an alpha value proportional to this coverage, blending the fill color smoothly with the existing background pixels to prevent jagged staircase artifacts.
