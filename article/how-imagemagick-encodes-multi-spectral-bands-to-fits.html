How ImageMagick Encodes Multi-Spectral Bands to FITS

ImageMagick encodes multi-spectral imaging bands into the Flexible Image Transport System (FITS) format by structuring multi-channel or multi-frame raster data into a three-dimensional data cube or sequential Header and Data Units (HDUs). By reading discrete spectral bands—whether supplied as separate input files or as native multi-channel images like RGB—the coder serializes pixel matrices into a planar array, updates structural FITS header keywords such as NAXIS, and scales quantum pixel values to fit standard astronomical bit depths.

The FITS Dimensional Hierarchy and NAXIS Mapping

The FITS standard organizes data using the NAXIS keyword family within a standardized 2880-byte header block. When ImageMagick encounters multi-spectral data, it organizes the data using a 3D volume:

  • NAXIS = 3: Informs the FITS reader that the file contains a three-dimensional data cube rather than a flat 2D image.
  • NAXIS1: Represents the width (X-dimension or number of columns) of the spatial grid.
  • NAXIS2: Represents the height (Y-dimension or number of rows) of the spatial grid.
  • NAXIS3: Represents the depth, which ImageMagick maps to the number of spectral bands or image channels (for example, 3 for standard RGB, or \(N\) for an arbitrary sequence of narrow-band filters).

Planar Pixel Ordering (Band-Sequential Encoding)

Standard raster image formats typically interleave color channels per pixel (RGBRGB...). FITS, conversely, requires contiguous spatial planes (band-sequential order).

ImageMagick extracts each spectral channel into an independent memory plane. During the encoding process, it writes the entire spatial array of the first band (NAXIS3 = 1) row by row, followed immediately by the entire array of the second band (NAXIS3 = 2), and continues sequentially until all spectral bands are serialized into the data segment.

Bit Depth Mapping and Normalization (BITPIX)

ImageMagick normalizes its internal Quantum depth to one of the standard FITS data types defined by the BITPIX keyword:

  • BITPIX = 8: 8-bit unsigned integers.
  • BITPIX = 16: 16-bit signed integers (using BZERO = 32768 and BSCALE = 1 offsets to store unsigned 16-bit image data without clipping).
  • BITPIX = 32: 32-bit signed integers.
  • BITPIX = -32 or -64: Single- or double-precision IEEE floating-point values, utilized when compiling ImageMagick with high-dynamic-range imaging (HDRI) enabled.

Pixel intensities are transformed linearly from ImageMagick’s internal representation to fit the target BITPIX range, preserving the dynamic range across all spectral bands uniformly.

Image Sequence Aggregation

When converting multiple distinct mono-spectral files (such as individual narrowband captures: H-alpha, OIII, and SII) into a unified FITS file, ImageMagick stacks the inputs as an image list:

magick band_red.tif band_green.tif band_blue.tif -combine multispectral.fits

Or using an image stack directly:

magick band1.fits band2.fits band3.fits -append-slices output_cube.fits

In this mode, ImageMagick verifies that all input dimensions (NAXIS1 and NAXIS2) match, assigns each input frame an index along the third axis (NAXIS3), and pads the trailing data block with null bytes (0x00) to conform to the standard 2880-byte record requirement of the FITS standard.
