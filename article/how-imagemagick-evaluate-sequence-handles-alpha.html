How ImageMagick Evaluate-Sequence Handles Alpha

ImageMagick's -evaluate-sequence operator combines a list of images into a single image by applying a mathematical, logical, or relational function across corresponding pixels. When dealing with images containing alpha transparency, -evaluate-sequence processes the alpha channel independently on a per-channel basis rather than performing standard alpha compositing. This guide explains how this mechanism works, the distinction between mathematical channel evaluation and alpha blending, and how to manage transparency correctly to avoid visual artifacts.

Per-Channel Independent Processing

By default, -evaluate-sequence iterates through every pixel coordinate across the entire image sequence and applies the specified method (such as Mean, Add, Max, or Min) to each active channel independently.

ImageMagick treats the alpha channel merely as another 8-bit, 16-bit, or 32-bit grayscale plane containing values ranging from zero (fully transparent) to the maximum quantum value (fully opaque):

  • Color Channels (RGB): The selected formula calculates output color values solely from the input color values, without taking into account whether a pixel is transparent.
  • Alpha Channel (A): The same formula is calculated strictly using the alpha values of the input images to determine the final opacity of that pixel.

Because of this channel independence, -evaluate-sequence does not perform Porter-Duff compositing or weighted alpha blending.

The Hidden Color Problem in Transparent Pixels

Because color channels are evaluated independently of alpha values, fully transparent pixels can skew the resulting color data. In digital imaging, a pixel with an alpha value of 0 still holds underlying Red, Green, and Blue values (often black, white, or leftover canvas colors).

When using methods like Mean or Add:

  • If an image sequence contains an opaque red pixel at (x,y) in Image 1 and a fully transparent black pixel at (x,y) in Image 2, the Mean operation averages both the RGB channels and the Alpha channel independently.
  • The result will be a 50% transparent dark red pixel, because the black color of the transparent pixel is averaged directly into the visible color data.

Controlling Alpha via Channel Masks

You can control whether the alpha channel is modified during the operation using the -channel setting:

  • Exclude Alpha: If you define -channel RGB, ImageMagick limits the sequence calculation strictly to color data. The alpha channel of the first image in the sequence is preserved as the output alpha mask.
  • Include Alpha: If you define -channel RGBA, both color and transparency channels are calculated using the chosen operator.

Achieving Proper Alpha-Weighted Blending

If the goal is to create an alpha-weighted average of multiple images rather than an independent mathematical calculation, -evaluate-sequence mean alone will yield incorrect results. To correctly account for transparency when combining sequences:

  1. Premultiply Alpha: Convert the images to premultiplied alpha before running the sequence (using -alpha associate in ImageMagick 7). This scales the color channels according to their corresponding alpha values.
  2. Execute the Sequence: Run -evaluate-sequence Mean across all channels (RGBA).
  3. Un-premultiply Alpha: Revert the color channels back to straight alpha (using -alpha disassociate).

Alternatively, if visual layering rather than mathematical reduction is required, use operators designed for compositing, such as -layers merge or iterative -composite commands, which naturally evaluate transparency using standard alpha blending rules.
