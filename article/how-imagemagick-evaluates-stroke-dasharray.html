How ImageMagick Evaluates stroke-dasharray

ImageMagick processes dashed strokes using the stroke-dasharray setting within its vector drawing subsystem, adhering closely to the SVG and Magick Vector Graphics (MVG) specifications. This article explains how ImageMagick parses comma- or space-delimited values, normalizes sequence lengths, factors in coordinate transformations and stroke properties, and calculates the final dashed border across vector paths.

Pattern Sequence Parsing

The stroke-dasharray parameter defines a pattern of alternating dashes and gaps specified as a list of numerical lengths (for example, stroke-dasharray 10, 5, 2, 5). ImageMagick reads this list as a continuous cycle:

  • The first value specifies the length of a rendered dash.
  • The second value specifies the length of the transparent gap.
  • Subsequent pairs continue alternating between dash and gap lengths.

If you supply a single value of 0 or the string none, ImageMagick disables dashing and renders a solid stroke.

Odd vs. Even Argument Normalization

Following SVG conventions, ImageMagick requires an even number of values to form a complete dash-and-gap cycle. When an odd number of entries is provided, the engine duplicates the entire list to generate an even sequence.

For example, if you provide:

stroke-dasharray 5, 3, 2

ImageMagick doubles the sequence internally to:

5, 3, 2, 5, 3, 2

This ensures that the cycle correctly alternates between dashes and gaps without misaligning the starting state on subsequent repetitions:

  1. Dash: 5
  2. Gap: 3
  3. Dash: 2
  4. Gap: 5
  5. Dash: 3
  6. Gap: 2

Coordinate Space and Resolution

Each value in stroke-dasharray is defined in user-space coordinates (pixels by default). When ImageMagick evaluates these lengths, it calculates them relative to the current graphics state:

  • Affine Transformations: If scaling or rotation transforms (-affine or scale matrices) are applied, dash lengths scale proportionally with the coordinate system along the path direction.
  • Stroke Width and Caps: The dash lengths strictly measure the distance along the center of the stroke path. However, cap styles (stroke-linecap) like round or square extend the visible dash beyond its measured length, effectively reducing the perceived size of the gap.

The Role of stroke-dashoffset

ImageMagick evaluates stroke-dasharray in tandem with stroke-dashoffset. The offset parameter dictates where along the defined dash-gap pattern rendering begins at the start of the path:

  • A positive offset shifts the pattern backward, starting the path further into the sequence.
  • A negative offset shifts the pattern forward.
  • The offset calculation is evaluated modulo the total length of the normalized pattern cycle.

Rasterization along the Path Perimeter

During the rasterization phase, ImageMagick traverses the stroke path calculating the cumulative arc length:

  1. The renderer begins at the origin of the path (or shape perimeter) at the phase specified by stroke-dashoffset.
  2. It tracks the distance traveled along the vector spline or polygon edge against the current segment of the dash pattern.
  3. Once the accumulated distance matches the current segment length, ImageMagick switches state (from drawing pixels to leaving empty space, or vice versa) and advances to the next value in the array.
  4. When reaching the end of the array, the pattern counter wraps back to the beginning until the path finishes.
  5. On closed paths (like rectangles and circles), the pattern wraps around the boundary, and unless the total perimeter length is an exact multiple of the total dash cycle, the final gap and initial dash will overlap or truncate at the closing vertex.
