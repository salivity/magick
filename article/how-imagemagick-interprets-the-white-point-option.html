How ImageMagick Interprets the White-Point Option

In ImageMagick, the -white-point command-line option is used to define the chromaticity coordinates of the reference white in an image. This article explains how ImageMagick reads these coordinates, the standard mathematical color space it relies upon, how the values are stored in output file formats, and how they influence color space transformations.

The Coordinate System: CIE 1931 xy

When you provide values to -white-point, ImageMagick expects a pair of floating-point numbers formatted as x,y. These values represent coordinates in the standard CIE 1931 xy chromaticity space:

  • x: The horizontal coordinate representing the normalized spectral weighting of red.
  • y: The vertical coordinate representing the normalized spectral weighting of green.

For example, standard daylight illuminant D65 is represented as -white-point 0.3127,0.3290, while the D50 illuminant used in standard print workflows is written as -white-point 0.3457,0.3585. ImageMagick does not accept absolute tristimulus values (XYZ) directly through this flag; it specifically interprets the inputs as two-dimensional projected xy chromaticity.

Role in Color Gamut Definition

The white point alone does not define an entire color space, but it acts as the neutral anchor point. When paired with -red-primary, -green-primary, and -blue-primary, the -white-point coordinates allow ImageMagick to establish the full RGB-to-XYZ transformation matrix for linear color calculations. Without chromaticity coordinates, rendering engines cannot properly map the intensity of standard RGB channels into absolute perceptual colors.

Metadata Tagging in Output Formats

In many common operations, setting -white-point does not alter the underlying raw pixel values directly. Instead, ImageMagick interprets the option as an instruction to embed these chromaticity coordinates into format-specific metadata:

  • PNG: Stored within the cHRM (primary chromaticities and white point) chunk.
  • TIFF: Stored in the WhitePoint (tag 318) baseline TIFF field.

Decoders and rendering applications reading these output files use this embedded metadata to perform accurate color rendering, especially when a full ICC profile is not embedded in the file.

Impact on Color Transformations

If an operation requires converting between different color spaces or adjusting chromatic adaptation (such as transforming to or from CIE XYZ), ImageMagick uses the specified white point to calculate the necessary Bradford or von Kries adaptation matrices. If an ICC color profile is explicitly applied or converted using -profile, the embedded ICC profile data generally takes precedence over manual -white-point coordinates.
