How ImageMagick Parses Sun Raster RAS Images

This article examines how ImageMagick reads and interprets legacy Sun Raster (RAS) image files, commonly generated as screen dumps on vintage Unix workstations. It covers the detection of the format's signature magic number, the processing of big-endian header metadata, the extraction of color maps, the decoding of run-length compressed scanlines, and the transformation of raw raster scanlines into ImageMagick's internal pixel representation.

Header Validation and Architecture Handling

When ImageMagick encounters a Sun Raster file, the decoding process is handled by the dedicated SUN coder (ReadSUNImage in coders/sun.c). The reader first inspects the initial 32 bytes of the file stream to validate the unique 32-bit magic number: 0x59a66a95.

Because Sun Microsystems hardware (such as SPARC and Motorola 68000 architectures) was natively big-endian, the raster header structure is stored in most-significant-byte (MSB) order. ImageMagick uses MSB reading routines to extract the following structural parameters regardless of the host machine's native endianness:

  • Width and Height: The horizontal and vertical dimensions of the screen dump in pixels.
  • Depth: The bit depth per pixel, typically 1 (monochrome), 8 (indexed color or grayscale), 24 (true color), or 32 (true color with padding or alpha).
  • Length: The byte size of the image payload following the header and colormap.
  • Type: The encoding scheme, which determines whether the data is raw (RT_STANDARD), run-length encoded (RT_BYTE_ENCODED), or formatted in alternative RGB channel sequences (RT_FORMAT_RGB).
  • Map Type and Map Length: Flags indicating whether an indexed palette is present (RMT_EQUAL_RGB) or omitted (RMT_NONE), followed by the byte size of the palette.

Colormap Extraction

If the header defines a colormap type of RMT_EQUAL_RGB, ImageMagick allocates an internal palette table. Sun Raster colormaps store color data in non-interleaved arrays where all red values appear first, followed by all green values, and then all blue values.

The reader reads the entire palette chunk and populates the pixel colormap accordingly. If the image bit depth is 8 but no palette is declared (RMT_NONE), ImageMagick builds a linear grayscale ramp as a fallback to ensure the image displays properly.

Scanline Decoding and Padding Alignment

A defining characteristic of the Sun Raster format is 16-bit scanline alignment: every row of pixels must end on an even 2-byte boundary. If a calculated scanline width in bytes is odd, an extra padding byte is appended at the end of the line. ImageMagick accounts for this padding during stream traversal.

The payload decompression proceeds based on the format type:

  • Standard (Raw): ImageMagick reads pixel rows directly from the file into memory buffers, discarding any line-padding bytes at the end of each scanline.
  • Byte-Encoded (RLE): For compressed screen dumps, ImageMagick evaluates byte streams using an escape-code system based on the byte value 0x80. If 0x80 is followed by a non-zero count byte, the subsequent byte is repeated \((count + 1)\) times. A literal 0x80 value within the stream is represented by the sequence 0x80 0x00. ImageMagick expands this run directly into a temporary scanline buffer until the row width, including padding, is satisfied.

Pixel Mapping and Color Space Conversion

Once a scanline is decoded into raw bytes, ImageMagick converts the data into internal quantum pixels using its cache views:

  • 1-bit: The coder processes each bit individually, setting pixels to black or white (or indexing entries 0 and 1 of the colormap).
  • 8-bit: Each byte indexes directly into ImageMagick's internal colormap.
  • 24-bit and 32-bit: Sun screen dumps typically store color components in BGR or standard RGB order depending on the header type. For 32-bit files, the first byte of every four-byte quad is often an unused padding byte, followed by red, green, and blue. ImageMagick maps the channels into their corresponding red, green, and blue quantum storage, discarding the pad byte unless an alpha channel is explicitly designated.

After all scanlines are processed and assigned to the pixel cache, ImageMagick finalizes the image geometry and returns the decoded raster image for rendering, conversion, or display.
