How ImageMagick Reads and Writes Radiance HDR Files

This article explains how ImageMagick processes Radiance HDR files (.hdr, .pic) using the 32-bit RGBE format developed by Greg Ward. ImageMagick translates high-dynamic-range color data between its internal pixel representation and the RGBE structure by parsing metadata, applying run-length compression, and mathematically converting linear floating-point color values to and from shared-exponent byte structures. Understanding this pipeline clarifies how ImageMagick maintains dynamic range precision while reading and writing high-contrast imagery.

The RGBE Format Architecture

The Radiance HDR format stores high-dynamic-range color using 32 bits per pixel. Instead of storing independent 16-bit or 32-bit floats for each color channel (which would require 48 to 96 bits per pixel), it packs three color channels and a shared exponent into four 8-bit bytes:

  • R (Red): 8-bit mantissa
  • G (Green): 8-bit mantissa
  • B (Blue): 8-bit mantissa
  • E (Exponent): 8-bit shared exponent biased by 128

This structure covers a dynamic range of over 76 orders of magnitude, providing sufficient precision for human visual perception while keeping file sizes compact.

Reading Radiance HDR Files in ImageMagick

When ImageMagick encounters a Radiance HDR file, it uses its dedicated HDR coder (coders/hdr.c) to parse and reconstruct the pixel data through several sequential stages:

1. Header Parsing

The decoder reads the plain-text ASCII header that begins with identification signatures such as #?RADIANCE or #?RGBE. It scans variables like FORMAT=32-bit_rle_rgbe to verify data compatibility and processes exposure or color-correction modifiers. It then reads the resolution string (e.g., -Y [height] +X [width]), which defines the image dimensions and scanline orientation.

2. Run-Length Decoding (RLE)

Radiance HDR files typically compress scanlines using run-length encoding. The decoder inspects the beginning of each scanline:

  • Modern Adaptive RLE: A scanline starting with byte values 0x02, 0x02 followed by the 16-bit scanline width indicates modern RLE. In this mode, the R, G, B, and E channels are de-interleaved across the scanline. ImageMagick unpacks each channel run separately for the full row.
  • Legacy RLE / Flat Data: If the signature is absent, ImageMagick falls back to decoding interleaved 4-byte pixels directly, handling simple run-length patterns if flagged.

3. Floating-Point Reconstruction

Once four bytes (\(R_{byte}, G_{byte}, B_{byte}, E_{byte}\)) are unpacked for a pixel, ImageMagick restores the linear floating-point values using the standard Radiance formula:

\[V = \frac{C_{byte} + 0.5}{256} \times 2^{(E_{byte} - 128)}\]

Where \(C_{byte}\) is the red, green, or blue byte, and \(V\) is the resulting linear color channel intensity. If \(E_{byte}\) is zero, all color channels are evaluated as zero.

4. Loading into the Pixel Cache

ImageMagick writes the calculated values directly to its internal pixel cache. If ImageMagick is compiled with High Dynamic-range Image support (HDRI enabled, which is the default in modern versions like ImageMagick 7), the floating-point values are preserved in memory without clipping. If HDRI is disabled, values above 1.0 are clamped to the maximum integer quantum, truncating the dynamic range.

Writing Radiance HDR Files in ImageMagick

Writing an HDR file reverses the decode process by converting internal linear floating-point pixel data into the quantized RGBE representation.

1. Writing the Header

ImageMagick generates a standard Radiance ASCII header containing:

  • The magic identifier #?RADIANCE.
  • Program metadata and gamma information (GAMMA=1.0 to denote linear space).
  • The required format specifier: FORMAT=32-bit_rle_rgbe.
  • The coordinate orientation and dimensions (typically -Y [height] +X [width]).

2. RGBE Conversion

For each pixel in the scanline, ImageMagick reads linear \(R\), \(G\), and \(B\) values from the pixel cache:

  1. Find the Maximum Component: It identifies the highest intensity among the three channels: \(M = \max(R, G, B)\).
  2. Calculate the Common Exponent: If \(M\) is smaller than a minimal threshold (\(< 10^{-32}\)), the entire pixel is encoded as [0, 0, 0, 0]. Otherwise, it uses the standard C library function frexp() to determine the exponent: \[E = \lfloor \log_2(M) \rfloor + 1\] This is biased by adding 128: \[E_{byte} = E + 128\]
  3. Scale Mantissas: The individual color channels are scaled against this shared exponent into the range \([0, 255]\): \[C_{byte} = \min\left(255, \left\lfloor \frac{C \times 256}{2^E} \right\rfloor\right)\]

3. Run-Length Encoding and Output

ImageMagick writes scanlines using modern de-interleaved RLE:

  1. It outputs the 4-byte scanline marker: 0x02, 0x02, followed by the two-byte row width.
  2. It groups all \(R\) bytes together, followed by all \(G\) bytes, all \(B\) bytes, and all \(E\) bytes.
  3. Each component array is compressed using run-length encoding (identifying repeated sequences of identical bytes) before writing the binary stream to disk.
