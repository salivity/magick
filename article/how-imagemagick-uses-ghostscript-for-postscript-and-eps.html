How ImageMagick Uses Ghostscript for PostScript and EPS

ImageMagick relies on an external delegate program, Ghostscript, to interpret and rasterize vector-based PostScript (PS) and Encapsulated PostScript (EPS) files. Because PostScript is a complex, Turing-complete page description language rather than a standard static raster format, ImageMagick does not parse the vector instructions natively. Instead, it delegates the execution and rendering of PostScript code to Ghostscript behind the scenes, capturing the rasterized output for further image processing, conversion, or display.

The Delegate Mechanism

ImageMagick uses an internal architecture based on "delegates" to handle file formats outside its core raster processing engine. When you pass a .ps or .eps file to ImageMagick, the program reads its configuration file—typically named delegates.xml—to determine which external utility handles PostScript decoding.

Ghostscript (the gs binary) is defined as the default interpreter. When ImageMagick receives a request to read a PostScript file, it executes Ghostscript as a child process using a dynamically constructed command line.

The Rendering Process Step-by-Step

  1. Format Identification: ImageMagick identifies the input file format either via the file extension (.ps, .eps) or by inspecting the file header (such as %!PS-Adobe).
  2. Subprocess Execution: ImageMagick launches Ghostscript in a headless, non-interactive mode using specific command-line switches (such as -dBATCH, -dNOPAUSE, and -dSAFER).
  3. Rasterization via Ghostscript Devices: Ghostscript executes the PostScript code and outputs the result using an internal raster device. Typically, it renders the page into an intermediate bitmap format (such as standard raw pixel data, PNM, or PNG) via standard output or a temporary file.
  4. Ingestion and Processing: ImageMagick captures the rendered raster stream from Ghostscript, loads the pixels into its internal image cache, and applies any requested ImageMagick operations (such as resizing, color adjustments, or format conversion).

Controlling Render Quality

Because PostScript and EPS files are vector formats, they do not have a fixed pixel resolution. To ensure high-quality rasterization, ImageMagick allows you to set the rendering density before reading the file:

magick -density 300 input.eps -background white -flatten output.png

In this process, the -density 300 parameter is translated into the -r300 resolution flag passed directly to Ghostscript. Setting this parameter before the input file ensures that Ghostscript rasterizes the vectors at 300 DPI rather than defaulting to standard 72 DPI rendering.

Security Considerations and Policy Configuration

Executing PostScript files involves running arbitrary code. To mitigate vulnerabilities associated with PostScript parsing, modern ImageMagick installations use a security configuration file named policy.xml.

System administrators frequently restrict or disable PostScript rendering by defining security policies:

<policy domain="coder" rights="none" pattern="PS" />
<policy domain="coder" rights="none" pattern="EPS" />

If these policies are set to none, ImageMagick will refuse to invoke Ghostscript, preventing potential command execution vulnerabilities from untrusted PostScript inputs. To allow processing, these rights must be explicitly adjusted to read or read|write.
