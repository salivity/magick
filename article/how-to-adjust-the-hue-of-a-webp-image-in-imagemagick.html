How to Adjust the Hue of a WebP Image in ImageMagick?

Adjusting the hue of a WebP image using ImageMagick requires manipulating the image's color channels via the command line, most commonly with the -modulate operator or HSL color space channel shifting. This guide walks through the required commands for both ImageMagick v6 and v7, explains how the hue values are calculated, and covers syntax for preserving transparency and compression quality in WebP files.

Understanding the Hue Adjustment Value

The standard and most versatile way to shift hue in ImageMagick is the -modulate operator. The syntax accepts values in the order of brightness, saturation, and hue:

-modulate brightness,saturation,hue

When using -modulate, a value of 100 represents no change (the baseline is 100%). For the hue parameter:

  • 100 leaves the hue unchanged (0 degrees rotation).
  • 0 rotates the hue 180 degrees counter-clockwise (-180 degrees).
  • 200 rotates the hue 180 degrees clockwise (+180 degrees).
  • 150 rotates the hue 90 degrees clockwise (+90 degrees).
  • 50 rotates the hue 90 degrees counter-clockwise (-90 degrees).

Basic Command Syntax

Depending on which version of ImageMagick you have installed, the entry command differs slightly. ImageMagick 7 uses the unified magick binary, while ImageMagick 6 uses convert.

ImageMagick 7 (Recommended)

To shift the hue by 90 degrees clockwise while leaving brightness and saturation unchanged:

magick input.webp -modulate 100,100,150 output.webp

To invert the color spectrum entirely (180-degree rotation):

magick input.webp -modulate 100,100,0 output.webp

ImageMagick 6

For older installations using legacy binary tools:

convert input.webp -modulate 100,100,150 output.webp

Preserving Transparency and Quality in WebP

WebP images often contain alpha channels (transparency) or specific lossy/lossless compression profiles. Applying color modulations directly can sometimes alter default encoding quality if not explicitly defined.

Maintaining Quality Settings

By default, ImageMagick applies its own default compression when writing out a new WebP file. To maintain visual fidelity, specify the -quality flag:

magick input.webp -modulate 100,100,125 -quality 90 output.webp

Forcing Lossless Output

If the source WebP is a graphic, logo, or icon that requires lossless compression:

magick input.webp -modulate 100,100,175 -define webp:lossless=true output.webp

Alternative Method: Precise Degrees via HSL Color Space

If you prefer defining the hue shift strictly in degrees (from 0 to 360) rather than working with the 0–200 percentage scale of -modulate, convert the image to the HSL color space, roll the hue channel, and return to sRGB:

magick input.webp -colorspace HSL -channel R -evaluate Add 25% +channel -colorspace sRGB output.webp

In this pipeline:

  • -colorspace HSL separates the image into Hue (Red channel), Saturation (Green channel), and Lightness (Blue channel).
  • -channel R isolates the Hue channel.
  • -evaluate Add 25% advances the hue by 25% of the 360-degree color wheel (90 degrees).
  • +channel unlinks the single channel selection so subsequent operators apply globally.
  • -colorspace sRGB converts the colors back for standard display.

Batch Processing WebP Files

To adjust the hue across multiple WebP images in a single directory, use the mogrify command. Note that this modifies files in place unless an output directory is designated.

magick mogrify -path ./adjusted_output -modulate 100,100,130 *.webp

This command processes all .webp files in the current folder, applies a 30% positive hue shift, and writes the output into the adjusted_output folder.
