How to Assemble Animated MNG with ImageMagick

This article explains how ImageMagick compiles sequential image frames into an animated Multiple-image Network Graphic (MNG) file. It details the command-line mechanics, how ImageMagick structures MNG-specific metadata chunks, and how animation properties like frame delays, loops, and layer disposal methods are processed into a unified output stream.

The Input and Sequencing Process

ImageMagick processes an animated MNG by loading input files—typically a series of static PNG or JPEG files—into an internal linked list of image structures. When globbing patterns (such as frame_*.png) or enumerated lists are passed via the command line, ImageMagick reads each image into memory in numerical or alphabetical order. Each image in this sequence forms a distinct frame within the intended animation timeline.

Configuring Timing and Geometry

Before writing the output, ImageMagick associates frame-level attributes to the in-memory sequence based on command-line flags:

  • Frame Duration (-delay): Specifies the time duration a frame is displayed. The default unit is in hundredths of a second (ticks). ImageMagick assigns this value as metadata to each following frame until a new -delay flag modifies it.
  • Repetition (-loop): Dictates how many times the animation cycles. Setting this value to 0 designates infinite looping, which is mapped directly to the animation control structures in the MNG format.
  • Canvas and Offsets (-page): If the input images are smaller than the full animation canvas or have dynamic coordinate placements, -page defines the bounding box and X/Y offsets for each individual layer.
  • Frame Disposal (-dispose): Instructs the decoder on what to do with the frame area before rendering the next one (e.g., leaving the frame as-is, clearing to the background, or restoring to the previous state).

Internal Structure and MNG Chunk Assembly

When ImageMagick specifies the output format as .mng, its internal MNG encoder converts the in-memory image sequence into a valid network byte stream made up of PNG-like chunks:

  1. MNG Signature and Header (MHDR): The encoder writes the standard 8-byte MNG signature followed by an MHDR chunk. This chunk defines the global canvas width, canvas height, nominal frame rate, layer count, nominal play time, and profile simplicity flags indicating the complexity of the file.
  2. Loop Control (TERM or LOOP): If iteration limits are specified via -loop, ImageMagick introduces looping chunks (LOOP/ENDL or termination chunks like TERM) to define repetitive playback boundaries.
  3. Frame Definition (FRAM): To apply per-frame timing and clipping, ImageMagick injects FRAM chunks. These instruct the rendering engine on display timing, inter-frame delays, and whether a frame constitutes an entirely new display or an overlay.
  4. Data Payloads (IHDR, IDAT, IEND): For each frame in the sequence, ImageMagick embeds standard PNG-compliant chunks. The image data is compressed via zlib and encapsulated into IDAT blocks, isolated between standard PNG IHDR (image header) and IEND (image end) markers.
  5. End Chunk (MEND): Once all image frames and timing controls are written sequentially to the stream, ImageMagick appends an MEND chunk, signaling the end of the MNG datastream, closes the file descriptor, and deallocates the image sequence from memory.

Basic Assembly Command

To assemble a standard animated sequence, the command combines the timing flags, the input frames, and the destination file:

magick -delay 10 -loop 0 frame_*.png animation.mng

In older versions of the suite, the identical operation is performed using:

convert -delay 10 -loop 0 frame_*.png animation.mng

ImageMagick reads the individual assets, applies a delay of 100 milliseconds per frame, configures infinite looping, and flushes the assembled MNG chunk architecture into animation.mng.
