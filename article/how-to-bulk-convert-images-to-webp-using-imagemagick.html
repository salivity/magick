How to Bulk Convert Images to WebP Using ImageMagick?

Converting large batches of images to modern formats like WebP significantly reduces file sizes without sacrificing visual fidelity. While standard command-line tools often process files one by one, ImageMagick provides flexible utilities like mogrify and shell scripting loops that automate this entire workflow. This guide explains how to install the necessary WebP delegates, convert single directories in place, process nested folders recursively, and fine-tune compression levels for optimal web performance.

Prerequisites and Verification

Before running batch operations, ensure ImageMagick is installed alongside the libwebp delegate. Without this delegate, ImageMagick cannot encode or decode WebP files.

Verify your installation and WebP support by checking your terminal:

magick -version

Look for webp in the Delegates (built-in) list. If you are on an older version of ImageMagick (ImageMagick 6), use convert -version instead.

Installing ImageMagick with WebP Support

  • macOS (via Homebrew):
brew install imagemagick
  • Ubuntu / Debian:
sudo apt update
sudo apt install imagemagick webp
  • Windows: Download and run the official installer from ImageMagick's website, ensuring the option to add utilities to your system PATH is checked.

Method 1: In-Place Conversion with mogrify

The quickest way to process an entire folder is using ImageMagick’s mogrify tool. Unlike the standard magick command, mogrify is specifically designed for batch operations across multiple files.

Navigate to the target directory and run:

magick mogrify -format webp -quality 80 *.jpg

Key arguments explained:

  • -format webp: Specifies the target output format, automatically swapping the file extension from .jpg to .webp.
  • -quality 80: Sets the compression level (0 to 100). For lossy WebP, values between 75 and 85 provide an ideal balance between low file size and sharp visuals.
  • *.jpg: Targets all JPEG images in the current working directory.

To target multiple input extensions simultaneously, specify them within a shell expansion:

magick mogrify -format webp -quality 80 *.{jpg,jpeg,png}

Method 2: Outputting to a Dedicated Directory

Overwriting or mixing converted files in the same directory can quickly clutter source assets. Using a shell for loop allows you to read original files, apply optimization flags, and output the WebP files into a separate folder.

Linux and macOS (Bash / Zsh)

Create the target output folder and execute the loop:

mkdir -p converted_webp

for img in *.{jpg,jpeg,png}; do
  [ -f "$img" ] || continue
  magick "$img" -quality 82 -define webp:lossless=false "converted_webp/${img%.*}.webp"
done

Windows (PowerShell)

In PowerShell, loop through the files and set destination paths dynamically:

New-Item -ItemType Directory -Force -Path .\converted_webp

Get-ChildItem -File -Include *.jpg,*.png,*.jpeg | ForEach-Object {
    $outName = "$($_.BaseName).webp"
    magick $_.FullName -quality 82 ".\converted_webp\$outName"
}

Method 3: Recursive Processing Across Subdirectories

If your assets are organized into nested category folders, use the find command on Unix-based systems to traverse the entire directory tree and convert each file:

find . -type f \( -name "*.jpg" -o -name "*.png" \) -exec sh -c '
  for file; do
    magick "$file" -quality 80 "${file%.*}.webp"
  done
' sh {} +

This approach preserves the directory structure, generating a .webp variant adjacent to each original nested file without modifying parent directory arrangements.

Fine-Tuning WebP Quality Flags

ImageMagick exposes specific encoder defines to refine how the underlying WebP library processes image data:

Lossless Conversion for Graphics and Icons

For screenshots, transparent PNGs, or vector-style illustrations where crisp lines are essential:

magick input.png -define webp:lossless=true output.webp

Compression Effort and Efficiency

The method parameter controls the trade-off between CPU encoding time and final file size:

magick input.jpg -quality 80 -define webp:method=6 output.webp

Values range from 0 (fastest encoding, larger file size) to 6 (slowest encoding, best byte-reduction efficiency). The default value is 4.
