How to Convert AVIF to AVIF with ImageMagick?

Re-encoding an AVIF file into another AVIF using ImageMagick allows you to reduce file size, strip unnecessary metadata, resize dimensions, or alter compression settings while maintaining the high efficiency of the AV1 image format. This guide explains how to verify your ImageMagick installation for AVIF support, run the basic re-encoding command, fine-tune compression quality, and automate batch processing across multiple files.

Prerequisites and Codec Verification

ImageMagick delegates AVIF encoding and decoding to external libraries such as libheif built with aom (Alliance for Open Media) or rav1e. Before processing files, ensure that your installed version of ImageMagick includes AVIF read and write delegates.

Run the following command in your terminal:

magick identify -list format | grep -i AVIF

A properly configured installation will return output indicating read and write support:

AVIF* rw+ AV1 Image File Format

If the format list only indicates read access or fails to list AVIF entirely, you must reinstall or rebuild ImageMagick with libheif and an underlying AV1 encoder enabled.

Basic AVIF to AVIF Re-encoding

To read an existing AVIF file and write it out to a new AVIF container using ImageMagick 7, use the magick command:

magick input.avif output.avif

If you are using ImageMagick 6, replace magick with convert:

convert input.avif output.avif

This operation decodes the source AV1 frames into raw pixel buffers in memory and re-encodes them into a fresh AVIF container using the default quality and compression parameters.

Controlling Quality and Compression

The primary reason to re-encode an AVIF file to AVIF is to alter file size or compression efficiency. ImageMagick controls lossy compression via the -quality flag, where values typically range from 1 (lowest quality, smallest file) to 100 (highest visual fidelity).

For typical web delivery, values between 50 and 75 provide an optimal balance of clarity and data savings:

magick input.avif -quality 65 output_compressed.avif

To adjust the encoding effort, you can supply encoder-specific definitions. Setting the encoding speed determines how thoroughly the encoder searches for compression efficiencies:

magick input.avif -quality 60 -define heic:speed=4 output_optimized.avif

Lower speed numbers produce smaller files at the cost of significantly higher processing time, while higher numbers speed up conversion.

Resizing Dimensions and Stripping Metadata

Digital cameras and software often inject EXIF tags, GPS coordinates, color profiles, and thumbnails into image files. When optimizing for web distribution, removing this data and downscaling dimensions substantially reduces overall payload.

The following command resizes an AVIF to a maximum width of 1920 pixels while preserving the aspect ratio and discarding all non-essential metadata:

magick input.avif -strip -resize 1920x\> -quality 70 optimized.avif

The \> flag ensures that ImageMagick only downsizes images larger than 1920 pixels wide, leaving smaller images untouched.

Batch Processing AVIF Files

When working with large collections of AVIF assets, processing individual files sequentially using custom scripts can be replaced with ImageMagick's built-in mogrify tool.

To optimize every AVIF file within a folder and place the results in an output directory without overwriting originals:

mkdir -p ./optimized
magick mogrify -path ./optimized -strip -quality 65 -define heic:speed=6 *.avif

This workflow reads every .avif file in the current working directory, applies the specified quality and stripping options, and writes a newly compressed counterpart into the optimized directory.
