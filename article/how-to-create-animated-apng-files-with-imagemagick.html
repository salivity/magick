How to Create Animated APNG Files with ImageMagick

ImageMagick can assemble animated APNG (Animated Portable Network Graphics) files from multiple individual image frames, provided your build includes APNG format support. This guide covers how to check your ImageMagick configuration for APNG compatibility, the exact command-line syntax to merge frames, how to control frame rates and loops, and how to resolve common output issues.

Verifying APNG Support in ImageMagick

Before attempting to create an APNG, ensure your installation of ImageMagick supports writing to the format. Run the following command in your terminal:

magick identify -list format | grep -i png

Look for APNG or PNG entries with read/write (rw+ or rw-) permissions. In ImageMagick 7, APNG support is typically handled through standard PNG delegates or explicitly via the APNG: format specifier.

Basic Command Syntax to Assemble Frames

To combine a sequence of still images (such as PNG, JPEG, or TIFF) into a single animated APNG, specify the frame delay, loop count, input files, and the output filename with the .apng extension.

magick -delay 10 -loop 0 frame1.png frame2.png frame3.png output.apng

If ImageMagick does not automatically detect the APNG coder by file extension, explicitly declare the format prefix:

magick -delay 10 -loop 0 frame*.png APNG:output.png

Parameter Breakdown

  • -delay <value>: Sets the duration each frame is displayed. The default unit is ticks per second (typically 1/100th of a second). A value of -delay 10 equals 100 milliseconds per frame (10 frames per second).
  • -loop <value>: Sets the number of animation iterations. A value of 0 creates an infinite loop, while a value of 1 plays the animation once and stops.
  • frame*.png: The input images, processed in alphanumeric order.

Setting Variable Delays per Frame

To assign different display times to individual frames, declare the -delay flag before each specific image:

magick -delay 50 frame1.png -delay 10 frame2.png -delay 10 frame3.png -delay 100 frame4.png -loop 0 output.apng

Handling Frame Disposal and Transparency

When working with transparent frames, residual pixels from previous frames may bleed into the next frame. Use the -dispose setting to control how previous frames are cleared:

magick -dispose Background -delay 10 -loop 0 frame*.png output.apng

Common -dispose methods include:

  • Undefined: No disposal method specified (default).
  • None: Do not dispose of the frame; overlay the next frame directly on top.
  • Background: Clear the frame area to transparent background before rendering the next frame.
  • Previous: Revert to the canvas state prior to rendering the current frame.

Optimization and Alternatives

APNG files created by ImageMagick are uncompressed by default regarding frame-diff optimization. If file size is critical, or if your local ImageMagick build lacks native APNG write capabilities, use dedicated APNG assembly tools such as apngasm or ffmpeg:

ffmpeg -framerate 10 -i frame%d.png -plays 0 output.apng
