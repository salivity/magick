How to Create OME-TIFF Files with ImageMagick

Creating an OME-TIFF biological imaging container with ImageMagick involves bundling multi-plane or multi-channel image data into a single multi-page TIFF file while embedding valid OME-XML metadata into the TIFF ImageDescription tag. Because ImageMagick lacks an automated OME-XML generator, you must supply the structural XML definition yourself and inject it during the TIFF compilation process.

The Core ImageMagick Syntax

To combine individual microscopy slices or timepoints into an OME-TIFF container with embedded metadata, use the following command structure:

magick input_z01.png input_z02.png input_z03.png -adjoin -set "tiff:ImageDescription" "@ome_metadata.xml" output.ome.tif

If you are using ImageMagick version 6 legacy commands, use convert:

convert input_*.tif -adjoin -set "tiff:ImageDescription" "@ome_metadata.xml" output.ome.tif

Parameter Breakdown

  • input_*.png / input_*.tif: The sequence of image planes representing the dimensions (Z-slices, channels, or time points) of your biological dataset.
  • -adjoin: Instructs ImageMagick to join all input images into a single multi-page (multi-directory) TIFF file rather than writing separate files.
  • -set "tiff:ImageDescription" "@ome_metadata.xml": Sets the TIFF tag 270 (ImageDescription). The @ prefix instructs ImageMagick to read the contents directly from the external file ome_metadata.xml. The OME-TIFF specification relies on this tag in the first IFD (Image File Directory) to describe dimensions, channels, acquisition settings, and physical pixel sizes.
  • output.ome.tif: The resulting file, saved with the standard .ome.tif or .ome.tiff extension recognized by bio-imaging software like Fiji/ImageJ and Bio-Formats.

Preparing the OME-XML Template

For bio-imaging tools to parse the file correctly as an OME-TIFF, the ome_metadata.xml file must contain a valid, well-formed <OME> block matching the exact dimensions of your input sequence:

<?xml version="1.0" encoding="UTF-8"?>
<OME xmlns="http://www.openmicroscopy.org/Schemas/OME/2016-06"
     xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
     xsi:schemaLocation="http://www.openmicroscopy.org/Schemas/OME/2016-06 http://www.openmicroscopy.org/Schemas/OME/2016-06/ome.xsd">
    <Image ID="Image:0" Name="Experiment">
        <Pixels ID="Pixels:0" DimensionOrder="XYZCT" Type="uint16"
                SizeX="512" SizeY="512" SizeZ="3" SizeC="1" SizeT="1"
                PhysicalSizeX="0.65" PhysicalSizeY="0.65">
            <TiffData FirstZ="0" FirstC="0" FirstT="0" IFD="0" PlaneCount="3"/>
        </Pixels>
    </Image>
</OME>

Ensure the values for SizeX, SizeY, SizeZ, SizeC, and SizeT correspond precisely to the pixel dimensions and frame counts of the images supplied on the command line.

Handling Multi-Channel and Multi-Z Sequences

When combining multiple dimensional planes, arrange the input files in the exact order declared by your metadata's DimensionOrder attribute (for example, XYZCT):

magick c0_z0.tif c0_z1.tif c0_z2.tif c1_z0.tif c1_z1.tif c1_z2.tif \
  -adjoin \
  -compress none \
  -depth 16 \
  -set "tiff:ImageDescription" "@ome_metadata.xml" \
  dataset.ome.tif
  • -compress none: Prevents lossy artifacts and maintains compatibility across diverse microscopy readers (alternatively, -compress lzw or -compress zip can be used for lossless compression).
  • -depth 16: Enforces bit depth preservation if working with 16-bit raw detector values common in fluorescence imaging.
