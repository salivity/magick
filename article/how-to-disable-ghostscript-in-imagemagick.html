How to Disable Ghostscript in ImageMagick

ImageMagick utilizes Ghostscript as a background delegate to parse PostScript, EPS, and PDF files, which has historically exposed web servers and applications to critical remote code execution (RCE) vulnerabilities. Disabling Ghostscript rendering inside ImageMagick is an essential security hardening step that blocks the execution of malicious vector files while preserving standard raster image processing. This guide explains how to locate ImageMagick’s security configuration file, apply the necessary policy restrictions, and verify that Ghostscript delegates are fully disabled.

Step 1: Locate the policy.xml File

ImageMagick controls delegate permissions and resource limits through an XML configuration file named policy.xml. The exact path depends on your operating system and the ImageMagick version installed:

  • Ubuntu / Debian: /etc/ImageMagick-6/policy.xml or /etc/ImageMagick-7/policy.xml
  • RHEL / CentOS / AlmaLinux: /etc/ImageMagick/policy.xml
  • macOS (Homebrew): /usr/local/etc/ImageMagick-7/policy.xml or /opt/homebrew/etc/ImageMagick-7/policy.xml

You can verify the exact active path on your system by running:

identify -list policy

Step 2: Modify the Security Policy

Open the policy.xml file in a text editor with administrative privileges:

sudo nano /etc/ImageMagick-6/policy.xml

Locate the <policymap> section. Add the following <policy> directives inside the <policymap> block to revoke read and write permissions for all file formats that rely on Ghostscript:

<policymap>
  <!-- Disable Ghostscript delegates -->
  <policy domain="coder" rights="none" pattern="PS" />
  <policy domain="coder" rights="none" pattern="PS2" />
  <policy domain="coder" rights="none" pattern="PS3" />
  <policy domain="coder" rights="none" pattern="EPS" />
  <policy domain="coder" rights="none" pattern="PDF" />
  <policy domain="coder" rights="none" pattern="XPS" />
  <policy domain="coder" rights="none" pattern="EPI" />
  <policy domain="coder" rights="none" pattern="PRT" />
</policymap>

Note: If your application strictly requires PDF processing via ImageMagick, ensure Ghostscript itself is updated to the latest patched version. However, disabling the PDF pattern entirely is the most secure approach.

Save the file and exit the editor. Changes take effect immediately; restarting the system is not required.

Step 3: Verify the Changes

Test the policy configuration by attempting to convert or identify a PostScript or PDF file:

convert -list policy

Check the output to ensure the rules with rights="none" are listed for PS, EPS, and PDF.

Next, run a test conversion on a dummy PostScript or PDF file:

convert sample.pdf sample.png

If the policy is properly enforced, ImageMagick will block the operation and return a security policy error:

convert: not authorized `sample.pdf' @ error/constitute.c/ReadImage/412.

This error confirms that Ghostscript processing is disabled and ImageMagick is protected from Ghostscript-related vulnerabilities.
