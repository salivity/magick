How to Disable PostScript Delegate in ImageMagick

ImageMagick relies on Ghostscript as an external delegate to process PostScript-based vector formats, such as PS, EPS, and PDF. Frequent security vulnerabilities (CVEs) in Ghostscript—often resulting in arbitrary code execution—make disabling these delegates an essential hardening measure for servers handling untrusted user uploads. This guide walks through locating ImageMagick's security policy configuration, disabling the relevant PostScript coders, and verifying that the mitigation works.

Step 1: Locate policy.xml

ImageMagick controls operational permissions through a configuration file named policy.xml. Its location depends on your operating system and the version of ImageMagick installed.

Common paths include:

  • /etc/ImageMagick-6/policy.xml (ImageMagick 6 on Debian/Ubuntu)
  • /etc/ImageMagick-7/policy.xml (ImageMagick 7 on Debian/Ubuntu)
  • /etc/ImageMagick/policy.xml (RHEL/CentOS/Fedora)
  • /usr/local/etc/ImageMagick-7/policy.xml (Custom or source installations)

To quickly find the active configuration file, run:

identify -list policy

Or search your file system:

find /etc -name "policy.xml" 2>/dev/null

Step 2: Update the Policy to Disable PostScript

Open policy.xml in a text editor with administrative privileges:

sudo nano /etc/ImageMagick-6/policy.xml

Locate the <policymap> block. Inside the <policymap> tags, add policy rules to disable rights for Ghostscript-dependent coders:

<policymap>
  <!-- Disable PostScript and related delegates to mitigate Ghostscript CVEs -->
  <policy domain="coder" rights="none" pattern="PS" />
  <policy domain="coder" rights="none" pattern="PS2" />
  <policy domain="coder" rights="none" pattern="PS3" />
  <policy domain="coder" rights="none" pattern="EPS" />
  <policy domain="coder" rights="none" pattern="PDF" />
  <policy domain="coder" rights="none" pattern="XPS" />
  <policy domain="delegate" rights="none" pattern="gs" />
</policymap>

Note: If your application strictly requires PDF processing, you must ensure Ghostscript is updated to the latest patched version. However, completely disabling the PDF pattern and the gs delegate is the only guaranteed mitigation against unpatched Ghostscript vulnerabilities.

Save the file and exit the editor.

Step 3: Verify the Mitigation

Test that the security policy is actively enforcing the restrictions. Attempt to process a PostScript or PDF file using ImageMagick:

convert -size 100x100 xc:white test.ps
identify test.ps

If the mitigation is working correctly, ImageMagick will refuse to process the file and return an error similar to:

identify: attempt to perform an operation not allowed by the security policy `PS' @ error/constitute.c/IsCoderAuthorized/408.

The error confirms that ImageMagick will no longer invoke Ghostscript for the disabled formats, successfully neutralizing the vector for related CVEs.
