How to Link ImageMagick with Jemalloc

This guide details how to compile ImageMagick with the Jemalloc memory allocator to mitigate memory fragmentation and enhance throughput during intensive image processing tasks. You will learn the exact configuration flags required to link Jemalloc at build time, verify the resulting binary, and understand runtime alternatives.

The Configure Flag for Jemalloc

ImageMagick's standard configure script does not feature a dedicated --with-jemalloc switch. Instead, you link Jemalloc using Autotools library definition flags passed directly to the configuration script:

./configure LIBS="-ljemalloc"

Alternatively, you can supply the flag via the linker flags variable:

./configure LDFLAGS="-ljemalloc"

If Jemalloc is installed in a non-standard directory (such as /usr/local or a custom prefix), provide both the include directory and the library search path alongside the flag:

./configure LDFLAGS="-L/usr/local/lib -ljemalloc" CFLAGS="-I/usr/local/include"

Step-by-Step Compilation Guide

1. Install Jemalloc Development Headers

Ensure the Jemalloc library and development headers are installed on your host system:

  • Debian / Ubuntu: 
    sudo apt-get update && sudo apt-get install libjemalloc-dev
  • RHEL / CentOS / Rocky Linux: 
    sudo dnf install jemalloc-devel
  • macOS (Homebrew): 
    brew install jemalloc

2. Configure ImageMagick Source

Navigate to your ImageMagick source directory and execute the configure script with LIBS="-ljemalloc":

./configure LIBS="-ljemalloc" --prefix=/usr/local

3. Build and Install

Compile the binaries across available CPU cores and install them:

make -j$(nproc)
sudo make install
sudo ldconfig

Verifying the Jemalloc Linkage

After installation, verify that the ImageMagick binary is dynamically linked against libjemalloc:

ldd $(which magick) | grep jemalloc

If linked successfully, the terminal will display the path to the resolved Jemalloc shared object, for example:

libjemalloc.so.2 => /lib/x86_64-linux-gnu/libjemalloc.so.2 (0x00007f8b9e200000)

Alternative: Runtime Linking via LD_PRELOAD

If you cannot recompile ImageMagick from source, you can achieve the same fragmentation reduction benefits by forcing the dynamic linker to load Jemalloc at runtime without any configure flags:

LD_PRELOAD=/usr/lib/x86_64-linux-gnu/libjemalloc.so.2 magick input.jpg -resize 50% output.jpg
