How to Make a Folder Read-Only in ImageMagick

Configuring ImageMagick security policies allows administrators to restrict file operations by granting read-only permissions while strictly blocking write operations on designated directories. By updating the policy.xml configuration file, you can enforce path-based access controls to safeguard critical folders from unintended file creation, modification, or security exploits.

Locating the policy.xml File

ImageMagick controls operational permissions via its policy.xml file. The exact path depends on your operating system and ImageMagick version:

  • Ubuntu/Debian: /etc/ImageMagick-6/policy.xml or /etc/ImageMagick-7/policy.xml
  • RHEL/CentOS/Fedora: /etc/ImageMagick/policy.xml
  • Custom/Source Installations: /usr/local/etc/ImageMagick-7/policy.xml

You can verify the active policy path by running:

magick -list policy

(Use convert -list policy on ImageMagick 6).

Configuring the Policy

Open the policy.xml file with administrative privileges in a text editor:

sudo nano /etc/ImageMagick-7/policy.xml

Locate the <policymap> section. To restrict a specific folder to read-only access, add a rule using the path domain and set rights to "read":

<policymap>
  <!-- Restrict target folder to read-only -->
  <policy domain="path" rights="read" pattern="/var/www/uploads/*" />
</policymap>

By assigning only the read value to the rights attribute, ImageMagick explicitly denies any write or execute actions for matching paths.

If you want to allow ImageMagick to read from a directory while globally preventing writes to that directory and all nested subdirectories, use a recursive wildcard pattern:

<policy domain="path" rights="read" pattern="/var/www/uploads/**" />

Policy Precedence and Strict Lockdown

ImageMagick processes path rules sequentially. To ensure strict isolation, place your specific path constraints above any broad permissions.

If you have a default configuration that allows writing, the specific rights="read" policy takes precedence for paths matching the pattern. Conversely, if you want an explicit denial of writes while ensuring reads are possible, you can split permissions:

<policymap>
  <!-- Allow reading images from this directory -->
  <policy domain="path" rights="read" pattern="/var/www/protected/*" />
  <!-- Explicitly block writing to this directory -->
  <policy domain="path" rights="none" pattern="/var/www/protected/*" />
</policymap>

Note: Using rights="read" by itself is the standard method, as it automatically omits write authorization.

Verifying the Configuration

Test the configuration using the command line to confirm the restrictions are active.

  1. Verify Read Access:

    magick identify /var/www/uploads/sample.jpg

    This command should succeed and output image metadata.

  2. Verify Write Restriction:

    magick logo: /var/www/uploads/output.png

    ImageMagick should immediately reject the operation with an error similar to:

    magick: not authorized `/var/www/uploads/output.png' @ error/constitute.c/WriteImage/1330.
