How to Monitor ImageMagick with -debug and -log

ImageMagick provides built-in diagnostic capabilities that allow developers and system administrators to inspect internal operations in real time. By utilizing the -debug and -log command-line flags, you can trace image decoding, memory allocation, cache operations, and color transformations to diagnose errors, identify performance bottlenecks, and understand how operations are handled internally.

The -debug Flag

The -debug flag instructs ImageMagick to emit diagnostic messages about specific internal operations. You can specify a single event type, a comma-separated list of events, or use wildcards.

Syntax:

magick input.jpg -debug <event_type> output.png

Common Event Types:

  • All: Logs every internal event. This produces very verbose output.
  • Annotate: Logs text annotation operations.
  • Blob: Tracks reading and writing of binary data (files, memory streams).
  • Cache: Monitors pixel cache access, allocations, and disk-swapping events.
  • Coder: Logs the encoding and decoding of specific image formats (e.g., JPEG, PNG).
  • Configure: Tracks the loading of configuration files (e.g., delegates.xml, policy.xml).
  • Exception: Displays internal warnings and error messages.
  • Resource: Tracks resource limits, such as memory, disk, and thread usage.
  • Transform: Monitors geometric operations like resizing, cropping, and rotating.
  • Trace: Traces the execution flow of internal ImageMagick functions.

Example: Debugging Format Decoding and Image Resizing

magick input.jpg -debug Coder,Transform -resize 50% output.png

The -log Flag

The -log flag defines the output format of the debug messages. It uses format specifiers to customize the metadata printed with each log entry.

Syntax:

magick input.jpg -log "<format_string>" -debug <event_type> output.png

Common Log Format Specifiers:

  • %d: The domain or subsystem generating the event.
  • %e: The event name.
  • %f: The function name where the event occurred.
  • %l: The line number in the source code.
  • %m: The source module (file name).
  • %p: The process ID (PID).
  • %r: The elapsed CPU time.
  • %t: The wall-clock time (timestamp).
  • %u: The elapsed real time.
  • %%: A literal percent sign.

Example: Customizing Log Output Structure

magick input.jpg -log "%t [%d] %e: %m/%f/%l - " -debug Resource,Cache -resize 200x200 output.png

Practical Monitoring Examples

Diagnosing Slow Performance and Resource Limits

To investigate high memory usage or unexpected disk caching:

magick large_image.tif -debug Resource,Cache -log "%u %e: " -resize 1000x1000 output.jpg

Troubleshooting Missing Delegates or Decoders

To determine why a specific file format fails to read:

magick unsupported_file.raw -debug Configure,Coder output.png

Redirecting Debug Logs to a File

By default, debug logs are printed to standard error (stderr). You can redirect the output to a text file for analysis:

magick input.png -debug All output.jpg 2> imagemagick_trace.log

Persistent Configuration via log.xml

For permanent or system-wide monitoring without passing flags via the CLI, you can modify the log.xml configuration file located in ImageMagick's configuration directory.

Inside log.xml, configure the <log> node:

<logmap>
  <log events="Coder,Resource" output="file" filename="magick.log" format="%t %r %e: " />
</logmap>

This configuration routes specified debug events directly to a designated log file automatically on every execution.
