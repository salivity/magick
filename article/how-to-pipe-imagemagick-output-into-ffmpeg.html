How to Pipe ImageMagick Output into FFmpeg

Piping output directly from ImageMagick into FFmpeg creates an efficient in-memory video encoding pipeline that avoids the performance penalty of writing intermediate image files to disk. By streaming continuous frame data through standard output (stdout) to standard input (stdin), you can perform complex image manipulation, filtering, and video encoding simultaneously.

Basic Syntax Pattern

The basic command structure sends ImageMagick's formatted output stream through a UNIX pipe (|) to FFmpeg's standard input reader (-i -):

magick <input_images_or_generation> <processing_options> <output_format>:- | ffmpeg <ffmpeg_input_flags> -i - <ffmpeg_output_flags> output.mp4

Note: In ImageMagick v6, replace magick with convert.

Method 1: Using the PAM Format (Recommended)

The Portable Arbitrary Map (PAM) format is ideal for piping because it includes image dimension and color space metadata in the header of each frame. This prevents the need to manually declare frame sizes in FFmpeg.

Syntax:

magick input_%03d.png -resize 1920x1080 pam:- | ffmpeg -f pam_pipe -r 30 -i - -c:v libx264 -pix_fmt yuv420p output.mp4

Breakdown:

  • pam:-: Tells ImageMagick to serialize the output as PAM data and write to standard output (-).
  • -f pam_pipe: Instructs FFmpeg to parse the incoming stream as a sequence of PAM frames.
  • -r 30: Sets the input framerate to 30 frames per second.
  • -i -: Reads the video stream from standard input.
  • -c:v libx264 -pix_fmt yuv420p: Encodes to standard H.264 video with widely compatible 4:2:0 chroma subsampling.

Method 2: Using the Y4M (YUV4MPEG2) Format

Y4M is an uncompressed video stream format that includes dimensions, framerate, and pixel layout metadata directly in the stream header.

Syntax:

magick input_*.jpg -resize 1280x720 -delay 1x30 y4m:- | ffmpeg -i - -c:v libx264 output.mp4

Breakdown:

  • -delay 1x30: Sets the frame duration within ImageMagick to achieve 30 fps.
  • y4m:-: Outputs the stream in the yuv4mpegpipe format.
  • FFmpeg automatically detects Y4M input stream properties without requiring manual -f or -s flags.

Method 3: Using Raw Video Data (RGB / RGBA)

Raw streaming provides maximum throughput without format wrapping overhead, but requires explicit resolution, pixel format, and framerate definitions in the FFmpeg input configuration.

Syntax:

magick input_*.png -resize 1920x1080 rgb:- | ffmpeg -f rawvideo -pixel_format rgb24 -video_size 1920x1080 -framerate 24 -i - -c:v libx264 -pix_fmt yuv420p output.mp4

Breakdown:

  • rgb:-: Instructs ImageMagick to output pure raw 8-bit RGB byte data to stdout.
  • -f rawvideo: Tells FFmpeg to expect an uncompressed, headerless video stream.
  • -pixel_format rgb24: Specifies the layout of each pixel in the raw stream.
  • -video_size 1920x1080: Defines the exact frame dimensions that match the ImageMagick output.
  • -framerate 24: Declares the playback rate for the raw byte sequence.

Best Practices

  • Avoid Compression in Transit: Always pipe uncompressed or lightly structured stream formats (pam, y4m, rgb) rather than compressed individual frames like jpeg or png to minimize CPU usage.
  • Match Pixel Formats: Ensure color channels match between both utilities (e.g., using rgba:- with -pixel_format rgba if your pipeline relies on transparency processing before the final encode).
