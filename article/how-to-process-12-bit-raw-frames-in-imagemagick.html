How to Process 12-Bit Raw Frames in ImageMagick

Industrial machine vision cameras often capture frames in uncompressed 12-bit raw formats to preserve high dynamic range. ImageMagick can decode, debayer, normalize, and convert these proprietary or headerless streams into standard image formats by manually specifying dimensions, bit depth, byte order, and pixel encoding. This guide explains how to configure ImageMagick commands to correctly interpret and process 12-bit sensor data.

1. Understanding 12-Bit Raw Data Formats

Raw sensor frames generally come in two memory layouts:

  • Unpacked (Mono12 / Raw12): Each 12-bit pixel is stored inside a 16-bit (2-byte) word. The remaining 4 bits are padded (most commonly zero-padded at the most significant or least significant bits). ImageMagick reads this natively using the GRAY: or RGB: decoders set to 16-bit depth.
  • Packed (Mono12p / Mono12Packed): Two pixels share 3 consecutive bytes (24 bits total). ImageMagick does not natively decode non-byte-aligned packed bitstreams; packed frames must be converted to unpacked 16-bit buffers via custom preprocessing tools, Python, or camera SDK utilities before calling ImageMagick.

2. Reading Unpacked 12-Bit Grayscale Frames

Because raw binary files lack header metadata, you must define the width, height, bit depth, and endianness explicitly on the command line.

To convert a 12-bit unpacked grayscale raw frame stored in a 16-bit container to a standard 16-bit TIFF:

magick -size 2048x1536 -depth 16 -endian lsb gray:frame_12bit.raw -auto-level output.tiff
  • -size 2048x1536: The exact sensor resolution (width × height).
  • -depth 16: Instructs ImageMagick to read 2 bytes per pixel.
  • -endian lsb: Sets little-endian byte ordering (change to msb if your sensor outputs big-endian).
  • gray:: Specifies raw single-channel monochrome data.
  • -auto-level: Stretches the 12-bit dynamic range (values 0–4095) across the full 16-bit range (values 0–65535) to normalize visual brightness.

3. Scaling Values Manually

If you need consistent radiometric calibration across multiple frames, avoid -auto-level and apply a static multiplier:

magick -size 2048x1536 -depth 16 -endian lsb gray:frame_12bit.raw -evaluate multiply 16 output_scaled.tiff

Multiplying by 16 (\(2^4\)) shifts the 12-bit data to fill the upper range of the 16-bit container (\(4095 \times 16 = 65520\)).

4. Demosaicing 12-Bit Raw Color Frames (Bayer CFA)

If the industrial camera uses a Bayer color filter array (e.g., RGGB, BGGR, GRBG, GBRG), you can debayer the data using ImageMagick’s pattern filters or delegate demosaicing to raw processors.

To process a raw 12-bit Bayer frame directly in ImageMagick:

magick -size 2048x1536 -depth 16 -endian lsb gray:frame_bayer.raw \
  -evaluate multiply 16 \
  -set colorspace Gray \
  -define bayer:pattern=rggb \
  -bayer demosaic \
  output_color.tiff

5. Exporting to 8-Bit Formats for Display

To export a 12-bit sensor capture directly to a web-ready or lightweight format (such as PNG or JPEG), downsample the bit depth after range normalization:

magick -size 2048x1536 -depth 16 -endian lsb gray:frame_12bit.raw \
  -auto-level \
  -depth 8 \
  output.png

6. Batch Processing Industrial Raw Streams

To process a sequence of sequentially named raw frames:

magick -size 2048x1536 -depth 16 -endian lsb gray:frame_%04d.raw[0-99] \
  -auto-level \
  -depth 8 \
  processed_frame_%04d.png
