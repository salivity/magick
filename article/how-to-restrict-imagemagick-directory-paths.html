How to Restrict ImageMagick Directory Paths

ImageMagick can be configured to enforce strict directory restrictions for reading and writing files by editing its security policy file (policy.xml). Restricting path access prevents unauthorized file system access, mitigating vulnerabilities such as arbitrary file disclosure and unintended file overwrite. This guide explains how to establish a default-deny security posture and grant read or write permissions only to designated directory paths.

1. Locate the policy.xml File

ImageMagick manages its security configurations through policy.xml. The location of this file depends on your operating system and ImageMagick version:

  • Ubuntu / Debian: /etc/ImageMagick-6/policy.xml or /etc/ImageMagick-7/policy.xml
  • CentOS / RHEL / Fedora: /etc/ImageMagick/policy.xml
  • Custom Builds / Source: /usr/local/etc/ImageMagick-7/policy.xml

You can verify the active policy path by running:

identify -list policy
# or for ImageMagick 7:
magick identify -list policy

2. Configure Path Domain Policies

ImageMagick uses the path domain in policy.xml to control access to the filesystem using standard glob patterns.

To secure your installation, follow a least-privilege approach: deny all directory access first, then explicitly whitelist only the paths your application requires.

Open policy.xml in a text editor with administrative privileges:

sudo nano /etc/ImageMagick-6/policy.xml

Insert the following rules inside the <policymap> element:

<policymap>
  <!-- 1. Deny read and write access to the entire filesystem by default -->
  <policy domain="path" rights="none" pattern="*" />

  <!-- 2. Allow read access to required application assets and temp directories -->
  <policy domain="path" rights="read" pattern="/var/www/my-app/uploads/*" />
  <policy domain="path" rights="read" pattern="/tmp/*" />

  <!-- 3. Allow write access only to specific output destinations -->
  <policy domain="path" rights="write" pattern="/var/www/my-app/processed/*" />
  <policy domain="path" rights="write" pattern="/tmp/*" />

  <!-- 4. (Optional) Allow access to standard system fonts if generating text -->
  <policy domain="path" rights="read" pattern="/usr/share/fonts/*" />
</policymap>

3. Policy Attributes Explained

  • domain="path": Specifies that the rule applies to filesystem paths and filenames.
  • pattern: The path expression to match. Use explicit paths along with wildcards (e.g., /path/to/dir/* or /path/to/dir/** for recursive directories).
  • rights: Defines the permitted operation:
    • none: Prohibits all access (read and write).
    • read: Permits reading files from the matched path.
    • write: Permits writing files to the matched path.
    • read|write: Permits both reading and writing.

Policies are evaluated in the order they appear. Placing <policy domain="path" rights="none" pattern="*" /> at the top ensures all unlisted directories are blocked.

4. Verify the Configuration

Test the policy to confirm that unauthorized paths are blocked and authorized paths remain accessible.

Test Unauthorized Read Access:

convert /etc/passwd /tmp/test.png

Expected Result: ImageMagick returns an error indicating that access to /etc/passwd is not authorized by the security policy.

Test Authorized Read and Write Access:

convert /var/www/my-app/uploads/input.jpg /var/www/my-app/processed/output.png

Expected Result: The operation completes successfully.
