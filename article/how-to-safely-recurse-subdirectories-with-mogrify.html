How to Safely Recurse Subdirectories with Mogrify

ImageMagick’s mogrify tool is designed for fast batch image processing, but it lacks a built-in recursive flag and overwrites source files by default. This guide covers how to safely pair mogrify with shell utilities like find to traverse nested directory trees, apply transformations consistently, and prevent accidental data loss.

Understanding the Risks of Mogrify

Unlike the standard magick or convert commands, mogrify operates in-place. If an operation is executed incorrectly, the original image data is permanently overwritten. Furthermore, mogrify does not natively support directory recursion (such as a -r flag). Relying on shell globbing like **/*.jpg can fail when dealing with large directory structures due to command-line argument length limits (ARG_MAX) or missing globstar configurations.

To process files across subdirectories safely, you must control file discovery using dedicated system tools and implement safeguards against file destruction.

Method 1: In-Place Recursion Using find

The most reliable way to traverse subdirectories across all Unix-like platforms is pairing find with mogrify.

find . -type f \( -iname "*.jpg" -o -iname "*.png" \) -exec mogrify -resize 1920x1080\> {} +

Why this method is safe:

  • Argument safety: The -exec ... + syntax batches arguments without exceeding system execution limits.
  • Path safety: It handles filenames with spaces, special characters, and arbitrary depth natively.
  • Precise filtering: The -type f flag prevents mogrify from attempting to open directories as images.

Note: Always create a backup of your root directory before running in-place batch modifications.

Method 2: Non-Destructive Conversion Using -format

You can recurse through directories while keeping original files completely untouched by altering the file format during the mogrify execution. When a new format is declared, mogrify writes a new file in the same subdirectory alongside the original rather than overwriting it.

find . -type f -iname "*.png" -exec mogrify -format webp -quality 80 {} +

In this example, every .png file found in any subdirectory will generate a corresponding .webp file in that same folder, leaving the source PNG intact.

Method 3: Mirroring the Directory Tree for Isolated Output

If you need to resize or modify images without changing formats or touching the source files, mirror the directory structure into a target directory first, then run mogrify with the -path parameter.

Step 1: Replicate the folder structure

find . -type d -exec mkdir -p /path/to/output_dir/{} \;

Step 2: Process images into the mirrored structure

find . -type d -exec sh -c '
  for dir do
    mogrify -path "/path/to/output_dir/$dir" -resize 50% "$dir"/*.jpg 2>/dev/null
  done
' sh {} +

This ensures that the output files are stored in an entirely separate location, preserving the source hierarchy and keeping original assets safe from corruption or bad parameter adjustments.

Essential Best Practices

  • Test on a small subset: Run the command with a -maxdepth 1 flag or on a single test folder before targeting thousands of files.
  • Quote geometry strings: Special characters like > (resize only if larger) or ^ (minimum dimensions) must be escaped or quoted so the shell does not interpret them as redirections.
  • Use case-insensitive matching: Always use -iname instead of -name in find commands to catch files ending in .JPG, .jpeg, and .jpg.
