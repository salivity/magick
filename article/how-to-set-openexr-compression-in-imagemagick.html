How to Set OpenEXR Compression in ImageMagick

This article provides a straightforward guide on configuring OpenEXR compression algorithms in ImageMagick. You will learn the exact command-line parameters required to apply standard compression schemes—such as PIZ, ZIP, and B44—to optimize the storage, read speeds, and quality of your high-dynamic-range (HDR) EXR files.

The -compress Parameter

ImageMagick handles OpenEXR compression primarily through the standard -compress command-line switch. Place the parameter before the output filename when invoking the magick (ImageMagick 7) or convert (ImageMagick 6) command.

Basic Syntax

magick input.png -compress <TYPE> output.exr

Replace <TYPE> with your desired compression algorithm. ImageMagick passes these settings directly to the underlying OpenEXR library.

Supported EXR Compression Schemes

OpenEXR supports several compression algorithms tailored for different types of imagery (e.g., noisy photographic plates, computer graphics renders, flat alpha masks). ImageMagick maps the following values:

Lossless Compression Options

  • None: Disables compression entirely. Yields the fastest export times but creates the largest file sizes. 
    magick input.png -compress None output.exr
  • PIZ: A wavelet-based compression method. It is often the most effective lossless scheme for noisy, photographic, or grainy images. 
    magick input.png -compress PIZ output.exr
  • Zip: Standard deflate compression operating on individual scanlines. It is efficient for graphics with smooth color gradients. 
    magick input.png -compress Zip output.exr
  • Zips: Similar to Zip, but processes 16 scanlines at a time, often yielding slightly better compression ratios than single scanline Zip. 
    magick input.png -compress Zips output.exr
  • RLE: Run-length encoding. It provides fast read/write performance and works well on images containing large solid blocks of uniform color, such as matte passes or ID passes. 
    magick input.png -compress RLE output.exr

Lossy Compression Options

  • B44: Compresses 4x4 pixel blocks into a fixed size. It provides a constant data rate and fast real-time playback at the cost of minor loss in quality. 
    magick input.png -compress B44 output.exr
  • B44A: An extension of B44 that applies additional lossless compression to flat-color areas within the 4x4 blocks, resulting in smaller files when dealing with empty backgrounds or uniform alphas. 
    magick input.png -compress B44A output.exr
  • Pxr24: Reduces 32-bit floating-point data to 24-bit floats before applying standard deflate compression. It is visually lossless for most color data and ideal for depth or camera passes, though it does not compress 16-bit half-float data. 
    magick input.png -compress Pxr24 output.exr
  • DWAA / DWAB: Modern DCT-based lossy compression methods (DreamWorks Animation). DWAA compresses in 32-scanline blocks, while DWAB compresses in 256-scanline blocks, offering small file sizes suitable for visual effects review. 
    magick input.png -compress DWAA output.exr

Controlling Lossy Quality for DWA Compression

When using DWAA or DWAB compression, you can control the compression level using the standard -quality parameter.

magick input.png -compress DWAA -quality 45 output.exr

A lower quality value yields smaller files with more compression artifacts, whereas a higher quality value retains greater fidelity at the expense of storage size. The default value typically aligns with the OpenEXR reference default (45.0).
