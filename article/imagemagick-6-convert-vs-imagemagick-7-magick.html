ImageMagick 6 Convert vs ImageMagick 7 Magick

The transition from ImageMagick 6 to ImageMagick 7 introduced a fundamental redesign of the suite's command-line interface, most notably replacing the ubiquitous convert tool with the unified magick command. While ImageMagick 6 relied on separate binaries for different tasks, ImageMagick 7 consolidates these utilities into a single executable, resolves long-standing operating system conflicts, enforces strict sequential command processing, and adds support for dynamic mathematical expressions directly inside command arguments.

The Unified Binary Architecture

In ImageMagick 6, the suite was split across several individual executables: convert, identify, mogrify, composite, and others. The convert binary was the primary workhorse used for reading, manipulating, and writing image files.

In ImageMagick 7, the single magick binary replaces all standalone utilities. The previous tools now exist as subcommands under the master binary:

  • convert becomes magick (or magick convert for legacy emulation)
  • identify becomes magick identify
  • mogrify becomes magick mogrify
  • composite becomes magick composite

This architecture resolves a notorious conflict on Windows systems, where the ImageMagick convert.exe utility conflicted with the native Windows file system conversion tool of the same name.

Strict Left-to-Right Processing

One of the most critical functional differences between convert and magick is how command-line options are parsed:

  • ImageMagick 6 (convert): Option parsing was permissive and often unpredictable. You could specify options before loading the image, after loading the image, or at the end of the command, and the utility would attempt to infer the intended execution order. This frequently led to unexpected output when chaining multiple operations.
  • ImageMagick 7 (magick): Operations are strictly interpreted from left to right. Settings, operators, and images are applied exactly in the sequence they appear. An operation only applies to images loaded prior to that operation in the command string.

Dynamic Expressions and Inline Calculations

ImageMagick 6 required external shell scripting (such as Bash arithmetic or bc) to calculate dimensions, coordinates, or percentages before passing them to convert.

ImageMagick 7 natively incorporates mathematical expressions into arguments via the FX engine. Using the syntax %[fx:...], you can compute values dynamically based on image attributes:

magick input.jpg -resize "%[fx:w/2]x%[fx:h/2]" output.jpg

This allows single-line commands to query image dimensions, aspect ratios, or color profiles and modify the image accordingly without external scripting logic.

Improved Alpha Channel and Color Handling

ImageMagick 7 modifies how channels, particularly the alpha channel, are handled:

  • HDRI by Default: High Dynamic Range Imaging (HDRI) is enabled by default in ImageMagick 7, using 32-bit floating-point values for color channels instead of the 8-bit or 16-bit integers common in ImageMagick 6 builds. This prevents clipping of out-of-gamut colors and improves precision during multi-step adjustments.
  • Separated Alpha: ImageMagick 7 treats transparency strictly as an alpha channel rather than blending it into a matte attribute, unifying the syntax for masking and blending workflows.

Backward Compatibility and Deprecation

While ImageMagick 7 often includes a symlink for convert, running convert directly invokes a legacy compatibility mode designed to mimic ImageMagick 6 behavior. This compatibility mode does not grant access to ImageMagick 7 features, such as inline calculations or advanced co-processing scripts (magick -script). To utilize the improvements and performance benefits of the modern suite, scripts must be updated to use the magick command.
