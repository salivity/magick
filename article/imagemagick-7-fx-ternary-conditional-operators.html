ImageMagick 7 FX Ternary Conditional Operators

This article explains how ImageMagick 7 evaluates ternary conditional operators within the -fx expression engine. It covers the syntax structure, numeric boolean evaluation rules, execution behavior such as short-circuit evaluation, operator precedence, and how pixel values are parsed when applying conditional logic across image channels.

Syntax and Structure

In ImageMagick 7, the -fx operator uses a standard ternary operator syntax borrowed from C-like languages:

condition ? expression_if_true : expression_if_false

When processing an image, -fx iterates over each pixel (and each active channel unless restricted by -channel), evaluates the condition, and returns the result of the corresponding expression.

Boolean Logic and Truth Values

ImageMagick’s expression parser handles values primarily as floating-point numbers rather than discrete boolean types. When evaluating the condition part of a ternary expression:

  • False: A result equal to 0.0 is treated as false.
  • True: Any non-zero numeric value (positive or negative) is treated as true.

Comparison operators such as <, <=, >, >=, ==, and != produce 1.0 for true and 0.0 for false. For example, in the expression u > 0.5 ? 1 : 0, the comparison u > 0.5 yields 1.0 if the source pixel intensity exceeds half brightness, triggering the true branch.

Short-Circuit Evaluation

ImageMagick 7 evaluates ternary operators with short-circuit execution. The engine first evaluates the condition. Depending on whether the outcome is true or false, it only evaluates the branch that needs to be executed:

  • If the condition is non-zero, expression_if_true is calculated, and expression_if_false is ignored.
  • If the condition is zero, expression_if_false is calculated, and expression_if_true is ignored.

This behavior protects against runtime calculation errors, such as division by zero. For example, the expression v == 0 ? 0 : u / v safely avoids an illegal arithmetic exception because u / v is never evaluated when v equals 0.

Operator Precedence and Nesting

The ternary operator has lower precedence than arithmetic (+, -, *, /) and relational (<, ==, >) operators. Consequently, expressions like u + 0.1 > 0.5 ? 1 : 0 evaluate the arithmetic and comparison first without requiring explicit parentheses around the condition.

Ternary operators are right-associative, enabling nesting for multi-condition branching:

u < 0.25 ? 0 : (u < 0.75 ? 0.5 : 1)

In this case, the engine processes the outermost condition first. If false, it moves to the second condition, effectively mimicking an if / else if / else structure.

Pixel and Channel Context

Pixel color values in the -fx context are normalized to the range [0.0, 1.0] regardless of the image bit depth (such as Q8 or Q16). Symbols like u reference the primary image, while specific channels can be queried using u.r, u.g, u.b, or u.a. When a ternary operator executes without specifying a channel, the expression evaluates independently for each channel in the image.
