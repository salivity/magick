ImageMagick 7 Read-Mask and Write-Mask Explained

This article explores the purpose, behavior, and practical differences between the -read-mask and -write-mask operators introduced in ImageMagick 7. In ImageMagick 6, a single -mask operator handled pixel protection, which often caused confusion during complex operations. ImageMagick 7 decouples this behavior into two distinct operators, granting precise control over which pixels are sampled (read) during an operation and which pixels are updated (written) in the final output.

The Problem with Legacy Masking

In ImageMagick 6, setting a -mask generally acted as a write mask, preventing changes to masked pixels. However, neighborhood-dependent operations like blurring, resizing, or morphology would still sample data from the masked regions. This caused edge artifacts, where protected pixels bled their colors into adjacent unmasked pixels. ImageMagick 7 solved this issue by splitting mask behavior into read masking and write masking.

The Write-Mask (-write-mask)

The primary purpose of -write-mask is to protect pixels from being altered. It determines where the results of an operation are allowed to be saved onto the canvas.

  • Behavior: When an operation runs, ImageMagick processes the image but only commits changes to areas permitted by the write mask. Typically, white areas in the mask allow pixel modifications, while black areas protect the original pixels from being overwritten. Gray values allow partial, blended modifications according to their transparency level.
  • Common Use Cases: Applying color corrections, vignettes, contrast adjustments, or overlays to a specific subject or background without modifying the rest of the image.

To apply and subsequently remove a write mask in the command line:

magick input.png -write-mask mask.png -modulate 120,100,100 +write-mask output.png

The +write-mask command removes the mask so subsequent operations affect the entire image.

The Read-Mask (-read-mask)

The purpose of -read-mask is to restrict which pixels ImageMagick can look at or sample during calculations.

  • Behavior: When operations calculate new values based on neighboring pixels (such as -blur, -convolve, or -morphology), a read mask prevents pixels marked as masked from contributing to the calculation. The masked pixels are treated as non-existent or transparent to the reading algorithm.
  • Common Use Cases: Preventing background colors from bleeding into a foreground subject during edge-detection, blurring, or sampling calculations.

To use and clear a read mask:

magick input.png -read-mask mask.png -blur 0x8 +read-mask output.png

Using Read-Mask and Write-Mask Together

The true power of ImageMagick 7's masking architecture appears when both operators are combined.

For example, when blurring only a background behind an isolated subject:

  1. Using only a -write-mask prevents the subject from being overwritten, but the subject's colors still bleed into the blurred background because the blur algorithm samples the subject's pixels.
  2. Using both a -read-mask and a -write-mask ensures the subject's pixels are not read by the blur algorithm (preventing halos) and are also not overwritten in the final composite.
magick input.png -read-mask bg_mask.png -write-mask bg_mask.png -blur 0x10 +read-mask +write-mask output.png

By explicitly isolating the input data pipeline (-read-mask) from the output rendering pipeline (-write-mask), ImageMagick 7 provides fine-grained control over complex pixel manipulation tasks.
