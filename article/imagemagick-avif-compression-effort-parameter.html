ImageMagick AVIF Compression Effort Parameter

When encoding AVIF images in ImageMagick, controlling the compression effort allows you to balance CPU encoding time with resulting file size. This guide explains the exact parameter used to adjust compression effort for AVIF files, how the values work, and how to implement it effectively in your command-line workflows.

The Compression Effort Parameter

In ImageMagick, the compression effort for AVIF images is controlled using the -define heic:speed parameter (or -define avif:speed, depending on your ImageMagick build and delegate libraries such as libheif or libaom).

Because AVIF is built on the HEVC/HEIF container format framework within ImageMagick delegates, the heic:speed definition directly maps to the underlying encoder's speed and effort settings.

Value Range and Behavior

The speed parameter typically accepts integer values ranging from 0 to 9 (or 0 to 10 on certain encoder builds):

  • 0 (Maximum Effort / Slowest): Directs the encoder to analyze the image thoroughly for maximum compression efficiency. This produces the smallest file size at a given quality level but requires the most CPU time.
  • 5 or 6 (Default / Balanced): Provides a standard balance between encoding speed and compression ratio, suitable for general-purpose batch processing.
  • 9 or 10 (Minimum Effort / Fastest): Minimizes CPU usage to encode the image as quickly as possible. This results in larger file sizes compared to lower speed values at the same visual quality.

Effort vs. Quality

It is essential to distinguish between compression effort and compression quality:

  • -quality <value>: Sets the visual fidelity and quantization level (0–100). Lower values reduce image quality to save space.
  • -define heic:speed=<value>: Sets the computational effort the encoder spends compressing the data. It does not intentionally degrade visual quality, but lower effort yields less optimal compression.

Command Examples

Maximum Compression (High Effort, Slow)

To achieve the smallest possible file size when encoding time is not a constraint:

magick input.png -quality 65 -define heic:speed=0 output.avif

Fast Encoding (Low Effort, Quick)

For real-time or high-throughput batch processing where processing speed is critical:

magick input.png -quality 65 -define heic:speed=8 output.avif

Lossless AVIF with Custom Effort

When creating lossless AVIF files, the speed parameter dictates how hard the encoder works to reduce the lossless payload:

magick input.png -quality 100 -define heic:lossless=true -define heic:speed=2 output.avif
