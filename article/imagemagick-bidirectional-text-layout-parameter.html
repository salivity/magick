ImageMagick Bidirectional Text Layout Parameter

This guide explains how to render bidirectional (BiDi) text layout in ImageMagick, focusing on the -direction parameter, necessary library dependencies, and practical command-line examples for correctly shaping Right-to-Left (RTL) scripts such as Arabic and Hebrew alongside Left-to-Right (LTR) text.

In ImageMagick, the primary parameter used to specify text layout direction is -direction.

The -direction Parameter

The -direction setting instructs ImageMagick how to flow and align the rendered glyphs. The supported values are:

  • right-to-left: Renders text starting from the right side, flowing to the left.
  • left-to-right: Default text rendering from left to right.

Example syntax:

magick -background white -fill black -font "Amiri-Regular.ttf" -pointsize 36 -direction right-to-left label:"مرحبا بالعالم" output.png

Requirements for Proper Bidirectional Shaping

Using the -direction parameter alone is often not enough for complex bidirectional text containing ligatures or mixed-direction phrases. For full bidirectional layout support, ImageMagick must be compiled with the following dependencies:

  • RAQM (libraqm): Enables complex text layout, bidirectional support, and script detection.
  • FriBidi: Implements the Unicode Bidirectional Algorithm.
  • HarfBuzz: Handles text shaping and proper OpenType glyph substitution.

To verify whether your ImageMagick build supports Raqm, run:

magick -version

Look for raqm in the Features or Delegates list.

Alternative Rendering via Pango

If ImageMagick is not compiled with libraqm, bidirectional text can be rendered accurately using the Pango delegate format (pango:). Pango natively handles bidirectional text layout and font shaping.

Example syntax using Pango:

magick -background white -fill black pango:"<span font='Amiri 24'>مرحبا بالعالم (Hello World)</span>" output_pango.png
