ImageMagick Connected Components Color Labeling

This article explores how the ImageMagick -connected-components operator detects, isolates, and assigns unique color labels to segmented text characters. It covers the underlying connected-component labeling (CCL) algorithm, pixel connectivity rules, sequential component identification, and the methods used to map raw integer identifiers to visual, distinct color values.

The Segmentation and Identification Process

Before assigning colors, the -connected-components operator requires a thresholded or binary image where text characters are cleanly separated from the background. The operator processes the raster grid using a standard connected-component labeling algorithm, typically adhering to either 4-connectivity (orthogonal neighbors) or 8-connectivity (orthogonal and diagonal neighbors) as defined by the -define connected-components:connectivity=... setting.

As the algorithm scans the image row by row:

  1. It detects contiguous foreground pixels representing individual glyphs or parts of glyphs.
  2. It tracks equivalences when two previously distinct labeled regions merge into a single shape.
  3. Once the scan is complete, it resolves all equivalences and assigns a unique, sequential integer identifier (ID) to each discrete component, typically reserving ID 0 for the background.

Mapping Component IDs to Pixel Values

By default, ImageMagick associates each detected component with its sequential integer ID. In the resulting label image, the pixel values themselves are replaced by these numeric IDs. Because digital images store pixel data within a specific bit depth (such as 8-bit or 16-bit Quantum depth), the raw IDs are written directly into the pixel channels.

If rendered directly to a display without normalization, low integer IDs (e.g., 1, 2, 3) appear visually black because their numeric values are nearly zero relative to the maximum channel depth (such as 255 in 8-bit or 65535 in 16-bit).

Generating Unique Color Labels

To transform these sequential integer IDs into distinct, visible colors for each segmented character, ImageMagick employs two primary strategies:

1. Mean Color Replacement
By setting -define connected-components:mean-color=true, ImageMagick samples the colors from the original source image and replaces all pixels within a component's boundary with the average (mean) color of that component. If the input characters have varying colors, the output visualizes these characters with flat, uniform versions of their original colors.

2. Pseudo-Coloring via Colormaps (CLUT)
To assign arbitrary, visually contrasting colors to each character, the raw ID image must be mapped through a Color Look-Up Table (CLUT). ImageMagick accomplishes this by:

  • Auto-leveling or normalizing the grayscale component image so that the IDs scale across the entire dynamic range from minimum to maximum.
  • Applying a gradient or custom palette using the -clut operator. Each distinct grayscale ID level maps directly to a distinct hue or RGB value in the lookup table, ensuring adjacent text characters receive visually distinct colors regardless of their initial appearance.
