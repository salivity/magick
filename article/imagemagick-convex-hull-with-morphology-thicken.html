ImageMagick Convex Hull with Morphology Thicken

In ImageMagick, the Thicken morphology operator provides a discrete method for generating a convex hull around arbitrary binary shapes. By using directional hit-and-miss structural kernels repeatedly until convergence, the operator systematically detects concave bays, notches, and indentations across a shape's perimeter and fills them with foreground pixels. This article explains the underlying morphological mechanism, the kernel logic, and the practical implementation of using the Thicken operator to enclose shapes within a digital convex hull.

The Role of the Thicken Operator

In mathematical morphology, thickening is a dual operation to thinning. It expands foreground structures by testing the image against a Hit-and-Miss kernel and adding pixels to the foreground wherever a match occurs:

\[\text{Thicken}(A, K) = A \cup (A \otimes K)\]

Where \(A\) is the input image, \(K\) is the kernel, and \(\otimes\) represents the Hit-and-Miss transform. While a basic dilation adds pixels uniformly around all boundaries, Thicken is selective. It only adds a pixel if the neighboring pixels strictly match the foreground and background configuration defined by the kernel.

How the Convex Hull Is Formed

To create a convex hull, ImageMagick provides a predefined kernel set labeled ConvexHull. This set consists of discrete \(3 \times 3\) directional structural elements designed to locate indentations and concave corners on a digital grid.

  1. Pattern Matching: Each kernel in the ConvexHull series searches for specific configurations where background pixels are partially enclosed by foreground pixels (such as a corner indentation between two extended points).
  2. Filling Recesses: When a kernel matches a concave configuration, the targeted background pixel is converted into a foreground pixel.
  3. Iterative Expansion: A single pass fills only the immediate concave edges. To produce a complete convex hull, the operator must run iteratively. As new pixels are added, they create new neighborhood patterns that match subsequent kernel passes, progressively bridging the gaps between external vertices.
  4. Convergence: The iterations continue until no further kernel matches occur, meaning all detectable concave indentations have been filled.

Syntax and Command Usage

The typical ImageMagick command for generating a convex hull uses the iteration count -1, which instructs the engine to repeat the operation until no further changes are detected:

magick input.png -morphology Thicken:-1 ConvexHull output.png

In this command:

  • -morphology Thicken calls the thickening operator.
  • :-1 specifies an infinite loop until the image reaches a steady state (convergence).
  • ConvexHull specifies the rotated series of \(3 \times 3\) kernels tailored to bridge concave gaps across the horizontal, vertical, and diagonal axes.

Discrete Grid Considerations

Because ImageMagick operates on a discrete raster grid, the resulting convex hull is a digital approximation rather than a continuous Euclidean polygon. Using standard \(3 \times 3\) neighborhood kernels, the hull typically resolves into an 8-sided bounded polygon (an octagonal hull), with boundary segments restricted to \(0^\circ\), \(45^\circ\), and \(90^\circ\) angles. Despite this discrete restriction, it effectively creates the minimal bounding convex shape achievable within standard 8-connected pixel space.
