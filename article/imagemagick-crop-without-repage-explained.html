ImageMagick Crop Without +repage Explained

When you crop an image in ImageMagick without using the +repage operator, the software retains the original virtual canvas dimensions and image offsets rather than resetting them to match the new cropped dimensions. This retained geometry data can cause unexpected display glitches, incorrect image alignment during compositing, and visual errors when saving to formats that support multi-layer or canvas metadata, such as GIF, PNG, TIFF, and PDF.

Retained Virtual Canvas and Offsets

ImageMagick’s -crop operator cuts out the specified region of pixels, but it leaves the virtual canvas metadata intact by default. For example, if you crop a 100x100 area starting at offset +50+50 from a 1000x1000 image, ImageMagick creates a 100x100 pixel image with a canvas coordinate metadata of 1000x1000+50+50.

Without +repage, the image keeps its knowledge of where it originally existed inside the larger parent canvas.

Issues with Specific File Formats

Different image formats handle virtual canvas metadata in distinct ways:

  • GIF: Animated and static GIFs strictly honor canvas offsets. If you omit +repage, a viewer may render the cropped area inside the full original canvas boundary surrounded by transparent or black space, rather than rendering just the cropped dimensions.
  • PNG and TIFF: These formats store page offset chunks (oFFs in PNG). Many modern image viewers and web browsers ignore these offsets, but graphics software like Photoshop, GIMP, or downstream ImageMagick scripts will read the offset and shift the image unexpectedly.
  • PDF: Omitting +repage when outputting to PDF often results in the cropped image floating at its original offset within an otherwise empty page sized to the original canvas.
  • JPEG: JPEG does not support virtual canvas metadata, so it discards the offsets on export. However, issues will still occur during any intermediate processing before the file is written to disk.

Problems in Multi-Step Image Pipelines

If your command pipeline performs subsequent operations after cropping—such as -resize, -extent, -border, or -composite—ImageMagick will calculate these transformations relative to the virtual canvas rather than the cropped pixel boundaries. This leads to misplaced overlays, wrong aspect ratio calculations, and unintended padding.

The Solution: Using +repage

The +repage operator (or -repage 0x0+0+0) removes the canvas offset and resets the image’s page geometry to match its actual cropped pixel size.

magick input.png -crop 300x300+50+50 +repage output.png

Adding +repage immediately following the -crop operation ensures the image behaves as a standalone graphic with clean metadata across all formats and viewing applications.
