ImageMagick Custom Morphology Kernel Syntax

This article provides a practical reference for defining custom morphology kernels in ImageMagick. It details the structural syntax required to construct user-defined kernel matrices, explains how to position the kernel origin, outlines the handling of special pixel values such as NaN, and demonstrates real-world command-line examples across standard morphological operations.

Basic Syntax Structure

A custom user-defined kernel string in ImageMagick uses the following standard format:

[width]x[height][+x+y]: [value_1], [value_2], ..., [value_N]

The components of this string are defined as follows:

  • [width]x[height]: The dimensions of the kernel matrix (e.g., 3x3, 5x5, 3x1). The product of the width and height must match the total number of values provided.
  • [+x+y] (Optional): Specifies the zero-based coordinate offset of the kernel's origin (the "hotspot" or center of action). If omitted, ImageMagick defaults to the exact geometric center: (width - 1) / 2, (height - 1) / 2.
  • : (Colon): Separates the geometry definition from the matrix values.
  • values: Floating-point numbers, integers, or special keywords separated by commas, spaces, or newlines, listed in row-major order (from left to right, top to bottom).

Special Value Identifiers

When defining kernels for operations like Hit-and-Miss or custom neighborhood filtering, certain keywords control pixel evaluation:

  • nan or NaN: Represents a "do not care" condition. The pixel at this relative location is completely ignored during the operation. This is essential for pattern matching and thinning/thickening operations.
  • Negative numbers: Permitted for convolution, correlation, and differential edge-detection filters.

Defining the Kernel Origin

By default, an odd-sized kernel automatically places the origin at the center. For asymmetric or directional operations, you can manually define the origin:

  • 3x3+0+0: places the origin at the top-left corner.
  • 3x3+2+2: places the origin at the bottom-right corner.
  • 3x1+0+0: places the origin at the leftmost position of a horizontal kernel.

Command-Line Usage Examples

Custom kernels are passed directly into the -morphology operator enclosed in quotes.

1. Custom 3x3 Edge Detection (Convolve)

A discrete Laplace filter with a standard 3x3 grid centered automatically:

magick input.png -morphology Convolve "3x3: 0,-1,0 -1,4,-1 0,-1,0" output.png

2. Hit-and-Miss Pattern Matching with NaN

A 3x3 corner detection kernel where corner elements are ignored:

magick input.png -morphology Hit-and-Miss "3x3: nan,1,nan 0,1,1 0,0,nan" output.png

3. Off-Center Custom Kernel (Dilate)

A 3x3 horizontal bias filter with an explicit origin set to the left edge (+0+1):

magick input.png -morphology Dilate "3x3+0+1: 1,0,0 1,1,0 1,0,0" output.png

4. Multiline Formatting

For readability in shell scripts or configuration files, values can be formatted across multiple lines using spaces or commas:

magick input.png -morphology Convolve "5x5:
  0.0, 0.2, 0.2, 0.2, 0.0,
  0.2, 0.4, 0.4, 0.4, 0.2,
  0.2, 0.4, 1.0, 0.4, 0.2,
  0.2, 0.4, 0.4, 0.4, 0.2,
  0.0, 0.2, 0.2, 0.2, 0.0" output.png
