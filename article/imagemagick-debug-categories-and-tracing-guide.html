ImageMagick Debug Categories and Tracing Guide

This guide provides a comprehensive overview of the debug categories available in ImageMagick, explaining how to monitor internal operations, diagnose performance bottlenecks, and resolve image processing errors using the command-line debugging features.

How to Enable Debug Tracing

ImageMagick provides the -debug option to log internal events. You can combine multiple categories using commas or use the special keyword All to log everything. To define how messages are displayed or stored, use the -log parameter.

magick input.jpg -debug Resource,Coder,Transform -log "%t %d %e: %m" output.png

Core ImageMagick Debug Categories

ImageMagick provides several specific categories to trace different operational stages:

  • Coder: Traces the decoding (reading) and encoding (writing) of specific image formats, such as PNG, JPEG, TIFF, or WebP. Use this category to troubleshoot corrupted files or unsupported format options.
  • Resource: Tracks resource allocation and limits, such as memory usage, disk storage for temporary files, map limits, and thread pool management.
  • Transform: Monitors image geometry adjustments, such as resizing, cropping, flipping, rotating, and affine transformations.
  • Cache: Logs pixel cache interactions, including allocation in RAM, memory-mapping, or offloading pixel data to temporary disk caches.
  • Blob: Traces Binary Large Object (BLOB) operations, which involve reading or writing image data directly to and from memory streams rather than physical files.
  • Configure: Logs the search and loading process of external configuration files (such as delegates.xml, policy.xml, and type.xml).
  • Policy: Monitors the security policy engine (policy.xml), logging whether certain coders, paths, or resource limits are allowed or blocked.
  • Draw: Traces 2D vector drawing operations, path parsing, and shape rendering.
  • Annotate: Logs font rendering, text layout, glyph mapping, and FreeType library integration.
  • Exception: Records internal warnings, non-fatal issues, and error generation during execution.
  • Module: Tracks the dynamic loading and unloading of external coder modules (.so or .dll files).
  • Accelerate: Traces GPU acceleration and OpenCL kernel executions.
  • Trace: Emits high-granularity entry and exit execution logs for low-level ImageMagick functions.
  • User: Displays custom debug messages injected by users via API calls or scripting interfaces.
  • Wand: Logs interactions and calls within the MagickWand C API level.
  • All: Activates debugging output across all available categories simultaneously.

Combining Debug Categories

Categories can be combined to isolate complex issues involving interdependent subsystems. For example, to troubleshoot memory pressure during format conversion and resizing:

magick -debug Cache,Resource,Transform large_image.tiff -resize 50% output.jpg
