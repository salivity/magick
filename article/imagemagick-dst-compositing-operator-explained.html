ImageMagick Dst Compositing Operator Explained

The ImageMagick Dst (Destination) compositing operator resolves image layering by prioritizing the destination image and discarding the source image. In digital image composition, the operator applies the classic Porter-Duff "Destination" rule, where destination pixels are preserved unchanged and incoming source pixels are multiplied by zero. This article explains the underlying pixel math, the distinction between source and destination layers in ImageMagick, and how the Dst operator behaves during processing.

Source vs. Destination in ImageMagick

To understand how pixels are evaluated, you must first identify the layers:

  • Destination (\(D\)): The base canvas or background image.
  • Source (\(S\)): The overlay or incoming image being composited onto the canvas.

When running ImageMagick commands, the order of images dictates which is source and which is destination. For example, in the command magick canvas.png overlay.png -compose Dst -composite output.png, canvas.png serves as the destination and overlay.png serves as the source.

The Porter-Duff Formulation

ImageMagick implements standard Porter-Duff alpha compositing formulas. The general equation for compositing color and alpha channels is:

\[\text{Color} = S_c \times F_s + D_c \times F_d\] \[\text{Alpha} = S_a \times F_s + D_a \times F_d\]

Where \(S_c\) and \(D_c\) represent source and destination color values, \(S_a\) and \(D_a\) represent alpha channel values, and \(F_s\) and \(F_d\) represent the blending factors.

For the Dst operator, the blending factors are defined strictly as:

  • \(F_s = 0\)
  • \(F_d = 1\)

Applying these factors to the equation yields:

\[\text{Color} = S_c \times 0 + D_c \times 1 = D_c\] \[\text{Alpha} = S_a \times 0 + D_a \times 1 = D_a\]

How Pixels Are Processed

Because the source factor (\(F_s\)) is zero, every channel (red, green, blue, and alpha) of the incoming source layer is multiplied by zero. The destination canvas pixel values are multiplied by one, leaving them completely unaltered.

  1. Overlapping Regions: Where the source image geometry overlaps the canvas, the destination canvas retains its original color and opacity. The source pixels are completely dropped from calculation.
  2. Non-Overlapping Regions: Outside the bounding box of the overlay, the destination canvas remains unchanged.
  3. Canvas Bounds: The final output dimensions match the destination canvas, preserving its canvas profile, color space, and metadata.

Practical Effect in Workflows

Because Dst effectively discards the incoming source image and leaves the destination untouched, applying it directly on two standard images produces an output identical to the destination canvas.

It is primarily used in complex masking chains, multi-step script pipelines, or channel-clearing operations where a process requires evaluating layer geometry without allowing source pixel data to alter the underlying canvas. If you intend for the source image to replace or overwrite the destination canvas, the opposite operator—Src—is used instead.
