ImageMagick Evaluate-Sequence Sum vs Compositing

This article explains the core differences between ImageMagick's -evaluate-sequence Sum operator and standard image compositing operations. While both approaches allow users to merge visual data from multiple inputs, they differ fundamentally in how they handle image stacks, perform color and alpha channel mathematics, process image geometry, and manage dynamic range.

Multiple Image Stacks vs. Pairwise Processing

The most prominent operational difference lies in how inputs are ingested. The -evaluate-sequence Sum operator is designed to process an arbitrary list of two or more images in a single step. It flattens the entire current image sequence by summing the values of corresponding pixels across all images simultaneously.

Standard compositing using -composite (or operators like -compose Over -composite) inherently operates as a pairwise function. It takes a background image and layers a foreground image on top. Merging more than two images through compositing requires chaining multiple commands or looping pairwise operations sequentially.

Raw Arithmetic Addition vs. Porter-Duff Blending

Standard compositing relies on Porter-Duff composition rules or specific blend formulas. When using -compose Over or even additive modes like -compose Plus, ImageMagick factors in the alpha channel to calculate visibility, premultiplying color channels by alpha and computing a weighted result:

\[\text{Color} = \text{Source Color} \times \text{Source Alpha} + \text{Destination Color} \times (1 - \text{Source Alpha})\]

In contrast, -evaluate-sequence Sum performs direct, unconditional mathematical addition across pixel channels. Unless restricted by channel masks (such as -channel RGB), the alpha channel itself is added numerically rather than used to calculate transparency weights. It treats the pixel values as raw numeric arrays rather than layered visual surfaces.

Handling Image Geometry and Offsets

Compositing is layout-aware. Commands using -composite respect image offsets, page geometries, and canvas positioning (often specified using -geometry). A smaller foreground image can be placed at specific coordinates over a larger canvas without altering the remaining canvas area.

The -evaluate-sequence Sum operator requires all images in the sequence to share identical dimensions. It executes a strict index-by-index matrix addition (\(Pixel_{x,y} = \sum Image_{i}[x,y]\)) and does not accommodate spatial translation offsets or localized placement.

Clipping and Dynamic Range

When using standard integer builds of ImageMagick (non-HDRI), both methods clip channel values that exceed QuantumRange (typically 255 for 8-bit or 65,535 for 16-bit), leading to pure white blown-out areas.

However, in HDRI (High Dynamic Range Imaging) environments, -evaluate-sequence Sum functions as an exact accumulator ideal for scientific computing, multi-exposure stacking, and noise reduction averaging, whereas standard compositing modes may still apply clamping or specialized Porter-Duff normalization depending on the chosen blend mode.
