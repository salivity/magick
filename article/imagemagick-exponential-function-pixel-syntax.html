ImageMagick Exponential Function Pixel Syntax

Evaluating exponential functions on floating-point pixel data in ImageMagick is typically achieved using either the -fx operator for complex expressions or the -evaluate operator for optimized single-operation execution. To ensure pixel values are processed as true floating-point values without integer truncation or clipping between 0 and 1, ImageMagick must be compiled with High Dynamic Range Imaging (HDRI) enabled, which is standard in ImageMagick 7.

Using the -fx Operator

The -fx operator interprets pixels as floating-point numbers normalized to the range [0.0, 1.0] (or beyond when HDRI is active). It supports standard mathematical expressions, including natural exponentiation (exp()) and power functions (pow() or ^).

To calculate the natural exponential (\(e^u\)) of each pixel:

magick input.exr -fx "exp(u)" output.exr

To calculate an arbitrary base or power (such as \(u^p\) or \(2^u\)):

# Raise pixel values to the power of 2.5
magick input.exr -fx "pow(u, 2.5)" output.exr

# Base-2 exponential
magick input.exr -fx "2^u" output.exr

In -fx, u refers to the primary input image pixel value. Calculations are evaluated per-channel and per-pixel in double precision.

Using the -evaluate Operator

The -evaluate operator is significantly faster than -fx because it executes compiled C routines rather than interpreting a custom expression string.

ImageMagick provides the Exp and Pow methods under -evaluate:

  • Exp: Multiplies the pixel value by the supplied constant and calculates the natural exponential. The mathematical formula applied is \(e^{(\text{value} \times \text{pixel})}\).
# Calculates e^(1.0 * pixel)
magick input.exr -evaluate Exp 1.0 output.exr
  • Pow: Raises the pixel value to the power of the specified exponent.
# Raises pixel values to the power of 2.2
magick input.exr -evaluate Pow 2.2 output.exr

HDRI and Value Scaling Considerations

Standard 8-bit or 16-bit non-HDRI builds will clamp pixel results exceeding standard ranges (QuantumRange) back to the maximum displayable integer. When working with mathematical functions like exp(), output values often grow rapidly. Using an HDRI-enabled version alongside floating-point formats such as .exr, .hdr, or 32-bit floating-point .tiff ensures that values greater than 1.0 or less than 0.0 remain unclamped and retain floating-point precision.
