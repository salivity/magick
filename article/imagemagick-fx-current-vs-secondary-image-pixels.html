ImageMagick -fx Current vs Secondary Image Pixels

The ImageMagick -fx operator enables complex, pixel-by-pixel mathematical evaluations across one or more images loaded into the current image sequence. When working with multi-image operations, -fx distinguishes between the primary image and subsequent images in the stack through predefined variable letters and index-based array notation. Understanding how to target these specific image layers, coordinates, and color channels is essential for precise multi-image synthesis and filtering.

Primary and Secondary Image Identifiers

By default, ImageMagick assigns letters to the first two images in the current image stack:

  • u: Represents the first image in the sequence (index 0).
  • v: Represents the second image in the sequence (index 1).

If you pass two images to ImageMagick, any reference to u pulls pixel data from the first image, while v pulls data from the second. For example, the expression -fx "(u + v) / 2" calculates the average intensity of the two images.

Numerical Index Notation for Larger Stacks

When working with more than two images in the sequence, letter variables become insufficient. ImageMagick uses zero-based array indexing to target any image in the stack:

  • u[0]: The first image (equivalent to u).
  • u[1]: The second image (equivalent to v).
  • u[2]: The third image in the stack.
  • u[n]: The n-th image in the sequence.

Negative indexes can also be used to reference images relative to the end of the stack, where u[-1] refers to the last loaded image.

Referencing Specific Pixel Coordinates

By default, referencing u or v evaluates the pixel at the current execution coordinate (x, y). To query pixels from alternate coordinates across images, append the .p[x, y] operator:

  • u.p[x, y]: The pixel value from the current/first image at absolute coordinates x and y.
  • v.p[x, y]: The pixel value from the secondary image at absolute coordinates x and y.
  • v.p[0, 0]: The top-left pixel of the secondary image, evaluated for every pixel position of the output.
  • u.p[-1, 0]: A relative offset addressing the neighboring pixel to the left within the current image.

Targeting Color Channels

Pixel references can be scoped down to individual color channels using channel suffixes. This applies to both the primary and secondary image references:

  • u.r, u.g, u.b: The red, green, and blue channel values of the primary image.
  • v.r, v.g, v.b: The red, green, and blue channel values of the secondary image.
  • v.a: The alpha channel value of the secondary image.

Combining coordinate lookups with channel selection follows the format v.p[x, y].r to extract a specific color channel from a specific pixel location on the secondary image.

Practical Example

To replace the red channel of a base image with the green channel of a secondary image:

magick base.png overlay.png -fx "channel(v.g, u.g, u.b)" output.png

In this command, base.png is assigned to u, and overlay.png is assigned to v. The expression explicitly routes the green channel of the secondary image into the red channel while retaining the primary image's original green and blue values.
