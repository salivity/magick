ImageMagick fx Operator: Custom Pixel Math Guide

The -fx operator in ImageMagick is a powerful image processing tool that allows users to apply arbitrary mathematical expressions to every pixel in an image. This guide explains how the -fx operator works, its core syntax and built-in variables, practical examples for manipulating pixel channels, and performance considerations when applying custom mathematical transformations.

What is the -fx Operator?

The -fx operator is an interpreted mathematical expression evaluator embedded directly within ImageMagick. Unlike standard operations (such as -brightness-contrast or -negate) that use pre-compiled, fixed algorithms, -fx calculates the value of each output pixel on the fly based on a user-defined mathematical formula.

Core Syntax and Concepts

In ImageMagick, the basic syntax for using the -fx operator is:

magick input.png -fx "expression" output.png

Normalized Color Values

The -fx engine operates in a normalized floating-point range from 0.0 (black/minimum) to 1.0 (white/maximum), regardless of whether the image is 8-bit, 16-bit, or uses high-dynamic-range (HDRI) color spaces.

Essential Built-in Variables

  • u: The primary (first) image in the current image list.
  • v: The secondary (second) image in the current image list.
  • r, g, b, a: The red, green, blue, and alpha channel values of the current pixel.
  • i, j: The current pixel's horizontal (x) and vertical (y) coordinates.
  • w, h: The width and height of the image in pixels.
  • p{x,y}: Look up the pixel value at a specific coordinate offset or absolute location.
  • u.p{x,y}: Look up a pixel specifically on image u.

Common Examples of Custom Pixel Math

1. Inverting an Image

To invert pixel values manually:

magick input.png -fx "1.0 - u" output.png

2. Custom Grayscale Conversion

Weight color channels manually using custom coefficients to compute luminance:

magick input.png -fx "0.299*r + 0.587*g + 0.114*b" output.png

3. Mathematical Coordinate Gradients

Create a horizontal gradient based on the ratio of the current pixel position (i) to the image width (w):

magick -size 256x256 xc:black -fx "i/w" gradient.png

4. Multi-Image Arithmetic (Blending)

Perform pixel-by-pixel multiplication between two images of the same dimensions:

magick base.png overlay.png -fx "u * v" multiplied.png

5. Conditional Logic

Apply expressions conditionally using the ternary operator (condition ? true_expr : false_expr):

magick input.png -fx "u > 0.5 ? 1.0 : 0.0" threshold.png

Performance Considerations

Because the -fx operator parses and evaluates expressions for every pixel (and often every channel) individually using an interpreter, it is significantly slower than native ImageMagick operations.

For batch processing or high-resolution images, consider native alternatives where possible:

  • Use -evaluate for uniform arithmetic operations across all pixels.
  • Use -compose along with -composite for multi-image blending.
  • Use color lookup tables (Hald CLUT) or polynomial color corrections (-poly) for faster execution.
