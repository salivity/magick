ImageMagick FX p{x,y} Pixel Query Explained

In ImageMagick’s -fx custom image processing operator, the p{x,y} symbol allows a developer to directly query the pixel value at specific spatial coordinates (x, y) rather than relying solely on the current pixel's location. This capability enables arbitrary pixel sampling across an image canvas, serving as the foundation for custom spatial convolutions, geometric distortion algorithms, and neighborhood-based filtering.

Anatomy of the p{x,y} Symbol

The ImageMagick -fx operator iterates through every pixel in a target image, running a mathematical formula to determine each pixel's new output value. Within this execution loop:

  • p represents the pixel data. By default, typing just p refers to the color or channel value of the pixel currently being evaluated at coordinate (i, j).
  • {x,y} serves as a coordinate lookup override. Enclosing an x (column) and y (row) coordinate within curly braces directs ImageMagick to fetch data from that exact canvas position instead of the current one.

Dynamic Sampling with i and j

While static coordinates like p{0,0} sample a fixed point (such as the top-left corner), developers frequently combine p{x,y} with the variables i (current horizontal index) and j (current vertical index). This allows relative neighborhood sampling:

  • p{i+1, j}: Queries the adjacent pixel immediately to the right.
  • p{i-1, j}: Queries the adjacent pixel immediately to the left.
  • p{i, j-1}: Queries the adjacent pixel immediately above.
  • p{i, j+1}: Queries the adjacent pixel immediately below.

Primary Use Cases

  1. Custom Convolution and Blurring: Developers can build custom spatial matrix operations by sampling neighboring pixels and computing weighted averages, such as (p{i-1,j} + p{i+1,j} + p{i,j-1} + p{i,j+1}) / 4.
  2. Edge Detection: Differential formulas, such as calculating horizontal gradients via abs(p{i+1,j} - p{i-1,j}), depend on querying offsets via p{x,y}.
  3. Geometric Warping and Displacement: Expressions can compute non-linear coordinate shifts, allowing dynamic lookups such as p{i + sin(j/10)*5, j} to create wave effects.

Channel Evaluation and Color Access

The value returned by p{x,y} depends on the active channel setting. When evaluating grayscale or single-channel targets, it returns a normalized floating-point number between 0.0 (black) and 1.0 (white). When working in multi-channel contexts, specific channel values can be appended directly to the query, such as p{x,y}.r for red, p{x,y}.g for green, p{x,y}.b for blue, or p{x,y}.a for alpha.

Handling Out-of-Bounds Coordinates

When calculated coordinates fall outside the boundaries of the image width w and height h, p{x,y} relies on the -virtual-pixel setting. Depending on whether the developer configures -virtual-pixel edge, mirror, tile, or background, ImageMagick automatically determines what value p{x,y} returns for non-existent image coordinates.
