ImageMagick -fx Variable V and Vertical Coordinates

In ImageMagick’s -fx DIY operator, the symbol v does not natively represent vertical coordinates on its own; instead, it designates the second image in the current image sequence, while coordinates are defined by i (horizontal) and j (vertical). However, in image processing and UV coordinate conventions, developers often use v to represent vertical subpixel positions across a canvas. Understanding how ImageMagick evaluates these positions requires examining the distinction between image references, floating-point coordinate lookups, and subpixel interpolation.

The Role of v in ImageMagick -fx

In standard ImageMagick -fx syntax:

  • u refers to the primary image (index 0).
  • v refers to the secondary image (index 1).
  • i represents the current column index (horizontal pixel coordinate, from 0 to w - 1).
  • j represents the current row index (vertical pixel coordinate, from 0 to h - 1).

When developers work with displacement maps, distortion grids, or UV mapping, the secondary canvas (v) often stores vertical or horizontal offset data. In these pipelines, values stored in canvas v dictate the vertical subpixel shifts applied to canvas u.

Mapping Vertical Subpixel Positions

Subpixel precision occurs when a coordinate calculation results in a non-integer floating-point value. While the canvas grid consists of discrete integer pixels, the -fx engine allows addressing arbitrary floating-point positions using the syntax:

v.p{x, y}

In this expression:

  • x is the horizontal coordinate across canvas v.
  • y is the vertical coordinate across canvas v.

Because y can be a floating-point number (such as j + 0.35 or a normalized scale (j / (h - 1)) * (v.h - 1)), it targets a location between physical pixel centers.

When mapping vertical UV coordinates, the normalized vertical coordinate is traditionally calculated as:

v_coord = j / (h - 1)

This scales the vertical span of the canvas continuously from 0.0 at the top edge to 1.0 at the bottom edge. When multiplied back by canvas height dimensions, it allows precise subpixel addressing.

Subpixel Interpolation Mechanics

When evaluating a vertical position between discrete pixel rows, ImageMagick does not truncate the decimal. Instead, the pixel value returned at subpixel coordinate y depends on the active interpolation algorithm defined by the -interpolate setting.

Common interpolation methods include:

  • Average / Bilinear: Calculates a weighted linear blend of the adjacent vertical rows based on the fractional distance of y.
  • Bicubic / Catmull-Rom: Samples a 4x4 neighborhood to fit a cubic spline, providing smooth vertical transitions across gradients.
  • Nearest: Rounds to the nearest discrete pixel center, effectively discarding subpixel accuracy.
  • Spline: Uses higher-order polynomials to prevent aliasing during fractional vertical shifts.

Example: Vertical Subpixel Displacement

A common implementation uses image v as a continuous vertical vector map to displace image u by fractional amounts:

magick input.png map.png -interpolate Bilinear -fx "u.p{i, j + (v.p{i, j} - 0.5) * 10}" output.png

In this calculation:

  1. v.p{i, j} fetches the intensity value of the second canvas at the current integer coordinate.
  2. Subtracting 0.5 centers the shift direction (negative values shift upward, positive values shift downward).
  3. The resulting offset added to j creates a floating-point vertical coordinate.
  4. The -interpolate Bilinear filter samples the surrounding vertical pixels on image u to construct the subpixel rendering.
