ImageMagick Geometry Evaluation With Unknown Dimensions

This article explains how ImageMagick resolves geometry specifications when the dimensions of the input image are not known in advance. It covers the two-stage parsing mechanism, how partial geometry strings (such as omitted widths or heights) are calculated against image metadata, and how ImageMagick defers execution until real image boundaries are decoded.

Two-Stage Evaluation: Parsing vs. Execution

ImageMagick treats command-line arguments and script operations through a deferred pipeline. When a command such as -resize, -crop, or -extent receives a geometry string, ImageMagick does not immediately attempt to resolve pixel values. Instead, it processes the request in two distinct phases:

  1. Geometry String Parsing: ImageMagick parses the string into an internal data structure (such as GeometryInfo). It breaks the string down into numeric components (width, height, x, y) and bitwise flags representing modifiers (e.g., %, !, <, >, ^). At this stage, no source image needs to be present in memory.
  2. Contextual Evaluation: The parsed geometry is evaluated only when an active image frame is loaded into memory and passed through the processing pipeline. ImageMagick calls functions like ParseMetaGeometry() or GetImageGeometry() using the target image's actual pixel attributes (image->columns and image->rows).

Handling Omitted Dimensions

When a geometry argument omits either the width or height, ImageMagick calculates the missing value dynamically to preserve the image's original aspect ratio.

  • Width specified, height omitted (800 or 800x): ImageMagick sets the target width to 800 and computes the target height as: \[\text{Target Height} = \text{round}\left(800 \times \frac{\text{image->rows}}{\text{image->columns}}\right)\]
  • Height specified, width omitted (x600): ImageMagick sets the target height to 600 and computes the target width as: \[\text{Target Width} = \text{round}\left(600 \times \frac{\text{image->columns}}{\text{image->rows}}\right)\]

If an offset is provided without dimensions (e.g., +10+20), the original image width and height are preserved entirely, and only the offset attributes are applied.

Resolving Percentages and Relative Dimensions

When a percentage symbol (%) is present in the geometry string:

  • ImageMagick does not compute a fixed pixel size during argument parsing.
  • Upon loading the image header, it multiplies the percentage by image->columns for width and image->rows for height.
  • If a single percentage is provided (e.g., 50%), it is applied uniformly to both axes. If two are provided (e.g., 50x75%), each axis scales independently.

Applying Modifiers to Dynamic Dimensions

ImageMagick geometry modifiers alter how unknown dimensions resolve against target boundaries:

  • Aspect Ratio Preservation (Default): The image is scaled to fit entirely within the specified bounding box without exceeding either dimension.
  • Ignore Aspect Ratio (!): Both dimensions are explicitly forced to the provided parameters. If one dimension is omitted, it defaults to the image's existing dimension rather than scaling proportionally.
  • Fill Area (^): The image scales so that the smaller dimension reaches its target bound, causing the larger dimension to exceed the target bound if necessary.
  • Conditional Scaling (> and <): ImageMagick checks image->columns and image->rows against the target bounds. With >, the calculation is skipped if the input is smaller than the target. With <, the calculation is skipped if the input is larger.

Streamed and Piped Inputs

When input arrives from a standard input stream (stdin) or an unseekable pipe, dimension headers are read sequentially before any geometry calculations occur. ImageMagick decodes the stream header to construct the canvas metadata, ensuring that relative geometry attributes are always computed against concrete pixel measurements before allocating pixel caches for the actual transformation.
