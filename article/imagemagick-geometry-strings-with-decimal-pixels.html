ImageMagick Geometry Strings with Decimal Pixels

In ImageMagick, geometry strings define dimensions, offsets, and scaling factors for image operations such as resizing, cropping, and positioning. While digital raster images consist of discrete, whole-pixel grids, ImageMagick accepts decimal (floating-point) values within its geometry arguments. This article explains how ImageMagick parses decimal geometry values, how different operators handle fractional pixels, and the practical effects on the final rendered output.

How ImageMagick Parses Decimal Values

ImageMagick's internal geometry parser reads input values as standard double-precision floating-point numbers. When you supply a string such as 150.5x100.25+10.75+20.2, the parser reads the entire floating-point number rather than truncating it at the decimal point during the initial parsing phase.

The interpretation of those decimals depends entirely on the operator processing the geometry.

Behavior in Resizing Operations

When applied to scaling operators like -resize, -thumbnail, or -adaptive-resize, decimal values influence the mathematical calculation of the target size:

  • Percentage Scaling: A geometry string like -resize 33.333% evaluates the fractional scale directly against the source dimensions.
  • Explicit Dimensions: Using fractional target dimensions (such as -resize 400.6x300.2) causes ImageMagick to calculate the target bounding box using the decimal numbers.

Because raster output cannot have a fractional width or height, the final dimensions are rounded to the nearest whole integer pixel (typically using standard rounding: values with fractional parts equal to or greater than 0.5 round up).

Behavior in Cropping and Offsets

When used with -crop, -extent, or canvas offsets, fractional values interact with the discrete pixel grid:

  • Dimensions: A crop size like -crop 100.5x100.5 rounds to integer dimensions (101x101) before cutting the image, because standard raster buffers cannot hold half a pixel.
  • Offsets: Offsets like +12.4+15.8 are converted to integer offsets (rounding to +12+16). Standard cropping operations snap strictly to the nearest integer coordinate on the pixel grid.

Decimal offsets in standard geometry strings do not trigger subpixel sampling, interpolation, or anti-aliasing.

True Subpixel Operations vs. Geometry Rounding

It is important to distinguish between geometry string rounding and true subpixel manipulation:

  • Standard Geometry Operators (-crop, -extent): These operate strictly on integer boundaries. Decimal inputs are rounded before execution, meaning fractional precision is effectively discarded at the grid level.
  • Distortion Operators (-distort, -affine): These operators do not use standard geometry strings in the same manner; they evaluate floating-point coordinates with interpolation filters (such as bilinear, bicubic, or Lanczos), calculating weighted pixel averages to produce anti-aliased, fractional-offset results.

Summary of Practical Effects

  1. Calculations Maintain Precision Before Rasterization: Decimals in percentage-based scaling strings allow for precise ratio calculations before final rounding.
  2. Output Snaps to Whole Pixels: Raster dimensions always round to the nearest whole integer.
  3. No Automatic Anti-Aliasing for Offsets: Fractional offsets in -crop or -page will not shift the image by a fraction of a pixel with interpolation; they simply round to the nearest whole pixel offset.
