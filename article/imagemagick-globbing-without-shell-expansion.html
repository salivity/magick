ImageMagick Globbing Without Shell Expansion

On operating systems that lack native command-line wildcard expansion, ImageMagick relies on its own internal file-globbing engine to locate and process multi-file inputs. While POSIX shells automatically resolve patterns like *.jpg before handing the argument list to an application, systems like Windows pass the unexpanded pattern directly. ImageMagick detects these wildcard literals and systematically expands them using native operating system directory enumeration APIs, ensuring consistent cross-platform batch-processing behavior.

Shell-Level vs. Application-Level Expansion

In a typical Unix environment, the shell (such as Bash or Zsh) performs filename generation (globbing). By the time ImageMagick's entry point (magick or legacy convert) receives the arguments via argv, the wildcards have already been replaced with a complete list of matching file paths.

On platforms like Windows, shells such as cmd.exe do not expand wildcard characters (*, ?, []). Instead, the executable receives the raw, unexpanded argument string (for example, input_*.png). If an application does not natively support pattern matching, it attempts to open the literal file name and fails.

ImageMagick's Internal Globbing Engine

To resolve this limitation, ImageMagick implements platform-specific fallback routines inside its core library (MagickCore):

  1. Pattern Detection: When parsing input filenames, ImageMagick inspects argument tokens for standard globbing characters, specifically asterisks (*), question marks (?), and brackets ([...]).
  2. Directory Traversal: Once a wildcard is identified, ImageMagick isolates the base directory path from the search pattern.
  3. API Enumeration: On Windows, it invokes low-level Win32 file-searching APIs—primarily FindFirstFile, FindNextFile, and FindClose. On other platforms lacking shell assistance, it uses POSIX directory functions like opendir() and readdir() combined with internal pattern-matching logic.
  4. List Construction: As matching file entries are located, ImageMagick sorts them alphanumerically and appends each valid file path to an internal image sequence queue.

Quoting Patterns on Non-Expanding Shells

Because Windows does not strip unquoted wildcards, passing patterns without quotes can occasionally lead to unexpected behavior if third-party shells (like PowerShell) or utilities partially intercept the characters.

To ensure ImageMagick handles the globbing internally on Windows:

  • Enclose the path pattern in standard double quotes: 
    magick "frames_*.png" output.gif
  • For subdirectories, relative and absolute paths are preserved during enumeration: 
    magick "C:\images\scan_???.tif" -resize 50% "C:\processed\output_%03d.tif"

Handling Explicit Filename Formats

When an input string could be ambiguous—such as containing both wildcard characters and ImageMagick-specific format specifiers or bracketed frame ranges (e.g., image_*.png[0])—ImageMagick separates the sub-image selector before evaluating the wildcard. The glob engine scans the file system for paths matching image_*.png, and subsequent operations extract frame [0] from each resolved file individually.
