ImageMagick Hough Circle Detection Guide

This guide explains how to identify and extract circular shapes from images using ImageMagick’s built-in Hough transform algorithm. By combining edge detection filters with the -hough-analyze operator, you can detect circles of specified radii and output their exact coordinates or overlay them visually onto your source image.

Understanding the Hough Circle Transform

The Hough transform is a feature extraction technique used in digital image processing to detect simple shapes, such as lines and circles. For circles, the algorithm maps edge pixels into an accumulator space corresponding to the circle equation:

\[(x - a)^2 + (y - b)^2 = r^2\]

Where (a, b) represents the center coordinate and r represents the radius. Peak values within the accumulator space represent the most probable circles.

Prerequisites and Preprocessing

The Hough transform requires a binary edge map to operate accurately. Feeding a raw, full-color image directly into the analyzer will cause false positives and poor performance.

  1. Convert to Grayscale: Removes color data to isolate luminance.
  2. Apply Edge Detection: ImageMagick’s Canny edge detector (-canny) generates clean, single-pixel-wide outlines required for the accumulator.

Basic Command Structure

ImageMagick utilizes the -hough-analyze operator alongside the -define hough-analyze:object=circle setting to search for circles rather than lines.

The geometry string for circle detection uses the following format:

-hough-analyze <min_radius>x<max_radius>+<threshold>
  • min_radius: The minimum circle radius in pixels to search for.
  • max_radius: The maximum circle radius in pixels to search for.
  • threshold: The minimum number of accumulator votes needed to register a detected circle. Higher values prevent false positives; lower values detect fainter or partial circles.

Step-by-Step Implementation

1. Detect and Draw Circles Directly on the Image

To visually highlight detected circles on your image:

magick input.png \
  -colorspace Gray \
  -canny 0x1+10%+30% \
  -define hough-analyze:object=circle \
  -hough-analyze 20x50+40 \
  output.png

In this command:

  • -canny 0x1+10%+30% isolates the edges.
  • -hough-analyze 20x50+40 searches for circles with a radius between 20 and 50 pixels that match or exceed an accumulator threshold of 40.
  • The output image replaces the canvas with a vector representation (drawn red circles) identifying the located features.

2. Overlay Circles onto the Original Image

To preserve the original image and draw the detected circles as an overlay:

magick input.png \
  \( +clone -canny 0x1+10%+30% \
     -define hough-analyze:object=circle \
     -hough-analyze 20x50+40 \
     -transparent black \) \
  -compose Over -composite detected_circles.png

This uses image cloning to run edge detection and Hough analysis on a secondary layer, makes non-circle areas transparent, and layers the resulting circles directly onto the original image.

3. Extracting Numeric Coordinates

If you require the coordinates (x, y, radius) for downstream automation rather than an image output, format the output to a text file:

magick input.png \
  -canny 0x1+10%+30% \
  -define hough-analyze:object=circle \
  -hough-analyze 20x50+40 \
  circles.mvg

The resulting .mvg (Magick Vector Graphics) file contains plain-text vector draw commands such as:

circle 124,156 124,186

In MVG syntax, circle x1,y1 x2,y2 defines a circle centered at (x1, y1) where the perimeter passes through (x2, y2). The radius is the Euclidean distance between these two points:

\[r = \sqrt{(x_2 - x_1)^2 + (y_2 - y_1)^2}\]

Fine-Tuning Detection

  • Reduce Noise: If the algorithm detects too many false circles, increase the threshold value (e.g., from +40 to +60) or raise the lower percentage bound in the -canny operator.
  • Narrow the Radius Range: Broad search windows (e.g., 10x200) require significant computational time and memory. Narrow the radius range as closely as possible to the expected circle sizes.
