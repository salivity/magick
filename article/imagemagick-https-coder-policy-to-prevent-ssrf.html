ImageMagick HTTPS Coder Policy to Prevent SSRF

ImageMagick provides robust security configuration through its security policy file to mitigate Server-Side Request Forgery (SSRF) and remote execution vulnerabilities. To prevent SSRF attacks, the ImageMagick policy disables the HTTPS (and related HTTP) coder by revoking its execution rights. This prevents the utility from performing outbound network calls when processing image files with remote resource references.

By default, ImageMagick includes built-in support for delegates and coders that can fetch remote images or external resources defined via URLs (such as in SVG, MVG, or MSL files). If an application accepts untrusted image uploads or input strings, an attacker can supply a payload referencing internal network addresses or cloud metadata endpoints (e.g., http://169.254.169.254/). ImageMagick would then attempt to resolve and retrieve these assets from the internal infrastructure, leading to SSRF.

To neutralize this attack vector, administrators configure ImageMagick's policy.xml file to restrict URL-handling delegates and coders. Specifically, the policy disables read and write permissions by setting the rights attribute to "none" for the HTTPS coder domain:

<policymap>
  <policy domain="coder" rights="none" pattern="HTTPS" />
</policymap>

When this policy is enforced, ImageMagick completely blocks the initialization and execution of the HTTPS handler:

  • Blocks Network Fetching: Any attempt by ImageMagick or underlying external delegates (such as curl or wget) to establish an HTTPS connection is rejected immediately.
  • Neutralizes Embedded References: If an input file (such as an SVG containing an <image xlink:href="https://..."> tag) attempts to load remote data, the operation fails before a network socket is created.
  • Stops Protocol Smuggling and Exfiltration: Disabling the coder stops attackers from using image transformations to exfiltrate sensitive local data through crafted HTTPS requests.

For comprehensive protection against SSRF, security best practices recommend disabling all URL-related coders alongside HTTPS, including HTTP, FTP, and URL, as well as file-inclusion coders such as MSL and MVG.
