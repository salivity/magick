ImageMagick Image Moments for Object Classification

This article provides an overview of how ImageMagick extracts image moments to classify shapes and objects within digital images. It examines the computational pipeline used by ImageMagick, moving from raw spatial moments to translation-, scale-, and rotation-invariant Hu moments. By understanding how pixel intensities are transformed into compact numerical descriptors, you can effectively use ImageMagick's moment calculations as feature vectors for computer vision and object classification tasks.

Pixel Intensity as a Distribution Function

ImageMagick treats a digital image as a two-dimensional continuous function \(f(x, y)\), where \(x\) and \(y\) represent spatial coordinates and \(f(x, y)\) represents the pixel intensity or brightness at that point. To extract quantitative descriptions of shapes, ImageMagick evaluates statistical moments over the image plane, transforming pixel distributions into geometric features.

The Calculation Pipeline

When invoking the -moments operator in ImageMagick (or through its C API function GetImageMoments()), the software executes a deterministic pipeline across several mathematical stages:

1. Spatial (Raw) Moments

The calculation begins with raw polynomial moments, denoted as \(M_{ij}\):

\[M_{ij} = \sum_{x} \sum_{y} x^i y^j f(x, y)\]

Here, \(i\) and \(j\) define the order of the moment:

  • \(M_{00}\): The zeroth-order moment represents the total intensity (or area/mass) of the object.
  • \(M_{10}\) and \(M_{01}\): The first-order moments provide structural orientation along the coordinate axes.

From these, ImageMagick calculates the object's centroid (center of mass): \[\bar{x} = \frac{M_{10}}{M_{00}}, \quad \bar{y} = \frac{M_{01}}{M_{00}}\]

2. Central Moments

To ensure the descriptors do not change when an object moves within the frame, ImageMagick computes central moments (\(\mu_{ij}\)) relative to the centroid:

\[\mu_{ij} = \sum_{x} \sum_{y} (x - \bar{x})^i (y - \bar{y})^j f(x, y)\]

By centering the coordinates around \((\bar{x}, \bar{y})\), the resulting values become invariant to translation.

3. Normalized Central Moments

To account for changes in scale (such as an object appearing closer or farther from the camera), ImageMagick normalizes the central moments:

\[\eta_{ij} = \frac{\mu_{ij}}{\mu_{00}^{\gamma}}\]

Where the scaling factor exponent is defined as: \[\gamma = \frac{i + j}{2} + 1 \quad \text{for } (i + j) \ge 2\]

This normalization step produces numbers that remain constant even if the image is resized or the object changes in area.

4. Hu Invariant Moments

For robust classification, descriptors must also tolerate arbitrary rotation. ImageMagick computes the classic set of seven Hu Invariant Moments (\(I_1\) through \(I_7\)), derived from combinations of second- and third-order normalized central moments:

  • \(I_1\) and \(I_2\): Capture spread and basic eccentricity.
  • \(I_3\) and \(I_4\): Measure skewness and asymmetry.
  • \(I_5\), \(I_6\), and \(I_7\): Distinguish complex asymmetries and mirror images (reflection invariance).

Because Hu moments can span multiple orders of magnitude, ImageMagick often outputs them in logarithmic form to make comparisons numerically stable.

Multi-Channel Moment Evaluation

ImageMagick evaluates image moments independently across each color channel (such as Red, Green, Blue, or Alpha) as well as an aggregated intensity/grayscale channel. For color-based classification, this provides channel-specific shape signatures, allowing classifiers to differentiate objects that share identical geometric outlines but differ in spectral distribution.

Utilization in Object Classification

Once ImageMagick extracts these invariant values, they serve as a lightweight feature vector:

  1. Feature Vector Assembly: The seven Hu moments (optionally multiplied across color channels) form a low-dimensional numerical array representing the target object.
  2. Dimensionality Reduction: Instead of comparing thousands of raw pixels, classifiers process a small set of rotation- and scale-invariant floats.
  3. Classification Matching: These vectors are fed into classification algorithms—such as k-Nearest Neighbors (k-NN), Support Vector Machines (SVM), or basic Euclidean distance matchers—to categorize the object against a pre-indexed database of known shape signatures.
