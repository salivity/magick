ImageMagick Laplacian of Gaussian Edge Detection

This article provides an overview of how ImageMagick implements Laplacian of Gaussian (LoG) edge detection. It covers the underlying mathematical principles, how ImageMagick utilizes kernel convolution through its morphology engine, the Difference of Gaussians (DoG) approximation, and the specific command-line parameters required to process edges and manage zero-crossing intensity ranges.

The LoG Algorithm Concept

Laplacian of Gaussian (LoG) is a two-step edge detection method combined into a single convolution operation:

  1. Gaussian Smoothing: Filters out high-frequency noise from an image.
  2. Laplacian Operator: Calculates the second spatial derivative of the smoothed image to identify areas of rapid intensity change.

Edges appear at "zero-crossings," where the second derivative changes sign from positive to negative.

Kernel Generation in ImageMagick

ImageMagick implements LoG through its morphology convolution engine (-morphology Convolve). When a user requests a LoG kernel, ImageMagick dynamically generates a discretized, circularly symmetric Mexican Hat kernel using the formula:

\[\text{LoG}(x, y) = -\frac{1}{\pi \sigma^4} \left( 1 - \frac{x^2 + y^2}{2\sigma^2} \right) e^{-\frac{x^2 + y^2}{2\sigma^2}}\]

In the CLI, the kernel is defined as LoG:radius,sigma. If radius is set to 0, ImageMagick automatically computes a radius of approximately \(3 \times \sigma\) to ensure the kernel covers the full bell-curve distribution.

magick input.png -morphology Convolve "LoG:0,1.5" output.png

Difference of Gaussians (DoG) Approximation

Because true LoG calculations can be computationally intensive, ImageMagick also provides a Difference of Gaussians (DoG) kernel. DoG approximates the LoG operator by subtracting one Gaussian-blurred version of the image from another with a different standard deviation (\(\sigma_1\) and \(\sigma_2\)):

magick input.png -morphology Convolve "DoG:0,1.0,2.0" output.png

ImageMagick implements DoG internally by calculating two Gaussian matrices, subtracting the second from the first, and normalizing the matrix sum to zero.

Handling Negative Values and Zero-Crossings

Because the Laplacian represents a second derivative, convolution generates both positive and negative values:

  • Zero-Crossings: Represent true edge locations.
  • Quantum Range Management: Since standard image formats (like PNG or JPEG) cannot store negative numbers, ImageMagick biases the convolution output. A value of zero in the derivative is mapped to the mid-point of the color quantum depth (50% gray), positive derivatives become brighter, and negative derivatives become darker.

To isolate true edges from this output, a high-pass threshold or zero-crossing edge detector is typically chained after the convolution:

magick input.png -morphology Convolve "LoG:0,1.5" -auto-level -threshold 50% output.png
