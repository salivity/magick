ImageMagick Log Colorspace Conversion Explained

ImageMagick provides native mechanisms and profile-driven workflows to convert linear and standard RGB imagery into logarithmic representations suitable for film production. This article explains how ImageMagick processes logarithmic transformations, the distinction between its generic mathematical log conversion and industry-standard film log curves (such as Cineon or modern camera log profiles), and how to achieve accurate conversions using built-in operators, DPX/Cineon handlers, and Lookup Tables (LUTs).

The Native -colorspace Log Transformation

ImageMagick includes a built-in -colorspace Log operator designed to remap pixel values along a logarithmic scale. When invoked, ImageMagick transforms the input pixel values using a standardized mathematical formula:

\[\text{Output} = \frac{\log(\text{Input} \times (\text{scale} - 1) + 1)}{\log(\text{scale})}\]

In this formula, pixel values are normalized to a 0.0–1.0 quantum range. This transformation redistributes dynamic range by allocating more bits to low-light values (shadows) and compressing highlights. While useful for general dynamic range compression and scientific imaging, this generic mathematical logarithmic curve does not directly correspond to proprietary digital cinema profiles such as ARRI LogC, Sony S-Log3, or REDLogFilm.

Handling Standard Cineon and DPX Film Curves

Historically, film log workflows revolved around the Kodak Cineon specification, which became the basis for the SMPTE DPX standard. ImageMagick includes built-in support for Cineon and DPX file formats and automatically manages their specific 10-bit logarithmic curves.

When ImageMagick decodes a native .cin or 10-bit .dpx file set to film log:

  1. It recognizes standard Cineon metadata (reference black at code value 95, reference white at 685, and a maximum code value of 1023).
  2. It converts the logarithmic data into linear color values internally by applying the inverse Cineon formula:

\[\text{Linear} = 10^{\frac{\text{DPX} - \text{RefWhite}}{\text{DensityPerCodeValue} \times \text{Gamma}}}\]

  1. When converting back from linear space to Cineon/DPX log space, ImageMagick applies the direct Cineon transformation, ensuring code values match traditional film exposure densities.

Manual Film Curve Adjustments with Operators

When fine-tuning log conversions without explicit format drivers, ImageMagick allows operators to simulate specific film log shoulders and toes:

  • -evaluate Log [value]: Scales the pixel data using a direct logarithmic multiplier.
  • -gamma [value]: Adjusts the midtones to align the mid-gray target (typically 18% reflective gray, mapped to ~38–40% in most film log profiles).
  • -fx [expression]: Permits custom mathematical formulas per-channel, allowing users to enter custom transfer equations (such as ITU-R BT.709 to Log formulas) directly at the cost of processing speed.

Advanced Film Log Conversions via HALD CLUT and ICC Profiles

Modern production pipelines rarely rely on single-equation log spaces. Camera manufacturers utilize specific piecewise functions containing linear segments in deep shadows to prevent sensor noise amplification, paired with precise logarithmic compression in the highlights.

Because ImageMagick's native -colorspace Log is purely mathematical, the software handles production-grade camera log transformations via color lookup tables (LUTs) or ICC profiles:

  1. LittleCMS and ICC Profiles: By compiling ImageMagick with LittleCMS support, users can map between linear/sRGB and log profiles using the -profile command.
  2. Hald CLUT Processing: For arbitrary film log curves like LogC3/4 or ACEScc/ACEScct, ImageMagick uses 3D LUTs converted into Hald CLUT identity images. Running magick input.exr identity_log.png -hald-clut output.dpx allows ImageMagick to translate linear high-dynamic-range image data into exact target film curves with zero mathematical deviation.
