ImageMagick Mesh Interpolation Coordinate Mapping

Mesh interpolation in ImageMagick is a resampling method used during geometric distortions, displacement maps, and coordinate transformations to reconstruct pixel values from non-integer coordinate locations. This guide explains how to enable and configure the Mesh interpolation setting in ImageMagick, how it handles coordinate mapping, and how to apply it across distortions and coordinate-based image operations.

Understanding Mesh Interpolation

When ImageMagick maps coordinates from a source image to a destination image—such as during affine transforms, perspective shifts, or custom coordinate displacements—it frequently lands on non-integer sub-pixel coordinates.

The Mesh interpolation method handles these coordinates by dividing each four-pixel grid cell (a 2x2 square of neighboring pixels) into two triangles along a diagonal. ImageMagick determines which triangle the target coordinate falls into and performs barycentric interpolation between the three vertices of that triangle. This results in a continuous surface with smooth transitions, often preserving edge definitions better than standard bilinear interpolation without introducing the ringing artifacts of higher-order methods like bicubic or spline.

Setting the Interpolate Method

To use mesh interpolation, set the -interpolate setting to Mesh before calling an operation that maps coordinates:

magick input.jpg -interpolate Mesh -distort Perspective "..." output.jpg

For ImageMagick version 6 legacy installations, replace magick with convert:

convert input.jpg -interpolate Mesh -distort Perspective "..." output.jpg

Applying Mesh Interpolation to Geometric Distortions

The primary use case for coordinate interpolation is the -distort operator. When applying transformations such as Affine, Perspective, or BilinearForward, ImageMagick uses the configured interpolation mode whenever pixel lookup requires continuous coordinate mapping:

magick input.jpg -interpolate Mesh \
  -distort Affine "0,0 10,15   100,0 120,5   0,100 5,90" \
  output.jpg

Unlike the default Resample filter mechanism, which utilizes EWA (Elliptical Weighted Average) filtering when downscaling, -interpolate directly determines how individual point lookups behave when resampling is turned off or bypassed (such as during polar distortions, polynomial mappings, or upscaling).

To force ImageMagick to rely exclusively on the -interpolate Mesh algorithm rather than EWA area resampling during a distortion, disable filtering using +filter:

magick input.jpg +filter -interpolate Mesh \
  -distort Perspective "0,0 20,10  200,0 180,25  0,200 15,190  200,200 185,175" \
  output.jpg

Coordinate Mapping with Displacement Maps

Mesh interpolation can also be configured when mapping pixels via displacement or vector coordinate maps using -compose Displace or absolute distortion grids.

When using a two-channel mapping image representing absolute X and Y target coordinates:

magick input.jpg coordinates.png +filter -interpolate Mesh \
  -compose Displace -set option:compose:args 20x20 -composite \
  output.jpg

In this pipeline, every mapped coordinate directed by coordinates.png references the source input.jpg using the triangular mesh interpolation scheme.

Practical Considerations

  • Artifact Reduction: Mesh interpolation avoids the overshoot (ringing or halos) that can occur with Cubic, Catrom, or Lanczos interpolations, making it ideal for mapped data containing high-contrast borders or raw data maps.
  • Sharpness: It produces slightly sharper diagonal transitions than Bilinear interpolation, though it may introduce subtle directional bias along the chosen triangulation diagonal.
  • Performance: Mesh requires minimal computational overhead—only evaluating three vertices instead of four (bilinear) or sixteen (bicubic)—making it fast for per-pixel coordinate lookups.
