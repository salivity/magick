ImageMagick MVG and MSL Security Risks Explained

Disabling the Magick Vector Graphics (MVG) and Magick Scripting Language (MSL) coders in ImageMagick's policy.xml is a critical hardening measure that prevents severe security vulnerabilities, including Remote Code Execution (RCE), arbitrary file read/write operations, and Server-Side Request Forgery (SSRF). Because both formats function as functional scripting languages rather than static image containers, restricting them removes complex processing surfaces that attackers frequently exploit when applications process user-supplied media.

Remote Code Execution (RCE)

The most severe threat mitigated by disabling MVG is command injection leading to RCE. MVG processes text-based vector drawing commands and historically allowed processing directives that could trigger external delegate programs. This was the primary vector behind the critical "ImageTragick" vulnerability (CVE-2016-3714), where shell meta-characters embedded in MVG drawing commands—such as fill 'url(https://example.com/image.jpg"|ls "-la)'—were executed by system shells during delegate invocations. Disabling MVG ensures these rendering instructions are entirely ignored.

Arbitrary File Read and Information Disclosure

Both MVG and MSL possess capabilities to include external content. In MVG, primitives like image over 0,0 0,0 'label:@/etc/passwd' force ImageMagick to read local files and render their contents directly onto the generated image canvas. This allows attackers to exfiltrate sensitive configuration files, system credentials, or source code. Disabling these coders blocks ImageMagick from interpreting file-inclusion directives inside image files.

Arbitrary File Write

MSL is an XML-based scripting language designed to automate ImageMagick tasks, including reading, transforming, and writing files. If an attacker can upload an arbitrary file containing MSL commands and trigger ImageMagick to process it (often via the MSL coder), they can instruct ImageMagick to write output anywhere the host process has write permissions using tags like <write filename="/var/www/html/shell.php" />. This makes MSL an ideal mechanism for dropping web shells. Disabling MSL eliminates this arbitrary output generation.

Server-Side Request Forgery (SSRF)

MVG commands can reference external URLs to fetch remote assets using protocols like HTTP, HTTPS, or FTP. When ImageMagick processes an MVG file containing remote resource paths, the server makes outbound network calls. Attackers leverage this behavior to scan internal networks, interact with local cloud metadata endpoints (e.g., http://169.254.169.254), and bypass firewall perimeters.

Implementation in policy.xml

These vectors are mitigated by adding explicit domain policies to the system's policy.xml file, which completely stops the parser from invoking the vulnerable coders:

<policymap>
  <policy domain="coder" rights="none" pattern="MVG" />
  <policy domain="coder" rights="none" pattern="MSL" />
</policymap>

By disallowing these coders, ImageMagick will immediately reject any file identified as MVG or MSL before parsing its directives, neutralizing the attack chain regardless of file extension masking.
