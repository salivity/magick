ImageMagick -page Operator PostScript Geometry

This article provides a concise guide to how ImageMagick's -page operator defines virtual page geometry for PostScript and PDF workflows. It covers the underlying geometry syntax, explains the relationship between virtual canvases and physical dimensions, and illustrates how coordinate offsets position rasterized images within standard or custom PostScript page layouts.

What is Virtual Page Geometry?

In ImageMagick, "virtual page geometry" refers to the overall canvas dimensions and the relative placement coordinates of an image within that canvas. While formats like PNG or JPEG focus primarily on pixel dimensions, document and vector-oriented formats like PostScript (PS, EPS) and PDF require layout metadata.

The -page operator establishes this layout by specifying:

  1. The Page Size (Canvas): The total printable or viewable boundary (such as Letter, A4, or custom point sizes).
  2. The Offsets: The horizontal and vertical position where the image data will be placed on that designated page.

The Syntax of the -page Operator

The -page operator uses standard ImageMagick geometry syntax:

-page widthxheight{+-}x{+-}y
  • widthxheight: Defines the virtual page size. By default, PostScript interprets these units in typographical points (1/72 of an inch). Alternatively, predefined media names like letter, legal, or a4 can be used.
  • {+-}x{+-}y: Defines the horizontal (x) and vertical (y) offsets from the origin.

For example:

magick input.jpg -page A4+36+36 output.ps

This instructs ImageMagick to set the PostScript bounding dimensions to standard A4 paper size, placing the image with a 0.5-inch (36 points) margin from the top/left boundary depending on the rendering coordinate system.

Coordinate Systems in PostScript

PostScript natively places its origin (0,0) at the lower-left corner, measuring dimensions upward and to the right in points. ImageMagick generally uses an upper-left origin for digital raster manipulation.

When generating PostScript via the -page operator:

  • ImageMagick automatically converts the provided offsets into the PostScript coordinate system.
  • The image's location on the page is written into the PostScript stream using standard operators such as translate and scale.
  • The overall canvas size specified in -page writes the %%BoundingBox header comments (e.g., %%BoundingBox: 0 0 612 792 for Letter size) which PostScript interpreters rely on to clip or scale the output for printing.

Differences Between -page and Other Sizing Operators

  • -page vs. -size: -size defines the dimensions of a raw image being read into memory. -page defines the metadata container dimensions (the sheet of paper) in which the image resides.
  • -page vs. -crop / -repage: When cropping images, ImageMagick preserves the original virtual canvas as page offsets unless reset by +repage. When exporting to PostScript, those residual offsets are translated directly into positions on the printed page unless explicitly overwritten by a new -page specification.

Practical Impact on Output

Using the -page operator ensures that an image is properly scaled or placed without altering its source aspect ratio or native pixel density. By controlling the virtual canvas, you prevent default behavior where ImageMagick might otherwise wrap the PostScript bounding box tightly around the raw pixel dimensions, ensuring consistent margins and proper page handling by print drivers and document viewers.
