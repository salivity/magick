ImageMagick Path Policy: Restricting Directory Access

The domain="path" directive in ImageMagick's policy.xml configuration establishes file-system-level access controls, enabling administrators to explicitly permit or deny read, write, and execute privileges across specific directories and files. By restricting file paths, this policy mitigates critical vulnerabilities—such as arbitrary file disclosure and remote code execution—by preventing ImageMagick from accessing sensitive areas of the underlying operating system during image processing operations.

Purpose of the domain="path" Policy

ImageMagick processes many complex and nested file formats that can reference external files or system resources (such as SVG, MVG, or PostScript). Without explicit constraints, an attacker could exploit these formats to read sensitive system files (e.g., /etc/passwd) or write malicious payloads to executable directories.

Setting a domain="path" rule restricts the utility to designated safe zones, achieving the following security objectives:

  • Preventing Arbitrary File Read (LFI/SSRF): Prohibits ImageMagick from reading files outside allowed storage, preventing attackers from exfiltrating system files or private keys.
  • Preventing Unauthorized File Creation or Overwrite: Blocks write operations to sensitive directories, such as web roots, /bin, or /etc, ensuring the engine cannot overwrite system files or upload backdoors.
  • Directory Sandboxing: Limits processing strictly to designated temporary or upload folders (such as /tmp or /var/app/uploads), isolating the image processor from the rest of the file system.

How the Policy Operates

The policy evaluates file paths requested during command execution against predefined rules in the policy.xml file. The rule uses three primary attributes:

  • domain="path": Specifies that the rule applies to file system paths.
  • rights: Defines the permissions granted or revoked. Values include none, read, write, or execute. Multiple rights can be combined using the pipe (|) symbol (e.g., read|write).
  • pattern: Defines the target directory or file using glob syntax.

Configuration Examples

Denying Access to Sensitive Directories

To block access entirely to system configuration directories, you can set the rights to none:

<policymap>
  <policy domain="path" rights="none" pattern="/etc/*"/>
  <policy domain="path" rights="none" pattern="/root/*"/>
  <policy domain="path" rights="none" pattern="/home/*"/>
</policymap>

Whitelisting Safe Directories

A more secure implementation involves a default-deny approach, where all paths are restricted except for dedicated operational folders:

<policymap>
  <!-- Deny access to the entire file system by default -->
  <policy domain="path" rights="none" pattern="/*"/>
  
  <!-- Explicitly allow reading and writing only in designated directories -->
  <policy domain="path" rights="read|write" pattern="/tmp/*"/>
  <policy domain="path" rights="read|write" pattern="/var/www/uploads/*"/>
</policymap>

Key Considerations

  • Rule Precedence: ImageMagick reads policies sequentially from top to bottom. If broader rules precede specific exceptions without proper ordering, the stricter rule may take precedence and block legitimate workflows.
  • Relative Paths and Symlinks: Path policies evaluate the resolved canonical path. When defining patterns, ensure absolute paths are used to prevent bypasses utilizing path traversal (../) or symbolic links.
  • Combined Defenses: While domain="path" secures the file system, it should be combined with domain="coder" rules to disable high-risk formats and delegate commands for defense-in-depth protection.
