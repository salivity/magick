ImageMagick Pattern Fill for Vector Shapes

This article explains how ImageMagick applies image textures and repeating tiles to vector primitives using pattern syntax. You will learn the mechanics behind the -fill pattern: protocol, how the rasterizer calculates pixel coordinates to tile graphics across shapes, and how to implement built-in patterns alongside custom image textures using memory registers.

The Mechanics of -fill pattern:

When rendering vector graphics using the -draw primitive, ImageMagick determines the color of every pixel inside the vector path via the -fill setting. While -fill commonly accepts solid colors (such as hex values or color names), passing a protocol prefix like pattern: instructs the rendering engine to source pixel data from an image tile rather than a uniform color value.

The pattern: prefix invokes ImageMagick’s built-in pattern generator. ImageMagick includes dozens of predefined geometric and textured tiles (such as pattern:checkerboard, pattern:bricks, or pattern:hexagons). When this setting is declared, ImageMagick instantiates the selected tile in memory and treats it as an infinite, repeating two-dimensional plane aligned to the canvas origin (0,0).

Coordinate Mapping and Rasterization

The process of filling a vector shape with a pattern operates through specific rendering stages:

  1. Path Rasterization: The vector engine calculates the boundaries of the shape (e.g., circle, polygon, path) on the target canvas using anti-aliased scanline conversion.
  2. Modulo Coordinate Lookup: For every pixel determined to lie within the vector path, the renderer queries the pattern texture. The sampling coordinates inside the texture are determined via modulo arithmetic: \[\text{Texture}_X = X_{\text{canvas}} \pmod{\text{Texture}_{\text{width}}}\] \[\text{Texture}_Y = Y_{\text{canvas}} \pmod{\text{Texture}_{\text{height}}}\] Because coordinates are mapped relative to the canvas origin (0,0) by default, the texture aligns consistently across multiple distinct shapes drawn on the same canvas.
  3. Alpha and Edge Blending: For pixels intersecting the boundary of the vector path, ImageMagick calculates fractional coverage. The pattern pixel color is then alpha-composited over the background canvas according to that coverage value, ensuring clean, anti-aliased vector edges.

Syntax and Practical Implementation

Using Built-In Patterns

To apply a predefined texture to a shape, declare -fill pattern:<name> before the -draw operation:

magick -size 600x400 xc:white \
  -fill pattern:checkerboard \
  -stroke black -strokewidth 2 \
  -draw "circle 300,200 300,50" \
  output.png

In this command, a 600×400 canvas is initialized, and a circle with a radius of 150 pixels is drawn at the center. The interior of the circle is filled with the repeating checkerboard texture.

Using Custom Image Textures via Memory Register

While -fill pattern: references ImageMagick's built-in pattern coder, external images can be used as textures by loading them into the Magick Persistent Registry (mpr:) and using the -tile operator, which acts as the custom texture equivalent of the pattern fill:

magick texture.jpg -write mpr:my_texture +delete \
  -size 800x600 xc:lightgray \
  -tile mpr:my_texture \
  -draw "polygon 100,100 700,150 600,500 200,450" \
  textured_polygon.png

This workflow loads texture.jpg, stores it in named temporary memory (mpr:my_texture), discards the initial read to free canvas space, and tiles the texture inside the designated polygon path using the exact same modulo coordinate mapping mechanism as built-in patterns.
