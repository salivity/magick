ImageMagick Percentage Geometry with Offsets

ImageMagick’s geometry syntax allows users to define dimension scaling alongside spatial coordinates using a single expression. When percentage values are combined with offset coordinates, ImageMagick applies the percentage exclusively to the width and height dimensions, leaving the offsets to be interpreted as absolute pixel distances. This article details how ImageMagick parses these hybrid geometry strings, how they function across different operations, and how to achieve relative offsets when needed.

The Parsing Rule: Dimensions vs. Offsets

In ImageMagick, the standard geometry argument follows the pattern:

[width][%][xheight[%]][{+-}x{+-}y]

When a percentage sign (%) is provided, the geometry parser flags the dimension values (width and height) for proportional calculation relative to the original image dimensions. However, the offset flags (+x and +y) do not inherit this percentage behavior. ImageMagick strictly treats offset values as integer pixel counts, regardless of whether a percentage modifier is present in the geometry string.

For example, given the geometry argument 50%x50%+100+50:

  • Width: Calculated as 50% of the target image's total width.
  • Height: Calculated as 50% of the target image's total height.
  • X Offset: Positioned exactly 100 pixels along the horizontal axis.
  • Y Offset: Positioned exactly 50 pixels along the vertical axis.

Attempting to attach a percent sign directly to an offset (such as +10%+10%) results in a parsing error or causes ImageMagick to ignore the offset values entirely, as standard geometry syntax does not support percentage-based offsets.

Behavior Across Common Operations

How this hybrid geometry is handled depends on the operator being invoked:

1. The -crop Operator

When using percentages with -crop, omitting offsets causes ImageMagick to segment the image into a grid of tiles matching those percentages. However, adding offsets switches the operation from tiling to a single extraction:

  • convert input.jpg -crop 50%x50%+20+20 output.jpg

This command extracts a single rectangle measuring half the source width and half the source height, starting 20 pixels from the left edge and 20 pixels from the top edge.

2. The -geometry and -composite Operators

When positioning an overlay image onto a background canvas:

  • magick composite -geometry 25%x25%+50+50 overlay.png canvas.png output.png

The overlay image is scaled down to 25% of its own original dimensions, and it is then placed 50 pixels right and 50 pixels down from the canvas origin.

The Influence of -gravity

Offset coordinates are calculated relative to the coordinate origin. By default, this origin is the top-left corner (NorthWest). If the -gravity setting is defined, the pixel offset is applied relative to the specified anchor point:

  • With -gravity Center -crop 50%x50%+10+0, ImageMagick extracts a box half the size of the image, centered vertically, but shifted 10 pixels to the right of the exact center.

Even with -gravity enabled, the offsets remain absolute pixel measurements.

Simulating Percentage-Based Offsets

Because standard geometry strings cannot interpret offsets as percentages, dynamic or relative positioning requires ImageMagick version 7's FX expressions. In ImageMagick 7, you can calculate offsets mathematically based on image dimensions:

magick canvas.png overlay.png -geometry "+%[fx:u.w*0.1]+%[fx:u.h*0.1]" -composite output.png

This syntax evaluates the canvas width (u.w) and height (u.h), dynamically passing a true 10% offset in pixels to the geometry operator.
