ImageMagick png:preserve-colormap Explained

The png:preserve-colormap define in ImageMagick prevents the PNG encoder from reorganizing, re-indexing, or pruning an image's existing color palette during export. By default, ImageMagick optimizes palette-based (indexed) PNG files by sorting colors and removing unused colormap entries to achieve smaller file sizes. Enabling this define forces the encoder to retain the exact order, index positions, and unused slots of the original colormap.

Default ImageMagick Palette Behavior

When exporting an indexed image (such as PNG8) without special defines, ImageMagick performs automatic palette optimization:

  • Reordering Indices: It often sorts the colormap entries by luminance or frequency, or places transparent pixels at specific low index positions to improve PNG compression.
  • Removing Unused Colors: Any palette entries not actively referenced by pixel data in the image are stripped to minimize the size of the PLTE chunk.
  • Re-indexing Pixels: Pixel values are updated to match the new positions of their corresponding colors in the newly structured palette.

While this optimization is ideal for standard web graphics, it alters the underlying byte-level index assignments.

What png:preserve-colormap Changes

Setting -define png:preserve-colormap=true instructs the PNG encoder to bypass its default optimization steps. Specifically, it guarantees that:

  1. Index Order Remains Intact: Color index 0, 1, 2, and so forth remain identical to their original values in the source image's colormap.
  2. Unused Slots Are Kept: If an original 256-color palette contains entries that are not used by any pixels, those empty or unused entries are still written to the final output file.
  3. No Pixel Re-mapping Occurs: The image data continues to reference the original index numbers directly, avoiding any shift in pixel data mapping.

Common Use Cases

Preserving the colormap is critical in specialized workflows where the color index itself carries functional meaning beyond visual display:

  • Retro Game Development: Sprite sheets and textures frequently rely on palette shifting, palette cycling, or specific index ranges for dynamic in-engine recoloring.
  • Scientific and GIS Data: Indexed images often store non-color metadata (such as elevation, classification, or heat maps), where a pixel's value strictly corresponds to a categorized data point rather than an arbitrary display color.
  • Strict Format Pipelines: Downstream software or legacy hardware decoders may expect fixed palette layouts that break when optimized dynamically.

How to Use the Define

To use this option, apply the define along with an indexed PNG format or palette setting:

magick input.png -define png:preserve-colormap=true output.png

If converting from a truecolor image to a palette image while attempting to preserve a specific external colormap, the source must already possess a defined palette (such as an image reduced via -remap or converted to indexed color before saving) so that the encoder has an existing colormap structure to preserve.
