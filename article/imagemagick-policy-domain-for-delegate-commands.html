ImageMagick Policy Domain for Delegate Commands

This article explains how ImageMagick secures command-line operations and prevents unauthorized external program execution. It covers the specific policy domain used to restrict system delegate commands, details how delegates function within the software, demonstrates the syntax required to disable or restrict them in the configuration file, and explains the security implications of managing these boundaries.

The Delegate Policy Domain

The policy domain that restricts the execution of system delegate commands in ImageMagick is the delegate domain.

In ImageMagick, delegates are external helper programs—such as Ghostscript, Potrace, or ffmpeg—that the application invokes to process formats it cannot natively decode or encode. Because invoking external binaries often involves passing system commands, delegate execution can present significant security risks, including command injection and arbitrary code execution, if left unconstrained.

To restrict or completely disable these commands, administrators define rules within ImageMagick’s master security configuration file, policy.xml.

Configuring the Delegate Domain in policy.xml

The policy.xml configuration file is typically located in /etc/ImageMagick-7/, /etc/ImageMagick-6/, or /etc/ImageMagick/ depending on the installation and version.

To restrict delegate execution, ImageMagick provides several enforcement rules using the delegate domain:

Disable All Delegate Execution

To prevent ImageMagick from calling any external system commands across all formats, set the rights to none with a wildcard pattern:

<policy domain="delegate" rights="none" pattern="*" />

Restrict Specific High-Risk Delegates

Administrators frequently disable delegates associated with complex external software libraries. For instance, to block external commands associated with PostScript (PS), Encapsulated PostScript (EPS), Portable Document Format (PDF), or web retrieval protocols:

<policy domain="delegate" rights="none" pattern="EPS" />
<policy domain="delegate" rights="none" pattern="PDF" />
<policy domain="delegate" rights="none" pattern="PS" />
<policy domain="delegate" rights="none" pattern="XPS" />
<policy domain="delegate" rights="none" pattern="HTTPS" />

How the Policy Works

When ImageMagick processes an image file:

  1. It determines whether internal decoders can handle the file format.
  2. If an external binary is required, ImageMagick queries delegates.xml to construct the shell command string.
  3. Before invoking the shell or child process, ImageMagick evaluates policy.xml.
  4. If a <policy domain="delegate" ... /> directive matches the target format or command and specifies rights="none", the operation is immediately blocked, throwing a security policy error.

Related Policy Domains

While delegate is the primary domain for system delegate commands, two complementary domains are often used in tandem:

  • coder Domain: Restricts specific format decoders and encoders entirely (e.g., <policy domain="coder" rights="none" pattern="MVG" />), stopping ImageMagick before it ever reaches the delegate stage.
  • system Domain: Enforces global operating constraints on system commands and system-wide execution environments.

Verifying Active Delegate Policies

To verify which delegate restrictions are active on a host, execute the following command:

magick identify -list policy

(For ImageMagick 6, run convert -list policy)

The output provides a list of all active policies, their domains, associated patterns, and permission rights, allowing administrators to confirm that the delegate domain is enforcing the required restrictions.
