ImageMagick policy.xml Location on Unix Systems

ImageMagick locates its primary security file, policy.xml, through a predefined search hierarchy rather than relying on a single static file path. On Unix-like operating systems, the software traverses environment variables, user configurations, relative application directories, and hardcoded compile-time installation paths to discover and load this file. Understanding this resolution sequence enables administrators and developers to inspect, modify, or override security policies applied to image processing workflows.

The Search Hierarchy

When an ImageMagick command is executed, its internal configuration manager searches for policy.xml in the following order:

  1. MAGICK_CONFIGURE_PATH Environment Variable: If this variable is defined, ImageMagick immediately checks the specified directory or colon-separated list of directories before any standard system locations.
  2. MAGICK_HOME Environment Variable: If MAGICK_HOME is set, ImageMagick checks subdirectories relative to that path, specifically looking within $MAGICK_HOME/etc/ImageMagick-X/ and $MAGICK_HOME/share/ImageMagick-X/ (where X corresponds to the major version, such as 6 or 7).
  3. User Configuration Directory: ImageMagick checks for local, user-level overrides. On modern Unix systems following the XDG base directory specification, it looks in $HOME/.config/ImageMagick/. It may also search $HOME/.magick/.
  4. Execution Path Relative Directories: If the binary was installed in an application-specific tree (such as a relocatable binary or custom prefix), ImageMagick checks paths relative to the current executable's location, such as ../etc/ImageMagick-X/.
  5. Compile-Time System Directories: If no overriding files are found in previous steps, ImageMagick falls back to the default system paths defined during the source code compilation. These typically include:
    • /etc/ImageMagick-7/ or /etc/ImageMagick-6/ (standard on Debian/Ubuntu)
    • /etc/ImageMagick/ (standard on RHEL/CentOS/Fedora)
    • /usr/local/etc/ImageMagick-7/ (common for default source builds)
    • /opt/local/etc/ImageMagick-7/ or custom paths set via --sysconfdir during build configuration.

How to Find the Active Location

Because multiple policy.xml files can exist on a system, ImageMagick merges configurations, with higher-precedence files overriding settings from lower-precedence ones.

To determine the exact directories your installation queries, run:

magick -list configure | grep CONFIGURE_PATH

(For ImageMagick 6, replace magick with convert.)

To view the loaded policies along with the active file path from which they were sourced, use:

magick -list policy

To see the real-time search resolution process, enable configuration debugging:

magick -debug configure logo: null:

This debug command outputs every directory ImageMagick inspects while attempting to open policy.xml.

Overriding the Default Policy Location

To force ImageMagick to use a custom policy.xml without altering system-level files, point the MAGICK_CONFIGURE_PATH variable to the directory containing your customized file:

export MAGICK_CONFIGURE_PATH="/path/to/custom/config"
magick convert input.png output.jpg

ImageMagick will prioritize this path, applying the policies defined in the custom directory ahead of the Unix system defaults.
