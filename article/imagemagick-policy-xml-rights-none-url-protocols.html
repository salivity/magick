ImageMagick policy.xml rights="none" URL Protocols

This article explains how ImageMagick utilizes its policy.xml configuration file to restrict remote resource fetching. By configuring the rights="none" attribute across coder and delegate domains, administrators can intercept network requests, block specific URL schemes, and effectively prevent Server-Side Request Forgery (SSRF) and arbitrary remote file inclusion vulnerabilities.

The Role of policy.xml in ImageMagick Security

ImageMagick processes a vast array of image formats, many of which (such as SVG, MVG, and generic text delegates) can reference external resources over network protocols like HTTP, HTTPS, and FTP. The policy.xml file acts as the primary access control configuration for the ImageMagick security subsystem. It establishes operational boundaries by regulating resource limits, execution rights, system path access, and coder capabilities before any media processing takes place.

The Mechanism of rights="none"

When a policy defines rights="none", ImageMagick removes all read, write, and execute permissions for the targeted pattern. For network fetching, this restriction is typically applied to two main domains: coder and delegate.

<policymap>
  <policy domain="coder" rights="none" pattern="URL" />
  <policy domain="coder" rights="none" pattern="HTTPS" />
  <policy domain="coder" rights="none" pattern="HTTP" />
  <policy domain="coder" rights="none" pattern="FTP" />
  <policy domain="delegate" rights="none" pattern="HTTPS" />
  <policy domain="delegate" rights="none" pattern="HTTP" />
</policymap>
  • The Coder Domain: Coders handle the decoding and encoding of specific formats or pseudo-protocols. When a filename or URI prefixed with http://, https://, or ftp:// is passed, ImageMagick identifies the prefix as an internal protocol coder. Setting domain="coder" rights="none" pattern="HTTP" explicitly revokes permission to initialize that handler.
  • The Delegate Domain: Delegates are external third-party programs (such as curl or wget) invoked by ImageMagick to handle tasks it cannot perform natively, including remote file retrieval. Restricting the delegate domain ensures that ImageMagick cannot spawn external processes to fetch URLs.

Internal Request Interception

The enforcement happens at the API and core library level before network sockets are created or external commands are executed:

  1. Protocol Parsing: When an image input or embedded reference is parsed, ImageMagick extracts the protocol scheme (for example, https://example.com/image.png).
  2. Policy Lookup: The internal security check queries the active policy table loaded in memory from policy.xml. It checks whether the protocol matches any registered pattern in the coder or delegate domains.
  3. Permission Evaluation: If a match is found and the assigned rights mask evaluates to 0 (corresponding to none), the security manager immediately denies access.
  4. Operation Termination: ImageMagick aborts the read routine and throws a fatal security exception (such as not authorized 'HTTPS' @ error/constitute.c/ReadImage). No network handshake, DNS resolution, or external process execution is allowed to occur.

By applying rights="none" to URL-related patterns, the security subsystem neutralizes external fetch attempts entirely within the application layer, ensuring isolated and deterministic local image processing.
