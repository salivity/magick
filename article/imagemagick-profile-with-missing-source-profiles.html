ImageMagick -profile with Missing Source Profiles

When converting an image to a target ICC profile, ImageMagick relies on an embedded source profile to calculate accurate color transformations. If an image lacks an embedded ICC profile, ImageMagick cannot perform an automatic color space conversion; instead, it treats the first provided profile as an assignment rather than a transformation. Understanding how ImageMagick interprets the -profile operator in the absence of source metadata is critical to avoiding unintended color shifts.

Assignment vs. Transformation

The ImageMagick -profile operator performs two distinct functions depending on the current state of the image:

  1. Profile Assignment (Tagging): If the image has no embedded ICC profile, applying -profile filename.icc embeds the profile metadata into the file without altering the underlying pixel values.
  2. Color Transformation (Conversion): If the image already contains an embedded ICC profile, applying -profile filename.icc translates the pixel values from the existing color space to the target color space using the LittleCMS (lcms2) engine, then updates the embedded profile.

The Single-Profile Pitfall

A common mistake is attempting to convert an untagged image to a target profile using a single command:

magick input_untagged.jpg -profile USWebCoatedSWOP.icc output.jpg

Because input_untagged.jpg has no embedded profile, ImageMagick does not convert the RGB data to CMYK. Instead, it assigns the CMYK profile directly to the existing pixel values. This results in severe color distortion because raw RGB numbers are now interpreted as CMYK percentages without mathematical translation.

The Correct Two-Profile Workflow

To convert an untagged image to a target profile, you must explicitly declare the assumed source profile before defining the destination profile. This requires chaining the -profile operator twice in a single command.

Most untagged web or digital assets are authored in the sRGB color space. To properly transform such an image to a destination profile (such as Adobe RGB or a CMYK press profile), use:

magick input_untagged.jpg -profile sRGB.icc -profile target.icc output.jpg

In this execution:

  • The first -profile sRGB.icc assigns the source profile to the untagged pixels without modifying pixel values.
  • The second -profile target.icc detects the now-present source profile and recalculates the pixel values to match the target color space.

Detecting Missing Profiles Programmatically

To avoid applying unnecessary source profiles to images that already contain color data, you can check for the presence of an embedded profile before processing:

magick identify -format "%[profile:icc]" input.jpg

If the output is empty, the image lacks an embedded ICC profile and requires the explicit two-step assignment-and-conversion syntax. If the output returns profile details, a single -profile target.icc call will correctly execute the color transformation.
