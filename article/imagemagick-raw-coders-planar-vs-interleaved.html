ImageMagick Raw Coders: Planar vs Interleaved

When decoding or encoding raw image streams in ImageMagick, the arrangement of color data determines how byte streams are mapped to pixel components. Raw coders lack standard container metadata, requiring the user to explicitly define whether color channels are pixel-interleaved or planar. This article explains the parameters used to configure planar versus interleaved color layouts in ImageMagick raw coders, including key command-line options and syntax examples.

Understanding the Layout Formats

Raw pixel formats store color values consecutively without header information or compression:

  • Interleaved (Pixel Interleaving): Color components for each pixel are grouped together sequentially. For an RGB image, the byte sequence is R1 G1 B1 R2 G2 B2 ... Rn Gn Bn.
  • Planar (Band Interleaving): Color components are divided into complete, separate channel planes. All red values are stored first, followed by all green values, and then all blue values: R1 R2 ... Rn G1 G2 ... Gn B1 B2 ... Bn.

Key Parameters Defining Color Layouts

ImageMagick relies on specific CLI flags to define the layout, dimensions, and depth of raw data.

1. The -interlace Parameter

The primary parameter controlling planar versus interleaved interpretation is -interlace.

  • -interlace None (Default): Configures pixel-interleaved mode. ImageMagick expects channel bytes to alternate per pixel (e.g., standard RGB, RGBA, CMYK).
  • -interlace Plane: Configures planar mode. ImageMagick processes the raw stream as distinct color planes, reading the entire first channel before moving to the next.
  • -interlace Partition: Similar to planar, but specifies that each channel resides in a separate raw file rather than consecutive planes within a single file.

2. Essential Complementary Parameters

Because raw streams do not contain self-describing metadata, the following flags must accompany the layout definition:

  • -size <width>x<height>: Sets the dimensions of the raw frame, enabling ImageMagick to calculate plane boundaries and stride.
  • -depth <bits>: Defines the bit depth per component (e.g., 8, 10, 12, or 16 bits).
  • coder:filename: Specifies the color model via the coder prefix (e.g., rgb:, rgba:, cmyk:, gray:, yuv:).

Command-Line Examples

Reading Interleaved Raw Data

To read an 8-bit, 1920x1080 pixel-interleaved RGB file:

magick -size 1920x1080 -depth 8 -interlace None rgb:input_interleaved.raw output.png

Reading Planar Raw Data

To read the same image stored in planar format (all red bytes, then green, then blue):

magick -size 1920x1080 -depth 8 -interlace Plane rgb:input_planar.raw output.png

Writing Raw Data to a Specific Layout

The -interlace parameter can also dictate the output layout when exporting from ImageMagick to a raw binary file:

# Export to planar raw
magick input.png -depth 8 -interlace Plane rgb:output_planar.raw

# Export to interleaved raw
magick input.png -depth 8 -interlace None rgb:output_interleaved.raw
