ImageMagick Reinhard Tone Mapping Operator Guide

This article provides an overview of the Reinhard tone mapping operator and its practical implementation within ImageMagick. It covers the core mathematical principles behind Reinhard tone mapping, the necessity of High Dynamic Range Imaging (HDRI) support, and the exact ImageMagick commands used to convert HDR images into viewable low dynamic range formats without losing shadow or highlight details.

What is Reinhard Tone Mapping?

The Reinhard tone mapping operator, introduced by Erik Reinhard et al. in 2002, is a widely used algorithm designed to compress High Dynamic Range (HDR) images into standard Low Dynamic Range (LDR) displays (such as standard 8-bit or 16-bit monitors).

The basic (global) Reinhard tone reproduction formula compresses luminance values smoothly to prevent clipping:

\[L_d = \frac{L}{1 + L}\]

Where:

  • \(L\) represents the original linear scene luminance (or input color value).
  • \(L_d\) represents the display-mapped luminance, scaled between 0.0 and 1.0.

The extended version allows a maximum luminance value (\(L_{\text{white}}\)) to burn out smoothly to pure white:

\[L_d = \frac{L \left(1 + \frac{L}{L_{\text{white}}^2}\right)}{1 + L}\]

Requirements: ImageMagick with HDRI

To apply tone mapping correctly, ImageMagick must be compiled with HDRI (High Dynamic Range Images) enabled. HDRI allows ImageMagick to handle pixel values outside the standard \([0, 1]\) or \([0, 255]\) range without clipping them immediately upon loading. HDRI is enabled by default in ImageMagick version 7.

You can verify your build by running:

magick -version

Look for HDRI in the Features output line.

Implementing Basic Reinhard Tone Mapping in ImageMagick

ImageMagick enables the implementation of mathematical formulas directly on images using the -fx operator or image arithmetic pipelines.

1. Using the -fx Operator (Simple & Direct)

The -fx operator evaluates mathematical expressions per pixel. To apply the basic Reinhard operator:

magick input_hdr.exr -fx "u / (1 + u)" -colorspace sRGB output_ldr.png
  • u: Refers to the input image pixel value.
  • -colorspace sRGB: Applies standard display gamma after mapping linear values.

2. Using Arithmetic Composition (High Performance)

The -fx operator processes pixels via an interpreter and can be slow on large images. A faster alternative uses native arithmetic and compositing operations:

magick input_hdr.exr \
  \( +clone -evaluate add 1 \) \
  -compose Divide -composite \
  -colorspace sRGB output_ldr.png

This workflow executes the following steps:

  1. Loads the linear HDR source file.
  2. Clones the image and adds 1 to every pixel value (1 + u).
  3. Divides the original image by the cloned image (\(u / (1 + u)\)).
  4. Converts the result to standard sRGB color space for display.

Implementing Extended Reinhard Tone Mapping

To prevent very bright light sources from appearing dull or gray, use the extended Reinhard formula by introducing a white point parameter (\(L_{\text{white}}\)).

For example, setting \(L_{\text{white}} = 2.5\):

magick input_hdr.exr -fx "u * (1 + (u / (2.5 * 2.5))) / (1 + u)" -colorspace sRGB output_ldr.png

Lowering the \(L_{\text{white}}\) value causes more highlights to reach pure white, increasing overall image contrast.

Exposure Pre-Scaling

Before applying tone mapping, the base exposure can be adjusted by scaling linear pixel values with the -evaluate multiply option:

magick input_hdr.exr -evaluate multiply 1.5 \
  \( +clone -evaluate add 1 \) \
  -compose Divide -composite \
  -colorspace sRGB output_ldr.png

Multiplying by a factor greater than 1.0 brightens underexposed shadow details prior to compression, while values below 1.0 recover highlights.
