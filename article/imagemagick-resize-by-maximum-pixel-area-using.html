ImageMagick Resize by Maximum Pixel Area Using @

This article explains how to constrain images to a maximum total pixel count using ImageMagick's at-sign (@) geometry option. By defining a total area rather than fixed width and height dimensions, you can scale images with varying aspect ratios proportionally so that none exceed a specified number of pixels.

Understanding the @ Geometry Flag

In ImageMagick, appending the @ symbol to a dimension value tells the -resize (or -scale) operator to treat that value as the total number of pixels in the output image (width × height), rather than a linear measurement.

ImageMagick calculates the new dimensions so that the image's original aspect ratio is preserved while adjusting the total area to match the target.

Basic Syntax

To set a target pixel count, specify the total number of pixels followed by @:

magick input.jpg -resize 1000000@ output.jpg

In this example, an input image of any aspect ratio will be scaled so that its total pixel count is approximately 1,000,000 pixels (1 megapixel).

  • A 4:3 image will resize to roughly 1155 × 866 (~1,000,230 pixels).
  • a 16:9 image will resize to roughly 1333 × 750 (~999,750 pixels).

(Note: If you are using ImageMagick version 6, replace magick with convert.)

Enforcing a Strict Maximum (Prevent Upscaling)

By default, the -resize command will upscale an image if its original pixel count is smaller than the target specified by @.

To ensure the value acts strictly as a maximum ceiling without enlarging smaller images, combine the @ symbol with the > flag (which means "shrink only"):

magick input.jpg -resize "1000000@>" output.jpg

Enclose the argument in quotes to prevent your command line shell from interpreting the > character as an output redirection operator.

With this command:

  • Images larger than 1,000,000 pixels will be downscaled to fit the target area.
  • Images equal to or smaller than 1,000,000 pixels will remain at their original dimensions.
