ImageMagick Security Policy Syntax in Containers

This article provides a comprehensive guide on configuring custom security policies for ImageMagick inside application containers like Docker. It outlines the core XML syntax required for policy.xml, demonstrates how to restrict vulnerable coders and allocate resource limits, and explains how to inject these rules into a containerized environment to defend against arbitrary code execution and resource exhaustion attacks.

The Policy File Structure

ImageMagick governs its runtime privileges, format handling, and resource limits using an XML file named policy.xml. The root element must always be <policymap>, containing one or more <policy> directives.

<policymap>
  <!-- Security rules go here -->
</policymap>

Syntax for <policy> Attributes

Each <policy> tag uses specific attributes depending on the security domain being controlled. The primary domains are coder, resource, path, and system.

1. Restricting Decoders and Encoders (domain="coder")

To prevent exploitation of insecure or vulnerable delegates (such as Ghostscript or HTTP wrappers), use the coder domain.

  • rights: Specifies permissions. Typically set to "none" to disable completely, or combinations of "read" and "write".
  • pattern: A case-insensitive pattern matching the file format or delegate.
<!-- Disable dangerous formats entirely -->
<policy domain="coder" rights="none" pattern="EPHEMERAL" />
<policy domain="coder" rights="none" pattern="URL" />
<policy domain="coder" rights="none" pattern="HTTPS" />
<policy domain="coder" rights="none" pattern="MVG" />
<policy domain="coder" rights="none" pattern="MSL" />
<policy domain="coder" rights="none" pattern="TEXT" />
<policy domain="coder" rights="none" pattern="SHOW" />
<policy domain="coder" rights="none" pattern="WIN" />
<policy domain="coder" rights="none" pattern="PLT" />

<!-- Restrict PostScript / PDF handling -->
<policy domain="coder" rights="none" pattern="PS" />
<policy domain="coder" rights="none" pattern="EPS" />
<policy domain="coder" rights="none" pattern="PDF" />
<policy domain="coder" rights="none" pattern="XPS" />

2. Limiting Container Resources (domain="resource")

To prevent Denial of Service (DoS) attacks via memory exhaustion or "pixel bombs," set hard resource limits using the resource domain.

  • name: The target resource (e.g., memory, map, width, height, area, disk, time, thread).
  • value: The limit assigned to that resource (supports units such as KB, MB, GiB, or plain integers).
<!-- Limit processing dimensions to prevent pixel bombs -->
<policy domain="resource" name="width" value="16KP"/>
<policy domain="resource" name="height" value="16KP"/>
<policy domain="resource" name="area" value="128MB"/>

<!-- Restrict execution memory and disk usage -->
<policy domain="resource" name="memory" value="256MiB"/>
<policy domain="resource" name="map" value="512MiB"/>
<policy domain="resource" name="disk" value="1GiB"/>

<!-- Limit execution time in seconds -->
<policy domain="resource" name="time" value="60"/>

<!-- Limit threading concurrency inside the container -->
<policy domain="resource" name="thread" value="2"/>

3. Restricting File System Paths (domain="path")

To prevent local file inclusion or reading sensitive paths, restrict directory access:

<!-- Block access to sensitive system paths -->
<policy domain="path" rights="none" pattern="/etc/*"/>

Implementing Custom Policies in Application Containers

In container environments, the policy.xml file is typically located at /etc/ImageMagick-6/policy.xml or /etc/ImageMagick-7/policy.xml.

You can apply custom policies using two main container strategies:

Method A: Overwrite via Dockerfile

Create your custom policy.xml in your repository and copy it directly to the ImageMagick configuration path during the image build:

FROM alpine:latest

RUN apk add --no-cache imagemagick

# Copy the custom policy file into the configuration path
COPY custom-policy.xml /etc/ImageMagick-7/policy.xml

Method B: Define via Environment Variable

ImageMagick allows you to specify a custom directory for configuration files using the MAGICK_CONFIGURE_PATH environment variable:

ENV MAGICK_CONFIGURE_PATH=/app/config/imagemagick

Mounting or placing your policy.xml into /app/config/imagemagick/ will instruct ImageMagick to prioritize that file over the default system rules.

Verifying Policy Enforcement in the Container

Verify the active policy configuration inside a running container by executing:

identify -list policy

This outputs all active resource limits and format restrictions, ensuring that the containerized environment is operating under the intended security controls.
