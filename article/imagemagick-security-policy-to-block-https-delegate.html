ImageMagick Security Policy to Block HTTPS Delegate

ImageMagick's ability to fetch remote resources can expose applications to Server-Side Request Forgery (SSRF) vulnerabilities if untrusted input is processed. This article details the specific security policy configuration within policy.xml required to disable the HTTPS delegate and coder modules, effectively preventing ImageMagick from making unauthorized outbound network requests.

The Security Policy Configuration

To disable the HTTPS delegate and prevent ImageMagick from making outbound network calls, you must modify the policy.xml file.

Add the following policy directive inside the <policymap> element:

<policy domain="delegate" rights="none" pattern="https" />

To provide comprehensive protection against SSRF, you should also disable the HTTP protocol and the URL/HTTPS coder domains:

<!-- Disable network delegates -->
<policy domain="delegate" rights="none" pattern="http" />
<policy domain="delegate" rights="none" pattern="https" />

<!-- Disable URL coders -->
<policy domain="coder" rights="none" pattern="HTTP" />
<policy domain="coder" rights="none" pattern="HTTPS" />
<policy domain="coder" rights="none" pattern="URL" />

Locating policy.xml

The policy.xml configuration file is typically located in one of the following paths depending on your operating system and ImageMagick version:

  • Linux (system-wide): /etc/ImageMagick-6/policy.xml or /etc/ImageMagick-7/policy.xml
  • Custom/Source Builds: /usr/local/etc/ImageMagick-7/policy.xml
  • macOS (Homebrew): /usr/local/etc/ImageMagick-7/policy.xml or /opt/homebrew/etc/ImageMagick-7/policy.xml

You can verify the exact path being loaded by running:

magick -list configure | grep CONFIGURE_PATH

How It Mitigates SSRF

When ImageMagick encounters image formats like MSL, MVG, or SVG, or receives an image path starting with https://, it invokes external delegates (such as curl or wget) to retrieve the remote file. Attackers exploit this to target internal endpoints, such as cloud metadata services (http://169.254.169.254) or local internal services behind firewalls.

Setting rights="none" on the delegate and coder domains for https ensures that ImageMagick immediately rejects network requests at the parser level before executing any network operations.

Verification

To verify that the policy is functioning, attempt to read an image from a remote HTTPS URL:

magick identify https://example.com/test.png

If configured correctly, ImageMagick will refuse the operation with an error similar to:

convert: not authorized `https://example.com/test.png' @ error/constitute.c/ReadImage/412.
