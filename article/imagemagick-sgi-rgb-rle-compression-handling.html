ImageMagick SGI RGB RLE Compression Handling

ImageMagick provides native support for Silicon Graphics Image (SGI) raster formats, including .sgi, .rgb, .rgba, and .bw files, handling both uncompressed and Run-Length Encoded (RLE) variants. Through its dedicated internal SGI coder module (coders/sgi.c), ImageMagick parses SGI header structures, resolves scanline offset tables, and decodes or encodes compressed pixel streams directly to and from its internal Quantum pixel cache.

Header Detection and Storage Identification

When reading an SGI file, ImageMagick first reads the fixed 512-byte header and inspects the two-byte magic number 0x01DA. Immediately following this signature, it evaluates the storage byte:

  • A value of 0 denotes uncompressed raw raster data.
  • A value of 1 signifies RLE compression.

The header also specifies the number of bytes per pixel channel (1 or 2 bytes), image dimensions (width, height), and channel count (1 channel for grayscale/B&W, 3 for RGB, 4 for RGBA).

Resolving Scanline Tables

SGI files utilizing RLE compression do not store contiguous compressed streams sequentially without index pointers. Instead, the format relies on two lookup tables located directly after the 512-byte header:

  1. Offset Table (start_tab): Stores absolute file offsets pointing to the beginning of each compressed scanline.
  2. Length Table (length_tab): Stores the exact byte length of each compressed scanline.

The size of each table equals the image height multiplied by the number of channels. ImageMagick allocates memory for both tables and populates them sequentially. If an offset points outside the file boundaries or exceeds the expected data range, ImageMagick triggers an exception to prevent buffer overflow vulnerabilities and malformed file reads.

The Decompression Process

To reconstruct the image, ImageMagick iterates through each channel and row:

  1. It seeks the file offset defined in the offset table for the specific row and channel.
  2. It reads the exact number of bytes indicated by the corresponding entry in the length table into a temporary buffer.
  3. It evaluates the RLE control bytes:
    • Repeat Run: If the control byte designates a repetition, the subsequent byte value is repeated across the designated count.
    • Literal Run: If the control byte indicates distinct data, the specified number of literal bytes are copied directly to the scanline buffer.
  4. The unpacked channel scanlines are assembled into ImageMagick’s internal pixel representation, scaling 8-bit or 16-bit integer values to ImageMagick’s native Quantum depth.

Writing RLE-Compressed SGI Files

When writing an SGI image with RLE compression (the default behavior or explicitly set via -compress RLE), ImageMagick reverses this process:

  1. It pre-calculates the scanline data per channel, applying SGI's RLE packing algorithm to identify sequences of identical pixel values versus distinct pixel sequences.
  2. It tracks the output byte size of each compressed row to construct the in-memory offset and length tables.
  3. It writes the standard 512-byte header with the storage flag set to 1.
  4. It writes the offset table and length table immediately following the header.
  5. Finally, it streams the compressed scanline data into the file at the mapped offsets, producing a standard-compliant SGI RGB file.
