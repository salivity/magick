ImageMagick Version Output: Depth, Endian, Date

This article explains how to inspect and interpret the build specifications reported by ImageMagick when running the -version command. Running magick -version (or convert -version in legacy releases) produces a detailed summary of the installed binary, revealing key compile-time attributes including the quantum depth, target architecture and endianness implications, and the build's release date.

When you execute magick -version in your terminal, ImageMagick outputs several lines of diagnostic text. The primary details appear on the very first line:

Version: ImageMagick 7.1.1-33 Q16-HDRI x86_64 22238 https://imagemagick.org

Older releases or alternative distribution packages may display a formatted release date in place of the commit/build index:

Version: ImageMagick 6.9.10-23 Q16 x86_64 20190101 https://imagemagick.org

Here is how ImageMagick encodes quantum depth, endianness, and release date information across this output.

Quantum Depth

The quantum depth defines the bit depth allocated per color channel for in-memory image processing (for example, red, green, blue, and alpha channels). ImageMagick reports this immediately following the release version number:

  • Prefix Indicator: The quantum depth is identified by the letter Q followed by an integer (typically 8, 16, 32, or rarely 64).
  • Interpretation:
    • Q8 uses 8 bits per channel (values 0–255), consuming the least memory.
    • Q16 uses 16 bits per channel (values 0–65,535), providing a balance between precision and system resources.
    • Q32 uses 32 bits per channel, suitable for high-precision scientific imaging.
  • HDRI Suffix: If compiled with High Dynamic Range Imaging enabled, the token appears as Q16-HDRI or Q32-HDRI. In ImageMagick 7, HDRI is enabled by default. HDRI allows pixels to store non-clamped floating-point values instead of integers.

Release Date

The release or build date specification appears toward the end of the primary version line:

  • Date Format: In source and standard distribution builds, this appears either as an ISO calendar date (YYYY-MM-DD), a compact date stamp (YYYYMMDD), or an internal build revision integer (such as 22238).
  • Significance: This token specifies the date when the source tree was packaged or compiled into the active binary. It allows administrators to verify whether security patches, hotfixes, or library updates released upstream on a specific date are present in the installed deployment.

Endianness and Architecture

ImageMagick reports host endianness indirectly through the target CPU platform architecture string on the version line:

  • Architecture Token: Following the quantum depth specifier, the command outputs the target compilation architecture (for example, x86_64, aarch64, armv7l, or powerpc).
  • Deducing Endianness:
    • Common architectures such as x86_64, i686, and aarch64 operate in little-endian mode.
    • Architectures such as ppc64 or s390x operate in big-endian mode.
  • Detailed Configuration Check: While the -version line itself outputs the architecture string, you can verify explicit byte-order handling by querying configuration delegates using magick -list configure. The HOST and ENDIAN directives within that configuration table will explicitly confirm whether the binary was linked for little-endian (1234) or big-endian (4321) execution.
