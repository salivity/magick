Ingest Raw Float32 Pixel Streams into ImageMagick

This article explains how to ingest raw binary 32-bit floating-point (float32) pixel streams into ImageMagick from files or standard input (stdin). Because raw streams contain pure pixel buffers without headers, you must explicitly declare metadata—such as dimensions, channel layouts, endianness, and numeric formats—prior to ingestion. The following sections provide the exact parameters, format specifiers, and command-line examples needed to reliably parse float32 binary data into standard or high-dynamic-range image formats.

Required Parameters for Raw Float32 Streams

Raw binary streams contain no header information describing resolution or color space. To process the data correctly, ImageMagick must be configured with explicit stream parameters before the input descriptor (- for stdin or a raw filename):

  • -size <width>x<height>: Defines the raster dimensions of the stream.
  • -depth 32: Declares that each channel sample is 32 bits wide.
  • -define quantum:format=floating-point: Informs the decoder that the 32-bit values represent IEEE 754 floating-point numbers instead of unsigned integers.
  • -endian <lsb|msb>: Specifies byte ordering. Most modern CPU architectures (x86_64, ARM) output little-endian (lsb) data.
  • Format Specifiers: Tells ImageMagick the channel arrangement. Standard identifiers include gray:, rgb:, and rgba:.

Ingestion Methods

Method 1: Using Quantum Format Definition

The standard method uses the -define quantum:format=floating-point flag combined with standard raw channel formats.

Grayscale (Single Channel):

cat raw_float32.bin | magick -size 1920x1080 \
  -depth 32 \
  -define quantum:format=floating-point \
  -endian lsb \
  gray:- output.png

RGB (Three Channels):

cat raw_float32_rgb.bin | magick -size 512x512 \
  -depth 32 \
  -define quantum:format=floating-point \
  -endian lsb \
  rgb:- output.tif

Method 2: Using Floating-Point Shorthand Formats

ImageMagick includes built-in floating-point raw formats that eliminate the need to specify the -depth and -define flags manually:

  • GRAYF: – Grayscale single-precision float
  • RGBF: – 3-channel RGB single-precision float
  • RGBAF: – 4-channel RGBA single-precision float

Grayscale Example:

cat raw_float32.bin | magick -size 1920x1080 -endian lsb grayf:- output.exr

RGBA Example:

cat raw_float32_rgba.bin | magick -size 1024x768 -endian lsb rgbaf:- output.exr

Handling Dynamic Range and Output Formats

Float32 image data is typically normalized in the range [0.0, 1.0]. When saving to integer formats (like 8-bit PNG or JPEG), values outside this range are clipped:

  • Retaining High Dynamic Range (HDR): Output to formats that support float representations natively, such as .exr or floating-point .tif.
  • Clamping/Scaling Values: If converting to standard 8-bit formats and the data contains values outside [0.0, 1.0], apply -auto-level to normalize the dynamic range before writing the output:
cat raw_float32.bin | magick -size 512x512 -endian lsb grayf:- -auto-level output.png
