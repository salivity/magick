JPEG XL Progressive Passes in ImageMagick

In ImageMagick, progressive decoding behavior for JPEG XL (JXL) files is primarily governed during encoding using the -define jxl:progressive-passes configuration. This article covers the specific define used to control progressive decoding passes, the valid integer values it accepts, and how to apply it in your image processing commands to enhance perceived load times for web and streaming delivery.

The Define: jxl:progressive-passes

To configure progressive decoding passes when creating or converting JPEG XL images in ImageMagick, use:

-define jxl:progressive-passes=<value>

(Note: In certain wrapper scripts or legacy bindings, -define jxl:passes is also accepted as an alias to the same underlying libjxl encoder setting).

How Progressive Passes Work in JPEG XL

JPEG XL supports progressive decoding, allowing an image viewer or browser to display a low-fidelity preview immediately and refine it in sequential passes as more data streams in.

Because progressive decoding structure must be embedded into the bitstream at creation time, ImageMagick controls this feature on write. The encoder divides spectral data (frequency coefficients) across multiple frames so decoders can perform multiple progressive rendering stages without needing to decompress the entire file first.

Supported Values

The jxl:progressive-passes define accepts integer values ranging from -1 to 4:

  • -1 (Default): Lets the encoder determine the number of progressive passes automatically based on heuristics such as image dimensions and target quality.
  • 0: Disables progressive passes entirely. The image will encode in a single pass, resulting in the smallest possible file size but requiring the complete stream before rendering.
  • 1 to 4: Explicitly forces the specified number of progressive passes. A higher number of passes yields more intermediate visual refinements during download, with a slight tradeoff in overall compression efficiency.

Example Usage

To encode a PNG image into a progressive JPEG XL file with three intermediate passes, run the following command:

magick input.png -define jxl:progressive-passes=3 output.jxl

To completely disable progressive passes for maximum compression density:

magick input.png -define jxl:progressive-passes=0 output.jxl

When decoders encounter files created with these defines, they automatically parse the embedded passes sequentially to render the image progressively.
