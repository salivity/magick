JPEG XL Speed and Effort Options in ImageMagick

This guide explains how to control compression speed, encoding effort, and decoding performance when converting images to JPEG XL (JXL) using ImageMagick. By default, ImageMagick relies on underlying libjxl encoder settings, but you can explicitly fine-tune the balance between file size, processing time, and playback efficiency using specific command-line defines.

The Primary Parameter: jxl:effort

The main parameter controlling encoding speed and compression efficiency in JPEG XL is jxl:effort. It is set using the -define flag:

magick input.png -define jxl:effort=7 output.jxl
  • Values: Integer ranging from 1 to 9.
  • Default: 7
  • Behavior:
    • 1 (Fastest): Minimal CPU usage and fastest encoding speed, resulting in larger file sizes. Suitable for real-time capture or batch processing large volumes where speed is critical.
    • 7 (Default): A balanced setting offering high compression density with reasonable processing time.
    • 9 (Slowest / Maximum Compression): The encoder tries all optimization passes to produce the smallest possible file size at the cost of significantly higher CPU and time usage. Recommended for static web asset deployment and archival.

The Decoding Speed Parameter: jxl:decoding-speed

JPEG XL also allows you to optimize how quickly the resulting file can be decoded by viewers or web browsers using the jxl:decoding-speed define:

magick input.png -define jxl:decoding-speed=0 output.jxl
  • Values: Integer ranging from 0 to 4.
  • Default: 0 (Standard decoding speed with maximum compression density).
  • Behavior:
    • 0: Highest compression density; decoding speed is unconstrained.
    • 1 to 4: Incrementally restricts certain encoding tools to ensure faster client-side rendering on low-power devices, at the expense of a slightly larger file size.

Interaction with Quality Settings

While jxl:effort controls computation intensity, -quality controls the visual fidelity:

  • -quality 100: Enables mathematically lossless compression by default.
  • -quality 1 to 99: Enables lossy compression, mapping directly to distance/butteraugli metrics.

When encoding lossless images, higher jxl:effort levels (such as effort=8 or effort=9) yield smaller file sizes without altering any pixel data.

Practical Examples

Fast encoding for drafts or rapid previews:

magick input.jpg -quality 85 -define jxl:effort=3 output.jxl

Maximum lossless compression for archival:

magick input.png -quality 100 -define jxl:effort=9 output.jxl

Web-optimized delivery (high compression, fast client decode):

magick input.jpg -quality 80 -define jxl:effort=7 -define jxl:decoding-speed=1 output.jxl
