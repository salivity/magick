Limit ImageMagick CPU Threads with OpenMP

ImageMagick is compiled with OpenMP support by default, enabling it to utilize all available CPU cores to accelerate image processing tasks. While this maximizes performance, it can easily saturate multi-core processors, leading to high system load and resource starvation for other critical processes. This guide outlines the most effective methods to limit CPU thread utilization in ImageMagick using OpenMP environment variables, command-line arguments, and global configuration files.

1. Using the OpenMP Environment Variable

The most straightforward way to restrict ImageMagick's thread consumption across a system or within a specific script session is by setting the standard OpenMP environment variable OMP_NUM_THREADS.

To limit execution to 2 CPU threads for a single command:

OMP_NUM_THREADS=2 magick convert input.jpg -resize 50% output.jpg

To enforce this limit globally for your current shell session or deployment environment:

export OMP_NUM_THREADS=2

2. Using the ImageMagick Thread Limit Variable

ImageMagick provides its own environment variable that explicitly overrides thread allocation without affecting other non-ImageMagick OpenMP applications:

export MAGICK_THREAD_LIMIT=2

Setting MAGICK_THREAD_LIMIT ensures that only ImageMagick processes respect the designated core ceiling.

3. Using the -limit Command-Line Parameter

If you need to define thread restrictions on a per-command basis directly within application code, use the -limit thread option:

magick input.jpg -limit thread 2 -resize 1920x1080 output.jpg

For legacy ImageMagick v6 installations, use:

convert input.jpg -limit thread 2 -resize 1920x1080 output.jpg

4. Enforcing Global Limits via policy.xml

For production web servers (such as those running PHP, Python, or Node.js background workers), the most robust approach is setting a permanent limit in ImageMagick’s security and resource configuration file.

  1. Locate your policy.xml file (commonly found in /etc/ImageMagick-6/policy.xml, /etc/ImageMagick-7/policy.xml, or /usr/local/etc/ImageMagick-7/policy.xml).
  2. Open the file in a text editor with administrative privileges:
sudo nano /etc/ImageMagick-7/policy.xml
  1. Add or modify the thread resource policy within the <policymap> section:
<policymap>
  <!-- Limit processing to 2 threads -->
  <policy domain="resource" name="thread" value="2"/>
</policymap>
  1. Save and close the file. All subsequent ImageMagick processes will strictly adhere to this constraint.

Verifying Thread Configuration

To confirm that the resource limits have been properly applied to your environment, run:

magick identify -list resource

Look for the Thread entry in the output:

Resource limits:
  ...
  Thread: 2
  ...

If the value reflects your configured limit, ImageMagick will no longer consume excessive CPU resources during intensive batch conversions or large image manipulations.
