Limit ImageMagick Execution Time in policy.xml

ImageMagick is a powerful suite for image manipulation, but processing complex, oversized, or maliciously crafted files can cause operations to hang and consume excessive CPU resources. This guide explains how system administrators can protect system stability by configuring the time resource policy directive in the policy.xml file, which enforces a strict execution time limit in seconds for all image processing tasks.

Locating policy.xml

The policy.xml configuration file is typically located in the system-wide configuration directory for ImageMagick. Common paths include:

  • Linux (Debian/Ubuntu): /etc/ImageMagick-6/policy.xml or /etc/ImageMagick-7/policy.xml
  • Linux (RHEL/CentOS): /etc/ImageMagick/policy.xml
  • Compiled from Source: /usr/local/etc/ImageMagick-7/policy.xml

Configuring the Time Directive

To set a maximum execution duration, open policy.xml in a text editor with administrative privileges and locate the <policymap> section. Within this block, add or update the policy tag where the domain is set to resource and the name is set to time.

The value attribute specifies the maximum wall-clock processing time allowed for a single command, measured in seconds. For example, to restrict execution time to 120 seconds:

<policymap>
  <!-- Set maximum execution time to 120 seconds -->
  <policy domain="resource" name="time" value="120"/>
</policymap>

Save and close the file. Changes take effect immediately for all subsequent ImageMagick commands without needing to restart any background services.

Verifying the Configuration

To verify that the execution limit has been applied correctly, run the following command in your terminal:

identify -list resource

Or, for ImageMagick 7:

magick -list resource

Look for the Time entry in the output list to confirm that the value reflects the limit set in policy.xml:

Resource limits:
  ...
  Time: 120

Behavior When the Limit is Exceeded

If an operation exceeds the defined time threshold, ImageMagick immediately halts processing, releases allocated memory, and exits with a non-zero status code, generating a fatal error:

fatal error: resource limit exceeded `time'

Setting this directive ensures that runaway loops or algorithmic complexity attacks (such as "ImageTragick" exploits or decompression bombs) cannot monopolize server resources indefinitely.
