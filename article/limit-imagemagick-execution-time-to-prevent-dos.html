Limit ImageMagick Execution Time to Prevent DoS

Processing untrusted images with ImageMagick can expose your server to Denial of Service (DoS) attacks caused by complex files or "image bombs" that consume excessive CPU and hang indefinitely. This guide demonstrates how to configure execution time limits in ImageMagick using the built-in security policy file, command-line arguments, and operating system-level process management to ensure your servers remain responsive and secure.

1. Configure the Global Policy File (policy.xml)

The most robust way to enforce time limits globally is through ImageMagick’s policy.xml file. Setting this limit ensures that no ImageMagick command—whether run manually or triggered by a web application—can exceed the allocated time.

Locate policy.xml

The configuration file is typically found in:

  • ImageMagick 7: /etc/ImageMagick-7/policy.xml
  • ImageMagick 6: /etc/ImageMagick-6/policy.xml
  • Custom/Local installations: /usr/local/etc/ImageMagick-7/policy.xml

Set the Time Limit

Open the file in a text editor with administrative privileges and add or update the time resource limit within the <policymap> tags:

<policymap>
  <!-- Limit maximum execution time to 10 seconds -->
  <policy domain="resource" name="time" value="10"/>
</policymap>

The value is specified in seconds. When an operation exceeds this duration, ImageMagick immediately aborts processing and throws a ResourceLimitExceeded error.

2. Apply Time Limits via the Command Line

If you cannot edit the global policy or need custom limits for specific tasks, pass the -limit parameter directly in your command:

magick -limit time 5 input.jpg -resize 50% output.jpg

For ImageMagick 6 installations, use the convert binary:

convert -limit time 5 input.jpg -resize 50% output.jpg

3. Implement System-Level Timeouts

Software-level limits can occasionally fail if a process deadlocks at the system level. Implementing OS-level process management adds a critical second layer of defense.

Linux timeout Command

Wrap your ImageMagick commands using the coreutils timeout tool:

timeout 10s magick input.png -resize 1000x1000 output.png

To send a forceful kill signal if the process ignores standard termination:

timeout -k 2s 10s magick input.png -resize 1000x1000 output.png

Application Runtime Timeouts

When executing ImageMagick from a backend programming language, enforce timeouts at the child-process level:

  • Node.js (child_process.exec): Set the timeout option (in milliseconds): 
    exec('magick input.jpg output.png', { timeout: 10000 }, (error, stdout, stderr) => { /* ... */ });
  • PHP: Use proc_open with stream timeouts, or use extensions like imagick while setting Imagick::setResourceLimit(Imagick::RESOURCETYPE_TIME, 10).
  • Python (subprocess.run): Use the timeout parameter: 
    subprocess.run(['magick', 'input.jpg', 'output.png'], timeout=10)

4. Verify Active Resource Limits

To confirm that your time limits are properly recognized by ImageMagick, check the current resource configuration:

magick identify -list resource

Look for the Time line in the output:

Resource limits:
  ...
  Memory: 256MiB
  Time: 10

Recommended Companion Resource Limits

Limiting time alone does not protect against all resource exhaustion attacks. Combine the time limit with other limits in policy.xml for complete DoS mitigation:

<policymap>
  <policy domain="resource" name="memory" value="256MiB"/>
  <policy domain="resource" name="map" value="512MiB"/>
  <policy domain="resource" name="area" value="128MB"/>
  <policy domain="resource" name="disk" value="1GiB"/>
  <policy domain="resource" name="thread" value="2"/>
  <policy domain="resource" name="time" value="10"/>
</policymap>
