Limit ImageMagick to a Single CPU Thread

This guide explains how to restrict ImageMagick processes to execute on a single CPU thread using its built-in security and resource policies. Modifying the policy.xml configuration file allows system administrators to prevent ImageMagick from consuming all available CPU cores via OpenMP, ensuring stable server performance and avoiding CPU starvation in shared or containerized environments.

To limit ImageMagick to a single thread, you must define the thread resource limit in the policy.xml file.

Locate the Policy File

Depending on your operating system and ImageMagick version, the policy.xml file is typically located in one of the following directories:

  • /etc/ImageMagick-7/policy.xml
  • /etc/ImageMagick-6/policy.xml
  • /usr/local/etc/ImageMagick-7/policy.xml

Add the Thread Policy Configuration

Open the policy.xml file with administrative privileges and add the following policy rule inside the <policymap> block:

<policymap>
  <!-- Restrict execution to a single thread -->
  <policy domain="resource" name="thread" value="1"/>
</policymap>

Setting name="thread" with value="1" instructs ImageMagick's OpenMP implementation to allocate only one worker thread per process, overriding the default behavior of spawning threads equal to the total number of available CPU cores.

Verify the Configuration

To verify that the thread restriction is active, run the following command in your terminal:

magick -list resource

(Note: Use identify -list resource if you are using ImageMagick 6).

Look for the Thread entry in the output list. It should display:

Resource limits:
  ...
  Thread: 1
  ...

Once applied, all subsequent ImageMagick operations executed by CLI commands or background workers will strictly adhere to the single-thread limit.
