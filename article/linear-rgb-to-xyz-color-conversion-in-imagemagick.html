Linear RGB to XYZ Color Conversion in ImageMagick

ImageMagick converts color coordinates between linear RGB and the CIE 1931 XYZ color space by applying standard \(3 \times 3\) linear matrix transformations. This article covers the mathematical operations ImageMagick uses to map color values between these spaces, detailing the normalization of internal quantum values, the forward matrix multiplication for linear RGB to XYZ, the inverse operation for XYZ to linear RGB, and how the internal color space engine executes these transformations.

Quantum Normalization

Before applying color space mathematics, ImageMagick standardizes pixel values. Regardless of whether an image is stored in 8-bit, 16-bit, or floating-point depth, pixel data is internally represented across an integer range defined by QuantumRange (such as 0 to 65,535 for Q16 builds) or as native floats in HDRI (High Dynamic Range Imaging) builds.

For linear RGB processing:

  1. Each channel value (\(R, G, B\)) is normalized to a floating-point range of \([0.0, 1.0]\) by dividing the raw channel value by QuantumRange.
  2. Because the source is strictly linear RGB, no gamma decoding or inverse companding (such as the sRGB transfer function) is performed. The normalized values directly represent linear light intensities.

Linear RGB to CIE 1931 XYZ Transformation

ImageMagick maps linear RGB coordinates to CIE 1931 XYZ coordinates using a standard matrix derived from the ITU-R Recommendation BT.709 primaries and a CIE Standard Illuminant D65 reference white point (\(X_n = 0.95047, Y_n = 1.00000, Z_n = 1.08883\)).

In ImageMagick’s core colorspace engine (primarily implemented in MagickCore/colorspace.c), the conversion executes the following linear system:

\[X = (0.4124564 \times R) + (0.3575761 \times G) + (0.1804375 \times B)\] \[Y = (0.2126729 \times R) + (0.7151522 \times G) + (0.0721750 \times B)\] \[Z = (0.0193339 \times R) + (0.1191920 \times G) + (0.9503041 \times B)\]

The resulting \(Y\) coordinate corresponds directly to the photometric luminance of the color, while \(X\) and \(Z\) define the chromaticity components relative to human tristimulus curves.

CIE 1931 XYZ to Linear RGB Transformation

To reverse the conversion and recover linear RGB from XYZ coordinates, ImageMagick uses the inverse of the D65 BT.709 matrix:

\[R = (3.2404542 \times X) + (-1.5371385 \times Y) + (-0.4985314 \times Z)\] \[G = (-0.9692660 \times X) + (1.8760108 \times Y) + (0.0415560 \times Z)\] \[B = (0.0556434 \times X) + (-0.2040259 \times Y) + (1.0572252 \times Z)\]

When converting out of XYZ, color coordinates that fall outside the gamut of the target RGB space can produce values less than \(0.0\) or greater than \(1.0\). Non-HDRI builds will automatically clamp these values to \([0, \text{QuantumRange}]\) during re-quantization, while HDRI builds retain the out-of-gamut floating-point values.

Scaling Back to ImageMagick Quantum Values

After the matrix multiplication:

  1. The floating-point results (\(X, Y, Z\) or \(R, G, B\)) are multiplied by QuantumRange.
  2. The values are assigned back to the image's pixel channels (where Channel 0 represents \(X\) or \(R\), Channel 1 represents \(Y\) or \(G\), and Channel 2 represents \(Z\) or \(B\)).
  3. ImageMagick updates the image metadata to reflect the target colorspace (XYZColorspace or RGBColorspace).
