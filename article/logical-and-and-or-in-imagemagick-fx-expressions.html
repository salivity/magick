Logical AND and OR in ImageMagick FX Expressions

ImageMagick's -fx special effects operator allows users to construct complex, per-pixel mathematical expressions using standard arithmetic and logical operations. This article explores how ImageMagick parses and evaluates logical AND (&&) and logical OR (||) operators within complex -fx strings, detailing their truthiness models, operator precedence, short-circuiting behavior, and integration with ternary conditionals.

Boolean Representation and Truthiness

The -fx engine handles pixel channel data as normalized double-precision floating-point values, generally falling between 0.0 (black/minimum) and 1.0 (white/maximum). Because it operates strictly on floating-point arithmetic rather than dedicated boolean types, logical evaluation relies on numeric zero and non-zero values:

  • False: Any expression resolving exactly to 0.0.
  • True: Any expression resolving to any non-zero value (typically 1.0, but negative or fractional numbers such as 0.2 or -1.5 are also treated as true).

When an expression using && or || is evaluated, the result itself is strictly normalized to a numeric boolean output: 1.0 for true and 0.0 for false. Unlike scripting languages such as Python or JavaScript, ImageMagick does not return the value of the resolving operand; it returns binary 1.0 or 0.0.

Operator Precedence

In complex arithmetic strings, ImageMagick follows standard C-style operator precedence rules. Logical operators sit relatively low in the hierarchy:

  1. Parentheses: ()
  2. Unary Operations: -, !
  3. Multiplicative Arithmetic: *, /, %
  4. Additive Arithmetic: +, -
  5. Relational Operators: <, <=, >, >=, ==, !=
  6. Logical AND: &&
  7. Logical OR: ||
  8. Conditional (Ternary): ? :

Because && has higher precedence than ||, the engine groups AND expressions before OR expressions. For example, the expression:

u > 0.5 || v < 0.2 && w == 1.0

is evaluated identically to:

(u > 0.5) || ((v < 0.2) && (w == 1.0))

Short-Circuit Evaluation

ImageMagick’s expression parser employs short-circuit logic when evaluating expressions containing && and ||:

  • For A && B: If A evaluates to 0.0 (false), B is skipped entirely, and the sub-expression immediately returns 0.0.
  • For A || B: If A evaluates to any non-zero value (true), B is skipped, and the sub-expression immediately returns 1.0.

This short-circuiting is critical when combining channel lookups or avoiding potential divide-by-zero errors in complex formulas, such as u != 0 && (v / u) > 0.5.

Use Within Ternary Expressions

Logical operators are most frequently paired with the conditional ternary operator (condition ? true_val : false_val) to build masks, segmentations, or channel blends.

Because the ternary operator has lower precedence than both && and ||, complex compound checks can be placed directly in the conditional slot without excessive nesting:

u.r > 0.5 && u.g < 0.2 || u.b > 0.8 ? 1.0 : 0.0

Explicit parentheses are still recommended in multi-level conditions to prevent ambiguity and ensure expressions remain predictable across different ImageMagick versions (ImageMagick 6 versus the updated syntax engine in ImageMagick 7).
