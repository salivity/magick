Measure Character Bounding Boxes in ImageMagick

This article provides a direct guide to identifying and measuring the bounding box dimensions of individual scanned characters using ImageMagick. By preprocessing the image and applying the connected-components labeling feature, you can extract the exact width, height, and positional coordinates of each character directly from the command line without external OCR frameworks.

Step 1: Preprocess the Scanned Image

Scanned documents generally contain noise, background gradients, and anti-aliasing around text glyphs. ImageMagick must first reduce the scan to a high-contrast binary (black and white) image.

Characters should ideally be isolated as white foreground objects against a black background, as connected-components analysis treats white pixels as distinct objects by default.

magick scanned_text.png -colorspace gray -negate -threshold 50% preprocessed.png
  • -colorspace gray: Strips color channels to simplify the pixel values.
  • -negate: Inverts the image so that black ink becomes white foreground objects.
  • -threshold 50%: Forces pixels to strictly black (0) or white (max value), removing compression artifacts. Adjust the percentage depending on the scan exposure.

Step 2: Run Connected-Components Analysis

ImageMagick provides the -connected-components operator to segment an image into distinct contiguous clusters of pixels. To output geometry and dimensions to the terminal without writing a new image, output to null:.

Execute the following command:

magick scanned_text.png \
  -colorspace gray \
  -negate \
  -threshold 50% \
  -define connected-components:verbose=true \
  -define connected-components:area-threshold=10 \
  -connected-components 8 \
  null:
  • -define connected-components:verbose=true: Outputs the statistical properties of each detected component to standard output.
  • -define connected-components:area-threshold=10: Discards any speckles or artifacts smaller than 10 total pixels to prevent stray scan noise from registering as characters.
  • -connected-components 8: Groups pixels sharing edges or corners (8-connectivity).
  • null:: Discards the visual image output while still generating the text stream.

Step 3: Parse the Bounding Box Data

When run with verbose mode enabled, ImageMagick generates a structured text table formatted like this:

Objects (id: box centroid area color):
  0: 1200x800+0+0 598.1,399.4 945120 srgb(0,0,0)
  1: 18x24+142+88 150.3,99.7 215 srgb(255,255,255)
  2: 12x25+164+87 169.8,99.2 145 srgb(255,255,255)
  3: 16x18+180+94 187.6,102.8 160 srgb(255,255,255)

The fields are defined as follows:

  • id: The component label identifier. Object 0 is typically the background.
  • box: The bounding box in WidthxHeight+X+Y syntax. For example, 18x24+142+88 indicates a character that is 18 pixels wide, 24 pixels high, offset 142 pixels from the left margin, and 88 pixels from the top margin.
  • centroid: The geometric center coordinate (X,Y) of the object.
  • area: The total pixel count inside the character.
  • color: The color used to identify the component (srgb(255,255,255) signifies foreground characters).

Step 4: Extract Only the Character Dimensions

To isolate the bounding boxes of characters and filter out the background entry, pipe the output through standard command-line filtering tools like awk:

magick scanned_text.png \
  -colorspace gray \
  -negate \
  -threshold 50% \
  -define connected-components:verbose=true \
  -define connected-components:area-threshold=10 \
  -connected-components 8 \
  null: | awk '/srgb\(255,255,255\)/ {print $2}'

This command filters exclusively for the white foreground components and prints a list of bounding box measurements (such as 18x24+142+88) suitable for parsing in automated batch pipelines.
