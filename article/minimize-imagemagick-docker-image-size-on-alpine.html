Minimize ImageMagick Docker Image Size on Alpine

Packaging ImageMagick in Docker using Alpine Linux provides a lightweight foundation, but default installations and unoptimized builds can still introduce unnecessary bloat. This guide covers practical techniques to minimize the resulting container image size, including utilizing multi-stage builds, compiling ImageMagick with only essential delegates, stripping binaries of debugging symbols, and properly managing Alpine package caches.

1. Avoid Default Package Installs When Possible

The simplest way to install ImageMagick on Alpine is via the package manager:

RUN apk add --no-cache imagemagick

While convenient, the Alpine package repository builds ImageMagick with support for dozens of delegate libraries (such as X11, font engines, and obscure image formats) that you may not need. If your application only processes specific formats like JPEG, PNG, or WebP, compiling ImageMagick from source lets you exclude unused delegates and significantly reduce image size.

2. Implement Multi-Stage Builds

When compiling ImageMagick from source, never leave build-time tools (like gcc, make, and header files) in the final image. Use a multi-stage Docker build to separate the compilation environment from the runtime environment.

  • Build stage: Contains compilers, development headers (-dev packages), and source code.
  • Final stage: Contains only the minimal Alpine base, runtime libraries, and the compiled ImageMagick binaries.

3. Disable Unnecessary Delegates and Features

When running ./configure during a source build, explicitly disable unused features. Common flags to reduce footprint include:

  • --without-x: Disables X11 windowing support.
  • --without-magick-plus-plus: Omits C++ bindings if you only need the CLI or C API.
  • --without-perl: Omits Perl language bindings.
  • --disable-openmp: Disables multi-core OpenMP overhead if running in low-resource containers.
  • --disable-docs: Prevents generating and copying manual pages and documentation.

4. Strip Debug Symbols

Compiled binaries and shared libraries contain symbol tables and debugging data by default. Stripping these reduces file sizes substantially:

strip --strip-all /usr/local/bin/magick
strip --strip-unneeded /usr/local/lib/libMagick*.so

5. Optimized Multi-Stage Dockerfile Example

The following Dockerfile demonstrates a minimal compilation of ImageMagick 7 on Alpine Linux, configured only for JPEG and PNG support:

# Stage 1: Build ImageMagick
FROM alpine:3.20 AS builder

ARG IM_VERSION=7.1.1-33

RUN apk add --no-cache \
    build-base \
    curl \
    libpng-dev \
    libjpeg-turbo-dev \
    zlib-dev

WORKDIR /tmp
RUN curl -SL https://github.com/ImageMagick/ImageMagick/archive/refs/tags/${IM_VERSION}.tar.gz | tar -xz && \
    cd ImageMagick-${IM_VERSION} && \
    ./configure \
        --prefix=/usr/local \
        --without-x \
        --without-perl \
        --without-magick-plus-plus \
        --without-modules \
        --disable-docs \
        --disable-static \
        --enable-shared \
        --with-jpeg=yes \
        --with-png=yes \
        --with-zlib=yes && \
    make -j$(nproc) && \
    make install && \
    strip --strip-all /usr/local/bin/magick && \
    strip --strip-unneeded /usr/local/lib/libMagickCore-*.so* && \
    strip --strip-unneeded /usr/local/lib/libMagickWand-*.so*

# Stage 2: Minimal Runtime
FROM alpine:3.20

# Install only runtime shared libraries
RUN apk add --no-cache \
    libpng \
    libjpeg-turbo \
    zlib

# Copy compiled binaries, configuration, and libraries from builder
COPY --from=builder /usr/local/bin/magick /usr/local/bin/
COPY --from=builder /usr/local/lib/libMagick* /usr/local/lib/
COPY --from=builder /usr/local/etc/ImageMagick-7 /usr/local/etc/ImageMagick-7

# Rebuild library cache links
RUN ldconfig /usr/local/lib

ENTRYPOINT ["magick"]

6. Clean Up Runtime Layers

If you opt for apk add instead of building from source:

  • Always use the --no-cache flag with apk add to avoid writing index files to /var/cache/apk/.
  • Combine package installations into a single RUN command to prevent intermediate, bloated layers.
  • Remove any temporary configuration or test assets created during container setup.
