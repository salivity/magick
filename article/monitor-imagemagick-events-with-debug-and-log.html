Monitor ImageMagick Events with Debug and Log

ImageMagick provides robust built-in logging capabilities that allow users and developers to inspect internal operations, diagnose processing errors, and optimize workflow performance. This article explains how to monitor internal ImageMagick events using the -debug and -log command-line options, select specific event categories, customize log output formats, and redirect event messages for analysis.

The -debug Option

The -debug option tells ImageMagick which internal events to log during execution. By default, debugging is disabled. You can target specific subsystems or enable logging across all operations.

Syntax

magick input.jpg -debug <events> output.png

Common Event Categories

You can pass one or more comma-separated event types to -debug:

  • All: Logs every internal event (generates substantial output).
  • Coder: Traces the reading and writing of image file formats.
  • Resource: Tracks resource management, such as memory allocation, pixel cache, and disk usage.
  • Transform: Monitors geometric operations, such as resizing, cropping, and rotations.
  • Blob: Tracks binary data (BLOB) reads and writes.
  • Exception: Logs internal warnings, errors, and fatal exceptions.
  • Performance: Logs execution times for various internal tasks.
  • Trace: Logs function entries and exits for low-level debugging.

Example

To log only image format decoding and encoding events:

magick convert input.png -debug Coder output.jpg

To monitor multiple specific categories simultaneously:

magick convert input.png -debug "Coder,Resource" output.jpg

The -log Option

The -log option controls the format and structure of the log messages generated by -debug. It accepts a format string composed of literal text and percent-encoded conversion specifiers.

Syntax

magick input.jpg -debug <events> -log <format> output.png

Common Format Specifiers

  • %d: Module domain or event category.
  • %e: Event description.
  • %f: Function name where the event occurred.
  • %l: Source code line number.
  • %m: Source code module name.
  • %p: Process ID (PID).
  • %r: Elapsed CPU time since the start of execution.
  • %s: Severity level (e.g., Information, Warning, Error).
  • %t: Current timestamp (wall-clock time).
  • %u: Total user CPU time consumed.

Example

To format log messages with a timestamp, the event domain, and the event description:

magick input.jpg -debug All -log "%t [%d] %e" output.png

Combining -debug and -log in Practice

Combining both options allows you to capture precise, timestamped diagnostic logs.

magick input.tif -resize 50% -debug "Transform,Resource" -log "%t (%r) [%d] %e" output.tif

Redirecting Log Output to a File

By default, ImageMagick sends all debug logs to standard error (stderr). To store the logs in a separate file without polluting the terminal, redirect standard error:

magick input.png -debug All -log "%t [%d] %e" output.jpg 2> debug.log

Persistent Configuration via log.xml

For system-wide or persistent logging configurations, ImageMagick references an internal XML configuration file called log.xml. This file defines default logging handlers (such as logging to the console, a file, or the system event log), default event filters, and formatting strings. While command-line options (-debug and -log) override these settings for individual commands, editing log.xml is useful for background services and automated server environments.
