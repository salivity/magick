Multi-Threaded ImageMagick Batch Conversion in C#

This article provides a practical guide on performing high-performance, multi-threaded batch image conversions in C# using the Magick.NET library. You will learn how to configure ImageMagick's internal resource settings to prevent CPU contention, implement asynchronous parallel processing with Parallel.ForEachAsync, and handle image cleanup to maximize throughput while preventing memory exhaustion.

1. Install the Magick.NET Package

First, add the Magick.NET library to your C# project. The standard 8-bit color depth version is typically sufficient for web images:

dotnet add package Magick.NET-Q8-AnyCPU

2. Configure Internal Concurrency

By default, ImageMagick uses OpenMP to execute single image operations across multiple threads. When batch processing many images concurrently using C#'s parallel constructs, these internal threads fight for CPU time, causing severe thread contention and performance degradation.

To achieve optimal throughput, restrict each ImageMagick operation to a single thread and manage the parallelism entirely inside your C# code:

using ImageMagick;

// Disable ImageMagick's internal multithreading per image
ResourceLimits.LimitThreads(1);

3. Implement the Multi-Threaded Conversion Pipeline

Use Parallel.ForEachAsync to distribute conversion tasks across available CPU cores. Set MaxDegreeOfParallelism to the system processor count to prevent oversubscription.

Here is the complete implementation for converting a directory of images (e.g., PNG, TIFF) to compressed WebP format:

using System;
using System.IO;
using System.Linq;
using System.Threading;
using System.Threading.Tasks;
using ImageMagick;

class Program
{
    static async Task Main(string[] args)
    {
        string inputDirectory = @"C:\Images\Input";
        string outputDirectory = @"C:\Images\Output";

        Directory.CreateDirectory(outputDirectory);

        // Limit internal threads so C# manages the concurrency
        ResourceLimits.LimitThreads(1);

        // Retrieve all files to convert
        var supportedExtensions = new[] { ".jpg", ".jpeg", ".png", ".tiff", ".bmp" };
        var imageFiles = Directory.EnumerateFiles(inputDirectory)
            .Where(f => supportedExtensions.Contains(Path.GetExtension(f).ToLowerInvariant()))
            .ToList();

        var parallelOptions = new ParallelOptions
        {
            MaxDegreeOfParallelism = Environment.ProcessorCount
        };

        await Parallel.ForEachAsync(imageFiles, parallelOptions, async (filePath, cancellationToken) =>
        {
            await Task.Run(() => ConvertImage(filePath, outputDirectory), cancellationToken);
        });

        Console.WriteLine("Batch conversion completed.");
    }

    private static void ConvertImage(string inputPath, string outputDirectory)
    {
        try
        {
            string fileNameWithoutExt = Path.GetFileNameWithoutExtension(inputPath);
            string outputPath = Path.Combine(outputDirectory, $"{fileNameWithoutExt}.webp");

            // MagickImage instances are NOT thread-safe; instantiate per thread
            using var image = new MagickImage(inputPath);

            // Apply conversions and optimizations
            image.Format = MagickFormat.Webp;
            image.Quality = 80;
            image.Strip(); // Remove metadata (EXIF, profiles) to reduce file size

            image.Write(outputPath);
        }
        catch (Exception ex)
        {
            Console.WriteLine($"Error processing {inputPath}: {ex.Message}");
        }
    }
}

Key Performance Considerations

  • Instance Isolation: Instances of MagickImage are not thread-safe. Always instantiate and dispose of a unique MagickImage within the executing thread. Never share an instance across multiple tasks.
  • Metadata Stripping: Calling image.Strip() removes color profiles, GPS data, and EXIF tags, which speeds up I/O and reduces the final file size.
  • Memory Management: High-resolution images consume substantial unmanaged memory. The using statement ensures native resources are freed immediately upon task completion rather than waiting for garbage collection.
