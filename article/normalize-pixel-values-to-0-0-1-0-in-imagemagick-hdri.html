Normalize Pixel Values to 0.0-1.0 in ImageMagick HDRI

This guide explains how to scale and normalize pixel intensity values to a standardized 0.0 to 1.0 floating-point range using ImageMagick compiled with High Dynamic Range Imaging (HDRI) support. In HDRI builds, pixels are stored as floating-point numbers that can exceed traditional bounds and negative values. Normalizing these values ensures compatibility across scientific data pipelines, computer vision frameworks, and floating-point image exports.

Understanding HDRI and QuantumRange

In standard ImageMagick HDRI builds (such as Q16HDRI or Q32HDRI), pixel values are represented internally as floating-point numbers relative to QuantumRange (which is 65535 for Q16 and 4294967295 for Q32), where 0 represents black and QuantumRange represents reference white. When normalizing to an absolute [0.0, 1.0] scale, you must map the minimum and maximum data points or divide by the quantum scale.

Method 1: Mathematical Min-Max Normalization (-auto-level)

If your HDRI image contains negative values or values exceeding standard white, and you want to stretch the exact minimum value to 0.0 and the exact maximum to 1.0 (relative to the quantum range):

magick input.exr -auto-level output.exr

-auto-level dynamically finds the lowest value in the image, shifts it to 0, and scales the highest value up to the maximum reference quantum range without clipping data.

Method 2: Direct Scaling to Absolute 0.0–1.0 Floating-Point Values

To explicitly convert the internal 0–QuantumRange values to a strict 0.0–1.0 numerical range, divide every pixel by QuantumRange:

magick input.exr -evaluate Divide "%[QuantumRange]" output.pfm

This ensures that the reference white point is exactly 1.0 and pure black is 0.0. Values originally brighter than standard white will remain proportionally greater than 1.0.

Method 3: Min-Max Mapping to Absolute 0.0–1.0 via FX

To perform true min-max normalization where arbitrary HDRI data is bounded strictly between 0.0 and 1.0 regardless of input ranges:

magick input.exr -fx "(u-minima)/(maxima-minima)" output.pfm

Note: The -fx operator processes pixels sequentially and is slower on large images, but it guarantees an exact mathematical transformation.

Exporting Pixel Data as 0.0–1.0

To ensure the exported file retains the 32-bit floating-point precision in the [0.0, 1.0] range, save the output in a float-compatible format (such as .pfm, .exr, or .tiff with floating-point formatting enabled):

magick input.exr -auto-level -define quantum:format=floating-point -depth 32 output.tif

To output the normalized data directly as plain text for verification:

magick input.exr -auto-level -evaluate Divide "%[QuantumRange]" txt:-
