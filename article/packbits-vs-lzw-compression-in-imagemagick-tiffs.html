PackBits vs LZW Compression in ImageMagick TIFFs

When generating TIFF files using ImageMagick, choosing the right compression method is critical for balancing file size, processing speed, and compatibility. PackBits and LZW (Lempel-Ziv-Welch) are two standard, lossless compression algorithms supported by ImageMagick via the -compress flag. This article explains the technical differences between PackBits and LZW, evaluates their performance regarding compression ratio and processing speed, and outlines when to use each format in your ImageMagick workflows.

Algorithmic Differences

  • PackBits (-compress PackBits): PackBits is a simple byte-level Run-Length Encoding (RLE) scheme introduced by Apple for Macintosh TIFF files. It identifies repeated sequences of identical bytes and stores them as a count followed by the byte value. Because it only looks for consecutive repeating bytes, it is extremely basic and computationally inexpensive.
  • LZW (-compress LZW): LZW is a dictionary-based compression algorithm. Instead of only looking for repeated single bytes, it builds a table of repeating strings and patterns as it reads the data, replacing frequent patterns with shorter codes. This allows LZW to compress more complex image data far more effectively than basic run-length encoding.

Compression Efficiency and File Size

  • Continuous-Tone Imagery (Photographs): PackBits performs poorly on photographic images, scanned gradients, or noisy data because adjacent bytes rarely have identical values. In some cases, PackBits can even slightly increase the file size of continuous-tone images due to run-length metadata overhead. LZW, while not as aggressive as ZIP (Deflate), handles continuous-tone imagery significantly better by identifying recurring bit patterns.
  • Simple Graphics and Line Art: For bilevel (1-bit black and white) images, simple line art, or screenshots with vast areas of solid color, PackBits can achieve adequate compression. However, LZW generally matches or exceeds PackBits even on these asset types.

Processing Speed and Resource Usage

  • PackBits: Because the algorithm requires virtually no memory structures and relies on simple loop checks, it encodes and decodes at near-instantaneous speeds with negligible CPU overhead.
  • LZW: Maintaining and parsing the pattern dictionary requires more memory and CPU cycles. While still fast on modern hardware, LZW is noticeably slower than PackBits during large batch-processing tasks in ImageMagick.

Compatibility

Both algorithms are part of the baseline TIFF specification and enjoy universal support across legacy imaging systems, modern software, desktop operating systems, and commercial printing RIP (Raster Image Processor) software. The historical patent issues surrounding LZW expired in the early 2000s, making both formats entirely free of licensing restrictions.

ImageMagick Usage and Recommendations

To specify either compression type in ImageMagick, use the -compress option before defining your output file:

# Using PackBits
magick input.png -compress PackBits output_packbits.tif

# Using LZW
magick input.png -compress LZW output_lzw.tif

When to choose PackBits:

  • You are generating simple images or line art where encoding speed is the absolute highest priority.
  • You are targeting legacy workflows or microcontrollers with severe CPU and memory limitations.

When to choose LZW:

  • You want a reliable, universally supported lossless compression method that delivers significantly smaller file sizes on diverse image types without sacrificing compatibility.
