Packing Sprite Atlases with ImageMagick

Creating a tightly packed texture atlas from non-uniform images using ImageMagick requires arranging varied dimensions efficiently to minimize wasted transparent space. While ImageMagick does not contain a native 2D bin-packing algorithm like MaxRects out of the box, you can achieve a dense layout by sorting your source assets, calculating coordinate offsets, and using ImageMagick’s composition and mosaic operators to build the final atlas.

Step 1: Pre-Process and Trim Images

Before packing, remove unnecessary transparent padding from individual sprites to ensure the tightest possible fit.

magick mogrify -trim +repage *.png

This command crops every PNG in the working directory to its non-transparent bounding box and resets the virtual canvas metadata.

Step 2: Understand the Limitations of Built-In Commands

ImageMagick provides basic concatenation tools:

  • +append: Appends images horizontally.
  • -append: Appends images vertically.
  • montage: Arranges images in uniform grid cells, which wastes space when images have non-uniform dimensions.

For irregularly sized assets, simple appending creates uneven rows or columns. To pack non-uniform images tightly, you must place each image at specific (X, Y) pixel offsets.

Step 3: Sort Assets by Dimension

Bin-packing heuristics work best when placing larger images first. Sort your sprite filenames by decreasing height or area using a script or terminal command before generating coordinates:

# Example (Linux/macOS): List images sorted by height using ImageMagick format tags
magick identify -format "%h %w %f\n" *.png | sort -nr

Step 4: Assemble the Atlas Using Coordinate Offsets

Once the coordinates for each sprite are calculated (either manually or via a packing script), assemble the final texture atlas using the -page operator and -mosaic or -layers merge.

Method A: Using -mosaic

magick -page +0+0 sprite_large.png \
       -page +256+0 sprite_tall.png \
       -page +0+128 sprite_small1.png \
       -page +64+128 sprite_small2.png \
       -background none -mosaic texture_atlas.png
  • -page +X+Y: Sets the offset for the image that follows it.
  • -background none: Ensures the unused canvas area remains transparent.
  • -mosaic: Merges all images onto a single canvas dynamically expanded to fit the outermost coordinates.

Method B: Using -layers merge

For larger workflows with predefined canvas dimensions:

magick -size 1024x1024 xc:none \
       \( sprite_large.png -geometry +0+0 \) -composite \
       \( sprite_tall.png -geometry +256+0 \) -composite \
       \( sprite_small1.png -geometry +0+128 \) -composite \
       atlas_1024.png

Step 5: Automate Packing with a Script

For dynamic generation of non-uniform sprite sheets, combine a lightweight packing algorithm (such as a shelf-packing or guillotine algorithm in Python or Node.js) with ImageMagick to handle the final image rasterization:

  1. Read sprite dimensions using magick identify -format "%w %h %f\n" *.png.
  2. Compute the tightest bounding box coordinates (x, y) for each asset.
  3. Output the coordinate arguments into a single ImageMagick execution command.
  4. Run the generated command to produce the finished .png texture atlas along with an accompanying coordinate data file (JSON or XML) for rendering engines.
