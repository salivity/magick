Parsing ImageMagick Custom Morphology Kernels

ImageMagick's morphology operations allow users to define custom convolution matrices and structuring elements using a specialized geometry:values string format. This syntax provides a compact, text-based method for specifying matrix dimensions, anchor point offsets, and cell-by-cell numerical weights. Understanding how ImageMagick parses this string allows for precise control over custom filters, edge detectors, thinning algorithms, and morphological transformations.

Syntax Breakdown: geometry:values

The kernel definition string is divided into two primary sections separated by a colon (:):

  1. Geometry ([width]x[height][+x+y]): Defines the matrix structure and the coordinate of the origin (hotspot).
  2. Values (val1,val2,val3...): A sequential list of numerical weights mapped to individual matrix cells.

Parsing the Geometry Component

The parser first isolates the substring preceding the colon to determine the matrix dimensions and kernel origin:

  • Dimensions (WxH): The integers preceding and succeeding the x character define the width (columns) and height (rows) of the kernel. If the height is omitted (e.g., 3: or 5x:), ImageMagick interprets the matrix as a square where height equals width.
  • Origin Offsets (+x+y): The optional +x+y parameters designate the kernel origin, which determines which pixel in the neighborhood corresponds to the output pixel being calculated. ImageMagick uses a zero-indexed coordinate system with +0+0 positioned at the top-left cell. If offsets are omitted, ImageMagick defaults the origin to the geometric center: floor((width - 1) / 2) and floor((height - 1) / 2).

For example, a geometry of 5x3+1+1 constructs a matrix 5 columns wide and 3 rows high, setting the center of operation on the second column of the second row.

Parsing the Values Component

The substring following the colon contains the cell data, parsed using the following rules:

  • Row-Major Ordering: Values are read sequentially from left to right, top to bottom. The first W values populate row 0, the next W values populate row 1, and so on until W * H values are assigned.
  • Delimiters: Values can be separated by commas, spaces, or tabs. When using spaces in command-line environments, the entire kernel string must be enclosed in quotes.
  • Value Types:
    • Floating-point numbers: Standard positive or negative decimal numbers (e.g., 1, -0.5, 2.3).
    • nan (Not a Number): Represents an undefined or "don't care" cell. In morphological operations (such as Hit-and-Miss or Dilate), cells marked as nan are ignored during neighborhood calculations, allowing non-rectangular or masked kernel shapes.
    • Empty Cells / Shorthand: Successive commas (e.g., 1,,1) or a trailing comma can be interpreted by ImageMagick's parser as nan depending on the operation context.

Execution Process

When a custom morphology argument is supplied (such as -morphology Convolve "3x3: 0,-1,0 -1,5,-1 0,-1,0"), ImageMagick processes the string internally through the following steps:

  1. String Splitting: ImageMagick splits the input string at the first colon character into a geometry token and a values token.
  2. Allocation: It calls internal geometry parsers to extract width, height, and origin offsets. Memory is allocated for a 1D floating-point array of size width * height.
  3. Tokenization: The values token is parsed into individual floating-point values or nan designations. If the number of parsed values is fewer than width * height, remaining elements default to nan or 0.0 based on the morphology method. Excess values beyond the specified dimension are ignored.
  4. Kernel Struct Creation: The array, dimensions, and normalized origin coordinates are bundled into a KernelInfo structure, which is then passed directly to the convolution or morphology processing pipeline.
