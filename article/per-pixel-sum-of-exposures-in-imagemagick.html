Per-Pixel Sum of Exposures in ImageMagick

Calculating the per-pixel sum of multiple exposure captures in ImageMagick involves stacking images and adding their corresponding pixel values together. This process is commonly used in astrophotography, long-exposure simulation, and computational photography to combine light data across several frames. This guide explains how to use the -evaluate-sequence operator, configure high dynamic range imaging (HDRI) to avoid highlight clipping, and export the resulting data into an appropriate format.

The Core Command: -evaluate-sequence sum

ImageMagick provides the -evaluate-sequence operator to perform arithmetic operations across an entire sequence of images at the pixel level. To calculate the sum across all input images, use the sum (or add) argument.

In ImageMagick 7, the standard syntax is:

magick capture1.tif capture2.tif capture3.tif -evaluate-sequence sum output.tif

If you have a large batch of images named sequentially or sharing an extension, you can use wildcard matching:

magick capture_*.tif -evaluate-sequence sum output.tif

Managing Dynamic Range and Highlight Clipping

When summing exposure captures, adding pixel values together will quickly exceed the maximum value of standard 8-bit (0–255) or 16-bit (0–65535) integer formats. If standard formats are used without precautions, any pixel sum exceeding the maximum threshold will clip to pure white.

To accurately preserve the summed data:

  1. Use ImageMagick with HDRI Enabled: ImageMagick 7 enables High Dynamic Range Imaging (HDRI) by default. HDRI allows pixels to hold floating-point values and numbers greater than 1.0 (or beyond the standard quantum depth) without clipping during processing.
  2. Save to a 32-bit Floating-Point Format: Export the final image to a format capable of storing values above standard limits, such as 32-bit TIFF, OpenEXR (.exr), or Portable Float Map (.pfm).
magick capture_*.tif -define quantum:format=floating-point -depth 32 -evaluate-sequence sum output.exr

Normalizing or Scaling the Sum

If your target format requires standard integer depths (such as an 8-bit or 16-bit TIFF/PNG for display purposes), the summed data must be scaled back down to fit within standard dynamic range.

Option A: Average Instead of Sum

If you want to combine multiple exposures to reduce noise without increasing overall brightness, use mean instead of sum:

magick capture_*.tif -evaluate-sequence mean averaged_exposure.tif

Option B: Divide the Summed Result

If you must calculate the raw sum first, you can scale it down by dividing the final image by the total number of frames (for example, 4 captures):

magick capture_*.tif -evaluate-sequence sum -evaluate divide 4 output_normalized.tif

Memory Optimization for Large Image Sets

Loading hundreds of high-resolution RAW or TIFF exposures simultaneously can consume significant system memory. To optimize throughput when summing large sequences, instruct ImageMagick to limit resource usage or process images using stream mechanisms:

magick -limit memory 4GiB -limit map 8GiB capture_*.tif -evaluate-sequence sum -depth 32 output.tif

Using -evaluate-sequence sum with HDRI and a 32-bit floating-point container guarantees an exact, unclipped per-pixel summation of all exposure data across your dataset.
