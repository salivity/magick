Pipe ImageMagick Output to FFmpeg Video Encoder

Piping ImageMagick output directly into the FFmpeg video encoder allows you to process or generate image frames in memory and encode them into a video stream without writing temporary files to disk. This workflow significantly reduces disk I/O, speeds up automated rendering pipelines, and saves storage space.

Basic Syntax

To stream frames from ImageMagick to FFmpeg, set ImageMagick's output format to an uncompressed stream like PPM (Portable Pixmap) or Y4M (YUV4MPEG2) targeting standard output (-), and configure FFmpeg to read from standard input (-i -).

Using the PPM format:

magick input_*.png ppm:- | ffmpeg -f image2pipe -framerate 24 -i - -c:v libx264 -pix_fmt yuv420p output.mp4

For ImageMagick v6, replace magick with convert:

convert input_*.png ppm:- | ffmpeg -f image2pipe -framerate 24 -i - -c:v libx264 -pix_fmt yuv420p output.mp4

Parameter Breakdown

  • ppm:-: Directs ImageMagick to format the image data as a continuous stream of PPM images and send it to standard output (stdout).
  • -f image2pipe: Informs FFmpeg that the input stream consists of a continuous sequence of piped images.
  • -framerate 24: Sets the incoming frame rate of the video. This must be placed before the -i parameter to apply to the input stream.
  • -i -: Instructs FFmpeg to read the input from standard input (stdin).
  • -c:v libx264: Encodes the video using the H.264 video codec.
  • -pix_fmt yuv420p: Sets the pixel format to YUV 4:2:0, ensuring broad compatibility across standard media players.

Alternative Syntax Using YUV4MPEG2

If you prefer to include frame rate and resolution metadata directly in the piped stream header, use the Y4M format:

magick input_*.png -define y4m:fps=30/1 y4m:- | ffmpeg -i - -c:v libx264 -pix_fmt yuv420p output.mp4

When using y4m:-, FFmpeg automatically detects the framerate, resolution, and pixel format from the Y4M header, allowing you to omit the -f image2pipe and -framerate flags.
