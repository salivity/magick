Pixel Dimensions vs Canvas Density in ImageMagick

This article explains the critical distinction in ImageMagick between physical pixel dimensions and canvas density units. While physical pixel dimensions define the raw raster data—the exact width and height measured in discrete pixels—canvas density specifies the spatial resolution metadata, such as dots per inch (DPI) or pixels per centimeter (PPCM). Understanding how these two attributes interact is essential for accurately controlling digital screen rendering, physical print scaling, and vector-to-raster conversions.

Physical Pixel Dimensions

Physical pixel dimensions represent the actual matrix of pixels that make up a digital raster image. Measured as width by height (for example, 1920x1080), this count represents the true data volume of the image.

In ImageMagick, operations like -resize, -scale, or -extent manipulate the physical pixel dimensions. Modifying these dimensions alters the underlying raster grid through interpolation or resampling, which directly impacts the image's file size, memory footprint, and display size on standard pixel-based screens.

Canvas Density Units

Canvas density defines how many pixels should be mapped to a physical unit of real-world measurement. It is represented as a ratio, typically PixelsPerInch (PPI/DPI) or PixelsPerCentimeter (PPCM).

In ImageMagick, density is set using the -density operator alongside the -units operator (such as -units PixelsPerInch). On raster formats like JPEG or PNG, setting the density does not add, remove, or modify any pixels in the image; it merely updates the metadata header to instruct output devices—primarily printers—how large to render those pixels physically.

The physical print size follows a straightforward formula: \[\text{Physical Size (Inches)} = \frac{\text{Pixel Dimension}}{\text{Density (PPI)}}\]

For example, an image measuring 3000x2000 pixels with a density of 300 PPI will print at 10x6.67 inches. If the density metadata is changed to 100 PPI without changing the pixel dimensions, the file size remains identical, but the intended print output expands to 30x20 inches.

Key Differences

  • Data vs. Metadata: Pixel dimensions define the actual raster data array. Canvas density is metadata instructing an output medium how densely to pack that data.
  • Storage and Memory: Altering pixel dimensions resamples the image, changing its memory use and detail level. Altering canvas density changes only a header value without rewriting the pixel grid.
  • Screen vs. Print: Digital displays render images based primarily on physical pixel dimensions. Physical mediums (printers, publishing workflows) rely on canvas density to calculate real-world dimensions.

Behavior with Vector Formats

A notable exception in ImageMagick occurs when working with vector input formats, such as PDF or SVG. Because vector graphics possess no inherent pixel grid, defining the -density before reading the input file dictates the physical pixel dimensions of the generated raster image:

magick -density 300 input.pdf output.png

In this context, canvas density acts as a scaling factor that directly determines the final physical pixel dimensions of the rasterized output. When applied to an existing raster format, -density functions solely as resolution metadata.
