Register Custom Fonts in ImageMagick with type.xml

ImageMagick allows you to render text dynamically using system or local fonts by mapping font families to file paths via configuration files. This guide explains how to register custom font directories using ImageMagick's type.xml configuration, define custom font mappings, and verify that ImageMagick recognizes the newly added fonts on your system.

Step 1: Locate Your ImageMagick Configuration Directory

ImageMagick reads font configurations from a global configuration directory or a user-specific directory. You can locate where ImageMagick looks for type.xml by running:

magick -list configure | grep CONFIGURE_PATH

(On ImageMagick v6, replace magick with convert.)

Common configuration paths include:

  • Linux (Global): /etc/ImageMagick-7/ or /usr/local/etc/ImageMagick-7/
  • Linux/macOS (User-level): ~/.config/ImageMagick/
  • Windows: The installation root directory (e.g., C:\Program Files\ImageMagick-7.x.x\)

Step 2: Understand the type.xml Format

ImageMagick does not scan raw directory paths directly from type.xml. Instead, it reads an XML file that maps each font face to its exact file location using the <typemap> root element and <type> child tags.

A standard font entry uses this syntax:

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE typemap [
<!ELEMENT typemap (type)+>
<!ELEMENT type (#PCDATA)>
<!ATTLIST type name CDATA #REQUIRED>
<!ATTLIST type fullname CDATA #IMPLIED>
<!ATTLIST type family CDATA #IMPLIED>
<!ATTLIST type weight CDATA #IMPLIED>
<!ATTLIST type style CDATA #IMPLIED>
<!ATTLIST type stretch CDATA #IMPLIED>
<!ATTLIST type glyph CDATA #REQUIRED>
]>
<typemap>
  <type name="CustomFont-Regular" 
        fullname="Custom Font Regular" 
        family="CustomFont" 
        weight="400" 
        style="normal" 
        stretch="normal" 
        glyphs="/path/to/custom_fonts/CustomFont-Regular.ttf" />
</typemap>

Step 3: Link Custom Font Files in type.xml

To keep custom fonts organized without modifying core system files directly, create a separate XML definition file for your custom font directory and include it within type.xml.

  1. Create a custom mapping file (e.g., /path/to/custom_fonts/type-custom.xml or ~/.config/ImageMagick/type-local.xml).
  2. Add your font definitions inside <typemap>...</typemap> tags in this new file.
  3. Open the primary type.xml file in your ImageMagick configuration path.
  4. Add an <include> directive referencing your custom XML file:
<typemap>
  <include file="/path/to/custom_fonts/type-custom.xml" />
</typemap>

Step 4: Automate Font Indexing for Large Directories

If your custom directory contains many fonts, creating <type> entries manually can be tedious. You can generate the required XML structure automatically using scripts such as the official ImageMagick Perl utility imagick_type_gen:

perl imagick_type_gen -d /path/to/custom_fonts > /path/to/custom_fonts/type-custom.xml

Alternatively, you can write a shell script to iterate over .ttf or .otf files in your directory and output valid <type> tags with their respective file paths into type-custom.xml.

Step 5: Verify the Font Registration

Once type.xml includes the reference to your font definitions, test that ImageMagick has registered the fonts:

magick -list font

To check for a specific registered font:

magick -list font | grep -i "CustomFont"

If registered correctly, you can now use the font by its assigned name or family attribute in standard ImageMagick commands:

magick -background white -fill black -font CustomFont-Regular -pointsize 36 label:"Hello World" output.png
