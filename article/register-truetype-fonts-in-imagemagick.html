Register TrueType Fonts in ImageMagick

This article provides a direct guide on how to register custom TrueType font (.ttf) locations within ImageMagick’s XML configuration files. By modifying the type.xml file or linking external type map files, you can make custom fonts accessible system-wide across all ImageMagick command-line tools and API bindings without needing to install them directly into system root directories.

Step 1: Locate the ImageMagick Configuration Directory

ImageMagick stores its font mappings in a file named type.xml. You can find the active configuration directory using the command line:

magick -list font
# Or for ImageMagick 6:
convert -list font

Look at the header lines of the output to see the Path where type.xml is loaded. Common locations include:

  • Linux (System-wide): /etc/ImageMagick-7/type.xml or /usr/local/etc/ImageMagick-7/type.xml
  • Linux (User-specific): ~/.config/ImageMagick/type.xml
  • macOS (Homebrew): /opt/homebrew/etc/ImageMagick-7/type.xml or /usr/local/etc/ImageMagick-7/type.xml
  • Windows: C:\Program Files\ImageMagick-7.x.x\type.xml

Step 2: Understand the Font Declaration Syntax

TrueType fonts are defined using XML elements inside a <typemap> root element. Each font entry requires a <type> tag with the following attributes:

  • name: The identifier used to reference the font in ImageMagick commands (e.g., -font MyCustomFont).
  • format: Set to ttf for TrueType fonts.
  • glyphs: The absolute filesystem path to the .ttf font file.
  • family (optional): The generic family name of the font.
  • weight (optional): Font weight (e.g., 400, 700, normal, bold).
  • style (optional): Font style (e.g., normal, italic, oblique).

Step 3: Add Fonts to the Configuration File

You can either add fonts directly to type.xml or create a separate file and include it.

Option A: Direct Entry in type.xml

Open type.xml in a text editor with administrative privileges if necessary:

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE typemap [
<!ELEMENT typemap (type)+>
<!ELEMENT type EMPTY>
<!ATTLIST type format CDATA #REQUIRED>
<!ATTLIST type glyphs CDATA #REQUIRED>
<!ATTLIST type fullname CDATA #IMPLIED>
<!ATTLIST type family CDATA #IMPLIED>
<!ATTLIST type weight CDATA #IMPLIED>
<!ATTLIST type style CDATA #IMPLIED>
<!ATTLIST type stretch CDATA #IMPLIED>
<!ATTLIST type name CDATA #REQUIRED>
]>
<typemap>
  <type format="ttf" name="Roboto-Regular" glyphs="/usr/share/fonts/custom/Roboto-Regular.ttf" family="Roboto" weight="normal" style="normal" />
  <type format="ttf" name="Roboto-Bold" glyphs="/usr/share/fonts/custom/Roboto-Bold.ttf" family="Roboto" weight="bold" style="normal" />
</typemap>

Option B: Use an External Included File (Recommended)

To keep custom fonts isolated from system updates, create a custom file named type-local.xml in your configuration directory and reference it within type.xml.

  1. Create type-local.xml:
<?xml version="1.0" encoding="UTF-8"?>
<typemap>
  <type format="ttf" name="Custom-Font" glyphs="/opt/fonts/CustomFont.ttf" />
</typemap>
  1. Add the <include> tag inside your main type.xml:
<typemap>
  <include file="type-local.xml" />
</typemap>

Step 4: Batch Registering Font Directories (Optional)

If you have a directory with many TrueType fonts, you can generate the XML mappings automatically using the Perl script provided by ImageMagick (imagick_type_gen):

perl -e "$(curl -fsSL https://raw.githubusercontent.com/ImageMagick/ImageMagick/main/PerlMagick/type-gen.pl)" --dir /path/to/your/ttf/fonts > type-local.xml

Place the generated type-local.xml into the ImageMagick configuration path and include it inside type.xml.

Step 5: Verify the Registered Font

Check if ImageMagick recognizes the newly registered font:

magick -list font | grep -i "Custom-Font"

To test rendering with the new font:

magick -size 400x100 xc:white -font Custom-Font -pointsize 24 -fill black -annotate +20+50 'Font Loaded Successfully' output.png
