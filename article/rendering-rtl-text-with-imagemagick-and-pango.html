Rendering RTL Text with ImageMagick and Pango

Rendering right-to-left (RTL) scripts like Arabic and Hebrew in standard ImageMagick pipelines often results in disconnected glyphs, broken ligatures, and reversed character ordering. Standard ImageMagick text primitives lack native complex text shaping and bidirectional (BiDi) layout algorithms. By delegating text processing to Pango—a dedicated library for layout and rendering of international text—ImageMagick can accurately shape, connect, and position RTL characters.

Why Pango Is Required

Standard text options in ImageMagick (such as label: or annotate:) draw characters sequentially using simple FreeType lookups. This approach fails for:

  • Arabic: Requires contextual glyph shaping (isolated, initial, medial, and final forms) and cursive ligature connections.
  • Hebrew and BiDi: Requires the Unicode Bidirectional Algorithm to properly handle mixed RTL and left-to-right (LTR) content, punctuation, and numbers.

Pango handles font shaping, HarfBuzz integration, and FriBidi layout internally before passing the rasterized output to ImageMagick.

Verifying Pango Support

Before rendering, confirm that your ImageMagick build has the Pango delegate enabled:

magick -version

Look for pango in the Delegates (built-in) list. Alternatively, run:

magick -list format | grep PANGO

If Pango is missing, install the libpango1.0-dev package (on Debian/Ubuntu) or pango (via Homebrew/macOS) and recompile or reinstall ImageMagick.

Basic Syntax

To use Pango in ImageMagick, use the pango: protocol prefix instead of label: or text:.

magick -background white -fill black pango:"Your text here" output.png

Rendering Arabic Text

Arabic requires an appropriate font that includes full Arabic shaping tables (e.g., Amiri, Cairo, or Noto Sans Arabic).

magick -background "#f5f5f5" \
       -fill "#111111" \
       -size 600x \
       pango:"<span font='Amiri 28'>مرحباً بكم في عالم البرمجة</span>" \
       arabic_output.png

Pango automatically identifies the Arabic script, runs HarfBuzz for correct contextual shaping, and aligns the text appropriately.

Rendering Hebrew Text

Hebrew scripts render correctly with fonts like Arial, DejaVu Sans, or Noto Sans Hebrew.

magick -background white \
       -fill "#003366" \
       -size 500x \
       pango:"<span font='DejaVu Sans 24'>שלום עולם! ברוכים הבאים.</span>" \
       hebrew_output.png

Handling Mixed BiDi Text and Alignment

When mixing RTL text with English words, numbers, or punctuation, use Pango's XML-like markup to explicitly define text direction and alignment:

magick -background white \
       -fill black \
       -size 600x200 \
       pango:"<span font='Amiri 22' dir='rtl'>النسخة رقم 2.0 من الإصدار التجريبي (Beta).</span>" \
       bidi_output.png

Key Pango Markup Attributes

  • dir="rtl" or dir="ltr": Forces the directional context of a block.
  • font_family="Font Name": Sets the specific typeface.
  • size="xx-large" or font="32": Sets the font size.
  • foreground="#hex": Changes inline text color without multiple ImageMagick commands.

Best Practices

  • Always Specify an RTL Font: If glyphs appear as empty boxes (tofu), ensure the specified font family exists on your system and covers the relevant Unicode blocks.
  • Define Dimensions Explicitly: Using -size WIDTHx allows Pango to handle automatic word wrapping while dynamically calculating the necessary image height.
  • Escape Special Characters: When generating commands dynamically in shell scripts, escape markup characters (<, >, &) to prevent Pango parsing errors.
