Restrict Dynamic Coders with MAGICK_CODER_FILTER_PATH

This article explains how to configure the MAGICK_CODER_FILTER_PATH environment variable in ImageMagick to restrict dynamic coder loading. ImageMagick relies on external coder modules to parse and convert various file formats, which can introduce significant security risks if untrusted or vulnerable format parsers are loaded. By defining or redirecting MAGICK_CODER_FILTER_PATH, system administrators can enforce strict boundaries on where ImageMagick searches for dynamic coder libraries, effectively limiting the attack surface.

Understanding Dynamic Coder Loading

ImageMagick uses dynamic shared libraries (such as .so on Linux or .dll on Windows) to process formats outside its core set. If an application accepts untrusted image uploads, malicious files might trigger legacy or vulnerable coders. Restricting the coder filter path ensures that ImageMagick only loads explicitly permitted coder modules from a secure, read-only directory or prevents loading external coders altogether.

Setting MAGICK_CODER_FILTER_PATH

The MAGICK_CODER_FILTER_PATH variable overrides the default directories where ImageMagick looks for coder modules.

1. Pointing to a Restricted Directory (Linux/macOS)

Create a dedicated directory containing only the specific dynamic coders your application requires:

mkdir -p /opt/imagemagick/safe_coders
cp /usr/lib/x86_64-linux-gnu/ImageMagick-*/modules-Q16/coders/png.so /opt/imagemagick/safe_coders/
cp /usr/lib/x86_64-linux-gnu/ImageMagick-*/modules-Q16/coders/jpeg.so /opt/imagemagick/safe_coders/
chmod -R 555 /opt/imagemagick/safe_coders

Export the variable in your environment:

export MAGICK_CODER_FILTER_PATH="/opt/imagemagick/safe_coders"

To make this setting persistent across the system, add it to /etc/environment or inside a shell configuration file like /etc/profile.d/imagemagick.sh:

echo 'export MAGICK_CODER_FILTER_PATH="/opt/imagemagick/safe_coders"' | sudo tee /etc/profile.d/imagemagick.sh

2. Disabling Dynamic Coders Entirely

If your workload only requires standard formats built directly into the core ImageMagick binary, you can point the variable to an empty, read-only directory:

sudo mkdir -p /var/empty/magick_coders
sudo chmod 555 /var/empty/magick_coders
export MAGICK_CODER_FILTER_PATH="/var/empty/magick_coders"

3. Configuring Systemd Services

If ImageMagick is executed by a background service (such as PHP-FPM, Node.js, or a web server), configure the environment variable directly within the systemd service unit:

[Service]
Environment="MAGICK_CODER_FILTER_PATH=/opt/imagemagick/safe_coders"

Reload and restart the service:

sudo systemctl daemon-reload
sudo systemctl restart your-service-name

4. Setting the Variable on Windows

In Windows environments, set the variable through PowerShell:

[System.Environment]::SetEnvironmentVariable('MAGICK_CODER_FILTER_PATH', 'C:\ImageMagick\SafeCoders', [System.EnvironmentVariableTarget]::Machine)

Alternatively, set it temporarily via Command Prompt:

set MAGICK_CODER_FILTER_PATH=C:\ImageMagick\SafeCoders

Verifying the Configuration

To verify that ImageMagick recognizes the path and properly restricts available formats, run the following diagnostic commands:

Check where ImageMagick is searching for configuration files and modules:

magick -debug configure logo: null:

List all currently available formats to ensure unauthorized coders are absent:

magick identify -list format

If configured correctly, only built-in formats and coders present inside the directory specified by MAGICK_CODER_FILTER_PATH will appear in the output.
