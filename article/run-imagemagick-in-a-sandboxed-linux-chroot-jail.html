Run ImageMagick in a Sandboxed Linux Chroot Jail

Isolating ImageMagick inside a Linux chroot jail minimizes security risks associated with parsing untrusted media files, protecting the host system from potential remote code execution and unauthorized file reads. This guide demonstrates how to establish a minimal filesystem directory structure, locate and copy necessary shared libraries, populate essential pseudo-devices, configure defensive security policies, and execute commands safely under an unprivileged user.

1. Create the Jail Directory Hierarchy

Define the target root directory for the jail and create standard system paths required for execution:

export JAIL="/var/jail/imagemagick"
sudo mkdir -p "$JAIL"/{bin,usr/bin,lib,lib64,dev,tmp,etc/ImageMagick-7}
sudo chmod 1777 "$JAIL/tmp"

2. Copy the ImageMagick Binaries

Locate the primary ImageMagick executable (typically magick or legacy convert) and copy it into the jail:

IM_BIN=$(which magick || which convert)
sudo cp "$IM_BIN" "$JAIL/usr/bin/"
sudo ln -sf "$JAIL/usr/bin/magick" "$JAIL/bin/convert"

3. Copy Required Shared Libraries

ImageMagick depends on dynamic libraries that must exist within the sandbox. Use ldd to find all linked dependencies and copy them to the corresponding paths inside the jail:

for lib in $(ldd "$IM_BIN" | grep -o '/lib[^ ]*'); do
    sudo mkdir -p "$JAIL$(dirname "$lib")"
    sudo cp -u "$lib" "$JAIL$lib"
done

If ImageMagick relies on runtime-loaded delegate libraries (such as libpng, libjpeg, or coder modules), identify and copy the modules directory:

MODULE_PATH=$(find /usr/lib* -name "ImageMagick-*" -type d | head -n 1)
if [ -n "$MODULE_PATH" ]; then
    sudo mkdir -p "$JAIL$(dirname "$MODULE_PATH")"
    sudo cp -r "$MODULE_PATH" "$JAIL$MODULE_PATH"
fi

4. Set Up Minimal Device Nodes

ImageMagick requires access to common pseudo-devices such as /dev/null and /dev/urandom for cryptographic operations and temporary files:

sudo mknod -m 666 "$JAIL/dev/null" c 1 3
sudo mknod -m 666 "$JAIL/dev/zero" c 1 5
sudo mknod -m 444 "$JAIL/dev/urandom" c 1 9

5. Configure Strict Policy Rules

Harden the installation by copying and editing the policy.xml file. This prevents ImageMagick from attempting network operations or spawning external delegates like Ghostscript inside the jail.

Copy the host policy into the jail:

POLICY_FILE=$(find /etc -name "policy.xml" | grep -i imagemagick | head -n 1)
sudo cp "$POLICY_FILE" "$JAIL/etc/ImageMagick-7/policy.xml"

Edit $JAIL/etc/ImageMagick-7/policy.xml to restrict resource usage and disable dangerous coders:

<policymap>
  <policy domain="resource" name="memory" value="256MiB"/>
  <policy domain="resource" name="map" value="512MiB"/>
  <policy domain="resource" name="disk" value="1GiB"/>
  <policy domain="coder" rights="none" pattern="EPHEMERAL" />
  <policy domain="coder" rights="none" pattern="URL" />
  <policy domain="coder" rights="none" pattern="HTTPS" />
  <policy domain="coder" rights="none" pattern="MVG" />
  <policy domain="coder" rights="none" pattern="MSL" />
  <policy domain="coder" rights="none" pattern="TEXT" />
  <policy domain="coder" rights="none" pattern="SHOW" />
  <policy domain="coder" rights="none" pattern="WIN" />
  <policy domain="coder" rights="none" pattern="PLT" />
</policymap>

6. Execute Inside the Jail

Never run commands inside the jail as the root user. Use chroot with the --userspec flag to switch execution to a low-privilege user such as nobody:

# Prepare a test file inside the jail's /tmp
sudo cp input.jpg "$JAIL/tmp/"

# Execute conversion under the 'nobody' user
sudo chroot --userspec=nobody:nogroup "$JAIL" /usr/bin/magick /tmp/input.jpg -resize 50% /tmp/output.png

# Retrieve the processed file
sudo mv "$JAIL/tmp/output.png" ./

To automate or wrap this process for web services, place incoming uploads directly into $JAIL/tmp, execute via chroot, and retrieve output files from the isolated environment.
