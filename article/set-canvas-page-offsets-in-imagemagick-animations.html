Set Canvas Page Offsets in ImageMagick Animations

This guide explains how to define custom canvas page offsets for animation sub-frames using ImageMagick's command-line tools. You will learn how the virtual canvas geometry functions, how to assign custom coordinate offsets (+X+Y) to individual animation frames during creation or post-processing, and how to combine these offsets with disposal methods to produce optimized animated GIFs or multi-layer graphics.

Understanding the Virtual Canvas Geometry

ImageMagick uses the page geometry syntax [width]x[height]+[x]+[y] to manage virtual canvas dimensions and offsets. In multi-frame animations (such as GIFs or APNGs):

  • Width and Height (WxH): Define the total size of the logical display screen (the virtual canvas).
  • Offsets (+X+Y): Define the horizontal (X) and vertical (Y) position where a smaller sub-frame is placed relative to the top-left corner (0,0) of the logical canvas.

By defining custom offsets, sub-frames only need to be as large as the area that changes, reducing total file size and allowing precise positioning of moving elements.

Defining Offsets During Input with -page

The -page operator sets the canvas size and offset for any image loaded or created immediately after the operator appears in the command line.

magick -dispose previous -delay 50 \
  -page 600x400+0+0   background.png \
  -page +100+50       sprite_frame1.png \
  -page +150+80       sprite_frame2.png \
  -page +200+110      sprite_frame3.png \
  -loop 0 output.gif

In this command:

  • The first frame sets the logical canvas to 600x400 positioned at +0+0.
  • Subsequent frames inherit the canvas dimensions while assigning custom X and Y coordinates to place sprite_frame files in specific positions across successive animation steps.

Modifying Existing Frame Offsets with -set page and -repage

If frames are already loaded into memory, use -set page or -repage to alter their virtual canvas coordinates.

1. Modifying Offsets on Specific Frames

Use image indexing combined with -set page to modify sub-frames individually:

magick frame0.png frame1.png frame2.png \
  -set page 500x500+0+0   -clone 0 \
  -set page 500x500+50+50 -clone 1 \
  -set page 500x500+80+30 -clone 2 \
  -delete 0-2 \
  -delay 20 -loop 0 animated.gif

Alternatively, apply offsets directly using parenthesis blocks to isolate operations:

magick -delay 30 \
  frame0.png -page 400x400+0+0 \
  \( frame1.png -repage +50+20 \) \
  \( frame2.png -repage +100+40 \) \
  -loop 0 result.gif

2. Relative Adjustments

To shift an existing offset relative to its current coordinates, use the + or - prefix with -repage:

magick animation.gif -repage +20+10 shifted_animation.gif

This shifts every frame in animation.gif 20 pixels to the right and 10 pixels downward.

Essential Settings for Custom Sub-Frame Animations

To ensure custom canvas offsets display properly across all viewers:

  1. Set a Frame Disposal Method: Sub-frames with custom offsets require proper disposal settings so that previous frames do not unintentionally bleed through. Use -dispose previous to restore the background canvas, or -dispose background to clear the previous sub-frame area before rendering the next frame.
  2. Avoid Coalescing at the End: The -coalesce operator expands every sub-frame to the full canvas size, overriding any custom page offsets. If you use -coalesce to read an animation, make your edits, and then either use custom -repage calls or run -layers optimize to re-apply compact sub-frame bounding boxes.
