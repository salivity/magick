Set TIFF LZW Predictor in ImageMagick

Setting the horizontal predictor tag for LZW-compressed TIFF images in ImageMagick significantly improves compression efficiency for continuous-tone images. This guide explains how to properly configure ImageMagick using command-line defines to apply horizontal differencing when encoding LZW TIFF files.

The Command Syntax

To enable the horizontal predictor for LZW-compressed TIFF files, use the -compress lzw option along with the -define tiff:predictor=2 setting.

For ImageMagick version 7:

magick input.png -compress lzw -define tiff:predictor=2 output.tif

For ImageMagick version 6:

convert input.png -compress lzw -define tiff:predictor=2 output.tif

Understanding Predictor Values

The TIFF specification defines three predictor modes via Tag 317:

  • 1 (None): No mathematical prediction scheme is applied before compression (default behavior).
  • 2 (Horizontal Differencing): Calculates the difference between adjacent horizontal pixels before compressing. This groups similar byte values together, substantially increasing LZW and Deflate/ZIP compression ratios for continuous-tone photographic data or smooth gradients.
  • 3 (Floating Point): Designed specifically for floating-point pixel data.

Why Use Horizontal Differencing with LZW

LZW compression identifies repeating byte patterns. In standard continuous-tone images, neighboring pixels often have similar values, but not identical byte sequences.

The horizontal predictor calculates the delta between each pixel and its preceding neighbor. For smooth gradients or photographic areas, these deltas result in long strings of identical small values (like zeros), which LZW compresses far more efficiently than the raw pixel values.

Verifying the Output

To verify that the horizontal predictor tag has been applied correctly to the generated TIFF, inspect the metadata using identify or tiffinfo:

magick identify -verbose output.tif | grep "tiff:predictor"

The output should confirm:

tiff:predictor: 2
