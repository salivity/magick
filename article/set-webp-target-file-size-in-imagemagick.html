Set WebP Target File Size in ImageMagick

This article provides a concise guide on using ImageMagick to compress WebP images to a specific target file size. You will learn the exact -define key-value syntax, how file size units are measured, and practical command-line examples to automate precise WebP optimization.

The WebP Target Size Define Syntax

ImageMagick interfaces directly with libwebp encoder options through the -define argument. To set a target file size, use the webp:target-size directive:

-define webp:target-size=<bytes>

The value must be specified in bytes. For example, to aim for a 50 KB file, you convert 50 kilobytes to bytes (50 * 1024 = 51200):

magick input.png -define webp:target-size=51200 output.webp

(Note: In ImageMagick version 6, replace magick with convert.)

Improving Precision with Passes

When webp:target-size is defined, the encoder iteratively tests different quality levels to get as close as possible to your desired byte count without exceeding it.

You can increase the accuracy of the target size estimation by adjusting the number of analysis passes using the webp:pass define:

magick input.jpg -define webp:target-size=102400 -define webp:pass=6 output.webp
  • webp:pass: Accepts an integer between 1 and 10 (default is typically 1). A higher number of passes results in a final file size closer to your target, but increases processing time.

Key Considerations

  • Lossy Only: The webp:target-size directive applies only to lossy WebP compression. It is ignored if lossless mode (-define webp:lossless=true) is activated.
  • Physical Limits: If the image dimensions are too large for the requested size, the encoder will compress down to its lowest quality factor, which may still result in a file larger than the specified target. Conversely, very simple images might naturally compress to a size smaller than the target even at maximum quality.
