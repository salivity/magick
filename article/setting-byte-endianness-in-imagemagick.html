Setting Byte Endianness in ImageMagick

When loading raw, headerless image files (such as 16-bit or 32-bit raw grayscale and RGB streams), ImageMagick cannot automatically detect how multi-byte values are ordered in memory. This guide explains how to use the -endian parameter in ImageMagick to define the byte order—either Most Significant Byte (big-endian) or Least Significant Byte (little-endian)—ensuring your raw pixel data is decoded accurately without distortion or color corruption.

The -endian Parameter

ImageMagick uses the -endian command-line option to explicitly define the byte order when reading or writing raw image formats. Because raw files lack metadata headers, specifying the correct endianness is critical for any data with a bit depth greater than 8 bits per channel (such as 16-bit or 32-bit integers and floating-point values).

Supported Values

The -endian parameter accepts the following options:

  • LSB (Least Significant Byte): Specifies little-endian format (common on x86 and ARM processors).
  • MSB (Most Significant Byte): Specifies big-endian format (common in network protocols and older architectures like PowerPC).
  • Native: Uses the host system's default byte order.
  • Undefined: Leaves byte order unspecified (defaults to system behavior).

Usage and Syntax

The -endian flag must be declared before the input file in your command so ImageMagick knows how to read the incoming raw stream.

Example: Reading 16-bit Raw Grayscale Data

To convert a 16-bit little-endian raw grayscale image with dimensions of 512x512 pixels into a PNG:

magick -size 512x512 -depth 16 -endian LSB gray:input.raw output.png

Example: Reading 16-bit Big-Endian RGB Data

To convert a 16-bit big-endian raw RGB stream with dimensions of 1920x1080:

magick -size 1920x1080 -depth 16 -endian MSB rgb:input.raw output.tiff

Why Specifying Endianness is Essential

If the wrong endianness is specified when loading raw data:

  • High-order and low-order bytes are swapped.
  • Smooth gradients will appear as extreme noise or static.
  • Dark values may incorrectly wrap to peak brightness and vice versa.

If your converted raw image appears completely distorted with high-frequency noise despite having the correct dimensions and bit depth, toggling between -endian LSB and -endian MSB will typically resolve the issue.
