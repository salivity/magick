Setting SVG Base URI Paths in ImageMagick

When rendering Scalable Vector Graphics (SVG) that contain relative references to external image files, ImageMagick needs a reference path to locate those assets accurately. Without explicitly setting this base path, the renderer fails to locate linked files, resulting in missing images or broken renders. This article outlines the primary methods for setting the SVG base URI in ImageMagick, including command-line definitions, internal SVG markup declarations, and execution context management.

Using the -define svg:base-uri Flag

The most direct way to inform ImageMagick’s SVG delegate (typically librsvg) of external file locations via the command line is by using the -define option before loading the SVG input file.

Syntax:

magick -define svg:base-uri="file:///path/to/assets/" input.svg output.png

Key considerations for this approach:

  • Place the -define flag before the input SVG file so the delegate parser receives the parameter before processing starts.
  • Use a fully qualified file URI format (e.g., file:///var/www/images/ or file:///C:/project/assets/) including the trailing slash.
  • If paths contain spaces, wrap the URI in quotes.

Declaring xml:base Inside the SVG File

If modifying command-line options is not feasible, define the base URI directly inside the SVG markup using the standard XML xml:base attribute. This attribute instructs XML parsers where to resolve relative href or xlink:href paths.

Add the attribute to the root <svg> element:

<svg xmlns="http://www.w3.org/2000/svg" 
     xmlns:xlink="http://www.w3.org/1999/xlink"
     xml:base="file:///path/to/assets/"
     width="500" height="500">
    <image href="graphic.png" width="100" height="100" />
</svg>

When ImageMagick processes this file, the underlying XML engine automatically appends the xml:base directory to relative targets like graphic.png.

Executing from the Target Working Directory

If neither flags nor internal XML tags can be applied, ImageMagick defaults to resolving relative assets relative to the current working directory of the shell execution.

Navigate to the directory containing the linked graphics before executing the command:

cd /path/to/assets/
magick /path/to/input.svg /path/to/output.png

This ensures that relative references such as <image href="graphic.png"/> resolve directly against the current directory.

Checking Security Policies

ImageMagick implements a strict security policy located in policy.xml. In many default installations, reading external paths or specific delegate protocols (such as HTTPS or local filesystem access from within vector formats) may be disabled.

If external files still fail to resolve after configuring the base URI:

  1. Locate policy.xml (commonly found in /etc/ImageMagick-7/ on Linux).
  2. Check for restrictions on delegate domains, specifically <policy domain="path" rights="none" pattern="@*" /> or rights restrictions on the SVG or HTTPS coders.
  3. Ensure the process running ImageMagick has filesystem read permissions for the target base directory.
