Specify Endianness for Raw Images in ImageMagick

Raw medical imaging files—such as raw CT, MRI, or ultrasound data lacking standard DICOM headers—often store pixel data as multi-byte integers (typically 16-bit grayscale). When reading these headerless streams, ImageMagick cannot auto-detect the byte ordering, leading to noisy or completely scrambled outputs if the wrong byte order is assumed. This guide explains how to properly configure pixel endianness using ImageMagick's command-line interface to ensure accurate image reconstruction.

Understanding Pixel Endianness in Raw Data

Multi-byte pixel values (such as 16-bit unsigned or signed integers) are stored in memory in one of two formats:

  • Little-Endian (LSB): The least significant byte is stored first. This is common on x86/x64 systems and many modern DICOM/raw imaging exports.
  • Big-Endian (MSB): The most significant byte is stored first. This is often found in legacy medical hardware or network-standard formats.

If a 16-bit raw image is interpreted with the wrong endianness, low-intensity pixel changes turn into massive value jumps, making the medical scan look like heavy static or high-contrast noise.

The -endian Option

ImageMagick provides the -endian setting to define byte order. When dealing with raw image streams, this flag must be placed before specifying the input file so that ImageMagick applies the setting while decoding the binary data.

Supported values include:

  • LSB (Least Significant Byte first / Little-Endian)
  • MSB (Most Significant Byte first / Big-Endian)

Command Syntax and Examples

When importing raw grayscale medical images, you must explicitly provide the image dimensions (-size), bit depth (-depth), the pixel format (gray:), and the byte order (-endian).

Reading 16-Bit Little-Endian Raw Data

To convert a 512x512, 16-bit Little-Endian raw file to a readable PNG or TIFF:

magick -size 512x512 -depth 16 -endian LSB gray:scan_data.raw output.png

For ImageMagick v6, use convert instead of magick:

convert -size 512x512 -depth 16 -endian LSB gray:scan_data.raw output.png

Reading 16-Bit Big-Endian Raw Data

If the raw data originates from a Big-Endian system:

magick -size 512x512 -depth 16 -endian MSB gray:scan_data.raw output.png

Handling Signed vs. Unsigned Pixels

Many medical scans use 16-bit signed integers (Hounsfield units in CT scans often require signed data representations). If the resulting image appears washed out or clamped, pair the -endian flag with the quantum:format define:

magick -size 512x512 -depth 16 -endian LSB -define quantum:format=signed gray:scan_data.raw output.png

For standard unsigned 16-bit integers:

magick -size 512x512 -depth 16 -endian LSB -define quantum:format=unsigned gray:scan_data.raw output.png

By ensuring that -size, -depth, -endian, and -define quantum:format precede the raw input file argument, ImageMagick will parse the raw medical data into an accurate visual representation.
