Split Image into Equal Quadrants in ImageMagick

Dividing an image into equal rectangular quadrants is a common image processing task easily accomplished from the command line using ImageMagick. By utilizing the -crop operator combined with the tile syntax (@), you can automatically slice any image into a 2x2 grid of four equal sections without calculating pixel dimensions manually. This guide demonstrates the exact command-line syntax required to split images into equal quadrants for both modern and legacy ImageMagick versions.

The Tile Syntax Command

To divide an image into four equal quadrants (2 columns by 2 rows), use the -crop parameter followed by 2x2@.

For ImageMagick v7 (Current):

magick input.jpg -crop 2x2@ +repage quadrant_%d.jpg

For ImageMagick v6 (Legacy):

convert input.jpg -crop 2x2@ +repage quadrant_%d.jpg

How the Command Works

  • input.jpg: Specifies the source image file you want to split.
  • -crop 2x2@: The @ symbol tells ImageMagick to treat the dimensions as a grid layout rather than explicit pixel sizes. Specifying 2x2@ instructs the tool to cut the image into 2 horizontal segments and 2 vertical segments, producing 4 equal quadrants.
  • +repage: Resets the virtual canvas geometry and page offsets. Without this flag, the cropped quadrants may retain metadata about their original canvas position, which can cause layout issues in viewers and downstream processing tools.
  • quadrant_%d.jpg: Defines the naming convention for the output files. The %d format specifier automatically increments to number the tiles sequentially (e.g., quadrant_0.jpg, quadrant_1.jpg, quadrant_2.jpg, and quadrant_3.jpg).

Output Tile Order

When ImageMagick splits an image using the 2x2@ grid, it generates the output files reading from left to right, top to bottom:

  • quadrant_0.jpg: Top-Left Quadrant
  • quadrant_1.jpg: Top-Right Quadrant
  • quadrant_2.jpg: Bottom-Left Quadrant
  • quadrant_3.jpg: Bottom-Right Quadrant

If your source image dimensions are not perfectly divisible by two, ImageMagick automatically rounds pixel counts to create the most evenly balanced partitions possible.
