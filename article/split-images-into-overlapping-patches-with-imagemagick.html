Split Images into Overlapping Patches with ImageMagick

This article demonstrates how to use ImageMagick to divide large images into overlapping patches or tiles for machine learning workflows. While standard image tiling creates non-overlapping grids, machine learning tasks such as object detection, semantic segmentation, and super-resolution often require overlapping sliding windows (patches with a specified stride) to prevent boundary artifacts and capture context across cut lines.

The Core Crop Syntax

ImageMagick uses the -crop operator along with offset parameters to extract a specific region:

magick input.png -crop [width]x[height]+[x_offset]+[y_offset] +repage output_patch.png
  • [width]x[height]: The dimensions of the extracted patch (e.g., 256x256 or 512x512).
  • +[x_offset]+[y_offset]: The coordinate offset from the top-left corner determining the patch position.
  • +repage: Removes the virtual canvas metadata, ensuring the output file matches the exact patch dimensions.

Generating Overlapping Patches with a Sliding Window

Standard ImageMagick -crop 256x256 without offsets produces non-overlapping tiles. To create overlapping patches, you must iterate over the image dimensions using a stride that is smaller than the patch size (where Overlap = Patch Size - Stride).

Automated Bash Script

The following script extracts patches of size 256x256 with a stride of 128 pixels (resulting in a 50% overlap horizontally and vertically):

#!/bin/bash

INPUT="input.jpg"
PATCH_SIZE=256
STRIDE=128

# Get input image dimensions
WIDTH=$(magick identify -format "%w" "$INPUT")
HEIGHT=$(magick identify -format "%h" "$INPUT")

# Calculate loop boundaries
MAX_X=$((WIDTH - PATCH_SIZE))
MAX_Y=$((HEIGHT - PATCH_SIZE))

# Iterate through coordinates
for ((y=0; y<=MAX_Y; y+=STRIDE)); do
    for ((x=0; x<=MAX_X; x+=STRIDE)); do
        magick "$INPUT" -crop "${PATCH_SIZE}x${PATCH_SIZE}+${x}+${y}" +repage "patch_${x}_${y}.png"
    done
done

Handling Image Boundaries

If your image dimensions are not perfectly divisible by your stride, edge pixels may be excluded. To resolve this, you can adjust the script to capture the remaining edge boundary:

# Capture the remaining right and bottom edges
if [ $((WIDTH % STRIDE)) -ne 0 ]; then
    for ((y=0; y<=MAX_Y; y+=STRIDE)); do
        magick "$INPUT" -crop "${PATCH_SIZE}x${PATCH_SIZE}+$((WIDTH - PATCH_SIZE))+${y}" +repage "patch_edge_right_${y}.png"
    done
fi

if [ $((HEIGHT % STRIDE)) -ne 0 ]; then
    for ((x=0; x<=MAX_X; x+=STRIDE)); do
        magick "$INPUT" -crop "${PATCH_SIZE}x${PATCH_SIZE}+${x}+$((HEIGHT - PATCH_SIZE))" +repage "patch_edge_bottom_${x}.png"
    done
fi

Batch Processing via Python

For integration into machine learning data pipelines (PyTorch, TensorFlow), you can invoke ImageMagick via Python:

import subprocess

def extract_overlapping_patches(image_path, patch_size=256, stride=128):
    # Retrieve dimensions
    cmd = ["magick", "identify", "-format", "%w %h", image_path]
    width, height = map(int, subprocess.check_output(cmd).decode().split())

    for y in range(0, height - patch_size + 1, stride):
        for x in range(0, width - patch_size + 1, stride):
            out_name = f"patch_{x}_{y}.png"
            crop_arg = f"{patch_size}x{patch_size}+{x}+{y}"
            subprocess.run(["magick", image_path, "-crop", crop_arg, "+repage", out_name])

extract_overlapping_patches("input.jpg", patch_size=512, stride=256)
