Split Sprite Sheet into Frames with ImageMagick

This guide explains how to decompose a sprite sheet into individual animation frames using ImageMagick from the command line. You will learn the exact syntax for slicing sprites using fixed pixel dimensions or grid counts, along with essential options to ensure output frames are properly aligned and numbered.

Basic Syntax: Splitting by Frame Dimensions

If you know the exact width and height of each individual frame in pixels, use the -crop option with the frame dimensions:

magick input_spritesheet.png -crop WIDTHxHEIGHT +repage frame_%03d.png

For ImageMagick version 6, replace magick with convert.

Example

To split a sprite sheet where each frame is 64 pixels wide and 64 pixels high:

magick character_sheet.png -crop 64x64 +repage frame_%02d.png

This command generates files named frame_00.png, frame_01.png, frame_02.png, and so on, reading the sprite sheet from left to right, top to bottom.

Alternative Syntax: Splitting by Grid Layout (Columns and Rows)

If you do not know the exact pixel dimensions but know the number of columns and rows in the grid, append the @ symbol to the grid dimensions:

magick input_spritesheet.png -crop COLUMNSxROWS@ +repage frame_%03d.png

Example

To split a sprite sheet arranged in a 4-column by 2-row grid (8 frames total):

magick animation.png -crop 4x2@ +repage frame_%02d.png

Parameter Breakdown

  • -crop WIDTHxHEIGHT: Defines the tile size for slicing the input image.
  • -crop COLSxROWS@: Tells ImageMagick to divide the image into equal segments across the specified number of columns and rows.
  • +repage: Crucial step. It resets the virtual canvas page offsets for each newly created frame. Omitting this can cause downstream software to misread the frame boundaries.
  • frame_%03d.png: Specifies the output file naming scheme using C-style printf formatting. %03d pads frame numbers with leading zeros (e.g., frame_000.png, frame_001.png), ensuring files sort correctly in operating systems and game engines.
