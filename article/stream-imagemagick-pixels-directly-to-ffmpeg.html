Stream ImageMagick Pixels Directly to FFmpeg

Streaming processed pixel data directly from ImageMagick into FFmpeg allows you to generate, manipulate, and encode video frames in memory without creating temporary files on your disk. By leveraging standard input and output streams (stdout and stdin), you can pipe raw or formatted pixel arrays directly between the two command-line utilities for efficient, high-performance video generation.

Raw Pixel Data Stream (RGB/RGBA)

When streaming raw, uncompressed pixel arrays, you must specify the pixel format directly to ImageMagick using the standard output identifier - and explicitly define the input parameters in FFmpeg (such as dimensions, frame rate, and pixel format), since raw streams lack container metadata.

magick input.jpg -resize 1920x1080 -depth 8 rgb:- | \
ffmpeg -y -f rawvideo -pixel_format rgb24 -video_size 1920x1080 -framerate 30 -i - -c:v libx264 -pix_fmt yuv420p output.mp4

Syntax Breakdown:

  • rgb:- (ImageMagick): Instructs ImageMagick to output raw 8-bit RGB byte data to standard output. Use rgba:- if transparency data is required.
  • -f rawvideo (FFmpeg): Forces FFmpeg to interpret the incoming standard input stream as raw video data.
  • -pixel_format rgb24 (FFmpeg): Defines the incoming raw pixel layout (rgba if using rgba:-).
  • -video_size 1920x1080 (FFmpeg): Required for raw video streams so FFmpeg knows frame boundaries.
  • -framerate 30 (FFmpeg): Defines the playback rate of the incoming raw frames.
  • -i - (FFmpeg): Tells FFmpeg to read the source data from stdin.

Self-Describing Pixel Streams (PAM / PPM)

To avoid manually setting dimensions and pixel formats in FFmpeg for every run, stream self-describing formats like Portable Arbitrary Map (PAM) or Portable Pixmap (PPM). These formats include simple headers with dimension and color depth data for each frame.

magick frame*.png -resize 1280x720 pam:- | \
ffmpeg -y -f image2pipe -c:v pam -framerate 24 -i - -c:v libx264 -pix_fmt yuv420p output.mp4

Syntax Breakdown:

  • pam:- (ImageMagick): Writes a continuous PAM stream with embedded frame dimensions and channel layout directly to standard output.
  • -f image2pipe (FFmpeg): Reads a continuous stream of concatenated image formats from standard input.
  • -c:v pam (FFmpeg): Explicitly specifies the PAM image codec for parsing incoming headers.

Looping and Dynamic Frame Generation

You can dynamically generate and pipe programmatic patterns, animations, or composite frames into an encoded video output in a single pipeline:

magick -size 640x360 xc:blue -fill white -draw "circle 320,180 320,220" rgb:- | \
ffmpeg -y -f rawvideo -pixel_format rgb24 -video_size 640x360 -framerate 1 -loop 1 -t 10 -i - -c:v libx264 -pix_fmt yuv420p output.mp4

This syntax creates a static image directly in memory, pipes the raw RGB pixel data, and commands FFmpeg to loop that incoming raw frame for 10 seconds into an H.264 video.
