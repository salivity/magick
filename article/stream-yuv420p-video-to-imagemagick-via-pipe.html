Stream YUV420p Video to ImageMagick via Pipe

Streaming uncompressed YUV420p video frames directly into ImageMagick allows you to process or convert raw video streams on the fly without writing temporary files to disk. Because raw video formats contain no headers or metadata, you must explicitly provide the frame dimensions, pixel depth, and sampling factors to ImageMagick via standard input (stdin). This guide demonstrates how to configure the command-line pipeline to ingest raw YUV420p frames from sources like FFmpeg.

Why Explicit Parameters Are Required

Raw YUV420p video consists of purely uncompressed planar Y, U, and V samples without container metadata. ImageMagick cannot auto-detect the video's width, height, or pixel format from standard input. Therefore, you must pass the exact geometry (-size), color depth (-depth), and format (yuv:-) to the magick (or legacy convert) command.

Basic Pipeline Syntax

To stream raw video data from a source into ImageMagick, pipe standard output (stdout) to standard input (stdin represented by - or yuv:-).

The general command pattern is:

<video_source_command> | magick -size <WIDTH>x<HEIGHT> -depth 8 -sampling-factor 4:2:0 yuv:- <output_options> <output_target>

Key Arguments Explained:

  • -size <WIDTH>x<HEIGHT>: Specifies the frame resolution (e.g., -size 1920x1080).
  • -depth 8: Sets the bit depth per channel (standard 8-bit YUV).
  • -sampling-factor 4:2:0: Tells ImageMagick that chroma channels are subsampled at 4:2:0.
  • yuv:-: Specifies that the input format is YUV and reads directly from the standard input pipe.

Practical Examples

1. Extracting Frames from FFmpeg to PNG via ImageMagick

To decode a video file with FFmpeg into raw YUV420p and pipe all frames to ImageMagick for processing and outputting as numbered PNG files:

ffmpeg -i input.mp4 -f rawvideo -pix_fmt yuv420p - | \
magick -size 1920x1080 -depth 8 -sampling-factor 4:2:0 yuv:- frame_%04d.png

2. Processing a Single Specific Frame

If you only want to process a single frame (e.g., at the 5-second mark), restrict the output at the source:

ffmpeg -ss 00:00:05 -i input.mp4 -vframes 1 -f rawvideo -pix_fmt yuv420p - | \
magick -size 1920x1080 -depth 8 -sampling-factor 4:2:0 yuv:- output.jpg

3. Applying Real-Time Image Adjustments

You can apply ImageMagick image manipulation filters directly to the stream:

ffmpeg -i input.mp4 -f rawvideo -pix_fmt yuv420p - | \
magick -size 1280x720 -depth 8 -sampling-factor 4:2:0 yuv:- \
-modulate 110,120 -gaussian-blur 0x1 processed_%03d.png

Troubleshooting Common Issues

  • Distorted, Skewed, or Greyscale Output: Ensure the -size argument matches the exact source video resolution. An incorrect width or height causes the byte alignment to break across Y, U, and V planes.
  • Colorspace Shifts: ImageMagick treats YUV inputs in the standard BT.601 or BT.709 colorspace depending on the version. If colors appear washed out, you can append -colorspace sRGB after the input definition to enforce the target color space.
  • High Bit-Depth Video: For 10-bit YUV streams (yuv420p10le), set -depth 10 or use 16-bit ImageMagick builds (Q16) to prevent quantization clipping.
