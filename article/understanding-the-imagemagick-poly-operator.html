Understanding the ImageMagick Poly Operator

This guide provides an overview of the ImageMagick -poly operator, detailing how it processes multiple images using polynomial weights and exponents. It explains the underlying mathematical formula, command-line syntax, and how individual color channels are computed. Additionally, it highlights practical use cases ranging from simple weighted averaging to complex, non-linear image blending.

What Is the -poly Operator?

The -poly operator in ImageMagick combines a sequence of images into a single output image by applying a polynomial expression to each corresponding pixel across the input stack. Instead of performing standard linear blending or simple arithmetic addition, -poly allows you to define both a scaling coefficient (weight) and an exponent (power) for every image in the sequence.

Mathematical Formula

For a given set of \(N\) images, each with an assigned weight \(w_i\) and power \(p_i\), the resulting pixel intensity (\(I_{\text{out}}\)) is calculated channel-by-channel using the following formula:

\[I_{\text{out}} = \sum_{i=1}^{N} w_i \cdot (I_i)^{p_i}\]

In expanded form:

\[I_{\text{out}} = w_1(I_1)^{p_1} + w_2(I_2)^{p_2} + \dots + w_n(I_n)^{p_n}\]

  • \(I_i\): The pixel value of the \(i\)-th image, normalized between 0.0 (black) and 1.0 (white) within the color space.
  • \(w_i\): The weight factor applied to scale the image intensity. This can be positive or negative.
  • \(p_i\): The exponent applied to the pixel value before multiplying by the weight factor.

Syntax and Argument Structure

The -poly operator requires a quoted string containing space- or comma-separated pairs representing the weight and power for each image:

magick image1.png image2.png -poly "w1,p1 w2,p2" output.png

The number of weight-power pairs must strictly match the number of input images provided in the sequence. If the counts do not match, ImageMagick will generate an error.

Example

magick layer1.png layer2.png -poly "0.5,1.0 0.5,2.0" combined.png

In this command:

  • layer1.png is scaled linearly: \(0.5 \times (layer1)^{1.0}\)
  • layer2.png is modified non-linearly: \(0.5 \times (layer2)^{2.0}\)
  • The two resulting values are added together to form the pixel values of combined.png.

Key Technical Behaviors

  • Channel-by-Channel Evaluation: The polynomial calculation is applied independently to each color channel (Red, Green, Blue, and optionally Alpha) unless limited by the -channel setting.
  • Pixel Value Normalization: By default, pixel intensities are treated as floating-point fractions between 0.0 and 1.0. Applying powers to values in this range alters midtones while anchoring absolute black (0^p = 0) and absolute white (1^p = 1), similar to gamma adjustments.
  • Clipping and HDRI: In standard non-HDRI (High Dynamic Range Imaging) builds of ImageMagick, if the sum of the polynomial exceeds 1.0 or falls below 0.0, the final pixel value is clipped. In HDRI builds, out-of-range values are preserved until explicitly clamped or saved to a dynamic-range-limited format.

Practical Applications

  • Weighted Blending: Setting all exponents to 1.0 allows for precise linear combinations, such as calculating weighted averages across multiple exposures.
  • Non-linear Compositing: Applying exponents other than 1.0 allows you to emphasize highlights or compress shadows in specific layers before merging them.
  • Image Subtraction and Difference Masks: Using negative weights enables the subtraction of one image from another with custom non-linear scaling, useful in astrophotography, noise reduction, and edge detection workflows.
