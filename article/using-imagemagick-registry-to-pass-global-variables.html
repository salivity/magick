Using ImageMagick Registry to Pass Global Variables

In complex ImageMagick processing chains, managing intermediate values and sharing dynamic data across different operations can be difficult without resorting to external shell variables or writing temporary files to disk. The ImageMagick -define registry: syntax provides a built-in, in-memory key-value store that lets you declare global variables at any point in an execution chain and recall them later. This guide explains how to set registry variables, access them using standard string formatting and percent escapes, and apply them across multi-step image transformations.

Setting Registry Variables

You can store a value in the global registry using the -define command-line option. The prefix registry: instructs ImageMagick to store the key-value pair in a global scope rather than attaching it as metadata to a specific image in the current sequence.

The standard syntax is:

-define registry:variable_name=value

Because the registry is scoped globally to the running ImageMagick process, variables defined this way persist across operations, parenthetical subshells, and image sequence manipulations like -delete, -clone, or +insert.

Accessing Registry Variables

To retrieve a value from the registry later in the command, use ImageMagick's percent-escape formatting:

%[registry:variable_name]

This syntax can be embedded anywhere ImageMagick expands format escapes, including -annotate, -label, -format, -crop, or canvas geometry arguments.

Example: Storing and Using Static Values

A common use case is setting a reusable label, color code, or margin that applies to multiple drawing or text-generation steps:

magick -define registry:theme_color="#3498db" \
       -define registry:banner_text="Confidential" \
       -size 800x400 xc:white \
       -fill "%[registry:theme_color]" -draw "rectangle 20,20 780,60" \
       -fill white -pointsize 24 -gravity north \
       -annotate +0+28 "%[registry:banner_text]" \
       output.png

In this command, both theme_color and banner_text are established upfront and injected into drawing and annotation steps downstream without needing external shell string interpolation.

Example: Storing Dynamic Calculations

Registry variables can also capture calculated values from images using -set combined with FX expressions or percent escapes, allowing you to pass metadata derived from one image to a completely unrelated operation.

magick input.jpg \
       -set registry:orig_width "%[w]" \
       -set registry:half_height "%[fx:h/2]" \
       -size "%[registry:orig_width]x%[registry:half_height]" xc:black \
       +swap -gravity south -composite \
       output.jpg

In this pipeline:

  1. input.jpg is loaded.
  2. The image's width is stored into registry:orig_width.
  3. Half of the image's height is calculated using an FX expression and stored in registry:half_height.
  4. A new black canvas is dynamically created matching the original image's width and half its height.
  5. The original image and the newly sized canvas are combined.

Registry vs. Image Attributes

ImageMagick provides image-specific properties (set via -set property:name value), but those attributes belong only to the current image or images selected in the sequence. If you clear the image list, load a new image, or perform transformations that discard attributes, those values are lost.

The registry: namespace bypasses the image list entirely. Once set, a registry variable remains accessible until the ImageMagick execution terminates, making it the ideal mechanism for cross-image calculations, state tracking, and layout coordination.
