WebP Sharp YUV in ImageMagick for Crisp Text

When encoding lossy WebP images containing colored text, high-contrast borders frequently suffer from color bleeding and blurring due to standard chroma subsampling. In ImageMagick, configuring the WebP encoder to use the sharp-yuv algorithm resolves this artifact by switching to an iterative, perceptually optimized RGB-to-YUV conversion. This article explains how ImageMagick implements this setting, how to configure it via the command line, and why it effectively preserves sharp text boundaries.

The Cause of Blurry Colored Borders

Lossy WebP compression defaults to the YUV 4:2:0 color space. In standard 4:2:0 downsampling, color information (chroma) is reduced to half its horizontal and vertical resolution by averaging 2x2 pixel blocks. When a graphic features high-contrast transitions—such as red text against a white background—this simple averaging introduces intermediate color shades at the boundaries. The result is visible fringing, artifacting, and blurred edges around text and iconography.

How Sharp YUV Preserves Edges

The Sharp YUV feature, developed within libwebp, replaces standard linear chroma averaging with an iterative optimization process. Instead of simply downsampling the color channels, Sharp YUV models the upsampling filter that the WebP decoder will eventually use to display the image. It then calculates the optimal 4:2:0 chroma values that, once unpacked and reconstructed by the decoder, will most closely match the original full-resolution RGB pixels. This mathematical alignment prevents color spillover and keeps high-contrast text borders sharp and legible.

Configuring Sharp YUV in ImageMagick

ImageMagick exposes WebP's underlying encoder settings through define switches. To enable Sharp YUV, pass the webp:use-sharp-yuv define set to true:

magick input.png -define webp:use-sharp-yuv=true output.webp

If you are using legacy ImageMagick (version 6), the syntax uses the convert command:

convert input.png -define webp:use-sharp-yuv=true output.webp

Underlying Implementation

Internally, ImageMagick communicates with libwebp using the WebPConfig structure. When the coder processes -define webp:use-sharp-yuv=true, it assigns:

config.use_sharp_yuv = 1;

This instructs the WebP encoder to allocate the necessary processing passes during the color conversion phase. Note that this feature requires ImageMagick to be linked against libwebp version 0.6.0 or newer.

Performance Trade-Offs

Using Sharp YUV does not meaningfully increase the final WebP file size; in fact, it often maintains the same bitrate while improving structural fidelity. However, the iterative optimization algorithm requires additional computational overhead, resulting in encoding times that are typically 1.5 to 2 times slower than default WebP conversions. Because of this, it is best reserved for UI assets, screenshots, typography, and graphics where edge contrast is paramount.
